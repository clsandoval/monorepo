<objective>
Make every recorded decision machine-readable, and link it in both directions with the code or spec
location it governs.

Purpose: ROADMAP Phase 4 criterion 2 requires each recorded decision to be machine-readable and
linked from the specific code location or rule it governs, "so no agent re-decides it later."
Machine-readable alone is not enough: a JSON file nobody's editor opens does not stop an agent
working inside `step7_distribute.rs` from inventing a reading. So the link is built twice — the
registry names the code, and the code names the decision.

Both directions rot differently, and both rots are silent. A registry entry can point at a function
that was renamed; an anchor site can lose its comment in a refactor. Plan 04-04's gate `G10` fails on
either, which is what makes this pair of files a control rather than documentation.

This plan also carries `LAWYER-07`'s second half. `REQUIREMENTS.md:119` asks for the conjugal
family-home reading to be recorded **and the spec hedge removed**. The hedge at
`specs/estate-tax-engine-spec.md:1008` is replaced by a pointer to the recorded decision. It is not
deleted, and it is not rewritten into a statement that Reading A is correct — either of those would
convert a recorded disagreement into an unrecorded ruling on a point of Philippine law.

Output: `.planning/lawyer-decisions.json`, and ten `LAWYER-DECISION` marker comments across seven
Rust files, one TypeScript file, and one spec file.
</objective>
