<objective>
Turn the line model into the pasteable text a lawyer copies (DEED-01).

Purpose: the audit's finding was that this product "computes to the centavo the exact numbers
whose only destination is that deed, and then makes the lawyer retype them into Word." This
module is the first half of the exit. It is a renderer in the exact sense
`frontend/src/lib/form1801-csv.ts` is one: it holds the layout and owns no value.

Output: `frontend/src/lib/deed/clause-text.ts` exporting `buildDeedClauseText` and
`deedClauseBaseName`, plus its test file. Plan 22-04 reuses the returned string as the DOCX
body so the two surfaces cannot disagree, and plan 22-05 renders it on screen.
</objective>

<constraints>
- This module constructs no value. Every peso string is `line.displayAmount` or
  `schedule.statedSumDisplay`, every article comes from `line.articles`, every notice is a
  constant imported from `./schedule-lines`. It must not import `formatDeedPesos` and must
  not call `BigInt`, `Number`, `parseInt` or `parseFloat`.
- Line separator is `\n` everywhere. No `\r`, no `\r\n`. The returned string carries **no
  trailing newline**, so `split('\n')` yields no empty final element and the DOCX gains no
  spurious empty paragraph.
- A refused line prints its refusal and nothing numeric: no `PHP ` token and no article line
  appear anywhere inside a refused heir's block.
- Line numbering runs `1..N` over **all** heir blocks, refused ones included, so a heir's
  position is stable whether or not the engine flagged them.
- Criterion 6: no parties clause, no publication clause, no bond clause, no undertaking, no
  acknowledgment, no *jurat*, no signature block, no notarial block and no operative
  adjudicating sentence. The clause's own scope notice says so on its face.
- No article literal. The module source must contain no match for `Art.` followed by a digit.
- No wall clock, no filesystem, no network.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own.
</constraints>

<threat_model>
A pure string builder over a `DeedSchedule` already computed in the browser. No network, no
filesystem, no persisted write, no authorisation decision.

**T-22-03 — free text becomes structure.** A heir name containing a newline, or the literal
substring `Share: PHP 999.00`, could forge a line inside the clause that a naive reader — or
a naive gate parser — takes for engine output. Severity: medium. Mitigation is placed on the
parser rather than the writer, because mangling a legitimate name is itself a defect on a
legal instrument: plan 22-07's gate aligns clause blocks to `per_heir_shares` **by index**,
not by scanning for the first line that looks like a share, and it compares the block's
rendered name against the engine's `heir_name` character for character. A forged inner line
therefore produces a block-shape mismatch rather than a silently accepted figure. This plan's
contribution is to make that alignment possible: exactly one block per share, in engine
order, separated by exactly one blank line, introduced by the fixed `SHARES` marker line.

**Plain text is inert.** The output of this module is copied to a clipboard and rendered
inside a `<pre>` by React, which escapes. No HTML, no XML and no shell ever consumes this
string directly; plan 22-04 owns the XML escaping for the DOCX surface.

No other threat at or above the configured blocking severity applies to this plan.
</threat_model>

Create `frontend/src/lib/deed/clause-text.ts`.

Open it with a module doc comment in the voice of `frontend/src/lib/form1801-csv.ts`: state
that this module renders and never computes, that every amount and every article arrives
already built from `buildDeedSchedule`, and that a refused line prints no number so a refusal
cannot be mistaken for a share.

Imports: `import type { DeedSchedule } from './schedule-lines';`, a value import of the
constants `DEED_CLAUSE_TITLE`, `DEED_SCOPE_NOTICE`, `DEED_AUTHORITY_NOTICE`,
`DEED_WORDING_OPEN_QUESTION`, `DOCUMENT_REFUSAL_HEADING`, `LINE_REFUSAL_LABEL`,
`REFUSAL_CLOSING` and `SUM_INCOMPLETE_NOTICE` from `'./schedule-lines'`, and
`import { slugifyName } from '../pdf-export';`. That last import follows the precedent already
set by `frontend/src/lib/form1801-csv.ts`, which imports the same symbol from the same module.

Declare three module-level constants used as structural markers the gate anchors on:
`const SHARES_MARKER = 'SHARES';`, `const SHARE_FIELD = '   Share: ';` and
`const ARTICLES_FIELD = '   Governing article(s): ';`. The three leading spaces are part of
the constant.

Export `export function buildDeedClauseText(schedule: DeedSchedule): string`.

Build an array of strings, one per output line, then return `lines.join('\n')`.

Header block, in this exact order:

```
SCHEDULE OF SHARES
<blank>
Estate of: {decedentName}
Date of death: {dateOfDeath}
Net distributable estate as entered: {netEstateDisplay}
<blank>
{DEED_SCOPE_NOTICE}
<blank>
{DEED_AUTHORITY_NOTICE}
<blank>
{DEED_WORDING_OPEN_QUESTION}
<blank>
```

The first line is `DEED_CLAUSE_TITLE`, not a literal.

Document-refusal block, emitted only when `schedule.documentRefusals.length > 0`, and placed
directly after the header block so it precedes every heir line:

```
{DOCUMENT_REFUSAL_HEADING}
- {documentRefusals[0]}
- {documentRefusals[1]}
...
<blank>
```

Heir block section. Emit the marker line `SHARES_MARKER`, then a blank line, then one block
per element of `schedule.lines` in array order, blocks separated by exactly one blank line.
Block `k` (zero-based) for a **stated** line:

```
{k+1}. {heirName} ({categoryLabel})
{SHARE_FIELD}{displayAmount}
{ARTICLES_FIELD}{articles.join('; ')}
```

Block `k` for a **refused** line:

```
{k+1}. {heirName} ({categoryLabel})
   {LINE_REFUSAL_LABEL}
   - {refusalReasons[0]}
   - {refusalReasons[1]}
   ...
   {REFUSAL_CLOSING}
```

Every continuation line inside a refused block is indented by exactly three spaces. Neither
`SHARE_FIELD` nor `ARTICLES_FIELD` appears in a refused block.

When `schedule.lines.length === 0`, emit the single line
`   No heir share was returned by the engine.` in place of the blocks, indented three spaces.

Footer block, after a blank line:

```
Lines stated: {statedCount}
Lines refused: {refusedCount}
Sum of the shares stated above: {statedSumDisplay}
```

and, only when `schedule.refusedCount > 0`, one further line `{SUM_INCOMPLETE_NOTICE}`.

Export `export function deedClauseBaseName(schedule: DeedSchedule): string` returning
`` `deed-schedule-of-shares-${slugifyName(schedule.decedentName)}-${schedule.dateOfDeath}` ``
with no extension. When `slugifyName` returns the empty string, substitute the literal
`unnamed-decedent`, so a blank name cannot produce a filename with two consecutive hyphens.

Create `frontend/src/lib/deed/__tests__/clause-text.test.ts`.

Open it with a provenance comment naming ROADMAP Phase 22 criteria 1, 3, 4 and 6 as what
these tests trace to.

Define local builders at the top exactly as `schedule-lines.test.ts` does, and build the
`DeedSchedule` inputs by calling the real `buildDeedSchedule` on locally-constructed
`EngineInput` and `EngineOutput` objects — never by hand-writing a `DeedSchedule` literal,
because a hand-written schedule would let the two modules drift.

Write these tests.

Header and shape:
- the first line is `SCHEDULE OF SHARES`.
- the text contains `Estate of: ` followed by the decedent name, and `Date of death: `
  followed by the date of death, each on its own line.
- the text ends without a trailing newline: `text.endsWith('\n')` is `false`.
- the text contains no `\r` character.
- `text.split('\n')` has no element with trailing whitespace.

Stated lines:
- a two-heir schedule produces the lines `1. ` and `2. ` in that order, and the heir named
  first in `per_heir_shares` appears in block 1.
- block 1 contains `   Share: PHP ` and `   Governing article(s): `.
- the article line joins a two-element `legal_basis` with `; ` in the engine's order.
- the peso token in block 1 equals `line.displayAmount` from the same `buildDeedSchedule`
  call, compared as an exact string.

Refused lines:
- a heir refused by an empty `legal_basis` produces a block containing
  `MANUAL REVIEW REQUIRED — NO SHARE STATED` and the closing sentence.
- that block contains **no** occurrence of `PHP ` and **no** occurrence of
  `Governing article(s):`.
- the block's number is still its engine position: with heir 2 of 3 refused, the blocks are
  numbered `1.`, `2.` and `3.`.
- a heir refused by a manual-review flag renders the flag's `category` and `description`
  verbatim inside the block.

Document refusals:
- a flag with `related_heir_id: null` puts `MANUAL REVIEW REQUIRED BEFORE THIS SCHEDULE IS
  USED` into the text, at an index **before** the index of the `SHARES` marker.
- with no such flag, that heading does not appear at all.

Footer:
- `Lines stated: 2` and `Lines refused: 1` appear for a three-heir output with one refusal.
- `Sum of the shares stated above: ` is followed by `schedule.statedSumDisplay` exactly.
- the incomplete-sum notice appears when and only when `refusedCount > 0`.

Criterion 6 — the clauses this phase does not ship. Assert the lower-cased text contains none
of these substrings: `parties`, `publication`, `bond`, `undertake`, `undertaking`,
`acknowledg`, `jurat`, `notar`, `witness whereof`, `hereby adjudicate`, `signature`.

Empty output:
- an output with zero `per_heir_shares` renders `No heir share was returned by the engine.`
  and `Lines stated: 0`.

`deedClauseBaseName`:
- for a decedent `Juan Dela Cruz` dead on `2024-03-15` it is
  `deed-schedule-of-shares-juan-dela-cruz-2024-03-15`.
- for a decedent whose name is `!!!` it is
  `deed-schedule-of-shares-unnamed-decedent-2024-03-15`.
