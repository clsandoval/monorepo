<constraints>
- The component composes nothing. It calls `buildDeedSchedule(input, output)` once, passes
  the result to `buildDeedClauseText` and to `buildDeedClauseDocx`, and renders the returned
  string. It must not read `per_heir_shares`, `legal_basis`, `warnings` or any `Money` field
  directly, and it must not contain a `PHP` literal or an article literal.
- Three `data-testid` attributes are fixed contracts that gate G38 selects on and must not be
  renamed: `deed-clause-section` on the section wrapper, `deed-clause-text` on the element
  carrying the clause, and `download-deed-docx` on the DOCX button. The copy control carries
  `copy-deed-clause`.
- `deed-clause-text` must be a `<pre>` whose `textContent` is exactly the builder's string —
  no wrapper spans, no per-line elements, no `whitespace` transformation that alters
  characters. Use Tailwind `whitespace-pre-wrap` for wrapping, which changes rendering and
  not `textContent`.
- The DOCX blob is built with `new Blob([bytes], { type: DOCX_MIME_TYPE })` and the object URL
  is revoked in a `finally` block, matching `downloadJson` in `ActionsBar.tsx`.
- The clause section is mounted **inside** `[data-testid="results-view"]` and **before**
  `<ActionsBar`, so it is part of the results document rather than an action.
- `ResultsView.tsx` changes by exactly one import line and one JSX element. No other line of
  that file is edited.
- Section styling copies `WarningsPanel.tsx`'s existing heading idiom
  (`<h2 className="font-serif text-lg font-semibold text-primary mb-4">`) and the existing
  `Button` primitive from `../ui/button` with `variant="outline"`. No new visual language is
  invented and no new UI primitive is added.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This

  `results-family-tree` perceptual steps will differ further; that is expected, disclosed, and

</constraints>

<threat_model>
A read-only render of data already in the page, plus a client-side download. No network call,
no server, no persisted write, no authorisation decision.

**T-22-05 — clipboard write.** `navigator.clipboard.writeText` is called only in the copy
handler, only with the clause string, and only in response to a user click. The same call
already exists at `ActionsBar.tsx` in `handleCopyNarratives`. It writes and never reads, so no
clipboard content leaves the page.

**T-22-05b — object-URL leak.** An object URL that is created and not revoked pins its blob
for the lifetime of the document. Severity: low, but the deed blob grows with the heir count
and the button is repeatable. Mitigation: `URL.revokeObjectURL` in a `finally`, and a test
asserting `revokeObjectURL` was called with the URL `createObjectURL` returned.

**T-22-05c — a name rendered as markup.** React escapes text children by construction, and
the clause is rendered as a single text child of a `<pre>`. `dangerouslySetInnerHTML` must not
appear anywhere in the component.

No other threat at or above the configured blocking severity applies to this plan.
</threat_model>

Body:

- `const schedule = useMemo(() => buildDeedSchedule(input, output), [input, output]);`
- `const clauseText = useMemo(() => buildDeedClauseText(schedule), [schedule]);`
- `handleCopy` calls `navigator.clipboard.writeText(clauseText)`, guarded by
  `if (typeof navigator !== 'undefined' && navigator.clipboard)`.
- `handleDownloadDocx` builds `const bytes = buildDeedClauseDocx(schedule)`, then
  `const blob = new Blob([bytes], { type: DOCX_MIME_TYPE })`, then
  `const url = URL.createObjectURL(blob)`, then creates an `<a>`, sets `href` to the url and
  `download` to `` `${deedClauseBaseName(schedule)}.docx` ``, calls `a.click()`, and revokes
  the url in a `finally` block.

Markup:

```
<section data-testid="deed-clause-section" className="space-y-3">
  <Separator />
  <h2 className="font-serif text-lg font-semibold text-primary mb-4">Schedule of Shares — Deed Clause</h2>
  <p className="text-sm text-muted-foreground">{DEED_CLAUSE_INTRO}</p>
  <pre data-testid="deed-clause-text" className="whitespace-pre-wrap break-words rounded-md border bg-muted/40 p-4 font-mono text-xs leading-relaxed">{clauseText}</pre>
  <div className="flex flex-col sm:flex-row gap-2 sm:gap-3">
    <Button type="button" variant="outline" data-testid="copy-deed-clause" onClick={handleCopy}>
      <Copy className="size-4" />
      Copy Clause
    </Button>
    <Button type="button" variant="outline" data-testid="download-deed-docx" onClick={handleDownloadDocx}>
      <FileDown className="size-4" />
      Download DOCX
    </Button>
  </div>
</section>
```

`DEED_CLAUSE_INTRO` is a module-level constant in this file with the exact value
`Paste this clause into the schedule section of your Deed of Extrajudicial Settlement. Every stated line carries the article the engine emitted for that heir.`

The `<pre>` takes `clauseText` as its single child expression so its `textContent` is the
builder's string unchanged. Do not wrap lines in elements and do not use
`dangerouslySetInnerHTML`.
