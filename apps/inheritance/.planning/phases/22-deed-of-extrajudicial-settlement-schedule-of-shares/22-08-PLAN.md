<objective>
Register the deed-parity gate so the coverage is permanent, and make the planning directory
tell the truth about it.

Purpose: CLAUDE.md invariant 2 says the gate set may only grow, and gate G5
(`node scripts/check-gate-manifest.mjs`) enforces it in both directions — a manifest gate
absent from the lock raises `UNLOCKED GATE`. Gate G33
(`node scripts/check-planning-truth.mjs`) additionally holds `.planning/ORIENTATION.md`'s
`The gate set holds N gates.` sentence and `RESUME.md`'s `ALL GATES PASSED (N/N)` sentence
against the manifest length, so a new gate that is not written into both files turns G33 red.

Output: 37 registered gates, a GATES.md section 28, and two updated counts.
</objective>

<constraints>
- **Order 35, deliberately.** `bash scripts/ci-gates.sh` exits 1 at G17, which sits at order
  15. A gate registered before that halt would move the halt earlier and cost the run the
  gates it reaches today — the trap that blocked Phase 20's G36 registration. G37 was placed
  at order 34 for the same reason and its ROADMAP row records it.
- `G8` (order 35) becomes 36 and `G9` (order 36) becomes 37, so G9 stays last. `order` is the
  only field that may change on any existing gate; every other field of every other gate must
  be byte-identical after the edit.
- The lock gains exactly one entry. No lock entry is removed, retyped or reordered.
- `blocking` is `true`. A new gate registered non-blocking is coverage that cannot fail.
- **`bash scripts/ci-gates.sh` exit 0 is not claimed.** The three owner-blocked causes stand
  and this phase touches none of them: the fifteen journey steps withheld for human review
  since Phase 16, G20 whose script commit `4ccf06270` deleted while its precondition still
  passes, and G21 which exits 2 because both `seo-smoke.mjs` and `seo-routes.json` are gone.
  Retiring or repairing any of them is owner action under CLAUDE.md invariant 2.
- The `proves` string states what the gate proves and cites its GATES.md section, in the style
  of G37's. It must not overstate: the gate does not prove the DOCX opens in Microsoft Word.
- No baseline, ledger, lock floor, lawyer decision or engine file is touched.
</constraints>

<threat_model>
Configuration and documentation changes. No runtime code, no network, no user data.

**T-22-08 — a registration that silently weakens the gate set.** The manifest and its lock are
the project's only defence against coverage quietly shrinking, and this plan edits both.
Severity: high, because a weakening here is invisible at runtime and permanent. Mitigations,
all required below: `node scripts/check-gate-manifest.mjs` is run and its output pasted; a
scripted comparison proves that `order` is the only field that differs on any pre-existing
gate; the lock diff is asserted to be additions only; and the manifest length is asserted to
be exactly 37.

**T-22-08b — a `proves` string that promises more than the gate delivers.** A future reader
trusts `proves`. Mitigation: the string names the two surfaces compared and the same-run
computation, and GATES.md section 28 carries an explicit "what this does not prove"
paragraph.

No other threat at or above the configured blocking severity applies to this plan.
</threat_model>
