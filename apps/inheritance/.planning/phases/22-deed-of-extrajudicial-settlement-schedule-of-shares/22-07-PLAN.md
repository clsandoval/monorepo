<objective>
Prove DEED-05: every peso figure in the clause equals the engine's centavo value exactly,
against a computation performed in the same run, on both surfaces.

Purpose: ROADMAP criterion 5. `22-RESEARCH.md` §7 designed the gate from the two that already
do this job — `journey/money-parity.mjs` (G19) for the succession screen and
`journey/return-parity.ts` (G37) for the return. `steps/output.json` records why a seeded
engine result is prohibited: `scripts/check-seed-fixture.mjs` rejects a seeded `output_json`
with `SEED WRITES OUTPUT` — "a seeded engine result is a per-heir peso figure nothing
computed." So the gate makes the product compute in a real browser and compares what it
prints.

Output: `frontend/journey/deed-parity.ts` and the observation record proving it was seen red
on four injections before anyone trusted it. Registration is plan 22-08's job; this plan runs
the gate directly.
</objective>

<constraints>
- Every comparison is exact `BigInt` equality. No tolerance constant, no epsilon, no
  `Math.abs`, no rounding helper anywhere in the file.
- No expected figure is committed. The only fixture input is the Alpha case's existing
  `input_json`, already in `frontend/supabase/fixtures.json`; no new fixture file is created.
- The gate parses and never formats. `parseDeedPesos` is the exact inverse of
  `formatDeedPesos`, and no formatting helper is written inside the gate — a formatter here
  would make the gate agree with itself rather than with the product.
- Every comparison runs in both directions: every heir the engine returned appears in the
  clause, and every block the clause prints corresponds to a heir the engine returned.
- Read-only. The gate never writes a file, never mutates a database row other than through the
  existing `RESETS['case-alpha-no-output']` helper, and has no flag other than the absence of
  flags. `--fix`, `--update`, `--accept`, `--regenerate`, `--approve` and `--force` must not
  appear in the source.
- Exit contract is the project's three-valued one: 0 passed, 1 failed, 2 could not run, with
  `DEED PARITY CANNOT RUN:` on stderr for the last. A missing local Supabase stack, an absent
  chromium and a failed preview build are all cannot-run, never failures.
- The gate prints a `GATE-SKIPS total=<n> skipped=0` line on every exit path, matching the
  convention gate G8 enforces on gate logs.
- `bash scripts/ci-gates.sh` exits 1 at G17 on this branch. This plan runs `deed-parity.ts`
  directly and makes no claim about the suite.
</constraints>

<threat_model>
A read-only verification harness. It runs only against the local Supabase stack and a local
preview build, and it is never shipped to a user.

**T-22-07 — a gate that passes because it measured nothing.** This is the real hazard and it
is not hypothetical: `21-GATE-OBSERVATIONS.md` records that two of G37's four injections
initially PASSED, one because a whole-document substring search was satisfied by an unrelated
row carrying the same amount, and one because a row dropped from the shared model shrank the
expectation and every surface together. Severity: high, because a gate believed to be
protecting a peso figure and protecting nothing is worse than no gate. Mitigations, all
required by this plan: the `DEED PARITY COMPARED NOTHING` guard; index-aligned block-to-share
mapping rather than substring search; an exact multiset comparison of every `PHP ` token in
the clause against the multiset the engine implies; bidirectional set comparison; and the four
observed-red injections in task 2.

**T-22-07b — credentials in the harness.** The gate reads the local stack's service key
through the existing `readStackEnv` / `adminClient` helpers and introduces no new secret, no
new environment variable and no new network destination.

No other threat at or above the configured blocking severity applies to this plan.
</threat_model>

Create `frontend/journey/deed-parity.ts`, modelled structurally on
`frontend/journey/return-parity.ts`. Copy that file's header-comment discipline: state what
the gate proves, that the expectation is computed and never stored, that every comparison is
exact BigInt, that the gate parses and never formats, that the comparison runs in both
directions, that a zero-comparison run is a failure, and that there is no exception list, no
baseline and no mutating flag.

Imports, using the same `@ts-expect-error` idiom `return-parity.ts` uses for the untyped
`.mjs` journey helpers: `readStackEnv`, `adminClient`, `getSession` from `./session.mjs`;
`readFixtures`, `seedAuthSession` from `./seed.mjs`; `buildApp`, `startPreview`,
`JourneyCannotRun` from `./serve.mjs`; `launchBrowser`, `newJourneyPage` from `./browser.mjs`;
`RESETS` from `./resets.mjs`; `computeEngineOutput` from `./engine.mjs`. Typed imports:
`buildDeedSchedule` from `../src/lib/deed/schedule-lines`, `buildDeedClauseText` from
`../src/lib/deed/clause-text`, `extractDocxParagraphs` and `DOCX_PART_NAMES` from
`../src/lib/deed/docx`, and `import fs from 'node:fs'`.

Constants: `const SETTLE_MS = 4000;` with a comment citing `steps/output.json`'s measured
reason (the `React.lazy` chunk and the 1500 ms Recharts animation), and
`const DOWNLOAD_TIMEOUT_MS = 60000;` matching `return-parity.ts`.

Write `export function parseDeedPesos(text: string): bigint`, the exact inverse of
`formatDeedPesos`: trim, require the literal prefix `PHP `, strip it, remove `,`, require the
remainder to match `/^\d+\.\d{2}$/`, and return `BigInt(pesoPart) * 100n + BigInt(centPart)`.
Anything else throws `` new Error(`DEED PESO UNPARSEABLE: ${JSON.stringify(original)}`) ``.
There is no sign handling: a deed line never states a negative amount, and a leading minus
must throw rather than be stripped.

Write `function readStoredZipParts(bytes: Uint8Array): Map<string, string>` — the archive
reader described in plan 22-04 task 2: scan backwards for the End of Central Directory
signature `0x06054b50`, read the entry count and the central-directory offset, walk each
46-byte central header reading the name length, extra length, comment length, compressed size
and local-header offset, then at each local-header offset verify the signature `0x04034b50`,
skip `30 + nameLen + extraLen`, slice `compressedSize` bytes and decode as UTF-8. Throw a
`JourneyCannotRun` on any signature mismatch — a malformed archive is an environment verdict
about the harness, and the FIGURE checks below are what report a product defect.

Write `function parseClauseBlocks(text: string): { number: number; header: string; name: string; label: string; body: string[] }[]`.
Locate the line equal to `SHARES`, take everything after it, split on `\n\n` into blocks,
drop the trailing footer block (the first block after the marker whose first line matches
`/^Lines stated: /`, and everything from it onward), and for each remaining block match its
first line against `/^(\d+)\. (.*) \(([^()]*)\)$/`, throwing
`` new Error(`DEED BLOCK UNPARSEABLE: ${JSON.stringify(firstLine)}`) `` when it does not
match. The `([^()]*)` group anchors on the LAST parenthesised run, so a heir name containing
parentheses still parses. The remaining lines of the block are its `body`.

`async function main()`:

1. `readStackEnv()`; when it is `null` or has no `API_URL`, call `cannotRun('local Supabase
   stack is not running')`.
2. `readFixtures()`, take `fixtures.orgs.alpha.case_id`, build the `adminClient`.
3. `await RESETS['case-alpha-no-output'](admin)`.
4. Read `cases.input_json` for that id; a read error or a null value is a `JourneyCannotRun`.
5. `const expected = await computeEngineOutput(input);` — **the expectation, computed this run.**
6. `const expectedSchedule = buildDeedSchedule(input, expected);` and
   `const expectedText = buildDeedClauseText(expectedSchedule);`
7. `buildApp()`, `startPreview()`, `launchBrowser()` — each failure a `JourneyCannotRun` with
   the same wording `return-parity.ts` uses.
8. `getSession(env, 'alpha')`, `newJourneyPage(browser)`, `seedAuthSession(...)`,
   `page.goto(`${origin}/cases/${caseId}?step=4`, { waitUntil: 'load' })`,
   `waitForSelector('[data-testid="review-step"]')`,
   `click('[data-testid="compute-distribution"]')`,
   `waitForSelector('[data-testid="results-view"]')`,
   `waitForSelector('[data-testid="deed-clause-section"]')`,
   `waitForTimeout(SETTLE_MS)`.
9. Read the screen clause:
   `const screenText = await page.$eval('[data-testid="deed-clause-text"]', (el) => el.textContent ?? '');`
   Use `textContent`, never `innerText`: `innerText` applies CSS whitespace collapsing and
   would destroy the three-space indentation the block grammar depends on.
10. Click `[data-testid="download-deed-docx"]` inside a `page.waitForEvent('download', {
    timeout: DOWNLOAD_TIMEOUT_MS })` race, exactly as `return-parity.ts:256-293` does; a
    missing download or a missing `path()` is a `JourneyCannotRun`. Read the bytes with
    `fs.readFileSync` and assert the first two bytes are `0x50 0x4b`; anything else is a
    `JourneyCannotRun` naming the observed bytes.

Comparisons. Collect every failure into a `failures` array and report them all rather than
throwing on the first.

- `DOCX PART SET MISMATCH` — the keys of `readStoredZipParts(docxBytes)`, in order, do not
  equal `DOCX_PART_NAMES`.
- `DOCX TEXT MISMATCH` — `extractDocxParagraphs(parts.get('word/document.xml'))` joined with
  `\n` does not equal `screenText`. Report the first differing line index and both lines.
- `CLAUSE TEXT MISMATCH` — `screenText` does not equal `expectedText`. This is the check that
  ties the browser to the engine run; the two below then locate the defect precisely.
- `HEIR LINE MISSING` / `HEIR LINE INVENTED` — the block count from
  `parseClauseBlocks(screenText)` differs from `expected.per_heir_shares.length`; report which
  direction and the two counts.
- For each index `k` with a block and a share: `DEED HEIR NAME MISMATCH` when the block's
  parsed `name` differs from `expected.per_heir_shares[k].heir_name`.
- `DEED AMOUNT MISMATCH` — for a block whose body has a line starting with `   Share: `,
  `parseDeedPesos` of the remainder does not equal
  `BigInt(expected.per_heir_shares[k].net_from_estate.centavos)`. Report both integers and
  their difference.
- `DEED AUTHORITY MISMATCH` — for a block whose body has a line starting with
  `   Governing article(s): `, the remainder split on `'; '` does not deep-equal
  `expected.per_heir_shares[k].legal_basis` as an ordered list. Report both lists.
- `REFUSAL SET MISMATCH` — the set of indices whose block contains
  `MANUAL REVIEW REQUIRED — NO SHARE STATED` does not equal the set of indices where
  `expectedSchedule.lines[k].kind === 'refused'`. Report both sets.
- `REFUSED LINE CARRIES AMOUNT` — a refused block contains the substring `PHP `.
- `PESO TOKEN MULTISET MISMATCH` — the multiset of every `PHP `-prefixed token found in
  `screenText` by the global regex `/PHP [\d,]+\.\d{2}/g` does not equal the multiset of the
  same tokens found in `expectedText`. This is the check that catches an amount printed in a
  place the block grammar does not reach, which is the shape of the defect that let two of
  G37's injections initially pass.
- `DEED PARITY COMPARED NOTHING` — the number of blocks compared is zero. A run that measured
  nothing is a failure.

On success print `DEED PARITY PASS blocks=<n> stated=<n> refused=<n> docxParagraphs=<n>` and
the `GATE-SKIPS total=<n> skipped=0` line, and exit 0. On failure print every entry of
`failures`, print the skip line, and exit 1. On `JourneyCannotRun` print
`DEED PARITY CANNOT RUN: <reason>` on stderr, print the skip line, and exit 2. Close the page,
the browser and the preview in `finally` blocks, matching `return-parity.ts`.
