<objective>
Write the deterministic, dependency-free ZIP writer the DOCX exporter is built on.

Purpose: `22-RESEARCH.md` §3 measured that `frontend/package.json` holds no ZIP library —
`jszip` was removed by the deletion milestone and there is no `fflate`, no `pizzip` and no
`adm-zip`. ROADMAP Phase 26 pins the runtime dependency count as one of five locked numbers,
so a 25th runtime dependency has a standing cost. A `.docx` is an OPC package, OPC permits
stored (uncompressed) entries, and a stored-entry writer is a fixed header layout plus a
CRC-32 with no compressor and no options. It is also the only version of this that is
byte-deterministic, which is what lets a test assert exact bytes and lets the phase-24 input
hash exist later.

Output: `frontend/src/lib/deed/zip.ts` exporting `buildStoredZip` and `crc32`, plus its test
file. This plan writes no DOCX, no clause and no XML — it produces one general-purpose
archive primitive and proves it byte for byte.
</objective>

<constraints>
- Zero dependencies. The module imports nothing at all: not `node:zlib`, not `node:buffer`,
  not any `@/` path. It runs unchanged in the browser, in jsdom and in `tsx`.
- Method 0 (stored) only. No deflate path is written, no compression level exists and no
  option selects one. The payload bytes are copied verbatim into the archive.
- No wall clock. Every entry's DOS modification date is the constant `0x0021`
  (1980-01-01) and every time is `0x0000`. `new Date()`, `Date.now()` and
  `performance.now()` must not appear anywhere in `frontend/src/lib/deed/`.
- No ZIP64, no data descriptors, no extra fields, no archive comment, no encryption, no
  UTF-8 general-purpose flag bit. All three DOCX part names are pure ASCII, so bit 11 stays
  clear.
- All multi-byte integers are little-endian and are written through `DataView` with the
  explicit `true` little-endian argument at every call site.
- The module never reads a file, never writes a file and never touches the network.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own.
  This plan runs the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A pure byte-layout function over caller-supplied names and payloads. No network, no
filesystem, no authorisation decision, no persisted state.

**T-22-01 — archive-entry injection through a caller-supplied name.** A ZIP entry name is a
path. A name containing `../` or an absolute prefix produces an archive that writes outside
its extraction root when a naive extractor unpacks it. Severity: medium in general, but the
exposure here is nil by construction and the plan keeps it that way — every entry name passed
to `buildStoredZip` in this codebase is one of three module-level string constants declared
in `frontend/src/lib/deed/docx.ts` (plan 22-04), and no user-supplied string ever becomes an
entry name. `buildStoredZip` additionally refuses a name that is empty, begins with `/`,
contains `\\`, or contains a `..` path segment, throwing rather than emitting the entry. The
decedent's name reaches the DOCX only as escaped XML *content*, never as a part name.

**Payload aliasing.** `buildStoredZip` copies every payload into the output buffer and
retains no reference to a caller array, so a caller mutating its input after the call cannot
change an archive already produced.

No other threat at or above the configured blocking severity applies to this plan.
</threat_model>

Export exactly two symbols.

1. `export function crc32(bytes: Uint8Array): number`

Standard IEEE CRC-32, reversed polynomial `0xEDB88320`. Build a 256-entry `Uint32Array`
lookup table once at module load in a module-level `const CRC_TABLE`, using the eight-shift
inner loop. The function starts at `0xFFFFFFFF`, folds each byte with
`crc = (crc >>> 8) ^ CRC_TABLE[(crc ^ byte) & 0xff]!`, and returns `(crc ^ 0xFFFFFFFF) >>> 0`.
The non-null assertion is required because `frontend/tsconfig.json` sets
`noUncheckedIndexedAccess: true`.

2. `export function buildStoredZip(entries: ZipEntry[]): Uint8Array`

with `export interface ZipEntry { name: string; data: Uint8Array }` also exported.

Validation, before any byte is written. For each entry, throw
`new Error('ZIP ENTRY NAME REJECTED: ' + JSON.stringify(name))` when the name is the empty
string, starts with `/`, contains a backslash, or has any `/`-separated segment equal to
`..`. Throw `new Error('ZIP DUPLICATE ENTRY NAME: ' + JSON.stringify(name))` when two
entries share a name. Throw `new Error('ZIP NO ENTRIES')` when `entries` is empty — an empty
archive is never something this codebase means to produce.

Encode each name with `new TextEncoder().encode(name)` and require the result to be pure
ASCII (every byte below `0x80`); throw `new Error('ZIP ENTRY NAME NOT ASCII: ' + ...)`
otherwise, because the general-purpose UTF-8 flag bit stays clear.

Layout, written in entry order, all integers little-endian through
`view.setUint16(off, v, true)` and `view.setUint32(off, v, true)`. Declare the three
constants `const DOS_DATE = 0x0021;` (1980-01-01), `const DOS_TIME = 0x0000;` and
`const VERSION = 20;` at module level with a comment naming what each fixes.

Local file header, 30 bytes plus the name:
