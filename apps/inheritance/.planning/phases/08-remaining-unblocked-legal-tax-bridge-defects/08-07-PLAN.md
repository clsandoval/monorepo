<objective>
Make a reserva troncal fact pattern impossible to compute silently.

`.planning/research/LEGAL-CONFORMANCE.md` §4 records the defect: Art. 891 attaches to *specific
property* by how the propositus acquired it and from which line, and `EngineInput` is a single scalar
`net_distributable_estate` with no asset inventory and no provenance fields, so the rule is
structurally unimplementable. The aggravating factor is that the spec **advertises** a
`RESERVA_TRONCAL` flag at `specs/inheritance-engine-spec.md:2313` and a `RESERVATION` narrative section
at `:2123`, so an engine that says nothing reads as "checked, nothing found."

Phase 5 built half the answer. `engine/src/flags.rs:31` declares `SPEC_FLAG_RESERVA_TRONCAL`,
`:122-128` detects it from `facts.reserva_troncal_property_present`, `engine/src/types.rs:366` declares
the field, and `scripts/check-observability.mjs` already requires all ten spec flag codes to be
declared and exercised. `frontend/src/types/index.ts:268` and `frontend/src/schemas/index.ts:670`
mirror the field on the TypeScript side.

What is missing is that the fact is unreachable and unstated. `grep -rn "manual_review_facts"
frontend/src --include=*.tsx` returns **zero** hits: no wizard control writes it, so in the running
product the flag can never fire. And no spec sentence says the reservation is not computed.

Output: one wizard control, one named engine vector proving the flag reaches output, and an express
spec declaration. No engine source file is edited — the detector already exists and already works.
</objective>
