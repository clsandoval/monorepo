<objective>
Put the refusal on the face of the return.

`20-RESEARCH.md` §1 measured that `Form1801View.tsx` ends at `Net Estate Tax Due` and prints no total
amount due at all — so today the false total is invisible on screen and lives only in
`cases.tax_output_json`. After `20-04` the engine carries a `penalties` object; this plan is what makes
a lawyer looking at the return see it.

Roadmap criterion 5 requires the compromise penalty to be *"expressly declared outside the engine's
competence **on the face of the return**"*, and criterion 2 requires each line to carry the section
that governs it. Four new rows and one note satisfy both:

| Item cell | Description cell | Total cell |
|---|---|---|
| `S-248` | `Surcharge — NIRC Sec. 248` | `NOT COMPUTED` |
| `I-249` | `Interest — NIRC Sec. 249` | `NOT COMPUTED` |
| `CP` | `Compromise penalty` | `OUTSIDE ENGINE COMPETENCE` |
| `Total` | `Total Amount Due` | `NOT A TOTAL — SEE NOTE BELOW` |

followed by a paragraph carrying `penalties.refusal` verbatim from the engine.

The words matter as much as the arithmetic. A row reading `0.00` and a row reading `NOT COMPUTED` are
the difference between a return that quietly understates a liability and a return that tells its
reader where the number has to come from.
</objective>

<constraints>
- Every displayed string is either a literal fixed in this plan or a value read from the engine's
  `penalties` object. The component computes no amount, formats no penalty figure and constructs no
  section citation.
- The description cells carry `line.authority` read from the engine for the two statutory rows, not a
  hardcoded `NIRC Sec. 248` literal. Gate `G14` fails a display layer that hardcodes an attribution;
  the literal appears in the plan so the test can assert the rendered text, and in the engine so the
  component can read it.
- The four rows render on every computation, including a zero-tax estate. A return with no tax still
  has an unknown penalty position, and hiding the rows when the tax is zero would restore the silence.
- When `penalties.complete` is true the four rows render the real figures through the existing peso
  formatter and the note is not rendered. That branch is unreachable today and is written now so the
  component does not need editing on the day the lawyer answers.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan runs
  the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A read-only presentational component rendering values from an in-memory object. No input, no network
call, no storage access, no authorisation decision.

The one hazard worth naming is **rendering attacker-influenced text as markup**. The refusal string is
built entirely from constants in `penalties.ts` plus two ISO date strings and an integer day count, and
React escapes text children by default. The component must render the refusal as a text child and must
not use `dangerouslySetInnerHTML`; Task 3 greps for that.

The second hazard is presentational and is the reason this plan exists: a currency formatter applied to
`null` produces `0.00` in this codebase's `formatPesos`, because `null / 100` is `0`. That would print
the exact number the phase is removing, on the exact document a lawyer signs. The defence is that the
declined branch never reaches the formatter, and Task 3 asserts the absence of `0.00` in the four rows
rather than only the presence of the words.

Severity: low technically, high in consequence — this is the surface where a wrong number becomes a
filed one.
</threat_model>
