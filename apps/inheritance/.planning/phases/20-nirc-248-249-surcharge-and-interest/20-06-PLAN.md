<objective>
Write the gate that keeps Phase 20 true after Phase 20 stops watching, and watch it fail before anyone
trusts it.

The failure this gate exists to catch is specific and predictable: **a future agent supplies a rate
because a consumer needed a number.** Nothing else in the repository would notice. The type system
accepts `0.25` as readily as `null`; the unit tests would be updated in the same edit; the display
would render a peso figure and look more finished than before. The only durable defence is a check that
asserts what is *absent*.

`frontend/scripts/check-penalty-refusal.ts` makes six assertions, each with its own literal marker so a
red run says which rule broke:

| Marker | What it catches |
|---|---|
| `SILENT ZERO SURVIVES` | a hardcoded penalty zero, or a total assigned from the base tax, back in `pipeline.ts` |
| `WALL CLOCK IN ENGINE` | any `new Date()` under `src/lib/estate-tax-engine/` |
| `TOTAL CLAIMS COMPLETENESS` | a real computation publishing a non-null total while any line is declined |
| `LINE MISSING ITS SECTION` | a penalty line with an empty `authority`, or a determined line still carrying a `lawyerDecision` |
| `RATE INVENTED` | a numeric literal in `penalties.ts` outside the fixed whitelist, or a `%` or `Math.round` |
| `DECLINED LINE UNRECORDED` | a declined line whose `lawyerDecision` id is not in `.planning/lawyer-decisions.json` |

Plus two error markers that refuse to pass: `CORPUS EMPTY` at exit 1 when zero cases were examined, and
`PENALTY CHECK CANNOT RUN:` at exit 2 when the environment, not the product, is at fault.

`RATE INVENTED` is the load-bearing one. The other five catch a regression; that one catches the
decision this whole phase was arranged to prevent, at the moment it is made.
</objective>

<constraints>
- The script is a **read-only runner**. It imports the real engine and the real registry and asserts.
  It contains no copy of the deadline rule, no copy of the sum rule and no expected peso figure.
- Its only flags are read-only path overrides: `--src` for the source directory and `--registry` for
  the decisions file, both existing so the empty-corpus path and a fixture registry can be driven. No
  flag writes anything.
- Exit codes: `0` clean, `1` violations or an empty corpus, `2` and only `2` for an environment
  failure, matching the project's `GATE CANNOT RUN` convention in `.planning/PLAN-STANDARD.md` §3.
- Every exit path prints `GATE-SKIPS total=<n> skipped=0`, which gate `G8` requires.
- `DECLINED LINE UNRECORDED` asserts **existence** of the id in the registry, never its status. An
  assertion that the status is still `awaiting-answer` would turn this gate red on the day the lawyer
  answers, and a gate whose correct fix is to weaken it is a gate that gets weakened.
- The numeric-literal whitelist is exactly `0`, `1`, `2`, `6`, `10`, `12`, `86400000`, and the check is
  a subset test: a literal outside the set is a violation; a whitelisted literal that disappears is
  not.
- This plan does not touch `gates.manifest.json`, `gates.manifest.lock`, `GATES.md`,
  `.planning/ORIENTATION.md` or `RESUME.md`. Registration is `20-07`.
- Every injected regression is reverted before the next one, and the working tree is proven clean
  before the commit.
</constraints>

<threat_model>
The script reads TypeScript source and one JSON file, imports the estate-tax engine in-process, and
prints. It opens no socket, needs no database, needs no browser and needs no built WASM artifact —
unlike `G34` and `G35`, this gate is pure TypeScript, which is why it can sit early in the order.

The hazard unique to gate scripts is **certifying its own absence**: a source scan whose glob matches
nothing prints no violations and exits 0 forever. Three defences are built in. A counter of examined
items is incremented at every check and a zero total exits 1 with `CORPUS EMPTY`. An unreadable
`penalties.ts`, an unresolvable engine import or an unparseable registry exits 2 rather than skipping a
check. And the computation check requires a **positive** `penalties.lines.length` of exactly three, so
an engine returning an empty tuple fails rather than passes.

The second hazard is this plan's own method: it deliberately injects four regressions into committed
source. Each injection is a single-line edit, reverted with `git checkout --` on the named path
immediately after the observation, and Task 6 proves `git status --porcelain` is clean before anything
is staged.

Severity: low, provided the revert discipline in Task 5 is followed exactly.
</threat_model>
