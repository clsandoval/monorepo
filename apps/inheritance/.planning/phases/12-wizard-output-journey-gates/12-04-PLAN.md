<objective>
Give every tab of the estate-tax wizard a passing screenshot-plus-rubric gate — ROADMAP Phase 12
criterion 2, requirement JRNY-06.

`12-RESEARCH.md` §4.2 measured all eight. `TAB_COUNT` is `8` at `src/types/estate-tax.ts:282`, every
tab component already carries a root testid, the tab strip renders a button per tab with
`data-testid="tab-<i>"` and `aria-selected`, and Phase 10's `?tab=` seam is read once at mount by
`readInitialTab()`.

The plan asserts the pairing rather than the panel alone: for tab *n*, `tab-<n>` has
`aria-selected` `"true"` **and** the matching panel root is visible **and** one non-matching panel
root is absent. A tab strip that highlights one tab while rendering another is exactly the defect a
screenshot alone would freeze as correct.

`12-RESEARCH.md` §4.2 also records the decision this plan does not have to make: **no
`tax_input_json` is seeded.** `$caseId.tax.tsx:56` applies a stored blob only when present, so the
eight tabs render from `createDefaultEstateTaxState()`. Seeding one would mean inventing property
valuations and deduction figures; the default state is deterministic, renders every tab, and carries
no legal content at all.

Output: one registry file holding eight step records, eight rubrics, eight approved references with
zero-tolerance sidecars.
</objective>

<constraints>

1. **No step performs a `fill` or a `click`.** `EstateTaxWizard` autosaves `tax_input_json`, so an
   interaction would leave the fixture different from how it started and run two would assert against
   a different row than run one. Every record's `actions` array holds `waitForSelector` entries only,
   and every record's `reset` is `"noop"` — the explicit declaration that the step mutates nothing.

2. **`frontend/supabase/seed.sql` and `frontend/supabase/fixtures.json` are not edited.** No
   `tax_input_json` is seeded, for the reason in `<objective>`.

3. **A reference is approved only after that tab's rubric has already passed**, and
   `maxDiffPixels` stays `0` on every sidecar. `node journey/approve.mjs <stepId>` is the only writer
   into `frontend/journey/references/`.

4. **No application source file is edited by this plan.** All eight root testids and all eight tab
   buttons already exist, verified one file at a time in `12-RESEARCH.md` §4.2. A missing hook is a
   BLOCKED report, not an edit here.

5. **No rubric assertion carries a peso figure.** The default tax state renders zeroes and empty
   inputs; asserting one would pin a formatting detail with no verification value, and money parity
   is plan 12-08's gate.

6. **`allowConsoleErrors` is `false` on all eight steps.** No tab has a reason to log an error, and
   using the flag to silence one a gate just found is prohibited.

7. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

8. **No point of Philippine law and no point of Philippine tax law arises in this plan.** Every
   assertion is a testid, an aria attribute or a tab label copied from `TAB_NAMES`.

</constraints>

### The eight rubrics

`{ "rubricId": "tax-tab-<n>", "assertions": [ … ] }`, five assertions each:

| assertion `id` | `kind` | fields |
|---|---|---|
| `wizard-visible` | `element_visible` | `[data-testid="estate-tax-wizard"]` |
| `panel-visible` | `element_visible` | the panel root selector for this tab |
| `tab-selected` | `attribute_equals` | selector `[data-testid="tab-<n>"]`, `attr` `aria-selected`, `expect` `"true"` |
| `other-panel-absent` | `element_absent` | the panel root selector of a **different** tab, chosen as tab `(n + 1) % 8`'s panel |
| `no-console-error` | `no_console_error` | none |

`element_visible` fails when more than one element matches, which is what makes `panel-visible`
meaningful: `EstateTaxWizard` renders exactly one panel at a time.

### The measurement that precedes everything

Assumption A1 in `12-RESEARCH.md` — that `?tab=` survives on this route in a built application — is
unmeasured. Task 1 measures it for all eight values before any rubric is written.
