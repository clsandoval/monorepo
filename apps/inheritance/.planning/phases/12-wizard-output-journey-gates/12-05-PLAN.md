<constraints>

1. **No application source file is edited.** No `data-testid` is added to any landing or blog route.
   The `h1` marker already exists in all three layout components.

2. **No dependency is installed and no `package.json` is edited.** The script imports
   `journey/browser.mjs` and `journey/serve.mjs`, both of which already exist, plus `node:`
   builtins.

3. **The exit contract is the project's three-valued one.** `0` every route passed, `1` at least one
   route failed, `2` the check could not start. A missing chromium, a failed `npm run build` or a
   preview server that will not bind is exit `2` with a `SEO CANNOT RUN:` prefix — never exit 1.
   Conflating the two is how a month-long loop silently redefines success.

4. **The route list is data, never derived at run time.** The script does not scan `src/routes/` to
   discover routes. A generated list would silently shrink when a route file moves; a committed list
   makes that shrink a visible diff. Plan 12-09 does not add a check that the two agree, and the
   route list's `$comment` says so plainly.

5. **`GATE-SKIPS total=<n> skipped=<n>` is printed on stdout on both the pass and the fail path.**
   `scripts/check-gate-skips.mjs` (G8) reads that line out of the gate log and treats a missing line
   as a failure rather than as zero skips.

6. **No route is exempted and no status code is allow-listed.** If a real route legitimately fetches
   something that answers 4xx, that is a finding to report, not a list to add to.

7. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

8. **No point of Philippine law arises in this plan.** The landing and blog pages contain legal
   prose, and this check reads none of it — it asserts that an `h1` exists and is non-empty, never
   what it says.

</constraints>

### `frontend/journey/seo-smoke.mjs`

Run from `frontend/`. No arguments; it always checks every route.

Sequence: `buildApp()` then `startPreview()` from `./serve.mjs`, then `launchBrowser()` from
`./browser.mjs`. All three wrapped so a `JourneyCannotRun` becomes exit `2`.

Per route, on a fresh page from `newJourneyPage(browser)`:

1. Register a `response` listener collecting `{ url, status }` for every response with
   `status >= 400`.
2. `page.goto(origin + path, { waitUntil: 'load' })`, then wait 1200 ms — the same settle window
   every registered journey step uses.
3. Evaluate in the page: the first `h1` element's `innerText`, trimmed.
4. Assert three things and record every failure, never short-circuiting:

| Marker | Fails when |
|---|---|
| `SEO RENDER FAILURE` | no `h1` element exists, or its trimmed text is empty |
| `SEO CONSOLE ERROR` | `page.__journeyConsoleErrors` is non-empty; the message names the first recorded error |
| `SEO BAD STATUS` | any collected response has `status >= 400`; the message names the status and the url |

5. Close the page.

Output contract:

- one line per failing route: `<marker> <path> — <detail>`
- always, on stdout: `GATE-SKIPS total=<route count> skipped=0`
- on the pass path: `SEO SMOKE PASS routes=<n> failed=0` and exit `0`
- on the fail path: `SEO SMOKE FAIL routes=<n> failed=<k>` and exit `1`
- on a start failure: `SEO CANNOT RUN: <reason>` on stderr and exit `2`

The browser is closed and the preview stopped in a `finally`, matching `journey/run.mjs`.

### The three observed failures

Each of the three markers is proven by injection against a scratch copy of `seo-routes.json` or a
scratch copy of a route component, never against the committed tree:

| Marker | Injection |
|---|---|
| `SEO RENDER FAILURE` | add a route entry with `path` `/this-route-does-not-exist` |
| `SEO BAD STATUS` | in a scratch copy of `src/components/blog/BlogIndex.tsx`, add an `<img src="/journey-missing-asset.png" />`, rebuild, and run |
| `SEO CONSOLE ERROR` | in the same scratch copy, add a `console.error('journey injected')` call in the component body, rebuild, and run |

Every scratch edit is restored with `git checkout --` and the check re-run green before the plan
commits.
