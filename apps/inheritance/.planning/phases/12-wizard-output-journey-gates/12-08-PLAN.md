<objective>
Make the second half of ROADMAP Phase 12 criterion 3 true: "a deterministic assertion that every
displayed peso figure matches engine output exactly", requirement JRNY-07.

`12-RESEARCH.md` §5 records why a rubric cannot express this. The eight assertion kinds are DOM
predicates over **literal expected strings** written into a committed JSON file, so a `text_equals`
carrying a formatted amount would be a transcription — correct on the day it is written and silently
wrong the day the engine changes. Constraint 5 of plans 12-03, 12-04, 12-06 and 12-07 therefore
forbids a peso figure in any rubric, and this gate is where the money claim actually lives.

The check recomputes with the same artifact the product loads: `journey/engine.mjs`, plan 12-02's
single harness-side loader over `src/wasm/pkg/inheritance_engine_bg.wasm`, the binary gate G2
rebuilds on every run. It then reads each displayed figure through the per-heir hooks plan 12-06
added and **parses it back to centavos** — `₱1,234.56` becomes `123456n`. Parsing is the inverse of
`formatPeso`, not a reimplementation of it, so this gate introduces no second source of truth for
money, which is what EXT-02 exists to prevent.

Output: one dependency-free check, five named comparison markers, and an observed failure on each of
three of them.
</objective>

<constraints>

1. **The gate never formats a peso figure.** It parses displayed text into a `BigInt` count of
   centavos and compares integers. Writing a second `formatPeso` would create the duplicate money
   implementation EXT-02 forbids, and would make the gate agree with itself rather than with the
   product.

2. **All arithmetic is `BigInt`.** `Money.centavos` is `number | string` on the TypeScript side
   precisely because a large estate exceeds `Number.MAX_SAFE_INTEGER`. `Number()` appears nowhere in
   a comparison path.

3. **The engine is loaded only through `journey/engine.mjs`.** No second `initSync` call site is
   created; plan 12-02 made that module the single one.

4. **No expected peso figure is committed anywhere.** Not in this script, not in a JSON file, not in
   a comment. Every expected value is produced during the run.

5. **No application source file, no rubric, no step record and no seed file is edited.** Plan 12-06
   added every hook this gate reads.

6. **The exit contract is the project's three-valued one.** `0` every comparison held, `1` at least
   one failed, `2` the check could not start. A stopped stack, a missing WASM binary, a failed build
   or a missing browser is exit `2` with a `MONEY PARITY CANNOT RUN:` prefix — never exit 1.

7. **`GATE-SKIPS total=<n> skipped=<n>` is printed on stdout on both the pass and the fail path.**
   `scripts/check-gate-skips.mjs` (G8) reads that line out of the gate log.

8. **No tolerance, no rounding allowance and no epsilon exists anywhere in the script.** The engine
   converts to centavos exactly once, in `step10_finalize.rs`, with largest-remainder distribution;
   a gate that allowed a centavo of slack would hide precisely the defect it exists to find.

9. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

10. **No point of Philippine law arises in this plan.** The gate asserts that two numbers are equal;
    it decides no share and interprets no article.

</constraints>

### `parsePesoText(text) -> BigInt`

The inverse of `formatPeso` (`src/types/index.ts:509-518`), which emits `₱` followed by
thousands-separated pesos and, only when the centavo remainder is non-zero, `.` and two digits.

- Strip a leading `₱`, any leading `−`, `-` or whitespace, and every `,`.
- If a `.` remains, the fractional part must be exactly two digits; otherwise throw
  `PESO UNPARSEABLE: <the original text>`.
- Return `BigInt(pesoPart) * 100n + BigInt(centPart ?? '00')`.
- Any leftover non-digit character throws the same error. A silently-tolerated stray character is how
  a wrong figure passes.

### The five comparison markers

| Marker | Fails when |
|---|---|
| `HEIR AMOUNT MISMATCH` | a displayed `heir-net-<id>` parses to a value other than that heir's `net_from_estate.centavos` in `expected` |
| `HEIR ROW SET MISMATCH` | the set of heir ids displayed differs from the set of `expected.per_heir_shares` entries whose `net_from_estate.centavos` is greater than zero |
| `TOTAL ESTATE MISMATCH` | the displayed total parses to a value other than `input_json.net_distributable_estate.centavos`, or the sum of displayed heir amounts differs from it |
| `BREAKDOWN MISMATCH` | a displayed `breakdown-net-<id>` parses to a value other than the `heir-net-<id>` for the same heir |
| `STORED OUTPUT DIVERGED` | the `output_json` the product wrote has a `scenario_code`, a `succession_type` or any `per_heir_shares` amount differing from `expected` |

`HEIR ROW SET MISMATCH` is what makes the check total rather than sampled: without it, a results view
that dropped an heir entirely would show only correct figures and pass.

Output:

- one line per failing comparison: `<marker> — <detail naming both the displayed and the expected integer>`
- always, on stdout: `GATE-SKIPS total=5 skipped=0`
- on the pass path: `MONEY PARITY PASS heirs=<n> centavos=<total>` and exit `0`
- on the fail path: `MONEY PARITY FAIL checks=5 failed=<k>` and exit `1`

Browser and preview are closed in a `finally`, matching `journey/run.mjs`.
