Register this phase's verification as gates, so nothing built in plans 12-03 through 12-08 depends
on an agent remembering to run it, and close the five requirements against the commands that prove
them.

`CLAUDE.md` states the invariant this plan operates under: the gate set in `gates.manifest.json` may
only grow, and `node scripts/check-gate-manifest.mjs` enforces it. This plan performs the only
manifest append permitted anywhere in Phase 12.

Three gates, for the reason recorded in `12-RESEARCH.md` §9:

- **G19** — money parity. `cd frontend && node journey/money-parity.mjs`. Needs the stack, the
  built WASM, a build and a browser.
- **G20** — share exposure. `cd frontend && node journey/share-exposure.mjs`. Needs the stack and
  nothing else.
- **G21** — SEO smoke. `cd frontend && node journey/seo-smoke.mjs`. Needs a build and a browser, and
  no database.

They are three gates rather than one because a red run must say whether a peso figure diverged, an
anonymous field set widened, or a marketing page stopped rendering, and those are three different
investigations.

The twenty-eight new screens registered by plans 12-03, 12-04, 12-06 and 12-07 need **no new gate**:
`G16` (static registry integrity) and `G17` (`node journey/run.mjs --all`) already cover every
record in `frontend/journey/steps/`, which is exactly why those two gates were written as they were.

Output: three manifest entries, three lock entries, a `GATES.md` section 14, a `JOURNEY.md` section
covering the wizard and output surfaces, a CI workflow with a raised timeout, and five requirements
marked Complete with the command that proves each.
