<objective>
Verify the results view and the family-tree visualizer — ROADMAP Phase 12 criterion 3, requirement
JRNY-07 — and add the per-heir hooks the money-parity gate of plan 12-08 needs to address a figure
by heir rather than by table column.

`12-RESEARCH.md` §4.3 records the constraint that shapes this plan.
`scripts/check-seed-fixture.mjs` rejects a seeded engine result with the marker
`SEED WRITES OUTPUT` — "a seeded engine result is a per-heir peso figure nothing computed" — so the
results view is not reached by writing `output_json` into SQL. It is reached by landing on the
review screen, clicking the real compute button, and waiting for the results view. That is stronger
verification than a seeded blob: it exercises the real WASM call, the real `updateCaseOutput` write
and the real render, in one path.

`12-RESEARCH.md` §5 records why the money hooks are needed here.
`DistributionSection.tsx` renders each amount in a bare `<TableCell>`, and the column index shifts
with `showDonations`, `showRepresentation` and the collateral layout. A gate that depended on column
position would break on a case shape change and report a money defect that is really a layout
change. Three components gain additive `data-testid` attributes, the same technique plan 11-02 used
for nineteen hooks.

Output: three hooked components, two step records, two rubrics, four approved reference files, and
no peso figure anywhere in a rubric.
</objective>

   entry, report BLOCKED with the pasted `npm run test:gate` output rather than editing a test or
   appending to the ledger.

   and computes fresh. A step that inherited the previous run's stored result would assert against a
   result nothing recomputed.
