<objective>
Verify the public share-link view — ROADMAP Phase 12 criterion 4, requirement JRNY-08: the view is
checked, "including an assertion that it exposes only the fields it should".

`12-RESEARCH.md` §6 records that the field set is already decided and written down.
`frontend/supabase/migrations/015_shared_case_single_signature.sql` collapses `get_shared_case` to a
single `UUID` signature whose `RETURNS TABLE` list is exactly six columns — `title`, `status`,
`input_json`, `output_json`, `decedent_name`, `date_of_death` — and its own header states that the
discarded overload returned two extra blobs "that no client reads, and widening what an anonymous
share link exposes is a decision this plan does not contain". This plan does not re-decide anything;
it makes that decision **checked**, by calling the RPC with the `anon` key and comparing the returned
object's key set against those six names and against nine names that must never appear.

`12-RESEARCH.md` §4.4 records the three reachable states and how each is produced without adding a
seed row: the same Alpha share token renders a populated result or a not-yet-computed message
depending on which named reset the step declares, and Beta's token — seeded with
`share_enabled` false — renders the not-found card.

Gate G18 already proves a **cross-tenant** share-token read returns nothing. It does not inspect the
column set of a legitimate read, so there is no overlap between the two checks.

Output: one field-set check, three step records, three rubrics, six approved reference files.
</objective>

<constraints>

1. **No migration, no policy and no grant is edited.** The six-column contract is what this plan
   asserts, not what it authors. If the live response does not match the migration, that is a finding
   to report, never a migration to change.

2. **The exposure check uses the `anon` key only.** It must exercise the same path an unauthenticated
   visitor takes. A service-role client is used for nothing in this script.

3. **The forbidden-name list is closed and written into the script literally**, not derived from the
   `cases` table's columns at run time. A derived list would shrink silently if a column were renamed,
   and the point of the list is that adding a field to the RPC has to change this file.

4. **All three steps use `"session": "none"`.** `/share/$token` hangs off `publicRootRoute`; a
   session would test a path no share-link recipient takes.

5. **No application source file is edited.** All three share states already carry root testids —
   `shared-case-loading`, `shared-case-not-found`, `shared-case-content` — plus `read-only-badge`.

6. **A reference is approved only after that step's rubric has already passed**, and
   `maxDiffPixels` stays `0` on all three sidecars. `node journey/approve.mjs <stepId>` is the only
   writer into `frontend/journey/references/`.

7. **`allowConsoleErrors` is `false` on all three steps.** The disabled-share state is a legitimate
   empty result, not an error, and the RPC answers 200 with zero rows.

8. **`GATE-SKIPS total=<n> skipped=<n>` is printed on stdout on both the pass and the fail path** of
   `share-exposure.mjs`, and its exit contract is the project's three-valued one: `0` passed, `1`
   failed, `2` could not run.

9. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

10. **No point of Philippine law arises in this plan.** Every assertion is a column name, a testid or
    a rendered label.

</constraints>

<interfaces>

### `frontend/journey/share-exposure.mjs`

Run from `frontend/`. No arguments.

Setup: `readStackEnv()` from `./session.mjs`; a null return or a missing `API_URL` is
`SHARE EXPOSURE CANNOT RUN: local Supabase stack is not running` on stderr and exit `2`. It then
builds an **anonymous** client with `createClient(env.API_URL, env.ANON_KEY, { auth: { persistSession: false, autoRefreshToken: false } })`.

Ids come from `readFixtures()`; no uuid is written literally.

Six checks, every one evaluated and none short-circuiting:

| Check | Marker on failure |
|---|---|
| The Alpha token returns exactly one row | `SHARE ROW COUNT` |
| That row's key set equals the six expected names exactly | `SHARE FIELD SET` |
| That row contains none of the nine forbidden names | `SHARE FIELD LEAKED` |
| The Beta token, whose `share_enabled` is false, returns zero rows | `SHARE DISABLED LEAK` |
| A token absent from `fixtures.json` returns zero rows | `SHARE UNKNOWN TOKEN` |
| The call returns no PostgREST error | `SHARE RPC ERROR` |

The six expected names, in a frozen array, transcribed from migration `015`:
`title`, `status`, `input_json`, `output_json`, `decedent_name`, `date_of_death`.

The nine forbidden names, in a second frozen array: `id`, `org_id`, `user_id`, `client_id`,
`share_token`, `share_enabled`, `tax_input_json`, `tax_output_json`, `comparison_output_json`.

The absent token is the literal `00000000-0000-4000-8000-0000000000fe`. It is deliberately one digit
different from the refusal token `scripts/check-journey-registry.mjs` already declares, so the two
cannot be confused, and it appears in no step url so no static rule sees it.

Output:

- one line per failing check: `<marker> — <detail naming the observed value>`
- always, on stdout: `GATE-SKIPS total=6 skipped=0`
- on the pass path: `SHARE EXPOSURE PASS fields=6 forbidden=0` and exit `0`
- on the fail path: `SHARE EXPOSURE FAIL checks=6 failed=<k>` and exit `1`
