<objective>
Give the return a printable exit.

`21-RESEARCH.md` §2 reproduced the audit's grep: `react-pdf`, `downloadPDF` and `generatePDF` return zero
hits across `src/components/tax/`. `@react-pdf/renderer` has been a dependency at `^4.3.2` the whole
time; the estate-tax surface simply never used it, so half the product's stated identity terminates on a
screen the lawyer must retype from.

Nothing here is invented. `21-RESEARCH.md` §3 tabulates seven existing artifacts on the succession side —
document composition, blob generation, filename building, the PDF-safe money formatter, the mocked-render
test pattern — every one of them gate-proven by `G22` through `G25`. This plan mirrors that shape for the
return.

The peso sign is the landmine and it is already measured. `components/pdf/pdf-text.ts` records that the
document's three fonts are base-14 and WinAnsi-encoded, that U+20B1 is written as the single byte `0xB1`,
and that the byte extracts as `±` at near-zero advance width, overprinting the first digit of the amount
it prefixes. Every amount in this document therefore goes through `formatPesoPdf`.
</objective>

<constraints>
- No new money formatter. `formatPesoPdf` and `PDF_PESO_PREFIX` from `components/pdf/pdf-text.ts` are the
  only currency transforms this document uses. A second formatter here would make `21-07`'s parser agree
  with the wrong thing.
- No section literal, item number or label is authored in this file. Every one comes from the line model,
  which is what keeps the engine the single attribution authority.
- No wall clock. Any date printed on the document is a parameter, never `new Date()`. The succession PDF
  needed `PDF_FIXED_CLOCK` in its capture harness precisely because `CaseSummarySection` reads the clock;
  this document does not repeat that.
- The firm profile is **not** included. `ActionsBar.tsx:49` passes `null` for it and `EstatePDF` gates the
  letterhead on it, so no PDF a user can obtain carries a header today. Letterhead and attorney
  attribution are Phase 23's subject; adding them here would assert a section the product does not render
  and would break `21-07` against a document the button cannot produce.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan runs
  the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A document generator over an in-memory object, plus one browser download. No network call, no storage
access, no authorisation decision.

The hazard with teeth is **a silently corrupted amount**. It is not hypothetical and it is not a bug this
plan could discover by testing at the component level: the mocked-renderer test renders to HTML and shows
a perfectly correct `PHP 5,000,000`, while the real document writes a byte that overprints the `5`. The
defence is layered on purpose — the component test proves composition, and `21-07` proves the extracted
text of real bytes, produced by the real button, through real poppler.

The second hazard is **the document quietly omitting a row it could not render**. `@react-pdf/renderer`
does not throw on an undefined child; it renders nothing. A row dropped that way would be invisible in
both the document and the mocked test. The defence is the same set-identity assertion the rest of this
phase uses: the test compares the rendered row count against `FORM1801_LINE_IDS.length`, and `21-07`
compares the extracted item set against the model's.

Severity: high in consequence. This is the artifact the lawyer files from.
</threat_model>

Structure, A4 portrait, reusing the page style block from `EstatePDF.tsx`:

1. A title line reading the literal `BIR FORM 1801 — ESTATE TAX RETURN`.
2. A provenance block of three labelled lines: `Decedent:` with `decedentName`, `Date of Death:` with
   `dateOfDeath`, `Generated:` with `generatedOn`. All three are parameters; no clock is read.
3. The line table, built from `buildForm1801Lines(output)`, with five columns in this order: `Item`,
   `Description`, `Exclusive`, `Conjugal`, `Total`. A sixth line under each row prints
   `Authority: ` followed by `line.authority` at a smaller font size, because a sixth column does not fit
   the A4 width the succession report already uses and a truncated authority is worse than a wrapped one.
4. A warnings block rendering each string the line model returned, under a heading reading the literal
   `MANUAL REVIEW`.
5. The penalty refusal paragraph, rendering `output.penalties.refusal` when `output.penalties.complete`
   is false.
6. The existing `DisclaimerSection`, imported and reused rather than reimplemented.

Amount rendering, identical in rule to the screen: a numeric `exclusive` or `conjugal` prints
`formatPesoPdf(value)`, a `null` prints the literal `—`; the total column prints `line.displayTotal` when
that is a string, otherwise `formatPesoPdf(line.total)` when `line.total` is a number, otherwise `—`.

Pass every warning, refusal and authority string through `toPdfSafeText` from `pdf-text.ts` before
rendering, so a peso sign inside engine prose does not reach the WinAnsi encoder.

Create `frontend/src/lib/form1801-pdf.ts` mirroring `lib/pdf-export.ts`:

- `buildForm1801PdfFilename(decedentName: string, date: string): string` returning `form1801-` plus
  `slugifyName(decedentName)` plus `-` plus `date` plus `.pdf`. Import `slugifyName` from
  `lib/pdf-export.ts` rather than copying it.
- `generateForm1801Pdf(output, decedentName, dateOfDeath, generatedOn): Promise<Blob>` lazy-loading
  `@react-pdf/renderer` and `../components/pdf/Form1801PDF` with the same `Promise.all` shape
  `generatePDF` uses, then `pdf(doc).toBlob()`.
- `downloadForm1801Pdf(output, decedentName, dateOfDeath, generatedOn): Promise<void>` doing the object
  URL, anchor click and revoke, exactly as `downloadPDF` does.

The `date` and `generatedOn` parameters are required and have no default.
