<objective>
Give the return a machine-readable exit that carries exact centavo integers.

Roadmap criterion 3 is a CSV *"carrying the same centavo integers"*. A file that only carries
`5,000,000.00` forces its reader to re-parse a locale-formatted string, and a locale-formatted string is
where centavos go to die. The CSV therefore carries both: a raw integer column that is the number the
gate compares, and a formatted column that is what a human reading the file in a spreadsheet sees.

No dependency is added. `21-RESEARCH.md` §7 records why: the classic quoted-comma corruption is a
*parser* hazard, and this module only writes. The escaping rule is fixed in this plan rather than left
to the executor, because a property location such as `Lot 4, Block 12, Quezon City` will contain a comma
on the first real estate a lawyer files.
</objective>

<constraints>
- The escaping rule, stated once and implemented once: a field is wrapped in double quotes when and only
  when it contains a comma, a double quote, a carriage return or a line feed; an embedded double quote is
  written as two double quotes; the record separator is CRLF; the file begins with a header row.
- No CSV parsing library and no parsing function. This module exports writers only.
- No money formatter is written here. The formatted column uses `formatPeso` from
  `frontend/src/types/index.ts`, which is the app's existing peso formatter. A second formatter in an
  export layer is the duplicate-implementation defect `EXT-02` forbids.
- No section literal, item number or label is authored in this file. Every one comes from the line model.
- The centavo cell for a line whose `total` is `null` is the empty string, never `0`.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan runs
  the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A pure string builder plus one browser download. No network call, no storage access, no authorisation
decision.

**CSV injection is the one real hazard here and it is in scope.** A cell beginning `=`, `+`, `-` or `@`
is executed as a formula by Excel and by Google Sheets when the file is opened. Two of this document's
cells are attacker-influenceable in the ordinary course of business: the decedent name and, through the
line model's warning strings, nothing — but the filename is built from the decedent name, and a future
line label is not guaranteed to stay literal. The defence is stated in the plan rather than discovered:
every text cell is prefixed with a single apostrophe when its first character is one of those four, and
the filename is built with the existing `slugifyName`, which already strips everything outside
`[a-z0-9\s-]`.

The second hazard is **a silently truncated download**. A blob built from a string cannot be partially
written by `URL.createObjectURL`, so this is not defended in code; it is defended by `21-07`, which reads
the bytes the browser actually produced rather than the string this module returned.

Severity: medium — the formula-injection path is real and the mitigation is one line, which is exactly
the kind of thing that gets skipped when it is not written down.
</threat_model>

<action>
Create `frontend/src/lib/form1801-csv.ts` with a module header stating that the file writes CSV and never
parses it, that the escaping rule below is the whole rule, and that every row and authority is read from
the line model.

Export `escapeCsvField(value: string): string` implementing exactly the rule in the constraints: return
the value unchanged when it contains none of comma, double quote, CR or LF; otherwise return it wrapped
in double quotes with every embedded double quote doubled.

Export `neutraliseFormula(value: string): string` returning the value prefixed with a single apostrophe
when its first character is `=`, `+`, `-` or `@`, and unchanged otherwise. Document the reason in one
line: a leading `=` is executed as a formula by Excel and Google Sheets.

Export `buildForm1801Csv(output: EstateTaxFullOutput, decedentName: string): string`.

It calls `buildForm1801Lines(output)` once, then writes:

A header row with exactly these six columns, in this order:
`Item`, `Description`, `Exclusive (centavos)`, `Conjugal (centavos)`, `Total (centavos)`, `Authority`.

Then one row per line, in the model's order:
- `Item` is `line.item`;
- `Description` is `line.label`;
- `Exclusive (centavos)` and `Conjugal (centavos)` are the raw integers, or the empty string when the
  value is `null`;
- `Total (centavos)` is the raw integer when `line.total` is a number, and when it is `null`, the
  `line.displayTotal` words — so the file says `NOT COMPUTED` where the screen says `NOT COMPUTED`, and
  never `0`;
- `Authority` is `line.authority`.

Then, when the model returned warnings, a blank row followed by one row per warning whose first cell is
the literal `MANUAL REVIEW` and whose second cell is the warning text.

Every text cell passes through `neutraliseFormula` and then `escapeCsvField`. Numeric cells are written
as bare integers with no grouping and no decimal point.

Prepend a provenance block above the header row: three two-cell rows carrying `Decedent` with
`decedentName`, `Document` with the literal `BIR Form 1801 — Estate Tax Return`, and `Amounts` with the
literal `All numeric columns are integer centavos.` Then a blank row. The provenance block exists so a
cell copied out of this file cannot be mistaken for pesos.

Export `buildForm1801CsvFilename(decedentName: string, date: string): string` returning
`form1801-` plus `slugifyName(decedentName)` plus `-` plus `date` plus `.csv`. The `date` parameter is
required and has no default: `21-RESEARCH.md` and gate `G36`'s subject both record that a wall-clock read
inside the engine or its exports is what makes an artifact non-reproducible.

Export `downloadForm1801Csv(output, decedentName, date)` building a `Blob` with type
`text/csv;charset=utf-8` from the built string, creating an object URL, clicking a generated anchor with
the filename, and revoking the URL — the same shape as `downloadPDF` in `lib/pdf-export.ts`.
</action>
