<objective>
Land the reconciliation on the screen, before anything is given an exit.

The roadmap's cross-cutting constraint for this phase is that a return whose display contradicts its own
arithmetic must not be given an exit. This is the plan that satisfies it. `Form1801View` today builds
its own row array inline — twenty-odd object literals reading engine fields by name — and
`21-RESEARCH.md` §1.3 measured three separate contradictions that follow from trusting those names:
Item 35A labelled *Standard Deduction* printing funeral expenses, a row `40` labelled *Gross Estate*
printing the net taxable estate while row `34` on the same table prints the real gross estate, and a row
`44` labelled *Total Deductions* printing the tax due.

After `21-02` all three are fixed in one place. This plan deletes the inline array and renders the
engine's line model, which is also what lets `21-04` and `21-05` produce documents that cannot disagree
with the screen.

A new column is added: **Authority**. Every line already carries one, and `RET-04` requires it on the
face of the document, not merely inside the object.
</objective>

<constraints>
- The component builds no line. Its only source of rows is `buildForm1801Lines(output)`, and its only
  source of warnings is the `warnings` array that call returns.
- No section literal, no item number and no label may be authored in this file. Gate `G14` fails a
  display layer that derives an attribution, and `21-05` and `21-04` inherit the same rule.
- The local `formatPesos` helper stays exactly as it is — `en-US` grouping, two decimals, no currency
  mark. It is the function `21-07`'s screen parser inverts, so changing its output grammar without
  changing that parser would make the gate wrong rather than red. Any change to it is a decision this
  plan does not contain.
- A `null` amount never reaches `formatPesos`. `formatPesos(0)` returns `0.00`, and that string on a
  declined line is the exact understatement Phase 20 removed.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan runs
  the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A read-only presentational component rendering values from an in-memory object. No input, no network
call, no storage access, no authorisation decision.

The hazard is **rendering engine-produced text as markup**. Authority strings and warning strings are
built from constants in `form1801-lines.ts` and `penalties.ts`; React escapes text children by default.
Every one of them must be rendered as a text child, and `dangerouslySetInnerHTML` must not appear in the
file. Task 3 greps for it.

The second hazard is presentational and is the reason this plan exists: applying a currency formatter to
`null` yields `0.00` here, because `null / 100` is `0`. Task 3 asserts the absence of `0.00` in every row
whose `displayTotal` is set, rather than only asserting the presence of the words.

Severity: low technically, high in consequence — this is the screen a lawyer reads the return from.
</threat_model>
