<objective>
Build the gate that makes criterion 5 true, and prove it can fail.

Roadmap criterion 5: *a blocking gate compares the displayed figures, the exported PDF figures and the
exported CSV figures against a same-run engine computation, and has been observed failing on a
one-centavo injection in each direction.*

Every seam this needs already exists and is gate-proven. `journey/money-parity.mjs` (G19) is the
exact-centavo screen comparison; `journey/pdf-capture.mjs` is the click-the-real-button capture;
`journey/pdf.mjs` is the single `pdftotext` seam; `scripts/check-one-fact-set.ts` is the precedent for a
`npx tsx` gate importing both the TypeScript tax engine and the `.mjs` journey helpers. This plan
composes them for the return.

The gate is written and falsified here. It is registered in `21-08`, because a gate that has never been
seen failing is decoration.
</objective>

<constraints>
- Three-valued exit contract, the project's own: `0` passed, `1` failed, `2` could not run, with
  `RETURN PARITY CANNOT RUN: ` on stderr. A stopped Supabase stack, an absent `pdftotext`, a download that
  never arrives, and bytes that do not begin `%PDF-` are all exit 2. None of them is a pass.
- A run that compares zero rows exits 1 with `CORPUS EMPTY`. Passing because it measured nothing is the
  single most dangerous outcome available to this design, and the same guard `check-citation-integrity.mjs`
  and `money-parity.mjs` both carry.
- No exception list, no baseline file, and no flag that writes, repairs, regenerates, accepts, updates or
  waives anything. The only permitted flags are read-only path overrides.
- The gate parses, it never formats. Its three parsers are the exact inverses of the three formatters the
  product uses — `formatPesos` in `Form1801View.tsx` for the screen, `formatPesoPdf` in `pdf-text.ts` for
  the document, and the bare integer the CSV writes. Writing a formatter inside the gate would make it
  agree with itself rather than with the product.
- Comparison runs in both directions on every surface: every amount the engine produced appears, and every
  amount the surface prints is one the engine produced. A one-directional check passes a surface that
  invented a line.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan runs
  the scoped commands below and makes no claim about the whole suite.
</constraints>

<threat_model>
A test harness that drives a real browser against a local stack and reads two downloaded files. It writes
to the database only through the reset it declares, and only into the Alpha fixture case.

The hazard specific to a parity gate is **agreeing with itself**. If the gate builds its expected values
by calling `buildForm1801Lines` and the surfaces also render `buildForm1801Lines`, then a wrong line model
passes on all three surfaces. That is accepted and it is the correct scope: `21-02`'s unit tests are what
verify the line model against `EstateTaxFullOutput`, and this gate verifies that three renderers
faithfully reproduce it. The plan states it rather than leaving it as an unexamined assumption, and the
`LINE SET MISMATCH` injection is the one that would catch a renderer silently dropping a row.

The second hazard is **a stale download**. Playwright's download machinery writes into its own temporary
directory; the gate must take the bytes from the download event of the click it performed, never from a
path it guessed. `pdf-capture.mjs` already does exactly this and is the pattern to copy.

Severity: low. This code runs only in CI and only against fixture data.
</threat_model>
