<objective>
Nothing carries form state out of the succession wizard until Compute is pressed.
`WizardContainerProps` declares exactly two props, `onSubmit` and `defaultValues`
(`WizardContainer.tsx:101-104`), and the form's values live inside `react-hook-form` where the route
cannot see them. That single missing segment is why `useAutoSave` has never had anything to save.

This plan adds the segment: a third, optional `onChange` prop, fed by a `methods.watch()`
subscription that fires on every value change and is unsubscribed on unmount. `19-04` connects the
route's end of it.

The plan also gives two controls a stable handle so the browser gate in `19-05` can drive them: the
**Add Person** button in `FamilyTreeStep` and the **Full Name** input inside each `PersonCard`.
Neither has one today, and neither can be addressed reliably by position when the number of cards is
the very thing under test. Both additions are `data-testid` attributes, which render nothing, so the
approved `wizard-family-tree` reference image stays valid.

The prop is optional on purpose. Seventeen committed cases in `WizardContainer.test.tsx` and five
registered journey steps render the wizard with no `onChange`, and all of them must keep passing
without edit.
</objective>

<constraints>
- Exactly four files are touched. Nothing else under `frontend/src/` is edited, and in particular
  `frontend/src/routes/cases/$caseId.tsx` is left alone — it is `19-04`'s file.
- The subscription is created inside a `useEffect` and torn down by calling `unsubscribe()` in that
  effect's cleanup. A subscription that outlives the component is a leak that fires against a
  destroyed form.
- `onChange` is optional (`onChange?:`). When it is absent, the effect creates no subscription at
  all, so a wizard rendered without one performs no extra work.
- The two new `data-testid` values are exactly `add-person` on the Add Person button and
  `person-name-<index>` on each card's Full Name input, where `<index>` is the same zero-based
  `index` prop `PersonCard` already receives.
- No visible text, no class name, no element and no ordering changes in any of the three source
  files. The only additions are the `onChange` prop with its effect, and the two attributes.
- `npx tsc -b --force` must exit 0 after every task in this plan.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this plan does not own. This plan runs
  scoped Vitest and `tsc`, and makes no claim about the whole suite.
</constraints>

<threat_model>
This plan adds a callback that fires on every keystroke and carries the whole form value to its
caller. The realistic hazards are performance and lifetime, not disclosure — the value never leaves
the browser here, and `19-04` hands it to the same `updateCaseInput` the Compute button already uses,
under the same RLS policy.

1. **A subscription that outlives its form.** `react-hook-form`'s `watch(callback)` returns a
   subscription; dropping the returned object without calling `unsubscribe()` leaves a callback bound
   to a destroyed control tree, which fires into the route after the wizard is gone. Mitigated by
   tearing down in the effect cleanup and by a test that unmounts and then asserts the spy's call
   count stops rising.
2. **Re-render feedback.** A callback that caused the wizard to re-render on every keystroke would
   drop focus mid-word. `WizardContainer` receives `defaultValues` and is uncontrolled, so the
   route's state does not flow back into it; a test types ten characters into one field and asserts
   the field still holds focus and all ten characters.
3. **A subscription firing at mount.** That would resurrect the redundant load-time write `19-02`
   removed. `watch(callback)` in `react-hook-form` 7 fires on change only; a test asserts the spy has
   zero calls immediately after mount.

Severity: low. No new data crosses a trust boundary.
</threat_model>
