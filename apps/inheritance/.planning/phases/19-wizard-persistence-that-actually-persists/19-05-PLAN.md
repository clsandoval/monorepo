<objective>
ROADMAP Phase 19 success criterion 5 requires a nine-heir family tree entered and then reloaded to
come back, *"proven by a journey step against the live database, not by a unit test alone"*. A unit
test cannot reload a page, and the two unit-level plans before this one both drive the code through
in-process fakes — which is exactly the sampling that certified this defect for as long as it
existed.

The journey harness offers two shapes. A **registry step** needs an approved reference image, and
`scripts/check-journey-registry.mjs` fails with `REFERENCE MISSING` without one; producing a first
reference is a human visual judgement no plan in this phase may make. A **standalone gate script** —
the shape `journey/money-parity.mjs` (G19) and `journey/rls-isolation.mjs` (G18) already use — drives
a real headless browser against a real local Supabase with no reference image, no perceptual diff and
no approval step.

This plan writes the second shape: `frontend/journey/persistence.mjs`, seven checks, composed from the
harness modules those two gates already compose. It does not register the gate — `19-06` does that,
after this plan has observed it failing on three separately injected regressions.

The gate asserts **structure and identity only**: nine rows, nine names, `output_json` still null. It
computes nothing and compares no money value, so it needs no engine run and cannot drift from one.
</objective>

<constraints>
- Exactly one file is created: `frontend/journey/persistence.mjs`. No source file under
  `frontend/src/` is edited permanently, no gate manifest is touched, and no journey step, rubric or
  reference is created or modified.
- The script imports only from the existing harness modules — `./session.mjs`, `./seed.mjs`,
  `./serve.mjs`, `./browser.mjs` — plus `node:` builtins. No dependency is added to
  `frontend/package.json`.
- The script reads no committed expected peso figure and performs no engine computation.
- The script never touches a seeded row. It inserts one case row through the admin client using only
  the columns `frontend/src/lib/cases.ts` `createCase` inserts, and deletes that row in a `finally`
  block that runs on every exit path including the failure and the cannot-run paths.

  same `import.meta.url` guard `journey/money-parity.mjs` ends with.
- Every regression injected during Task 3 is reverted in the same task, and
  `git status --porcelain -- frontend/src` must print nothing before the commit in Task 4.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this plan does not own. This plan runs
  the new script directly and makes no claim about the whole suite.
</constraints>

<threat_model>
This script holds an admin (service-role) Supabase client, builds the application, starts a preview
server and drives a browser. That is the widest capability set in this phase, and all three hazards
are about what it leaves behind.

1. **Corrupting a fixture other gates depend on.** `RESETS['case-alpha-no-output']`
   (`journey/resets.mjs:104-120`) nulls `output_json`, `decedent_name` and `date_of_death` and sets
   `status` to `draft` — it does **not** restore `input_json`. A gate that typed nine heirs into the
   seeded Alpha case would leave them there, and G19 money parity computes against that same
   `input_json`. Mitigated absolutely: the gate creates its own row and reads no seeded case. Check 7
   asserts the seeded Alpha case's `input_json` is byte-identical before and after.
2. **Leaking a row.** A failed run that returned early would leave an orphan case in the local
   database, and the next run would accumulate another. Mitigated by deleting in `finally`, and by
   printing the deletion outcome on every path so a failed delete is visible rather than silent.
3. **Holding a service-role key.** The key comes from `readStackEnv()`, which reads the local stack's
   own environment exactly as `journey/rls-isolation.mjs` and `journey/money-parity.mjs` already do.
   No new credential source is introduced, no key is written to a file, and no key is printed.

Severity: medium, entirely bounded by the local development stack. The script contacts no remote
host.
</threat_model>

<action>
Create `frontend/journey/persistence.mjs` with a file-header comment in the style of
`journey/money-parity.mjs`, stating: what it proves (SAVE-05), why it is a standalone script rather
than a registry step, that it creates and deletes its own case row because
`RESETS['case-alpha-no-output']` does not restore `input_json`, and that it asserts structure and
identity and never a peso figure.

Declare four module constants: `TARGET_HEIRS = 9`, `DEBOUNCE_SETTLE_MS = 4000`,
`SAVED_TIMEOUT_MS = 15000` and `TOTAL_CHECKS = 7`. Declare a `cannotRun(reason)` helper that prints
`PERSISTENCE CANNOT RUN: ${reason}` to stderr and exits `2`.

`main()` performs the following, collecting every failure into a `failures` array rather than
throwing, exactly as `money-parity.mjs` does.

**Setup.** `readStackEnv()`; `cannotRun` when it is `null` or has no `API_URL`. `readFixtures()`;
`adminClient(env)`. Read `../engine/examples/cases/02-married-3lc.json` with `node:fs` and
`JSON.parse` it as the starting input. `cannotRun` when its `family_tree` length is below `1` or above
`TARGET_HEIRS - 1`, because the run needs at least one Add Person click to be meaningful.

**Fixture snapshot.** Read and keep `JSON.stringify` of the seeded Alpha case's `input_json`, selected
by `fixtures.orgs.alpha.case_id`. This is check 7's prior.

**Own row.** Insert one `cases` row through the admin client with `user_id`
`fixtures.orgs.alpha.user_id`, `org_id` `fixtures.orgs.alpha.org_id`, `title`
`Journey — wizard persistence`, `status` `draft`, `input_json` the starting input, `output_json`
`null`, `decedent_name` and `date_of_death` taken from the starting input the same way `createCase`
takes them. Select `id`. `cannotRun` on error. Keep the id in a variable declared **outside** the
`try`, so the `finally` can delete it.

**Browser.** `buildApp()`, `startPreview()`, `launchBrowser()` wrapped so a launch failure becomes
`JourneyCannotRun('chromium is not installed or failed to launch: ...')`, `getSession(env, 'alpha')`,
`newJourneyPage(browser)`, `seedAuthSession(page, preview.origin, session)`.

**Drive.** `page.goto(\`${preview.origin}/cases/${tempCaseId}?step=2\`, { waitUntil: 'load' })`, then
`page.waitForSelector('[data-testid="family-tree-step"]')`. Count
`[data-testid="person-card"]` elements; when that count differs from the starting input's
`family_tree` length, raise `JourneyCannotRun` naming both numbers, because a harness mismatch must
not be reported as a product defect. Click `[data-testid="add-person"]` exactly
`TARGET_HEIRS - startCount` times, after each click waiting for the card count to reach the expected
running total. Then for each index `0` through `TARGET_HEIRS - 1`, fill
`[data-testid="person-name-<index>"]` with the literal `Heir <index + 1>`.

**Check 5 — the indicator.** Wait for `[data-testid="wizard-save-status"]` to exist and for its text
to become `Saved`, with `SAVED_TIMEOUT_MS`. On timeout push a failure beginning
`STATUS NOT SHOWN` carrying whatever text the element held, or the fact that it was absent.

**Settle.** `page.waitForTimeout(DEBOUNCE_SETTLE_MS)`. Compute has deliberately not been clicked.

**Checks 1, 2 and 4a — what the database holds.** Select `input_json, output_json` for the temporary
case. Push `NOT PERSISTED` when `input_json.family_tree` length is not `TARGET_HEIRS`, naming both
numbers. Push `COMPUTE LEAKED` when `output_json` is not `null`, because a non-null output would mean
the row was written by a computation rather than by autosave. Push `NAME LOST` for each index whose
stored `family_tree[index].name` is not the literal `Heir <index + 1>`.

**Checks 3 and 4b — what survives a reload.** `page.reload({ waitUntil: 'load' })`, wait for
`[data-testid="family-tree-step"]`, count `[data-testid="person-card"]` and push `RELOAD LOST` when it
is not `TARGET_HEIRS`. Read the `value` of every `[data-testid^="person-name-"]` input and push
`NAME LOST` for any that is not its expected literal.

**Check 6 — the unmount flush.** Fill `[data-testid="person-name-0"]` with the literal
`Flushed Heir`, then within 600 ms click `page.locator('a[href="/cases"]').first()`, which is a
client-side `Link` and therefore unmounts the case route without a page load. Wait
`DEBOUNCE_SETTLE_MS`, re-read the row, and push `UNMOUNT LOST` when
`input_json.family_tree[0].name` is not `Flushed Heir`.

**Check 7 — the fixture.** Re-read the seeded Alpha case's `input_json` and push `FIXTURE MUTATED`
when its `JSON.stringify` differs from the snapshot taken at setup.

**Teardown and reporting.** In `finally`, close the browser and stop the preview, then delete the
temporary case row and print `TEMP CASE DELETED <id>` on success or a line beginning
`TEMP CASE DELETE FAILED` on error. Print every collected failure to stderr. Print
`GATE-SKIPS total=7 skipped=0` with `console.log` on **both** the pass and the fail path. Exit `1`
with `PERSISTENCE FAIL checks=7 failed=<n>` when `failures` is non-empty, and exit `0` with
`PERSISTENCE PASS heirs=9 checks=7` otherwise. End the file with the same
`import.meta.url === \`file://${process.argv[1]}\`` guard `money-parity.mjs` uses.
