<objective>
`19-02` made the hook able to save and `19-03` made the wizard able to emit. This plan joins them and
puts the result on screen.

Three edits to `frontend/src/routes/cases/$caseId.tsx`:

1. Pass `onChange={setAutoSaveInput}` to `<WizardContainer>`. `setAutoSaveInput` is a `useState`
   setter and is therefore referentially stable across renders, which is what keeps `19-03`'s
   subscription effect from tearing down and rebuilding on every render.
2. Capture the `status` that `useAutoSave` already returns and that the route currently discards —
   `$caseId.tsx:39` calls the hook and ignores its return value entirely.
3. Render that status above the wizard.

The indicator is extracted to `frontend/src/components/case/SaveStatusBadge.tsx` rather than inlined,
for two reasons: a presentational component can be tested directly without a router, and the one rule
that matters — **`idle` renders nothing** — becomes a property of a named component with a named test
instead of a conditional buried in a route.

That rule is load-bearing beyond taste. Five registered journey steps screenshot the succession
wizard on a screen nobody has typed into, so the status there is always `idle`. A badge that rendered
at idle would change five approved reference images, and approving a first reference is a human
visual judgement no plan in this phase is permitted to make.
</objective>

<constraints>
- Exactly three files are touched. `frontend/src/hooks/useAutoSave.ts`,
  `frontend/src/components/wizard/`, `frontend/src/lib/` and `frontend/src/routes/cases/$caseId.tax.tsx`
  are not edited.
- The four labels are exactly the four `EstateTaxWizard.tsx:99-104` already uses: `Saving...` for
  `saving`, `Saved` for `saved`, `Save error` for `error`, and nothing rendered for `idle`. The copy is
  copied, not invented, so the two wizards say the same thing.

  and error phases are untouched.
- The rendered wrapper is itself inside the conditional, so at `idle` the DOM gains no element and no
  spacing. An always-present wrapper with conditional children would shift the layout and is
  prohibited.
- `npx tsc -b --force` must exit 0 after every task in this plan.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this plan does not own. This plan runs
  scoped Vitest and `tsc`, and makes no claim about the whole suite.
</constraints>

<threat_model>
This plan connects a keystroke to a database write, so it is the point at which this phase's data
actually starts moving.

1. **Reporting success over a failure.** The single worst outcome here is a lawyer seeing `Saved`
   while `updateCaseInput` rejected — they close the tab and the family tree is gone. The status
   originates in one place, `useAutoSave`'s `catch` branch, and the badge is a total function of it
   with no default-to-success branch. The test asserts absence of the success copy in the error
   state, not merely presence of the error copy.
2. **Writing to a case the user cannot read.** No new query is introduced: the write goes through the
   same `updateCaseInput` the Compute button already calls, under the same RLS policy on `cases`, with
   the `caseId` taken from the route parameter the user already loaded. No privilege boundary moves.
3. **Silently invalidating an approved reference image.** Mitigated by rendering nothing at idle and
   by an explicit test for it. If a journey step nonetheless reports a diff, this plan requires
   reporting it for human review rather than approving it.

Severity: medium, concentrated entirely in hazard 1, and covered by two assertions rather than one.
</threat_model>
