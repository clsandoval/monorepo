<objective>
Make approving a PDF page reference an attributed act, then re-approve gate G24's references for the
document this phase produced — after looking at every page and writing down what changed.

Purpose: ROADMAP Phase 23 success criterion 5 and requirement INST-05. `23-RESEARCH.md` §9 measured
that `journey/pdf-approve.mjs` takes no arguments at all and writes `{"maxDiffPixels": 0}` and
nothing else, while its browser-step sibling `journey/approve.mjs` has accepted `--by` and written
`approvedOn` and `approvedBy` since Phase 10. `journey/pdf-references/README.md` already states that
raising a tolerance "requires whoever raised it to be named in an `approvedBy` field"; this plan
extends that naming to every approval, including approvals at tolerance zero.

`23-RESEARCH.md` §7 also measured that G24 is ALREADY RED before this phase — Phase 21's report
recorded page 1 at 2627 and page 2 at 1975 differing pixels, caused by `b7cdb230e` changing
`PerHeirBreakdownSection.tsx` after the last approval in `6f02c89e4`. This phase changes that same
document again, deliberately and in five places, and G39 certifies the content of every one of those
changes deterministically before any image is promoted.

Output: an attribution-requiring approval command, re-approved page references, the two stale notes
in `journey/JOURNEY.md` corrected, and a written record of what each page image now shows.
</objective>

<constraints>
- `--by` becomes REQUIRED. The command refuses with exit 1 when it is absent. That is a
  strengthening: today an unattributed approval is possible and after this plan it is not. The
  default value `unattended-loop` that `journey/approve.mjs` uses is deliberately NOT copied here.
- The sidecar's `maxDiffPixels` stays `0` on every page. Nothing raises it. `journey/REFERENCES.md`
  permits raising a tolerance for exactly one measured reason — a platform whose text rasterisation
  genuinely differs — and that reason does not apply to a change the product made on purpose.
- `journey/pdf-visual.mjs` is NOT modified. It has no write path into the references directory and
  must keep none. The separation between the gate and the approval command is the entire reason
  either exists.
- Approval is whole-document. `pdf-approve.mjs` takes no page id, and this plan does not give it
  one: promoting page 2 while leaving page 1 at an older revision would leave the directory
  describing a document that never existed.
- **The images are opened and looked at before they are promoted.** The executor reads every
  `.journey-runs/<stamp>/pdf/page-<n>.png` the failing run produced and every existing
  `frontend/journey/pdf-references/page-<n>.png` with the image reader, and writes the observed
  differences into the plan summary. An approval of a diff nobody inspected is the exact failure the
  approval command exists to prevent.
- **G39 must be green before any image is approved.** The content of every change is certified
  deterministically from the extracted text first; the image approval then records a change that is
  already proven, rather than deciding one by eye.
- If a page image shows a change this phase did not make — a money figure, a heir row, a table
  column, a computation-log line, a disclaimer word — the executor STOPS, approves nothing, and
  reports it for human review with the observed description. Only the five changes this phase made
  may be approved: the letterhead, the removal of the credentials line from the letterhead, the
  attribution block, the warnings section's new heading and fields, the removal of markdown
  asterisks from narratives, and the single-article citation lines.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan
  runs G24 directly and makes no claim about the whole suite.
</constraints>

- `--by <string>`: refuse with `PDF APPROVE REFUSED: --by requires a value` when the following
  token is absent or empty.
- any other token beginning with two dashes: refuse with
  `` `PDF APPROVE REFUSED: unknown flag '<token>'` ``.
- any positional token: refuse with
  `` `PDF APPROVE REFUSED: this command takes no positional arguments; approval is whole-document (got '<token>')` ``,
  which preserves the existing whole-document rule and its wording.

`PDF APPROVE REFUSED: --by is required; an unattributed reference change is a change nobody can be asked about`
and exit 1. There is no default value. `journey/approve.mjs` defaults `by` to `unattended-loop`;
that default is deliberately not copied, and the header comment says so.

(`new Date().toISOString().slice(0, 10)`), and change the sidecar write from
`{ maxDiffPixels: 0 }` to `{ maxDiffPixels: 0, approvedOn: utcDate(), approvedBy: by }`, keeping the
two-space indentation and the trailing newline the file already writes. `maxDiffPixels` stays the
literal `0` and no flag sets it: `journey/REFERENCES.md` permits raising a tolerance for one
measured reason only, and this command is not where that decision is made.

Extend the final log line to `` `PDF APPROVE OK pages=${n} from=${stamp} by=${by}` ``.

Extend the header comment with a paragraph stating: that `--by` is required rather than defaulted;
that `journey/diff.mjs` reads only `sidecar.maxDiffPixels` and ignores every other key, so the two
recorded fields cannot change any comparison; and that the attribution exists so a reference change
