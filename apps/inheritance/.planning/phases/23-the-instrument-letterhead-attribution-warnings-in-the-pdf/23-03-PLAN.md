<objective>
Stop the exported report printing raw markdown asterisks, and stop it printing the same article
number twice on one citation line.

Purpose: INST-04. `23-RESEARCH.md` §5 measured that all twenty committed engine cases emit at least
one narrative containing `**`, that `**` appears in narratives ONLY — not in the computation log and
not in any warning — and that `toPdfSafeText` deliberately strips nothing but the peso sign.
`23-RESEARCH.md` §6 measured that the audit's literal string `Art. 996: Art. 996` no longer occurs
anywhere in `frontend/src/`, because Phase 17 added the missing map entry and replaced the key
fallback; what survives is the same duplication in its post-Phase-17 form. Rendering the real
document confirmed it character for character:

`Art. 980: Children of the deceased shall always inherit from him (Art. 980 NCC)`

Fifteen of the seventy-five entries in `NCC_ARTICLE_DESCRIPTIONS` end in such a parenthetical.

Output: one new pure helper in the PDF text module, two one-line changes in two PDF sections, and a
rendered-output test file. No data file and no engine output is edited.
</objective>

<constraints>
- `frontend/src/data/ncc-articles.ts` is NOT edited. Gate G14
  (`node scripts/check-citation-integrity.mjs`) and gate G27
  (`node scripts/check-spec-legal-text.mjs`) both read that file, and rewriting sixty descriptions
  to fix a rendering defect would move a presentation change inside the attribution authority.
- The transform lives in `frontend/src/components/pdf/pdf-text.ts`, whose own header already calls
  itself "the only money and text transforms the PDF layer uses". It does NOT live in
  `PerHeirBreakdownSection.tsx`: that file is item four of the eleven `DISPLAY_LAYERS` in
  `scripts/check-citation-integrity.mjs`, which raises `LAYER DERIVES ARTICLE` for any line in it
  matching `/Art\.\s*\d/`, and a regular expression naming an article would sit one edit away from
  tripping it.
- `stripMarkdownBold` is IMPORTED from `frontend/src/components/results/utils.ts`. No second regular
  expression that removes markdown is written anywhere. That function is already used by
  `ActionsBar.tsx` and `NarrativePanel.tsx`, so importing it keeps one implementation.
- The engine's own `legal_basis` string is what survives on the left of the colon. The helper never
  reformats it, never normalises its spacing and never substitutes a different article for it.
- The loud `CITATION NOT RESOLVED` behaviour Phase 17 installed is preserved exactly: an
  unresolvable citation still renders that literal, and is never silently dropped.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan
  runs the scoped commands below and makes no claim about the whole suite.
</constraints>

seventy-five entries in `NCC_ARTICLE_DESCRIPTIONS` end with a parenthetical naming the same article
the citation's own left-hand side already names; that the PDF prints `raw`, a colon and the

parenthetical at render time rather than editing the data file, because the data file is what gates
G14 and G27 read.

The pattern matches a run of optional whitespace, an open parenthesis, the three letters of the
article abbreviation followed by a period, optional whitespace, one or more digits, optional
whitespace, the three letters `NCC`, and a close parenthesis. Give it the global flag so a
description carrying two such parentheticals loses both.

`export function citationLine(raw: string, text: string): string` returns `raw`, then the two
characters colon and space, then `text` with every match of the pattern removed and the result
trimmed at its right edge only. The function performs no other change: it does not lowercase, does
not collapse internal whitespace, does not add a full stop and does not touch `raw` at all.
