<objective>
Create the one module that decides what an engine warning says, so the results screen and the
exported PDF render the same array instead of composing two independent layouts.

Purpose: `23-RESEARCH.md` §4 measured both renderers. The screen
(`components/results/WarningsPanel.tsx`) prints a heading `Manual Review Required`, a severity word,
the description, and `Related heir: <name>`. The PDF (`components/pdf/WarningsSection.tsx`) prints a
heading `Warnings` and `[category] description`, with no severity and no heir name. INST-03 requires
every engine warning shown on screen to be printed in the PDF; two renderers with two independent
literal layouts is the structural defect Phase 21 removed with `form1801-lines.ts` and Phase 22
removed with `deed/schedule-lines.ts`, and this plan applies the same shape a third time.

Output: `frontend/src/lib/warnings-lines.ts` plus its tests. This plan changes no renderer — plan
23-06 rewires both surfaces onto the model, in a later wave, so the model exists and is proven
before anything depends on it.
</objective>

<constraints>
- The module is pure. It reads no clock, opens no socket, touches no DOM and imports nothing from
  `frontend/src/components/`. Its only import is the type-only one from `../types`.
- `getWarningSeverity` MOVES here. It is deleted from
  `frontend/src/components/results/utils.ts` and re-exported from there, so exactly one
  implementation exists and every existing importer and test keeps compiling unchanged. The six
  category-to-severity pairs are copied verbatim from the current implementation and none is added,
  removed or altered.
- The module decides nothing about Philippine law. It classifies a category string the engine
  already emitted and resolves an id the engine already emitted; it never reads a warning's prose
  and never infers a rule from it.
- No article literal is written into this file. `23-RESEARCH.md` §6 records that
  `scripts/check-citation-integrity.mjs` raises `LAYER DERIVES ARTICLE` for such a literal in a
  display layer, and plan 23-07 adds this module to that gate's list.
- `bash scripts/ci-gates.sh` exits 1 on this branch for reasons this phase does not own. This plan
  runs the scoped commands below and makes no claim about the whole suite.
</constraints>

|-----------|----------|-----------|-------------|-----------------|
| T-23-02a | Information disclosure | `relatedHeirName` resolution | mitigate | The lookup is an exact `heir_id` equality against the `shares` array the caller already renders, so it can only surface a name already on the same page. | T-23-02b | Tampering | severity classification | mitigate | `getWarningSeverity` is a lookup into a frozen literal record with an `info` fallback. It contains no regular expression over `description`, so a warning's prose cannot steer its own severity. |

The tests assert `result.length === warnings.length` on every case, and an unmatched `related_heir_id` produces a loud marker rather than a dropped field. |

Import types only: `import type { ManualFlag, InheritanceShare } from '../types';`

Export exactly six symbols.

1. `export type WarningSeverity = 'error' | 'warning' | 'info';`

2. `export const WARNINGS_HEADING = 'Manual Review Required';`
   The literal is taken verbatim from the heading `components/results/WarningsPanel.tsx` renders
   today, so the screen keeps the words it already uses and the PDF adopts them.

3. `export const RELATED_HEIR_LABEL = 'Related heir:';`
   Taken verbatim from the same component.

4. `export interface WarningLine { severity: WarningSeverity; category: string; description: string; relatedHeirName: string | null; }`

5. `export function getWarningSeverity(category: string): WarningSeverity`
   Move the body from `frontend/src/components/results/utils.ts`. Copy the six pairs verbatim:
   `preterition` and `max_restarts` map to `error`; `inofficiousness`, `disinheritance` and
   `vacancy_unresolved` map to `warning`; `unknown_donee` maps to `info`. Anything else falls
   through to `info`. Declare the lookup as a module-level `const` record so the map is stated once.

6. `export function buildWarningLines(warnings: ManualFlag[], shares: InheritanceShare[]): WarningLine[]`
   Returns exactly one entry per element of `warnings`, in input order. For each warning:
   - `severity` is `getWarningSeverity(warning.category)`
   - `category` and `description` are copied through unchanged
   - `relatedHeirName` is `null` when `warning.related_heir_id` is `null` or `undefined`
   - otherwise it is the `heir_name` of the first element of `shares` whose `heir_id` equals
     `warning.related_heir_id`
   - when `related_heir_id` is non-null and no share matches, `relatedHeirName` is the string
     `` `UNRESOLVED HEIR ${warning.related_heir_id}` ``. A warning that names a heir the
     computation did not award is an anomaly, and stating it is the loud behaviour this project
     requires; the current screen drops it silently.

   The function never filters, never sorts and never de-duplicates.

Then edit `frontend/src/components/results/utils.ts`: delete the `getWarningSeverity` function body
and its doc comment, and replace them with a re-export —
`export { getWarningSeverity } from '@/lib/warnings-lines';` — placed where the function was, with a
one-line comment saying the implementation moved so exactly one copy exists. Leave every other
export in that file untouched. `frontend/src/components/results/__tests__/utils.test.ts` imports
`getWarningSeverity` from `../utils` and must keep passing without being edited.
