<objective>
Remove the two schema-level blockers that make every database-backed screen in this application
unreachable, and extend the seed fixture with the rows a tenant-isolation assertion needs in order to
mean something.

`11-RESEARCH.md` §2 reproduced the first blocker end to end. A real password grant for the seeded
Alpha user succeeds and returns a 744-character access token, but `GET /rest/v1/organizations` with
that token returns HTTP 403 and PostgREST's own hint:
`Grant the required privileges to the current role with: GRANT SELECT ON public.organizations TO
authenticated;`. The cause was read out of `pg_default_acl`: the `postgres`-owned default ACL for
schema `public` is `anon=Dxtm/postgres,authenticated=Dxtm/postgres,service_role=Dxtm/postgres`, and
`Dxtm` is TRUNCATE, REFERENCES, TRIGGER, MAINTAIN — it contains none of INSERT, SELECT, UPDATE or
DELETE. All eleven `public` tables carry that ACL, and a full `supabase db reset` reproduces it, so
this is a property of the committed migration set and not of one machine's drift.

`11-RESEARCH.md` §3 found the second blocker, which Phase 10 did not see. `get_shared_case` exists
twice: `migrations/004_shared_case_rpc.sql:11` creates the `UUID` form and
`migrations/011_create_org_rpc.sql:39` creates a `TEXT` form afterwards. PostgREST answers HTTP 300
`PGRST203 Could not choose the best candidate function`, and the built application at
`/share/a0000000-0000-4000-8000-000000000005` — a case whose `share_enabled` is `true` — renders
`Case Not Found`. The `TEXT` form is additionally non-functional on its own: with the `UUID` form
dropped it returns `42883 operator does not exist: uuid = text`, because `cases.share_token` is
`uuid`. It has never worked.

Both fixes were proven live during research and then reverted. With per-table grants applied, Alpha
reads exactly its own org and case, Beta reads exactly its own, Alpha's query for Beta's case id
returns `[]`, and an anonymous read of `cases` stays 42501. With the `TEXT` overload dropped, the
anonymous share RPC returns Alpha's full case row for Alpha's token and `[]` for Beta's disabled one.

Output: two migrations, four new seeded fixture rows, and one probe script that re-proves all of it
on demand.
</objective>

<constraints>

1. **`anon` receives no table privilege.** Not `SELECT`, not anything, on any table. The only
   anonymous data path in this product is `get_shared_case`, which is `SECURITY DEFINER` and already
   carries `GRANT EXECUTE ON FUNCTION get_shared_case(UUID) TO anon` at
   `migrations/004_shared_case_rpc.sql:29`. A blanket `GRANT ALL ON ALL TABLES IN SCHEMA public TO
   anon, authenticated, service_role` is the Supabase boilerplate and is prohibited here.

2. **Grants are per table and per verb, transcribed from the policy table in `11-RESEARCH.md` §7.**
   That table was read from `pg_policies`, not composed. Do not add a verb a table has no policy for
   and do not omit one it does.

3. **No existing migration file may be edited.** `001` through `013` are applied history. The two
   corrections arrive as new files `014` and `015`. Editing `011` in place would leave every database
   already provisioned from it unchanged.

4. **`seed.sql` and `fixtures.json` change together.** `node scripts/check-seed-fixture.mjs` fails
   when a uuid appears in one and not the other, in either direction. The seeded case `input_json`
   stays a byte-for-byte copy of `engine/examples/cases/02-married-3lc.json` and is not touched.

5. **The service-role key is never written to a file and never printed.** `db-access-probe.mjs`
   obtains it exactly the way `journey/seed-smoke.mjs` already does: `supabase status -o env`, parsed
   into a local variable. `scripts/setup-env.sh:149` keeps it out of `frontend/.env.local` for this
   reason.

6. **Commit explicit paths only.** Use `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited — a concurrent auto-committer runs on
   this monorepo.

7. **Do not register a gate in this plan.** `gates.manifest.json` and `gates.manifest.lock` are
   read-only here; plan 11-08 performs the only permitted append.

</constraints>
