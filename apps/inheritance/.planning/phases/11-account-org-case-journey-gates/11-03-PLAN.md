<objective>
Build the live journey runner: the thing that turns Phase 10's harness, which only ever saw committed
HTML fixtures, into a gate that screenshots the real application backed by the real database.

`GATES.md` §12 draws the line explicitly — G15 "needs no Docker, no Supabase, no built application
and no network", and "the gates that drive the real application belong to Phases 11 and 12". This
plan is the mechanism half of that sentence. It authors exactly one step, `auth-signin`, to prove the
mechanism end to end; plans 11-05, 11-06 and 11-07 add the other seventeen as data.

Every hop was proven during research and is recorded in `11-RESEARCH.md` §4:

- `npm run build` exits 0 in 17.2 s and `npx vite preview --port 4173 --strictPort` serves the SPA
  history fallback, so `/auth`, `/cases/new` and `/share/<token>` are all reachable directly. Port
  4173 was measured free.
- `supabase-js` stores a session at `sb-127-auth-token` as the raw session JSON, which is exactly
  what `journey/seed.mjs:seedAuthSession` writes, and `src/main.tsx:20` reads it through
  `supabase.auth.getSession()` on mount, so a session installed before first paint arrives with no
  reload.
- Driving `/` with a seeded Alpha session produced a 32,631-byte PNG, the body text
  `… alpha@example.test Sign Out Dashboard New Case RECENT CASES … Seeded Case Alpha draft`, and zero
  console errors.

The registry is data rather than code because eighteen steps written as eighteen scripts is eighteen
places for a selector convention to drift, and because gate G16 in plan 11-08 can only check a
registry it can read.

Output: five new modules, one committed step registry holding one step, one rubric, one approved
reference pair, and a probe that proves the cannot-run path.

### `frontend/journey/steps/` — the registry directory

`run.mjs` reads **every** `*.json` file in `frontend/journey/steps/`, in alphabetical file order, and
concatenates their `steps` arrays into one registry. One file per requirement group keeps three plans
out of each other's way: this plan creates `account.json`, plan 11-06 creates `org.json`, plan 11-07
creates `intake.json`.

Each file is one object with one key, `steps`, holding an array. Every record has exactly these fields, and a
record carrying an unknown field is rejected:

| Field | Type | Closed set / rule |
|---|---|---|
| `id` | string | unique across the file; matches `^[a-z0-9-]+$`; is the artifact directory name and the reference file stem |
| `requirement` | string | one of `JRNY-02`, `JRNY-03`, `JRNY-04` |
| `url` | string | a path beginning with `/`, appended to the preview origin |
| `session` | string | one of `none`, `alpha`, `beta`, `orphan` |
| `localStorage` | object | string keys to string values; a value of the form `@file:<name>` is replaced by the contents of `journey/fixtures/<name>` |
| `sessionStorage` | object | same shape and same `@file:` rule |
| `reset` | string or null | `null`, or one of the reset names exported by `journey/resets.mjs` |
| `actions` | array | zero or more action records, shape below |
| `settleMs` | integer | milliseconds to wait after navigation and after the last action, before capture; `1200` is the value measured sufficient in research |
| `rubric` | string | a file name inside `journey/rubrics/` |
| `allowConsoleErrors` | boolean | when `true`, the runner does not treat a console error as a step failure on its own; the rubric still decides |

An action record is `{ "kind": …, … }` with `kind` from this closed set:

| `kind` | Extra fields | Behaviour |
|---|---|---|
| `click` | `selector` | `page.click(selector)` |
| `fill` | `selector`, `value` | `page.fill(selector, value)` |
| `waitForSelector` | `selector` | `page.waitForSelector(selector)` |
| `waitForUrlContains` | `value` | polls `page.url()` until it contains `value`, for at most 10000 ms |

The single record this plan commits:

```json
{
  "id": "auth-signin",
  "requirement": "JRNY-02",
  "url": "/auth",
  "session": "none",
  "localStorage": {},
  "sessionStorage": {},
  "reset": null,
  "actions": [{ "kind": "waitForSelector", "selector": "[data-testid=\"auth-page\"]" }],
  "settleMs": 1200,
  "rubric": "auth-signin.json",
  "allowConsoleErrors": false
}
```

### `frontend/journey/run.mjs`

```
node journey/run.mjs --all
node journey/run.mjs --step <stepId>          # repeatable
node journey/run.mjs --list                   # print every step id, exit 0, start nothing
```

| Exit | Meaning | Marker printed |
|---|---|---|
| 0 | every selected step passed | `JOURNEY PASS steps=<n> failed=0` |
| 1 | at least one step failed | `JOURNEY FAIL steps=<n> failed=<k>` plus one `JOURNEY STEP FAILED <id>: <markers>` line per failure |
| 2 | the run could not start | `JOURNEY CANNOT RUN: <reason>` |

Cannot-run reasons, enumerated so nothing is judged: the local Supabase stack is not reachable;
`npm run build` exited nonzero; the preview server did not answer within 30000 ms; chromium is not
installed; `journey/steps/*.json` is unparseable; a requested `--step` id is not in the registry.

The runner prints `GATE-SKIPS total=<selected step count> skipped=0` on **both** the pass and the fail
path, because `scripts/check-gate-skips.mjs` reads that line out of the gate log regardless of
outcome. It is not printed on the cannot-run path, where no step was selected.

Per step the runner: applies `reset`, opens a page, seeds session and storage **before first paint**
through `journey/seed.mjs`, navigates, runs `actions`, waits `settleMs`, captures, evaluates the
rubric, compares against the reference, and writes artifacts through
`journey/artifacts.mjs:writeStepArtifacts`. A step passes when the rubric passed **and** the diff
passed. A thrown error is caught, reported with the `STEP ERROR` marker from
`journey/diff.mjs:DIFF_MARKERS`, and does not stop the remaining steps.
