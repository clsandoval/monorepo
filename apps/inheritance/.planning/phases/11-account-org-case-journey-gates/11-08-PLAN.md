<objective>
Register the phase's verification as gates, so nothing built in plans 11-03 through 11-07 depends on
an agent remembering to run it.

`CLAUDE.md` states the invariant this plan operates under: the gate set in `gates.manifest.json` may
only grow, and `node scripts/check-gate-manifest.mjs` enforces it. This plan performs the only
manifest append permitted anywhere in Phase 11.

Three gates, for the reason recorded in `11-RESEARCH.md` D-E:

- **G16** — journey registry integrity. Static: no Docker, no Supabase, no build, no browser. It is
  the half that runs on a bare runner and catches a step declared without a rubric or without an
  approved reference.
- **G18** — tenant isolation. `node journey/rls-isolation.mjs`. Needs the local stack, but no build
  and no browser.
- **G17** — the live journey run. `node journey/run.mjs --all`. Needs the local stack, a build and
  chromium.

G17 and G18 are separate gates rather than one conjoined command because a red run must say whether a
screen regressed or a tenant boundary did, and those are different investigations.

`11-RESEARCH.md` D-G records the CI consequence honestly. `.github/workflows/inheritance-ci.yml`
installs Rust, wasm-pack, Node and npm dependencies and then runs `scripts/ci-gates.sh`; it has no
Supabase CLI and never starts a stack, so G17 and G18 would be red there. The workflow gains the
provisioning steps. **Unmeasured:** no CI run has ever executed for this project — Phase 1's GATE-04
finding — so whether `supabase start` succeeds on a GitHub-hosted runner is not known from this
machine. That is recorded as a risk below rather than asserted as working.

There is no way to make a Docker-dependent gate quietly not run. `scripts/ci-gates.sh` halts the
whole run with exit 2 on a false `precondition`, and maps every other nonzero to `GATE FAILED`. Both
outcomes are loud, which is the correct behaviour for this project: `PROJECT.md` ranks silent
wrongness as categorically worse than loud failure.

Output: one new static gate script, three manifest entries, three lock entries, a new `GATES.md`
section 13, and a CI workflow that provisions what the live gates need.

### `scripts/check-journey-registry.mjs`

Dependency-free, `node:` builtins only, exit 0 on zero violations and 1 otherwise, in the style of
`scripts/check-gate-manifest.mjs`. It reads every `frontend/journey/steps/*.json`, every
`frontend/journey/rubrics/*.json` and the contents of `frontend/journey/references/`, and prints one
line per violation with the marker shown:

| Marker | Condition |
|---|---|
| `STEP FIELD INVALID` | a step record carries an unknown field, or an out-of-set value for `requirement`, `session`, `reset` or an action `kind`, or an `id` not matching `^[a-z0-9-]+$`, or a `settleMs` that is not a non-negative integer |
| `DUPLICATE STEP ID` | the same `id` appears in more than one record across all registry files |
| `RUBRIC MISSING` | a step's `rubric` names a file that is not in `frontend/journey/rubrics/` |
| `RUBRIC KIND INVALID` | a rubric assertion carries a `kind` outside the eight in `journey/rubric.mjs:ASSERTION_KINDS`, or omits a field that kind requires |
| `RUBRIC ID MISMATCH` | a rubric's `rubricId` differs from the step id that names it |
| `REFERENCE MISSING` | `references/<stepId>.png` or `references/<stepId>.json` is absent |
| `TOLERANCE RAISED` | a reference sidecar's `maxDiffPixels` is not `0` and the sidecar carries no `approvedBy` value |
| `ORPHAN REFERENCE` | a `references/<name>.png` exists whose `<name>` is not a declared step id |
| `UNKNOWN URL TOKEN` | a step `url` contains a uuid-shaped literal that is neither present in `frontend/supabase/fixtures.json` nor the single declared refusal token `00000000-0000-4000-8000-0000000000ff` |

It prints `GATE-SKIPS total=<number of checks performed> skipped=0` on both the pass and the fail
path, then `JOURNEY REGISTRY ok steps=<n> references=<n>` on the pass path.

`TOLERANCE RAISED` allows a non-zero tolerance only when `approvedBy` is recorded, because
`REFERENCES.md` permits exactly one measured reason — a platform whose text rasterisation differs —
and requires that whoever raised it be named. An unattributed non-zero tolerance is the silent
widening that document prohibits.

### The CI workflow addition

Two steps, inserted after `Install frontend dependencies` and before `Run all gates`:

```yaml
      - name: Install Supabase CLI
        uses: supabase/setup-cli@v1
        with:
          version: 2.110.0

      - name: Start local Supabase stack
        working-directory: apps/inheritance/frontend
        run: supabase start
```

Version `2.110.0` is the version measured on the development machine
(`supabase --version` → `2.110.0`), so CI and local run the same CLI.

Also raise the job's `timeout-minutes` from `30` to `45`: the two live gates add a Supabase container
pull, a `npm run build` (17 s locally) and nineteen browser steps, and a timeout that fires mid-run
reports a product failure for an environment reason.

Also add, before `Run all gates`, a chromium install step, because `journey/run.mjs` needs the browser
Phase 10's `journey/browser.mjs` launches:

```yaml
      - name: Install Playwright chromium
        working-directory: apps/inheritance/frontend
        run: npx playwright install --with-deps chromium
```
