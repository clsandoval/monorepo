<objective>
Fix the three product defects that make the account and organization journeys unverifiable, and give
every screen this phase screenshots a stable hook a rubric can address.

All three defects were found by driving the built application in a real browser during research; none
is hypothetical and none is a point of law.

`11-RESEARCH.md` D-1: `src/lib/organizations.ts:10` declares
`createOrganization(firmName: string, slug?: string)`, and the RPC `create_organization(p_name TEXT,
p_slug TEXT DEFAULT NULL)` derives its owner from `auth.uid()` and accepts no user id. Two call sites
pass a user id first — `src/routes/auth.tsx:85` and `src/routes/auth/callback.tsx:32` — so a signup
creates an organization named after the user's uuid, with the firm name stored as the slug.
`src/routes/onboarding.tsx:58` already calls it correctly with one argument. A `grep` over `src/`
found no test asserting either wrong call, so the correction conflicts with nothing.

`11-RESEARCH.md` D-2: `accept_invitation` returns `{"success": false, "error": …}` without raising,
and `src/routes/invite/$token.tsx:22` navigates to `/settings/team` on any resolved promise. Measured
in the browser: `/invite/00000000-0000-4000-8000-0000000000ff` landed on `/settings/team` showing
`No organization found…`, exactly as though the invitation had been accepted.

`11-RESEARCH.md` D-3: `src/routes/settings/team.tsx:48` reads `.from('profiles')`. The eleven tables
in `public` are `case_deadlines, case_documents, case_notes, case_pdfs, cases, clients,
conflict_check_log, organization_invitations, organization_members, organizations, user_profiles` —
there is no `profiles`. The `.catch(() => {})` on line 58 swallows the error, so member names never
load and nothing says so.

The testid work exists because a rubric assertion needs a selector that resolves to exactly one
element. Phase 10's `evaluateRubric` fails `text_equals`, `text_contains`, `element_visible` and
`attribute_equals` when a selector matches more than one node, and `AppLayout.tsx` renders the string
`Sign Out` twice — once at line 75 and once at line 179.

Output: three corrected behaviours, nineteen `data-testid` attributes, and a frontend suite whose
known-failure ledger has been shrunk by exactly the entries these fixes turn green.
</objective>
