<objective>
Round and emit the legitime/free-portion/intestate split that Step 7 already computes, and populate
the legitime fraction that Step 5 already computes, so a lawyer reading a per-heir row can see which
pesos are protected legitime and which are freely disposable.

Purpose: `engine/src/step10_finalize.rs` hardcodes all three sub-components to zero at lines 538-542
(the distribution path) and again at lines 561-565 (the zero-share path), and sets
`legitime_fraction: String::new()` in both. Measured live over the 140 committed inputs, this
produces **0 nonzero sub-components and 0 non-empty fractions across 564 per-heir rows**. The data is
not missing: `HeirDistribution` carries all three as `Frac` with a documented contract at
`engine/src/step7_distribute.rs:41` that `total = from_legitime + from_free_portion + from_intestate`,
and `Step10Input.heir_legitimes` already holds each heir's `legitime_fraction: Frac`. Step 10 throws
both away.

The one decision this plan needs and therefore states in full is the rounding rule. The estate-level
allocation already rounds each heir's net share against the estate; the three sub-components must be
rounded again *within* each heir so they sum to that heir's own rounded total. The rule is written
literally in task 1, including its tie-break, so no executor has to invent one.

Output: a `step10_finalize` that emits four previously-dead fields, plus Rust tests asserting the
per-heir sum identity and the fraction format.
</objective>

  <action>
Replace the three hardcoded zeros in the distribution-path `InheritanceShare` construction
(currently lines 538-540, the block whose first field is `from_legitime`) with rounded values derived
from the matching `HeirDistribution`.

**The rounding rule, stated in full.** For each heir, after `total_money` has been computed:

1. Build the ordered triple of `Frac` components from `dist`, in this fixed order:
   `[("legitime", dist.from_legitime.clone()), ("free_portion", dist.from_free_portion.clone()),
   ("intestate", dist.from_intestate.clone())]`.
2. Call the existing `allocate_with_rounding` with that triple and `&total_money` as the target.
   That function floors each component to centavos and distributes any positive shortfall by the
   largest-remainder method, which is the same rule already used at the estate level, so the two
   levels cannot disagree about how a half-centavo is treated.
3. `allocate_with_rounding` only distributes a **positive** remainder. When flooring has overshot —
   which is possible because `total_money` is itself a rounded figure — the three floors can sum to
   one or two centavos more than `total_money`. Correct that deterministically: compute
   `diff = total_money.centavos - (legitime + free_portion + intestate)`, and when `diff` is
   negative, subtract its magnitude from the **first** component in the fixed order above that is
   large enough to absorb it without going negative, testing `legitime`, then `free_portion`, then
   `intestate`. When no single component can absorb it, subtract as much as each can in that same
   order until the difference is exhausted. There is no randomness and no tie to break: the order is
   fixed by the triple above.
4. Assign the three results to `from_legitime`, `from_free_portion` and `from_intestate`.

Add a private helper `fn split_components(dist: &HeirDistribution, target: &Money) -> (Money, Money, Money)`
implementing steps 1 through 3, placed next to `allocate_with_rounding` in the file's helper region,
with a `///` doc comment stating the identity it guarantees:
`from_legitime + from_free_portion + from_intestate == target`.

Leave the zero-share path (currently lines 555-570, the `2b. Add zero-share entries` loop) with all
three sub-components at `Money::new(0)`. Those heirs receive nothing, so zero is the correct value,
not a placeholder. Delete the `// TODO: round sub-components` trailing comment on the distribution
path, since it no longer describes the code.

Add two unit tests at the end of the existing `mod tests` block:

- `test_split_components_sums_to_target` — construct a `HeirDistribution` whose three `Frac`
  components are `1/3`, `1/3` and `1/3` of `1000` centavos and a target of `Money::new(1000)`, call
  `split_components`, and assert with `assert_eq!` that the three returned centavo values sum to

- `test_split_components_absorbs_overshoot` — construct a distribution whose three components each
  floor upward relative to a target one centavo smaller than their exact sum, call
  `split_components`, and assert with `assert_eq!` that the sum equals the target exactly and that no
  component is negative.

the rule is purely mechanical and needs no reduction step:

- when `f.denom()` equals one, return `f.numer().to_string()`
- otherwise return `format!("{}/{}", f.numer(), f.denom())`
