<objective>
Promote the sum-conservation and heir-uniqueness invariants from test assertions into runtime checks
that reject a corrupt distribution before it can be shown to a lawyer.

Purpose: `engine/tests/fuzz_invariants.rs:65-72` already asserts
`sum(net_from_estate) == net_distributable_estate` over the 100 fuzz cases and passes today, and a
live corpus run over all 140 committed inputs found **zero** sum violations and **zero** duplicate
`heir_id` values. That is what makes this plan safe: neither predicate is new, and neither can turn a
green suite red. What is new is *where* they run. Today they run only when somebody runs the test
suite. After this plan they run on every computation, including the one a lawyer triggers from the
browser, and a violation stops the number from being displayed at all.

`ROADMAP` Phase 5 criterion 3 is explicit that this must be a runtime rejection rather than a test
assertion, which is why the checks live in a module the pipeline calls rather than in a `#[test]`.

The escheat case was checked before choosing the unconditional form:
`engine/tests/integration.rs:1283` asserts that scenario I15 produces **one** share holding the whole
estate — a synthesised State row — not an empty distribution. So no legitimate case has an empty
`per_heir_shares` alongside a nonzero estate, and the conservation check needs no carve-out.

Output: `engine/src/output_check.rs`, a `run_pipeline_checked` entry point, and both production
callers switched to it.
</objective>

Create `engine/src/output_check.rs` and register it in `engine/src/lib.rs` with
`pub mod output_check;`, placed alphabetically after `pub mod main` has no entry — put it directly
before `pub mod pipeline;`.

**The defect type.**

`#[derive(Debug, Clone, PartialEq, Eq)] pub enum OutputDefect` with exactly two variants:

| Variant | Fields | Meaning |
|---|---|---|
| `SumMismatch` | `expected: BigInt`, `actual: BigInt` | The per-heir `net_from_estate` values do not sum to the distributable estate |
| `DuplicateHeirId` | `heir_id: HeirId`, `occurrences: usize` | The same `heir_id` appears more than once in `per_heir_shares` |

Implement `std::fmt::Display` for it. `SumMismatch` renders as
`sum conservation violated: per-heir net_from_estate totals <actual> centavos, distributable estate is <expected> centavos`.
`DuplicateHeirId` renders as
`duplicate heir_id in per_heir_shares: <heir_id> appears <occurrences> times`.
Both messages are the exact text a lawyer or a support engineer will read, so they name the field and
the number rather than an error code.

**The check.**

`pub fn check_output(output: &EngineOutput, net_estate: &Money) -> Result<(), Vec<OutputDefect>>`.

It collects **every** defect before returning, never short-circuits on the first, and returns
`Ok(())` only when the vector is empty.

1. Conservation. Fold `output.per_heir_shares.iter().map(|s| s.net_from_estate.centavos.clone())`
   into a `BigInt` starting from zero, and compare with `net_estate.centavos`. This is the identical
   predicate `engine/tests/fuzz_invariants.rs:65-72` already applies; use `net_from_estate` and not
   `total`, because `total` is the gross entitlement and includes collated donations that never came
   out of the physical estate. Push `SumMismatch` on inequality. Run this unconditionally: scenario
   I15 synthesises a State share rather than producing an empty distribution
   (`engine/tests/integration.rs:1283` asserts exactly one share holding the whole estate), so an
   empty `per_heir_shares` with a nonzero estate is a defect and not a legitimate escheat.
2. Uniqueness. Count occurrences of each `heir_id` with a `std::collections::HashMap<&str, usize>`,
   and push one `DuplicateHeirId` per id whose count exceeds one. Sort the pushed defects by
   `heir_id` before returning so the output is deterministic regardless of hash order.

The function must not panic on any input: no `unwrap`, no `expect`, no indexing by position, no
integer conversion that can fail. `grep -cE "unwrap\(\)|expect\(|panic!" engine/src/output_check.rs`
must return `0`.

**Tests.** Add a `#[cfg(test)] mod tests` with five tests, each building an `EngineOutput` by hand:

- `test_clean_output_passes` — two shares of 600 000 and 400 000 centavos against an estate of
  1 000 000 returns `Ok(())`.
- `test_sum_mismatch_is_rejected` — the same output with the first share incremented by one centavo
  returns `Err`, the vector has length 1, and it holds a `SumMismatch` whose `actual` is exactly
  1 000 001.
- `test_duplicate_heir_id_is_rejected` — an output whose two shares carry the same `heir_id` returns
  `Err` holding a `DuplicateHeirId` with `occurrences` equal to 2.
- `test_both_defects_are_reported_together` — an output that is both unbalanced and duplicated
  returns a vector of length 2, proving the check does not short-circuit.
- `test_empty_shares_with_nonzero_estate_is_rejected` — an output with no shares against a nonzero
  estate returns `Err` holding a `SumMismatch` whose `actual` is 0.

Every assertion uses `assert_eq!` on an exact value, never `assert!(result.is_err())` alone.
