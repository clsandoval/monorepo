<objective>
Make a frontend error something that is captured and can be read back, instead of something that
blanks the page and vanishes.

Purpose: `grep -rln "ErrorBoundary|componentDidCatch|getDerivedStateFromError" frontend/src` returns
zero files. `frontend/src/main.tsx` mounts `<RouterProvider>` inside `<React.StrictMode>` with no
boundary, so an uncaught throw inside a route component — a malformed engine payload, a null
dereference in a results table — unmounts the whole tree to a blank white page with nothing recorded
anywhere. `.planning/codebase/` records this as a gap for verification design: a later screenshot
gate that induces a failure must be able to assert that *some* page rendered.

No error-tracking service is configured in this repository, and none is referenced in `fly.toml` or
the nginx Dockerfile. Picking a vendor would be an ungrounded decision of exactly the kind `LOOP-01`
forbids, so the sink is in-process: a bounded ring buffer with a read API, plus a mirror to
`console.error` so nothing that is captured is also silenced.

This plan has no dependency on the engine and shares no file with any other plan in this phase, so
it runs in wave 1 alongside 05-01.

Output: `frontend/src/lib/error-reporting.ts`, `frontend/src/components/ErrorBoundary.tsx`, both
wired into `frontend/src/main.tsx`, and two test files that observe capture happening.
</objective>

  <action>
Create `frontend/src/lib/error-reporting.ts`, a dependency-free TypeScript module with no imports
from any other project file.

**Exported type.** `export interface ErrorReport` with exactly five fields:

| Field | Type | Meaning |
|---|---|---|
| `id` | `number` | Monotonic counter starting at 1, incremented for every report |
| `at` | `string` | `new Date().toISOString()` at capture time |
| `source` | `"boundary" \| "window" \| "unhandledrejection" \| "manual"` | Which entry point captured it |
| `message` | `string` | The error's message, or `String(value)` when the thrown value is not an `Error` |
| `stack` | `string \| null` | The error's stack, or `null` when the thrown value carries none |

**Module state.** A module-level `const MAX_REPORTS = 50;` and a module-level
`let reports: ErrorReport[] = [];`. When a push would exceed `MAX_REPORTS`, drop the oldest entry
first, so the buffer is bounded and a render loop cannot exhaust memory.

**Exported functions**, all four:

- `export function reportError(value: unknown, source: ErrorReport["source"] = "manual"): ErrorReport`
  — normalises `value` into an `ErrorReport`, appends it under the cap, calls
  `console.error("[error-report]", report.source, report.message, value)`, and returns the report.
  Normalisation rule, stated so it is not invented: when `value instanceof Error`, `message` is
  `value.message` and `stack` is `value.stack ?? null`; otherwise `message` is `String(value)` and
  `stack` is `null`.
- `export function getReportedErrors(): ErrorReport[]` — returns a shallow copy of the buffer, so a
  caller cannot mutate module state through the returned array.
- `export function clearReportedErrors(): void` — empties the buffer. The id counter is **not** reset,
  so ids stay unique across a session.
- `export function installGlobalErrorHandlers(target: Window = window): () => void` — attaches an
  `error` listener that calls `reportError(event.error ?? event.message, "window")` and an
  `unhandledrejection` listener that calls `reportError(event.reason, "unhandledrejection")`, and
  returns a function that removes both. Calling it twice must not attach duplicates: guard with a
  module-level `let handlersInstalled = false;` and return a no-op remover when it is already true.

Then create `frontend/src/lib/__tests__/error-reporting.test.ts` following the conventions in
`.planning/codebase/` — a `describe` per exported function, `beforeEach(() => clearReportedErrors())`,
and no mocking, since the module has no external boundary. Cover exactly these cases:

1. `reportError(new Error("boom"))` returns a report whose `message` is `"boom"`, whose `source` is
   `"manual"`, and whose `stack` is a non-null string.
2. `reportError("plain string", "window")` returns a report whose `message` is `"plain string"` and
   whose `stack` is `null`.
3. `getReportedErrors()` returns both reports in insertion order after the two calls above.
4. Mutating the array returned by `getReportedErrors()` does not change what the next call returns.
5. Pushing 55 reports leaves `getReportedErrors()` with exactly 50 entries, and the first surviving
   entry's `message` is the sixth one pushed.
6. `clearReportedErrors()` empties the buffer, and the next report's `id` is still greater than the
   last cleared one.
7. `installGlobalErrorHandlers()` followed by dispatching
   `new ErrorEvent("error", { message: "global boom" })` on `window` records a report with `source`
   `"window"`; the returned remover then detaches it, and a second dispatch adds nothing.

Use `vi.spyOn(console, "error").mockImplementation(() => {})` in a `beforeEach` so the suite output
stays readable, and restore it in an `afterEach`.

  <name>Task 2: Add the React error boundary and prove it catches a render throw</name>
  <files>frontend/src/components/ErrorBoundary.tsx, frontend/src/components/__tests__/ErrorBoundary.test.tsx</files>

  <action>
Create `frontend/src/components/ErrorBoundary.tsx` exporting a single default-free named class
component, `export class ErrorBoundary extends React.Component<ErrorBoundaryProps, ErrorBoundaryState>`.
React has no hook equivalent for error boundaries, so a class is the only shape available.

**Props.** `children: React.ReactNode` and an optional `fallback?: React.ReactNode`.

**State.** `{ hasError: boolean; message: string }`, initialised to `{ hasError: false, message: "" }`.

**Behavior.**

- `static getDerivedStateFromError(error: unknown): ErrorBoundaryState` returns
  `{ hasError: true, message: error instanceof Error ? error.message : String(error) }`.
- `componentDidCatch(error: unknown)` calls `reportError(error, "boundary")` imported from
  `@/lib/error-reporting`.
- `render()` returns `this.props.children` when `hasError` is false. When `hasError` is true it
  returns `this.props.fallback` when that prop was supplied, and otherwise the built-in fallback
  described next.

**Built-in fallback markup**, specified literally so it is not invented. A single `<div>` with
`role="alert"` and the Tailwind class string
`"flex min-h-screen flex-col items-center justify-center gap-3 p-6 text-center"`, containing:

- an `<h1>` with class `"text-xl font-semibold"` and the exact text `Something went wrong`
- a `<p>` with class `"text-sm text-muted-foreground"` and the exact text
  `The page could not be displayed. The error has been recorded.`
- a `<p>` with `data-testid="error-boundary-message"`, class `"text-xs text-muted-foreground"`, and
  `{this.state.message}` as its content
- a `<button type="button">` with class `"underline text-sm"` and the exact text `Reload this page`
  whose `onClick` calls `window.location.reload()`

Then create `frontend/src/components/__tests__/ErrorBoundary.test.tsx` using
`@testing-library/react`'s `render` and `screen`, following the file conventions already used in
`frontend/src/components/results/__tests__/`. Cover exactly these cases:

1. A non-throwing child renders normally and `screen.queryByRole("alert")` is `null`.
2. A child whose render body executes `throw new Error("kaboom")` causes `screen.getByRole("alert")`
   to exist and `screen.getByText("Something went wrong")` to exist.
3. In that same case, `screen.getByTestId("error-boundary-message")` has text content `kaboom`.
4. In that same case, `getReportedErrors()` contains exactly one report whose `source` is
   `"boundary"` and whose `message` is `kaboom`.
5. A supplied `fallback` prop renders instead of the built-in markup, asserted by finding the
   fallback's own text and asserting `screen.queryByText("Something went wrong")` is `null`.

Call `clearReportedErrors()` in `beforeEach`. React logs caught boundary errors to `console.error`,
so spy on it with `vi.spyOn(console, "error").mockImplementation(() => {})` in `beforeEach` and
restore in `afterEach`; that is noise suppression in the test harness, not suppression of the
production behavior, which task 1 already covered with its own assertion.
