<objective>
Lock the phase in: prove over the whole committed corpus that observability is actually on, and make
its removal fail the build.

Purpose: every plan in this phase changed a behavior that is invisible unless something looks for it.
The measured starting point was stark — across 140 committed inputs and 564 per-heir rows, **zero**
rows had a nonzero `from_legitime`, `from_free_portion` or `from_intestate`, **zero** rows had a
non-empty `legitime_fraction`, **zero** cases produced a warning, and **every** case reported exactly
one computation-log step. Those are the six numbers this plan turns into assertions.

Two mechanisms, because they catch different failures. The corpus test
(`engine/tests/observability.rs`, running under the existing gate `G1`) catches a behavioral
regression: someone changes a step and the fractions go empty again. The static gate
(`scripts/check-observability.mjs`, registered as `G11`) catches a source regression: someone
reintroduces `warnings: vec![]` or re-zeroes a sub-component while the tests happen not to cover that
path. `.planning/research/LEGAL-CONFORMANCE.md` records that both of those exact lines survived in
this codebase for the whole of its life, unnoticed, which is why a grep-level guard is warranted
alongside a behavioral one.

Registration constraint carried forward from `04-RESEARCH.md` and re-verified in `05-RESEARCH.md`
section 6: `scripts/check-gate-results.mjs` (`G9`) fails with `RESULTS INCOMPLETE` when any gate other
than itself is `not-run`, and the runner republishes after every gate, so `G9` must stay last. `G11`
therefore takes `order: 9`, `G8` moves to `10` and `G9` moves to `11`. That also puts `G11` ahead of
the skip-accounting gate, so its own `GATE-SKIPS` line is checked rather than exempted.

Output: a corpus test, a static gate with six verdicts and five fixtures, gate `G11`, `GATES.md`
section 9, and an updated `README.md`.
</objective>

4. `FLAG CODE UNTESTED` — a spec code appears in the flags file but nowhere in the flags file's

5. `OUTPUT CHECK MISSING` — the output-check file lacks either `SumMismatch` or `DuplicateHeirId`, or

a named file is missing or unreadable. Never exit 0 on an internal error.

**All matching is literal, never regular-expression.** The searched strings contain `[`, `]`, `!`,
`:` and `(`, which are regex metacharacters, and treating them as a pattern would silently change
what is matched. Use `String.prototype.includes` and `split("\n")` line scanning.

**Comment hygiene.** Verdicts 1 and 2 must ignore lines whose trimmed form starts with `//`, because
`GATES.md` and this script's own header quote the forbidden literals as prose, and a doc comment in
the finalize file explaining what was removed must not re-trigger the gate it documents.

**Output on success:** a line containing the literal string `OBSERVABILITY OK` plus three counts, in
the shape `OBSERVABILITY OK — 10 flag codes, 5 files scanned, 0 suppressed lines`. Then a second line
`GATE-SKIPS total=<n> skipped=0`, where `<n>` is the number of files scanned. Print that line on
**every** exit path, success and failure alike, immediately before the script exits — gate `G8` fails
with `SKIP REPORT MISSING` on a log that lacks it.

**Exit codes:** `0` only when there are zero violations, `1` otherwise. No other exit code.
