<objective>
Construct and emit all ten manual-review flag categories the engine spec defines, so the human-in-the-loop
mechanism the spec describes stops being unreachable.

Purpose: `specs/inheritance-engine-spec.md:2303-2321` says "These 10 situations require human
judgment" and tables them by flag code. `grep -rn` over `engine/src` finds **zero** of the ten
anywhere in the crate. The six category strings the crate does construct — `unknown_donee`,
`preterition`, `disinheritance`, `inofficiousness`, `max_restarts`, `vacancy_unresolved` — are a
disjoint set of internal pipeline events. Both sets are needed and both survive this plan.

A flag is the engine saying *a human must decide this*. It changes no peso amount and takes no
position on any reading, which is why building all ten decides nothing. Five of the ten are already
expressible from fields on the current `EngineInput`; the other five need a fact the input cannot
state today. Those five arrive as one serde-defaulted struct hung off `EngineConfig` — a shape chosen
because `grep -rn "EngineConfig {" engine/src engine/tests` finds exactly two sites plus one test
helper, whereas scattering the fields across `Person`, `Donation`, `Legacy`, `Devise` and
`Disinheritance` would require editing 89 exhaustive struct literals. `05-RESEARCH.md` section 2.2
records both measurements.

Output: `engine/src/flags.rs` with ten codes and ten detectors, `ManualReviewFacts` on
`EngineConfig`, a single detector call in `pipeline.rs`, and an optional mirror member on the
TypeScript `EngineConfig` so `tsc` stays clean and Phase 11 has somewhere to put the wizard fields.
</objective>

**Step A — extend the input.** In `engine/src/types.rs`, add a new struct immediately above
`pub struct EngineConfig`:

```
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
pub struct ManualReviewFacts { ... }
```

with these five `#[serde(default)]` public members, each carrying a `///` doc comment quoting the
spec trigger it serves. Every one is a fact the person entering the case asserts, never a conclusion
the engine derives:

| Member | Type | Doc comment |
|---|---|---|
| `disputed_donation_ids` | `Vec<DonationId>` | Ids of donations the parties dispute as to collatability or value (Art. 1077). |
| `usufruct_or_annuity_disposition_ids` | `Vec<DispositionId>` | Ids of legacies or devises that give a usufruct or a life annuity (Art. 911 ¶3). |
| `dual_line_ascendant_ids` | `Vec<PersonId>` | Ids of persons appearing in both the paternal and the maternal ascending line (Art. 890). |
| `unborn_disinherited_ids` | `Vec<PersonId>` | Ids of persons disinherited by the will who were not yet born when it was executed (Arts. 915-923). |
| `reserva_troncal_property_present` | `bool` | True when the estate includes property the decedent acquired by gratuitous title from an ascendant, brother or sister (Art. 891). |

Then add `#[serde(default)] pub manual_review_facts: ManualReviewFacts,` to `EngineConfig` **after**
`max_pipeline_restarts`, and add `manual_review_facts: ManualReviewFacts::default(),` to
`impl Default for EngineConfig`. Read constraint 5 before editing this struct.

**Step B — create `engine/src/flags.rs`** and register it in `engine/src/lib.rs` with
`pub mod flags;`, placed alphabetically before `pub mod fraction;`.

The module declares the ten codes as public string constants, transcribed verbatim from
`specs/inheritance-engine-spec.md` §13.1:

`GRANDPARENT_OF_ILLEGITIMATE`, `CROSS_CLASS_ACCRETION`, `RESERVA_TRONCAL`, `COLLATION_DISPUTE`,
`RA_11642_RETROACTIVITY`, `ARTICULO_MORTIS`, `USUFRUCT_ANNUITY_OPTION`, `DUAL_LINE_ASCENDANT`,
`POSTHUMOUS_DISINHERITANCE`, `CONTRADICTORY_DISPOSITIONS`.

Declare them as `pub const SPEC_FLAG_<NAME>: &str = "<NAME>";` and also as one
`pub const SPEC_FLAG_CODES: [&str; 10] = [ ... ];` array holding all ten in the spec's table order,
so the complete set is auditable in one place.

Then implement `pub fn detect_spec_flags(input: &EngineInput) -> Vec<ManualFlag>`. It returns flags
in the fixed order of `SPEC_FLAG_CODES`, so output is deterministic. Each `ManualFlag` uses the code
as its `category`, a description from the table below, and `related_heir_id` set to the id named in
the table or `None`:

| Code | Trigger, as a field comparison | `related_heir_id` | Description |
|---|---|---|---|
| `GRANDPARENT_OF_ILLEGITIMATE` | `input.decedent.is_illegitimate` is true **and** some `p` in `family_tree` has `p.is_alive_at_succession` and `p.relationship_to_decedent == Relationship::LegitimateAscendant` and `p.degree >= 2` | that person's `id` | `Art. 903 names the parents of an illegitimate decedent, not the ascendants generally. A surviving ascendant beyond the first degree requires review.` |
| `CROSS_CLASS_ACCRETION` | some `p` has `p.relationship_to_decedent == Relationship::IllegitimateChild` and `p.has_renounced` **and** some other `q` has `q.is_alive_at_succession` and `q.relationship_to_decedent` in `{LegitimateChild, LegitimatedChild, AdoptedChild}` | the renouncing person's `id` | `An illegitimate child renounced while concurring with legitimate children. Arts. 1018 and 968 point in different directions on where the vacant portion goes.` |
| `RESERVA_TRONCAL` | `input.config.manual_review_facts.reserva_troncal_property_present` is true | `None` | `The estate includes property stated to have been acquired by gratuitous title from an ascendant, brother or sister. Art. 891 reservation is not modelled by this engine.` |
| `COLLATION_DISPUTE` | `disputed_donation_ids` is non-empty | `None` | `The parties dispute the collatability or the value of at least one donation. Art. 1077 requires a dual computation that this engine does not produce.` |
| `RA_11642_RETROACTIVITY` | some `p` has an `adoption` whose `regime == AdoptionRegime::Ra8552` and whose `decree_date` is lexicographically less than `"2022-01-01"` | that person's `id` | `A pre-2022 adoption decree under RA 8552 raises the RA 11642 Sec. 41 retroactivity question. See .planning/LAWYER-AGENDA.md entry LAWYER-08.` |
| `ARTICULO_MORTIS` | `input.decedent.marriage_solemnized_in_articulo_mortis` is true | `None` | `The marriage was solemnized in articulo mortis. The Art. 900 paragraph 2 conditions require review.` |
| `USUFRUCT_ANNUITY_OPTION` | `usufruct_or_annuity_disposition_ids` is non-empty | `None` | `At least one disposition gives a usufruct or a life annuity. Art. 911 paragraph 3 lets the parties convert it by agreement, which cannot be computed.` |
| `DUAL_LINE_ASCENDANT` | `dual_line_ascendant_ids` is non-empty | first id in the list | `A person is stated to appear in both the paternal and the maternal ascending line. Art. 890 division by line requires review.` |
| `POSTHUMOUS_DISINHERITANCE` | `unborn_disinherited_ids` is non-empty | first id in the list | `The will disinherits a person stated to have been unborn when it was executed. Arts. 915 to 923 require review.` |
| `CONTRADICTORY_DISPOSITIONS` | a will exists **and** either some `DispositionId` occurs more than once across `will.institutions`, `will.legacies` and `will.devises` combined, **or** some `institutions[i].heir.person_id` that is `Some` occurs more than once | `None` | `The will contains repeated disposition identifiers or institutes the same person more than once. The conflicting instructions require court resolution.` |

Use `std::collections::HashSet` and `HashMap` for the duplicate scans. The date comparison for
`RA_11642_RETROACTIVITY` is a plain string comparison: `Date` is `pub type Date = String` holding
ISO-8601, which sorts lexicographically, and `"2022-01-01"` is the boundary the spec's own words
"Pre-2022 adoption" name.

Add ten unit tests in this module's `#[cfg(test)] mod tests`, one per code, each named
`test_detects_<lowercase_code>`. Every test builds a minimal `EngineInput`, calls
`detect_spec_flags`, and asserts with `assert!` that the returned vector contains a flag whose
`category` equals the corresponding constant. Add an eleventh test
`test_clean_input_produces_no_spec_flags` that builds an input with none of the ten triggers and
asserts with `assert!(detect_spec_flags(&input).is_empty())` — without it, an always-on detector
would pass all ten tests and be useless.
