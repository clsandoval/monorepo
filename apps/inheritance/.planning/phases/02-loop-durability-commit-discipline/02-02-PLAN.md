<objective>
Turn "closed-world" from a slogan into a lint that fails the build.

Purpose: LOOP-01 requires every plan to name every decision the executing agent needs. This is the requirement most likely to decay into an unchecked assertion, because it is about prose. PROJECT.md's executor is a deliberately cheap model whose only job is to follow plans, and a plan that hands it an open decision produces an invented one — in this codebase that means an invented legal reading or an invented money unit. So the definition has to be mechanical.

The mechanism, decided in 02-RESEARCH.md section 6 so no executor has to decide it: a written standard at `.planning/PLAN-STANDARD.md` and a dependency-free lint over every `.planning/phases/**/*-PLAN.md`, with one distinct marker per rule. Prose checks skip fenced code blocks and inline code spans, because a hedge word inside a literal command or a grep pattern is inert — and because Phase 1's plans legitimately quote prohibited tokens inside backticks.

This plan also specifies the BLOCKED report protocol that LOOP-02's machine half (plan 02-04) pairs with: what an executor writes when a gate cannot run, and where a legal question goes instead of being answered.

Output: `.planning/PLAN-STANDARD.md`, `scripts/check-plan-closed-world.mjs`, and five fixture plans proving the lint fires.
</objective>

Default input: every file matching `.planning/phases/*/*-PLAN.md`, discovered by directory walk rather than a glob library. Resolve paths relative to the script's own location so the lint works from any working directory.

Two flags, and no others:
- `--file <path>` — lint only that one file. Exists so fixtures can drive each failure path.
- `--list` — print the discovered plan files and exit 0, for diagnosis.

**Frontmatter parsing, without a YAML dependency.** Take the text between the first two `---` lines. For each line matching `^([a-z_]+):(.*)$` record the key. Values are read in three forms only: a bare scalar, a flow array such as `[GATE-01, GATE-02]` or `["01-02"]`, and a block sequence whose items are the following lines matching `^\s+-\s+(.+)$`. Strip surrounding quotes from array items. For `must_haves`, presence of the key is checked plus the presence of a `truths:` line before the next top-level key.

**Scanning region for prose checks.** Build a per-line prose view of the body — everything after the closing frontmatter delimiter — by removing fenced code blocks entirely, where a fence is a line whose trimmed form starts with three backticks, and by replacing every inline code span delimited by single backticks with a single space. Prose checks run only against this view. Structural checks run against the raw text.

**Checks**, each collecting all violations and reporting `<file>:<line>: <MARKER> — <detail>`:

1. `MISSING FRONTMATTER KEY` — any of `phase`, `plan`, `wave`, `depends_on`, `files_modified`, `autonomous`, `requirements`, `must_haves` absent; or `must_haves` present without a `truths:` line.
2. `UNKNOWN REQUIREMENT` — a `requirements` id absent from `.planning/REQUIREMENTS.md`. Build the known set by matching `\b[A-Z][A-Z0-9]*-[0-9]{2}\b` across that file.
3. `BROKEN DEPENDENCY` — a `depends_on` id with no matching `<id>-PLAN.md` in the same directory as the file being linted.
4. `MISSING SECTION` — the raw text lacks any of the literal lines `<objective>`, `<constraints>`, `<tasks>`, `<verification>`, `<success_criteria>`.
5. `INCOMPLETE TASK` — split the raw text on lines starting with `<task`, ignoring the `<tasks>` container line by requiring the next character to be a space or `>`. For each task block, any of `<read_first>`, `<action>`, `<verify>`, `<acceptance_criteria>`, `<done>` absent or containing only whitespace.
6. `THIN ACCEPTANCE` — an `<acceptance_criteria>` block with fewer than two lines whose trimmed form starts with `-`.
7. `OPEN WORLD PHRASE` — a case-insensitive match in the prose view for any phrase in the list below, except `TBD`, `TODO` and `???` which match case-sensitively with word boundaries. Store the list as a top-level `const` array in the script so it is auditable in one place.

```text

choose the best
some reasonable
the reasonable reading
figure out
something like
as desired
or similar
whatever makes sense
TBD
TODO
???
```

8. `LEGAL JUDGMENT IN PLAN` — a case-insensitive match in the prose view for any of the phrases below, stored as a second top-level `const` array.

```text
decide whether art
interpret art
the correct legal reading
pick the reading
choose the reading
decide the legal
determine the correct interpretation
```

9. `UNGROUNDED LEGAL FIX` — if `requirements` contains `LAW-06` the raw text must contain `LAWYER-06`; if it contains `LAW-07` it must contain `LAWYER-04`; if it contains `LAW-12` it must contain `LAWYER-08`.

If a plan file is unreadable, print a message containing `PLAN UNREADABLE` and exit 1. Never exit 0 on an internal error, and never exit 0 when zero plan files were discovered — print `NO PLANS FOUND` and exit 1, because a lint that silently passes on an empty set is worse than no lint.

Exit codes: `0` only when there are zero violations across all files, `1` otherwise. No other exit code.

Success output: a line containing the literal string `PLANS OK` plus the file count and the total task count checked.

The script must never write to any plan file. Do not add a fix flag, a waiver flag, or a suppression comment. Constraint 7 forbids all three.
