<objective>
Make the concurrent auto-committer harmless, by making the safe commit path a single command and a mixed commit a red gate.

Purpose: LOOP-05 exists because this app lives inside a monorepo with an auto-committer that has already landed unrelated commits during this project's sessions. A broad stage absorbs its in-flight work into ours, and its next commit absorbs our staged work into a commit named `fitness log`. Either direction loses work and corrupts history. `git add -A` cannot be blocked from inside a plan, because the executor has a shell. What can be done is to make the correct path shorter than the wrong one, and to make the damage visible within one gate run.

The mechanism, decided in 02-RESEARCH.md section 5: a wrapper that stages exactly the paths it was given and verifies the staged set before committing, plus a history audit asserting that every commit touching `apps/inheritance/**` touches nothing outside the allowlist. Measured on 2026-07-31: that rule produces zero violations over `bdee3c498..HEAD`, so the audit starts green and any red is real.

Deliberately not filtered by author or commit message. If the auto-committer ever swallows our staged work, the resulting commit will touch `apps/inheritance/**` alongside `projects/` or `entities/` — which is exactly the commit that must be surfaced. An author filter would hide the one case the requirement exists for.

Output: `scripts/safe-commit.sh`, `scripts/check-commit-discipline.mjs`, two fixtures, and the rule stated as mandatory in `README.md` and `CLAUDE.md`.
</objective>

  <action>
Create `scripts/safe-commit.sh`, a Bash script with `set -euo pipefail`. Follow the commenting style of `scripts/ci-gates.sh`: a header block explaining why the script exists, then the logic.

Usage: `bash apps/inheritance/scripts/safe-commit.sh -m "<message>" <path> [<path> ...]`

It always operates from the git root, resolved with `git rev-parse --show-toplevel`, so a caller's working directory does not change which paths are staged.

Behavior, in order:

1. Parse `-m <message>` and treat every remaining argument as a path. Reject and print a line containing `REFUSED` plus the reason when: the message is missing or empty; zero paths were given; or any path argument is one of `-A`, `--all`, `-a`, `.`, `./`, `:/`, `*`, or begins with `-`. Exit 1 on any refusal.
2. Reject with `REFUSED` when any path is outside the allowlist. The allowlist is: any path beginning with `apps/inheritance/`, plus the exact path `.github/workflows/inheritance-ci.yml`. Paths are interpreted relative to the git root.
3. Reject with `REFUSED` when the index is not empty before staging, printing the already-staged paths. Rationale, which must appear as a comment: a pre-populated index means another process staged something, and committing on top of it is precisely the absorption this script exists to prevent. The operator resolves it with `git restore --staged`, never this script.
4. Stage exactly the given paths with `git add -- <path>...`. The `--` separator is required so a path can never be read as a flag.
5. Compare `git diff --cached --name-only` against the requested set. Note that a requested directory expands to the files under it, so the rule is that every staged path must be equal to, or lie under, one of the requested paths. When any staged path fails that test, print a line containing `REFUSED` naming the unexpected paths, run `git restore --staged -- <each unexpected path>`, and exit 1 without committing.
6. Commit with `git commit -m "<message>"`.
7. On success print a line containing `SAFE COMMIT OK` plus the new SHA and the committed path count.

Exit codes: `0` on a successful commit, `1` on any refusal or git failure. No other exit code.

Add a `--dry-run` flag that performs steps 1, 2 and 5 and then unstages, without committing. It exists so the refusal paths can be exercised without writing history. It must never commit.

The script must never call `git add -A`, `git add .`, `git commit -a`, `git commit --amend`, `git rebase`, `git reset --hard`, or `git push`.
  </action>

Create `scripts/check-commit-discipline.mjs`, a Node ESM script importing only `node:fs`, `node:path` and `node:child_process`. Follow `frontend/scripts/check-test-baseline.mjs`: collect every violation, print all of them, exit once.

Hard-code the floor as a top-level constant:

```text
const AUDIT_FLOOR = 'bdee3c498c7c7a801125ab21e97be32f88b57593';
```

Hard-code the allowlist as a second top-level constant: a path is allowed when it starts with `apps/inheritance/` or equals `.github/workflows/inheritance-ci.yml`.

Two flags, and no others:
- `--from-json <path>` — read the commit list from a JSON file instead of invoking git. The file is an array of objects with keys `sha`, `subject`, `files`. Exists so the failure path can be driven by a fixture without ever creating a real mixed commit.
- `--range <rev-range>` — override the default range for diagnosis only. The default is `AUDIT_FLOOR..HEAD` and the constant itself is never rewritten by any flag.

Gathering commits from git, using `spawnSync` with `shell: false` and an explicit argument array:
- `git log --format=%H%x09%s <range>` to get sha and subject.
- For each sha, `git show --name-only --format= <sha>` to get its changed paths, dropping empty lines.
- Set `cwd` to the git root, resolved with `git rev-parse --show-toplevel`.

Checks:

1. `MIXED COMMIT` — a commit that touches at least one path starting with `apps/inheritance/` **and** at least one path outside the allowlist. Report the sha, the subject, and every foreign path. This is the whole point of the audit: it fires whether our stage absorbed the auto-committer's work or the auto-committer's stage absorbed ours.
2. `FLOOR NOT ANCESTOR` — `git merge-base --is-ancestor <AUDIT_FLOOR> HEAD` exits nonzero, meaning the floor commit is no longer in history. That indicates a rewrite, which constraint 4 forbids. Exit 1.
3. `GIT UNAVAILABLE` — git is absent or the repository is not a git repository. Print the marker and exit 1. Never exit 0 on an internal error.

Exit codes: `0` only when there are zero violations, `1` otherwise. No other exit code.

Success output: a line containing the literal string `COMMIT DISCIPLINE OK` plus the number of commits audited and the number that touched `apps/inheritance/`.

Do not filter by author, committer, or commit message. Constraint rationale, which must appear as a comment in the script: filtering out the auto-committer would hide the exact commit the audit exists to catch.

The script must never write to the repository and must never invoke `git add`, `git commit`, `git rebase`, `git reset`, or `git push`.
  </action>
