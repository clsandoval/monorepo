<objective>
Freeze the gate set into a manifest that an executing agent can grow but cannot shrink, weaken or rename.

Purpose: LOOP-03 requires the gate manifest to live where the executing agent is forbidden to widen or weaken it without owner action. A file an agent is merely asked not to edit is edited. This plan makes the prohibition mechanical: a lock file records every gate's identity, command string and blocking flag at freeze time, and a dependency-free check fails the build when a locked gate disappears, changes command, or stops blocking. Adding a gate stays legal, because the loop must be able to gain coverage over fifteen phases. This is the test ledger's shrink-only rule inverted — see 02-RESEARCH.md section 2.

Scope note: this plan seeds the manifest with exactly the four gates the runner already executes, so the tree is internally consistent the moment this plan lands. Plan 02-04 appends the three meta-gates and makes the runner read the manifest. This plan does not modify `scripts/ci-gates.sh`.

Output: `gates.manifest.json`, `gates.manifest.lock`, `scripts/check-gate-manifest.mjs`, four fixtures proving the check fires, and section 1 of `GATES.md`.
</objective>

  <read_first>gates.manifest.json, gates.manifest.lock, frontend/scripts/check-test-baseline.mjs</read_first>
  <action>
Create `scripts/check-gate-manifest.mjs`, a Node ESM script importing only `node:fs` and `node:path`. Read `frontend/scripts/check-test-baseline.mjs` first and follow its shape: collect every violation rather than returning on the first, print all of them, then exit once.

Resolve both input paths relative to the script's own location so the check works from any working directory.

Two flags, and no others:
- `--manifest <path>` — read the manifest from `<path>` instead of `gates.manifest.json`. Exists so the failure paths can be driven by committed fixtures.
- `--lock <path>` — read the lock from `<path>` instead of `gates.manifest.lock`.

Checks, in this order, collecting all violations:

1. `GATE REMOVED` — a `locked_gates` entry whose `id` has no gate with that `id` in the manifest.
2. `GATE COMMAND CHANGED` — a locked entry whose `id` is present but whose `command` string differs. Print both the locked and the current string.
3. `GATE WEAKENED` — a locked entry with `blocking` true whose manifest gate has `blocking` false.
4. `MALFORMED GATE` — a manifest gate missing any of the nine required keys, or with a non-integer `order`, or with an empty `command`, or with a duplicate `id`.
5. `UNLOCKED GATE` — a manifest gate whose `id` is absent from `locked_gates`. This is a violation, not a silent pass: a gate that runs but is not frozen can be deleted next week without tripping check 1. The message must instruct the operator to append the gate to `gates.manifest.lock`.

If either file is missing or unparseable, print a message containing `MANIFEST UNREADABLE` and exit 1. Never exit 0 on an internal error.

Exit codes: `0` only when there are zero violations, `1` otherwise. No other exit code.

Success output: a line containing the literal string `MANIFEST OK` plus the gate count and the locked count, for example the shape `MANIFEST OK — 4 gates, 4 locked`.

The script must never write to either file. Do not add an update flag. Constraint 6 forbids it.
  </action>

<threat_model>

| T-2-01b | An agent swaps a strict gate command for a lenient one, for example `npm run test:gate` to `npm test` | High | `GATE COMMAND CHANGED` locks the exact command string. Fixture `manifest-command-changed.json` uses this precise substitution and is required to exit 1. |

| T-2-01d | An agent adds an update flag to the checker and regenerates the lock to match its own edit | High | Constraint 6 forbids it; acceptance criteria grep the script for `writeFileSync`, `appendFileSync` and the four flag names and require zero hits. |
| T-2-01e | A new gate is added to the manifest but never locked, so it can be silently dropped later | Medium | `UNLOCKED GATE` treats an unlocked manifest gate as a violation rather than a pass. | T-2-01f | The manifest drifts from what the runner actually executes | Medium | Constraint 7 requires byte-identical command strings copied from `scripts/ci-gates.sh`.
