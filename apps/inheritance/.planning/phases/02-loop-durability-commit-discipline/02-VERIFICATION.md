## Roadmap success criteria

**1. Every plan is closed-world.** `node scripts/check-plan-closed-world.mjs` → exit 0,
`PLANS OK — 10 plan file(s), 40 task(s) checked`. Nine machine-checkable rules; all nine markers
observed rejecting a violating fixture, and `plan-fenced.md` observed passing to keep the
scanning-region exemption honest. **No plan file was edited to achieve this** — the lint passed over
the unmodified Phase 1 corpus on its first run.

**2. When gates cannot run, execution halts and reports.** The runner distinguishes three states,
observed on the same gate:

| Injection | Exit | Marker |
|---|---:|---|
| `GATES_INJECT_MISSING_TOOL=cargo` | 2 | `GATE CANNOT RUN: preflight` / `HALT: missing tool: cargo` |
| `GATES_INJECT_PRECONDITION_FAIL=G6` | 2 | `GATE CANNOT RUN: G6` / `HALT: precondition failed` |
| `GATES_INJECT_NOT_FOUND=G6` | 2 | `GATE CANNOT RUN: G6` / `HALT: command not found` |
| `GATES_INJECT_GATE_FAIL=G6` | 1 | `GATE FAILED: G6 (exit 3)` |

The halt output itself instructs the operator to report BLOCKED. The report format is specified in
`.planning/PLAN-STANDARD.md` §3 with five fields including `Real command output:` and the rule that a
paraphrase is not a BLOCKED report.

**3. The gate manifest lives where widening/weakening is forbidden.** `GATES.md` states "the gate set
may only grow" and `CLAUDE.md` carries it as loop invariant 2. Enforcement is mechanical, not
advisory: `manifest-removed` → `GATE REMOVED`, `manifest-command-changed` → `GATE COMMAND CHANGED`,
`manifest-weakened` → `GATE WEAKENED`, `manifest-grown` → `UNLOCKED GATE`, all exit 1. The legal
growth path was exercised in this very phase — four gates became seven — and `check-gate-manifest`
accepted it.

**4. Progress is measured against the frozen manifest.** `gate-coverage.mjs` joins the manifest
(expectation) against the run record (observation).
`--run scripts/fixtures/run-narrowed.json` → exit 1, `GATE COVERAGE 6/7`,
`SCOPE NARROWED … G3 (frontend suite vs ledger) status=not-run` — a run whose `outcome` is `pass`.
`--run scripts/fixtures/run-halted.json` → exit 0 at `GATE COVERAGE 2/7`, so the halt behavior stays
usable. Current: `GATE COVERAGE 7/7`, `REQUIREMENT COVERAGE 6/94 gated`.

**5. Every commit lists explicit files.** `node scripts/check-commit-discipline.mjs` → exit 0,
43 commits audited since the hard-coded floor `bdee3c498…`, 23 touching the app, **0 mixed**. Every
commit in this phase was made either with an explicit `git add` path list or through
`scripts/safe-commit.sh`, which refuses `-A`, `--all`, `-a`, `.`, `:/`, `*`, zero paths, a missing
message, a path outside the allowlist, and a pre-populated index — all seven refusals observed
exiting 1. The rule is documented as mandatory in `README.md` and in `CLAUDE.md`.

**6. A stalled loop produces a visible signal.** `LOOP-STATUS.md` is committed and regenerated by
every full run; line 2 carries the state and, on `STALLED`/`BLOCKED`, `NEEDS OWNER ATTENTION`. Both
halves of the fixed stall rule observed firing (`history-stalled` streak 3 identical signature;
`history-mixed` streak 5 mixed signatures), recovery observed returning `GREEN` immediately, and the
two-entry boundary observed staying `RED`. `loop-status.mjs check` exits 1 on `STALLED` and is
verified absent from `ci-gates.sh` (`grep -c` → 0).
