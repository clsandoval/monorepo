<objective>
EXT-05 asks that `CLAUDE.md` state the invariants an implementing agent must not violate, naming
three subjects the file is silent on today: **unit conventions**, **single-source-of-truth rules**,
and **what requires a lawyer**.

`CLAUDE.md` already carries a hand-written `## Loop invariants` section with three rules — commit
scope, gate immutability, halt over guess — each naming the command that enforces it. That shape is
correct and is kept. This plan grows the section from three invariants to six, adds the three missing
subjects in the same shape, and then makes the section itself gate-held so it cannot rot or be
deleted.

Two facts measured during research shape the design and are not re-derivable by reading `CLAUDE.md`
alone:

1. **`CLAUDE.md` is partly generated.** Lines 1 to 309 sit inside seven `<!-- GSD:*-start -->` /
   `<!-- GSD:*-end -->` marker pairs whose contents are regenerated from `.planning/codebase/`.
   Anything written inside a span is destroyed by the next regeneration. The existing invariants
   section is correctly placed between `<!-- GSD:skills-end -->` and `<!-- GSD:workflow-start -->`,
   outside every span, and the new check asserts that placement rather than trusting it.
2. **The only live single-source-of-truth enforcement is gate G28**,
   `node scripts/check-legal-traceability.mjs`, which raises `MARKER NOT UNIQUE` when one article's
   `// LEGAL-VECTOR:` marker occurs at more than one site. The registry gate `G14` that Phase 9 plan
   `09-06` was to add is still unregistered, and the dead duplicate classifier in
   `frontend/src/wasm/bridge.ts` still exists. The invariant is therefore written to state the rule
   and to name G28 as what enforces it today, with the surviving duplicate pointed at
   `.planning/DOC-DEBT.md` — the ledger plan `15-03` creates — rather than claimed to be gone.
</objective>

<action>
Create `scripts/check-claude-invariants.mjs`, modelled on the structure of
`scripts/check-blocked-requirements.mjs`: a header comment enumerating every violation marker, a
top-level `const` array holding the six expected invariant titles in order, a `violation(marker,
detail)` collector, and a single exit path that prints the `GATE-SKIPS` line.

Its default input is `CLAUDE.md` at the app root, overridable read-only by `--claude <path>`. Its
second input is `gates.manifest.json`, which is not overridable, because an invariant must be checked
against the real gate set.

The six checks, each with the literal marker given in `## Reference B`:

`INVARIANT SECTION MISSING` — no line equal to `## Invariants an implementing agent must not violate`.

`INVARIANT INSIDE GENERATED BLOCK` — the heading's byte offset falls inside any span delimited by a
`<!-- GSD:<name>-start` line and its matching `<!-- GSD:<name>-end` line. The spans are computed from
the file, never hardcoded, so adding a new generated block is covered automatically.

`INVARIANT COUNT` — the number of lines matching `^[0-9]\. \*\*` between the section heading and the
next `^## ` heading is not exactly 6.

`INVARIANT TITLE MISSING` — one of the six titles in the expected array is not the bolded title of
the invariant at its expected position. The message names the position, the expected title and the
title found.

`INVARIANT COMMAND UNGATED` — a backticked string inside the section that matches the shape of a gate
command, meaning it starts with `node scripts/`, `cd engine && ` or `cd frontend && `, is not present
as a `command` value of any gate in `gates.manifest.json`. The message names the string.

`CLAUDE MD UNREADABLE` — the input file or `gates.manifest.json` is missing or unparseable. This path
prints the marker and exits **2**, not 1, because a missing input is a cannot-run condition rather
than a violation.

On zero violations the script prints
`CLAUDE INVARIANTS OK — 6 invariant(s) checked, all commands gated`, then
`GATE-SKIPS total=6 skipped=0`, and exits 0. On one or more violations it prints the violation list,
the same `GATE-SKIPS` line, and exits 1. There is no other exit code.
</action>
