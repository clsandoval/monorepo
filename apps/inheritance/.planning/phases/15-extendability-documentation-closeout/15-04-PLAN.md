<objective>
EXT-08 asks that a returning owner can determine current state, what is verified, and what is next
from the planning directory alone. Today they cannot, and the failure is measurable rather than
impressionistic.

`.planning/ROADMAP.md`'s Progress table disagrees with the filesystem on **7 of its 15 rows**. It

four new gates and three requirements recorded as lawyer-blocked. The same file's checkbox list above
the table marks phases 6, 7 and 8 as `[x]`, so the roadmap contradicts itself as well as the tree.
`.planning/STATE.md`'s frontmatter says `percent: 93` while its own body prints
`Progress: [███████░░░] 73%`. `RESUME.md` tells the reader the suite should print
`ALL GATES PASSED (13/13)`; it prints 28/28 today and will print 32/32 after plan `15-05`.

Every one of those numbers is rewritten by tooling at phase boundaries, which is exactly why a
hand-written orientation page decays — `RESUME.md` went stale within four days of being written. So
this plan ships two things that must exist together:

- `.planning/ORIENTATION.md`, a short page that answers the three EXT-08 questions by **pointing at
  the file that holds each answer**, never by restating the answer;
- `scripts/check-planning-truth.mjs`, which re-derives every count from the filesystem on every gate
  run and fails when a document disagrees.

The check is deliberately red-on-drift. When Phase 16 lands and the roadmap table is not updated, the
build goes red and says which row is wrong. The remedy is to update the row, never to edit the gate.
</objective>

<constraints>
- **Status is derived by counting files, never judged.** A phase's derived status is fixed by
  `## Reference A`: `Complete` when its summary count equals its plan count and both are greater than
  zero; `Executed` when both are greater than zero and unequal; `Planned` when it has plans and no
  summaries; `Not started` when it has neither. No other value is legal, and no agent decides which
  applies.
- **The in-flight phase gets one narrow, deterministic exemption**, fixed by `## Reference D`. A
  phase's own row necessarily moves while that phase is executing — each landing summary changes the
  numerator — so demanding exact equality for the phase currently under execution would paint the
  build red at every plan boundary for a bookkeeping reason. The exemption applies to exactly one
  phase, identified by `.planning/STATE.md`'s `^Phase: <N>` line, and it relaxes only the numerator:
  the row may under-report the in-flight phase but may never over-report it. The check prints the
  exempted phase number on every run, so the exemption is never silent.
- The roadmap's `Completed` date column and its prose phase descriptions are **not** touched. Only
  the `Plans Complete` and `Status` cells of the Progress table are corrected, plus the checkbox on
  any phase whose checkbox disagrees with its derived status.
- `.planning/STATE.md` is edited only in its `progress:` frontmatter block and in the single body
  line matching `^Progress: \[`. Its narrative sections are left alone; they are a phase-by-phase
  record and rewriting them would destroy history.

  `## Open decisions waiting on the owner` items are preserved verbatim — they are owner-owned and
  still open.
- `.planning/ORIENTATION.md` restates no fact that lives elsewhere. Every answer is a pointer to a
  path plus one sentence saying what that file holds. The only number it carries is the gate count,
  and that number is checked against `gates.manifest.json` on every run.
- `scripts/check-planning-truth.mjs` is dependency-free Node ESM using `node:` builtins only. It

</constraints>

Applied to each `.planning/phases/<N>-*/` directory. No other value is legal and no judgement is
involved.

| plans | summaries | Derived status |
|---|---|---|
| 0 | 0 | `Not started` |
| > 0 | 0 | `Planned` |
| > 0 | equal to plans | `Complete` |
| > 0 | > 0 and not equal to plans | `Executed` |

A checkbox is `[x]` exactly when the derived status is `Complete`.

## Reference C — the eight violation markers

| Marker | Fires when | Exit |
|---|---|---|
| `ROADMAP PLAN COUNT` | a Progress-table row's counts differ from the phase directory | 1 |
| `ROADMAP OVER CLAIMS` | the in-flight phase's row reports more completed plans than there are summaries | 1 |
| `ROADMAP STATUS DISAGREES` | a row's status or checkbox differs from the derived status | 1 |
| `STATE PLAN COUNT` | a `progress:` counter differs from the derived value | 1 |
| `STATE PERCENT DRIFT` | `percent` or the body's progress-bar percentage disagrees | 1 |
| `ORIENTATION POINTER BROKEN` | a named path does not resolve, or a required path is absent | 1 |
| `ORIENTATION GATE COUNT` | the stated gate count differs from `gates.manifest.json` | 1 |
| `PLANNING TRUTH UNREADABLE` | a document or a derived input is missing or unparseable | 2 |

## Reference D — the in-flight phase exemption

The in-flight phase is the single phase named by `.planning/STATE.md`'s `^Phase: <N>` line. Exactly
one phase qualifies; if that line is missing the check exits 2 rather than guessing.

| Field | Every other phase | The in-flight phase |
|---|---|---|
| denominator (`/<plans>`) | exact equality with the `*-PLAN.md` count | exact equality with the `*-PLAN.md` count |
| numerator | exact equality with the `*-SUMMARY.md` count | may be lower than the summary count; may never exceed it |
| `Status` cell | equal to the derived status | one of the four legal values |
| checkbox | `[x]` exactly when derived status is `Complete` | `[ ]` unless numerator equals denominator |

Why the asymmetry: a phase's own row necessarily moves as its plans land, so demanding exact equality
would paint the build red at every plan boundary for a bookkeeping reason and stall an unattended
loop. Under-reporting the phase you are standing in is harmless — the summaries are on disk and the
next closeout corrects the row. Over-reporting is not harmless: it is a claim of work that does not
exist, which is the exact failure this check exists to catch, so that half is never relaxed. The
exemption is printed on every run rather than applied quietly.
