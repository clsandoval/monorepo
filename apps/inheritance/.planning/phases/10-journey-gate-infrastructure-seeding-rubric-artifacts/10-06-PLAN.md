<objective>
Turn four working mechanisms into one gate that keeps them working, and write down the seams so
Phases 11 and 12 do not have to re-derive them.

Plans 10-01 through 10-05 each ship a probe, and each probe proves its own piece. A probe nobody runs
is documentation. `PROJECT.md` fixes the standard this project is built to: *a passing gate set
genuinely implies a working app*. Until the harness is inside `scripts/ci-gates.sh`, a later phase can
silently break the rubric evaluator or the artifact writer and no gate goes red — and Phases 11 and 12
would then misread a harness bug as an application defect.

Two constraints shape what this gate can be, and both are measured rather than assumed:

1. **It must run in CI.** `10-RESEARCH.md` §7 and §6 record the precedent: Phase 3 built
   `scripts/check-env-ready.mjs` and deliberately left it out of the manifest because GitHub Actions
   has neither Docker nor a Supabase stack. So G15 asserts only against committed HTML fixtures — no
   database, no built app, no dev server beyond a local `node:http` listener.
2. **It must run before the halt.** `10-RESEARCH.md` §2.5 measured that `ci-gates.sh` still halts at
   G3 on Phase 5's unresolved OBS-05/OBS-06 product decision, so any gate ordered after 8 never
   executes. G15 takes `order` **6**, which `GATES.md` §1 permits in as many words: *"`order` is
   deliberately not covered by the lock, so reordering is legal."*

The gate id is **G15**, not G14. `10-RESEARCH.md` §2.5 measured that Phase 9's `09-06-PLAN.md:59`
reserves `G14` for `scripts/check-single-source.mjs`, whose SUMMARY records it as *"Not started"* with
`requirements-blocked: [EXT-02]`. Reserved-but-unregistered is still reserved; taking G14 here would
collide with a Phase 9 replan.

State this plainly, as Phases 6 and 9 did: **`ALL GATES PASSED (14/14)` is not achievable in this
phase and must not be claimed.** G3 still runs, still fails, and still stops the run.

Output: one blocking gate at order 6, a fourteen-gate manifest, and the seams document.
</objective>

**`frontend/journey/selftest.mjs` exit contract:**

| Exit | Meaning |
|---|---|
| 0 | Every self-test case passed; the `GATE-SKIPS` line was printed |
| 1 | A self-test case failed; the failing case is named on stdout |
| 2 | The harness could not run — chromium is not installed |

Exit 2 on a missing browser matters: a machine that has never run `npx playwright install chromium`
has an environment problem, not a broken harness, and conflating the two is what
`GATES.md` §2 exists to prevent.

Structure it as a list of named cases, each an async function returning nothing and throwing on
failure, and run every case even after one fails — collecting failures rather than stopping at the
first, for the same reason plan 10-02 requires the rubric to evaluate every assertion. The eleven cases:

1. `rubric-positive` — `rubrics/fixture-basic.json` against `fixtures/basic.html` passes 8 of 8.
2. `rubric-negative` — the same rubric against `fixtures/mutated.html` fails, and the failing ids
   include the `text_contains`, `text_absent` and `element_visible` assertions.
3. `rubric-all-kinds` — the union of kinds exercised by the rubric equals `ASSERTION_KINDS`, so no kind
   is left untested. `10-RESEARCH.md` §8 requires all eight.
4. `rubric-unknown-kind` — `evaluateRubric` throws `RUBRIC INVALID:` on kind `vibe_check`.
5. `diff-reference-missing` — comparing against an empty temp directory yields `REFERENCE MISSING`.
6. `diff-pass` — comparing a capture against itself yields `status: 'pass'` and `diffPixels === 0`.
7. `diff-failure` — comparing the mutated capture against the basic reference yields `DIFF FAILURE`,
   `diffPixels > 0`, and a `diffPng` Buffer longer than 1000 bytes.
8. `diff-size-mismatch` — a 10x10 reference yields `REFERENCE SIZE MISMATCH` and `diffPixels === null`.
9. `artifacts-both-markers` — a step failing both mechanisms writes `actual.png`, `reference.png`,
   `diff.png`, `assertions.json` and `FAILURE.txt`, all non-empty, and `FAILURE.txt`'s first line
   contains both `RUBRIC FAILURE` and `DIFF FAILURE`.
10. `seed-storage-and-params` — with a local `node:http` server on port 4173, the `seed-readout`
    element reads exactly `probe-draft|true|3` on first paint.
11. `approve-refuses` — `node journey/approve.mjs no-such-step` run as a child process exits non-zero.

Every case that needs a reference directory must use `fs.mkdtempSync` under `os.tmpdir()` and remove it
afterwards, so `frontend/journey/references/` is never written to, per constraint 5.

Wrap the browser launch so that a `chromium` executable-missing error prints
`JOURNEY SELFTEST cannot-run: chromium is not installed; run npx playwright install chromium` to
stderr and exits **2**, distinct from a case failure.

On completion print one line per failed case in the form `SELFTEST FAILED <caseName>: <message>`, then
print `GATE-SKIPS total=11 skipped=0` and exit 0 when every case passed, or exit 1 when any failed.
The `GATE-SKIPS` line must print on both the pass and the fail path, because gate G8 reads it from the
gate's log regardless of outcome.
