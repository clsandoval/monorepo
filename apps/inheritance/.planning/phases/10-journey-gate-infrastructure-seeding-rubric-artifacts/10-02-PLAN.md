<objective>
Build the rubric mechanism, and make "never free-form judgment" mechanically true rather than a
promise.

JRNY-09 requires *"a fixed list of yes/no assertions returning structured output, never free-form
judgment."* `10-RESEARCH.md` D-1 records the decision that gives that sentence teeth: a rubric
assertion is a **deterministic predicate evaluated against the live page**, not a model call. The
grounds are measured, not stylistic — `.github/workflows/inheritance.yml` declares no model secret, so
a vision-API rubric could not run in CI at all; and a model verdict is by construction the free-form
judgment the requirement exists to exclude.

`PROJECT.md:111` justifies pairing a diff with a rubric by their blind spots: *"A diff cannot see that
a spouse's share reads ₱1.5M instead of ₱1.0M; a rubric cannot see a layout silently collapse."* The
first blind spot is exactly what a text predicate closes, and `10-RESEARCH.md` §3 measured a predicate
closing it — distinguishing `PHP 1,000,000.00` from `PHP 1,500,000.00` in a real browser. Both
mechanisms survive this phase; only the rubric's backend is pinned to something reproducible.

The load-bearing detail is the **closed kind set**. An evaluator that falls back to "interpret the
assertion somehow" when it meets an unrecognised kind has reintroduced free-form judgment through the
back door. This evaluator throws instead, and Task 4 observes it throwing.

Output: an eight-kind evaluator, a committed rubric exercising every kind, and a probe that watches it
pass, fail, and refuse.
</objective>

<constraints>

1. **Exactly eight kinds, and the list is closed.** The eight are fixed in `<interfaces>` below,
   transcribed from `10-RESEARCH.md` D-1. No ninth kind is added in this plan, and no kind is dropped.
   A kind outside the set is a thrown error, never a skipped assertion and never a pass.

2. **A rubric result contains no prose verdict field.** Each assertion result carries `id`, `kind`,
   `passed`, `expected` and `actual`. There is no `comment`, no `explanation`, no `confidence` and no
   `severity`. Those fields are where free-form judgment re-enters a structured format.

3. **Evaluate every assertion, never short-circuit.** A rubric with three failing assertions must
   report all three. Stopping at the first turns a rubric into a single assertion and destroys the
   per-assertion structured output JRNY-09 requires.

4. **The evaluator writes nothing to disk and prints nothing.** It returns a value. Plan 10-04 owns
   artifact writing and plan 10-06 owns gate output; an evaluator that prints cannot be composed.

5. **Do not edit `frontend/journey/browser.mjs`.** It is plan 10-01's artifact and is read-only here.
   This plan consumes `page.__journeyConsoleErrors`; it does not change how that array is populated.

6. **Do not register any gate.** `gates.manifest.json` and `gates.manifest.lock` are read-only until
   plan 10-06.

7. **Commit explicit paths only,** via `bash scripts/safe-commit.sh`. `git add -A`, `git add .` and
   `git commit -a` are prohibited.

</constraints>

<interfaces>

**The eight assertion kinds.** Transcribed from `10-RESEARCH.md` D-1; this table is the specification.

| `kind` | Required fields | Passes when |
|---|---|---|
| `text_equals` | `selector`, `expect` | The selector's trimmed `innerText` equals `expect` exactly |
| `text_contains` | `selector`, `expect` | The selector's `innerText` contains `expect` as a substring |
| `text_absent` | `selector`, `expect` | No element matching the selector has `innerText` containing `expect` |
| `element_visible` | `selector` | Exactly one element matches the selector and it is visible |
| `element_absent` | `selector` | Zero elements match the selector |
| `element_count` | `selector`, `expect` | The number of matching elements equals the integer `expect` |
| `attribute_equals` | `selector`, `attr`, `expect` | The selector's `attr` attribute equals `expect` |
| `no_console_error` | none | `page.__journeyConsoleErrors` has length 0 |

**Exports of `frontend/journey/rubric.mjs`:**

| Export | Signature | Contract |
|---|---|---|
| `ASSERTION_KINDS` | `string[]` | The frozen list of the eight names above, in the table's order |
| `validateRubric` | `(rubric) => void` | Throws when a rubric is malformed or names a kind outside `ASSERTION_KINDS` |
| `evaluateRubric` | `async (page, rubric) => RubricResult` | Evaluates every assertion and returns the structured result |

**`RubricResult` shape**, fixed here so plans 10-04 and 10-06 can serialise it without inventing keys:

```
{
  rubricId: string,
  passed: boolean,              // true only when every assertion passed
  total: number,
  failedCount: number,
  assertions: [
    { id: string, kind: string, passed: boolean, expected: <as written in the rubric, or null>, actual: <observed value, or null> }
  ]
}
```

**Rubric document shape:**

```
{ "rubricId": "<string>", "assertions": [ { "id": "<string>", "kind": "<one of the eight>", ... } ] }
```

`validateRubric` throws when: `rubricId` is missing or empty; `assertions` is absent or empty; any
assertion is missing `id`; two assertions share an `id`; any `kind` is outside `ASSERTION_KINDS`; or a
required field for the named kind is absent. Each thrown message begins with the literal token
`RUBRIC INVALID:` so a caller can distinguish a malformed rubric from a failing one.

</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rubric document → verdict | A committed JSON file decides whether a money-path screen is considered correct; a rubric that silently skips an assertion reports a pass it did not earn |
| page DOM → assertion result | The evaluator reads a live page; a selector that matches nothing must fail loudly rather than resolve to an empty string that happens to equal an expectation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02 | Tampering | `frontend/journey/rubric.mjs` | mitigate | `ASSERTION_KINDS` is frozen with `Object.freeze` and an unknown kind throws `RUBRIC INVALID:`; Task 4 observes the throw, so the rejection path is exercised rather than assumed |
| T-10-02b | Repudiation | rubric evaluation | mitigate | Every assertion is evaluated and reported with its `id`, `expected` and `actual`, so a failure names which assertion failed and what was seen instead — a bare boolean would be unactionable in a Phase 12 gate |
| T-10-02c | Information Disclosure | `actual` capture on failure | accept | A failing assertion records the observed page text, which for a seeded journey is fixture data from `frontend/supabase/fixtures.json`, never production client data. The fixture is committed to this repository already |
| T-10-02d | Elevation of Privilege | selector evaluation | mitigate | Selectors are applied with Playwright locator APIs against the page; the evaluator never calls `page.evaluate` with a rubric-supplied string, so a rubric cannot execute arbitrary script in the page context |
</threat_model>

Add `evaluateRubric(page, rubric)` to `frontend/journey/rubric.mjs`. It calls `validateRubric` first,
then evaluates every assertion in order and returns the `RubricResult` shape fixed in `<interfaces>`.

Implement each of the eight kinds exactly as the `<interfaces>` table's `Passes when` column states,
using Playwright locator APIs — `page.locator(selector)`, `.count()`, `.innerText()`, `.isVisible()`,
`.getAttribute(attr)`. Do not pass any rubric-supplied string to `page.evaluate`; constraint T-10-02d
depends on that.

Three rules bind every kind:

- **A selector matching zero elements fails the assertion.** It never resolves to an empty string that
  might coincidentally equal an expectation. The two exceptions are `element_absent` and `text_absent`,
  where zero matches is the passing outcome.
- **A selector matching more than one element fails `text_equals`, `text_contains`,
  `element_visible` and `attribute_equals`,** because those four are singular by intent and an
  ambiguous match is a defect in the rubric rather than a property of the page. `element_count` and
  `text_absent` are the multi-match kinds.
- **Every assertion is evaluated.** Wrap each in its own try/catch so a locator throwing on one
  assertion records that assertion as `passed: false` with `actual` set to the error message, and the
  remaining assertions still run. Never short-circuit on the first failure.

`no_console_error` reads `page.__journeyConsoleErrors` — the array plan 10-01's `newJourneyPage`
attaches — and records `actual` as its length.

Set `passed` on the result to `true` only when `failedCount` is 0.
