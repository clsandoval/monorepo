<objective>
Make every UI state a later gate needs reachable without clicking through the steps before it.

JRNY-01 and ROADMAP Phase 10 criterion 1 name four seams: a DB row, a `localStorage` draft, a route
param, and app context. `10-RESEARCH.md` §2.2 measured that the *documentation* half is largely
already done — `.planning/codebase/ARCHITECTURE.md:288` holds a fifteen-row seeding table. What does
not exist is any code a gate can call, and one seam does not exist at all.

That missing seam is the finding this plan turns on. Both wizards keep their position in local React
state with no URL encoding:

- `WizardContainer.tsx:76` — `const [currentStepIndex, setCurrentStepIndex] = useState(0)`
- `EstateTaxWizard.tsx:51` — `const [activeTab, setActiveTab] = useState<TabIndex>(0)`

`ARCHITECTURE.md` states the consequence: *"Not URL-encoded — cannot deep-link to 'step 3'; must click
Next, or mount the component with custom test harness state."*

A React prop cannot fix this. Phases 11 and 12 drive a **real browser**, which cannot reach into a
component tree — it can set a URL, a cookie, or web storage, and nothing else. Phase 12 must
screenshot every step of a six-step wizard and every one of eight tax tabs; without a URL seam each
screenshot costs a click-through of everything before it, and `REQUIREMENTS.md:274` says exactly that:
*"per-step screenshots are unaffordable without state seeding."*

So the seam is URL-borne, and it is additive: with no search param present, both components behave
precisely as they do today, which is why every committed test for them keeps passing untouched.

Output: two URL-addressable wizards, a seeding helper module, and two probes — one that needs no
database and one that does.
</objective>

<constraints>

1. **The seam is additive and default-preserving.** With no `step`, `hasWill` or `tab` search param
   present, `WizardContainer` starts at index 0 with `hasWill` false, and `EstateTaxWizard` starts at
   tab 0 — byte-identical behaviour to today. jsdom gives `location.search` as the empty string in
   every committed test, so no test file is edited in this plan.

2. **No test file may be edited, skipped or weakened.** If a committed wizard test fails after this
   change, the change is wrong. Report BLOCKED with the pasted failure; do not adjust the test.

3. **Clamp, never trust.** A `step`, `hasWill` or `tab` value that is absent, non-numeric, negative,
   or beyond the last valid index resolves to the first step. An out-of-range index would make
   `visibleSteps[currentStepIndex]` `undefined` and render a blank card, which a screenshot gate could
   then approve as a reference.

4. **Read the URL once, in the `useState` initialiser.** Do not add a `useEffect` that re-syncs state
   to the URL, and do not push history entries on navigation. That would turn an additive seam into a
   behavioural change to the two wizards' navigation, which is out of scope for a phase that builds
   gate infrastructure.

5. **Never write a service-role key to disk.** `scripts/setup-env.sh:149` deliberately excludes
   `SERVICE_ROLE_KEY` from `frontend/.env.local` because nothing in `frontend/src` reads it.
   `seed-smoke.mjs` obtains it at runtime from `supabase status -o env` and holds it in memory only.

6. **Reuse the published fixture ids.** DB seeding uses the org, user, client, case and share-token
   uuids in `frontend/supabase/fixtures.json`. Inventing new ids would create a second notion of the
   test tenant, which is what that file exists to prevent, and `scripts/check-seed-fixture.mjs` guards
   it.

7. **Register no gate.** `seed-smoke.mjs` needs Docker and a running Supabase stack, which GitHub
   Actions has neither of. `10-RESEARCH.md` §7 records the precedent: Phase 3 built
   `scripts/check-env-ready.mjs` and deliberately left it out of the manifest, and STATE.md assigns
   that registration to Phase 11. This plan adds no second unregisterable gate.

8. **Commit explicit paths only,** via `bash scripts/safe-commit.sh`. `git add -A`, `git add .` and
   `git commit -a` are prohibited.

</constraints>

<interfaces>

**Search params, fixed here.**

| Component | Param | Range | Absent or invalid resolves to |
|---|---|---|---|
| `WizardContainer` | `step` | integer `0`–`5` | `0` |
| `WizardContainer` | `hasWill` | the literal string `1` | `false` |
| `EstateTaxWizard` | `tab` | integer `0`–`7` | `0` |

`WIZARD_STEPS` at `WizardContainer.tsx:19` has six entries, one of which (`will`) carries
`conditional: true`. At mount `hasWill` decides whether five or six steps are visible, so the valid
`step` upper bound is `5` when `hasWill=1` is present and `4` otherwise. `TAB_COUNT` at
`src/types/estate-tax.ts:282` is `8`, so `tab`'s upper bound is `7` and the parsed value is cast to
`TabIndex`.

**Exports of `frontend/journey/seed.mjs`:**

| Export | Signature | Contract |
|---|---|---|
| `seedLocalStorage` | `async (page, origin, entries) => void` | Installs key/value pairs before first paint |
| `seedSessionStorage` | `async (page, origin, entries) => void` | The same for `sessionStorage` |
| `seedSearchParams` | `(url, params) => string` | Returns the URL with the params appended |
| `readFixtures` | `() => object` | Parses and returns `frontend/supabase/fixtures.json` |
| `seedAuthSession` | `async (page, origin, session) => void` | Writes a supabase-js session into `localStorage` under the project's storage key, before first paint |

`seedLocalStorage` and `seedSessionStorage` must use `page.addInitScript`, not `page.evaluate` after
navigation. An `evaluate` call runs after the app has already mounted and read storage, which is too
late for a draft-recovery path — the exact path JRNY-04 (Phase 11) has to verify. `addInitScript` runs
before any page script on every navigation, which is the only correct seam.

Because web storage is origin-scoped, each helper navigates to `origin` first when the page is still
on `about:blank`, then installs the values.

</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL search param → component state | A crafted URL now influences which wizard step renders; an unclamped index renders an undefined step as a blank card |
| service-role key → seeding process | DB seeding uses a key that bypasses row-level security; anywhere it is written down is a place it can leak |
| seed fixture → gate expectation | Every later journey gate asserts against seeded ids; a second, divergent set of ids would make two gates disagree about what the test tenant is |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05 | Tampering | `WizardContainer.tsx`, `EstateTaxWizard.tsx` | mitigate | Every parsed value is clamped to a valid index and falls back to `0`; Task 4 asserts a negative, an overlarge and a non-numeric value all render step 1 rather than a blank card |
| T-10-05b | Information Disclosure | service-role key | mitigate | Constraint 5 keeps it out of `.env.local` and out of any committed file; `seed-smoke.mjs` reads it from `supabase status -o env` into a local variable and never logs it. Task 6 asserts the key string is absent from the script's output |
| T-10-05c | Spoofing | fixture identity | mitigate | Constraint 6 binds seeding to the ids in `frontend/supabase/fixtures.json`, which `scripts/check-seed-fixture.mjs` already keeps in agreement with `seed.sql` in both directions |
| T-10-05d | Elevation of Privilege | the new search params in production | accept | `step`, `hasWill` and `tab` only choose which already-permitted step of the user's own wizard renders. They grant no data access: every route guard, and the row-level-security policies in `010_rls_org_scope.sql`, are unchanged and unreferenced by this plan |
