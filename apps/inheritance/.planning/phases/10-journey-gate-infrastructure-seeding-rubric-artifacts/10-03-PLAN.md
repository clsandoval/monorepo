<objective>
Build the perceptual half of the gate, and keep its failures distinguishable from the rubric's.

JRNY-10 has two clauses. The first — *"a perceptual-diff failure is distinguishable from a rubric
failure"* — is not satisfied by a log a human can read. A Phase 12 gate must be able to **branch** on
which mechanism failed, because the two have different remedies: a rubric failure means the app shows
a wrong value and the app is wrong; a diff failure means the layout moved and either the app is wrong
or the reference is stale. `10-RESEARCH.md` D-2 fixes a five-marker vocabulary for exactly that, and
this plan implements it.

The second clause — *"reference images have a documented re-approval flow"* — is where the project's
governing principle bites. A gate that can approve its own reference is a gate that goes green by
rewriting its own expectation. `10-RESEARCH.md` D-3 therefore makes approval a **separate command**,
never a flag on the gate, and makes it refuse when no run produced an image to approve.

`10-RESEARCH.md` §3 measured the underlying mechanism working here: `pngjs` read two captures and
`pixelmatch` reported `DIFF pixels = 69` between a `₱1,000,000.00` render and a `₱1,500,000.00` one,
emitting an 11,448-byte diff image.

One scope boundary, from `10-RESEARCH.md` §5: **this plan commits no golden PNG of the real app.**
Font rasterisation differs between a developer machine and a CI container, no CI run has ever executed
for this project, and a committed golden would be an unmeasured claim. The self-test in plan 10-06
generates its reference at run time from a committed HTML fixture, which tests the mechanism without
importing the portability problem. Phases 11 and 12 commit real references using the flow this plan
writes down.

Output: a comparator with five named outcomes, a separate approval command, and a probe that watches
each outcome occur.
</objective>

<constraints>

1. **Five markers, spelled exactly.** `RUBRIC FAILURE`, `DIFF FAILURE`, `REFERENCE MISSING`,
   `REFERENCE SIZE MISMATCH`, `STEP ERROR`. These strings appear in `10-RESEARCH.md` D-2 and in plan
   10-06's gate output. A marker spelled differently in one place breaks the distinction JRNY-10 asks
   for.

2. **A step failing both a rubric assertion and the diff reports both markers.** Collapsing them into
   one destroys the very distinction this plan exists to create.

3. **Approval is never a flag on the gate.** `frontend/journey/diff.mjs` must contain no code path that
   writes into `frontend/journey/references/`. Only `frontend/journey/approve.mjs` writes there, and it
   is not invoked by the gate registered in plan 10-06.

4. **Raising `maxDiffPixels` to clear a red gate is prohibited.** It is the perceptual equivalent of
   widening a test tolerance, which this project forbids. `REFERENCES.md` must say so in those terms.

5. **Commit no golden PNG of the real application in this plan.** `frontend/journey/references/`
   ships holding only `.gitkeep`. This is `10-RESEARCH.md` §5's boundary.

6. **Do not edit `frontend/journey/browser.mjs` or `frontend/journey/rubric.mjs`.** They belong to
   plans 10-01 and 10-02 and are read-only here.

7. **Do not register any gate.** Plan 10-06 owns the single permitted manifest append.

8. **Commit explicit paths only,** via `bash scripts/safe-commit.sh`. `git add -A`, `git add .` and
   `git commit -a` are prohibited.

<interfaces>

**Reference layout**, fixed by `10-RESEARCH.md` D-3:

```
frontend/journey/references/<stepId>.png     the approved image
frontend/journey/references/<stepId>.json    { "maxDiffPixels": <int>, "approvedOn": "<ISO date>", "approvedBy": "<string>" }
```

Default `maxDiffPixels` is **0**. A sidecar missing when its PNG exists is treated as
`REFERENCE MISSING`, because an image with no declared tolerance has no pass condition.

**Exports of `frontend/journey/diff.mjs`:**

| Export | Signature | Contract |
|---|---|---|
| `DIFF_MARKERS` | frozen object | Maps the five marker names to their exact strings |
| `compareToReference` | `(actualPngBuffer, stepId, referencesDir) => DiffResult` | Compares and classifies; writes nothing anywhere |

**`DiffResult` shape:**

```
{
  stepId: string,
  status: 'pass' | 'fail',
  markers: string[],          // empty on pass; one or more of the five on fail
  diffPixels: number | null,  // null when no pixel comparison was possible
  maxDiffPixels: number | null,
  diffPng: Buffer | null,     // the diff image, present only when a pixel comparison ran
  actualSize: { width, height },
  referenceSize: { width, height } | null
}
```

Classification, in this precedence order:

1. Reference PNG absent, or sidecar JSON absent → `markers: ['REFERENCE MISSING']`, `status: 'fail'`.
2. Reference and actual differ in width or height → `markers: ['REFERENCE SIZE MISMATCH']`,
   `status: 'fail'`. No pixel comparison is attempted, because pixelmatch requires equal dimensions.
3. `diffPixels > maxDiffPixels` → `markers: ['DIFF FAILURE']`, `status: 'fail'`, `diffPng` populated.
4. Otherwise → `status: 'pass'`, `markers: []`, `diffPng` populated.

`pixelmatch` is called with `{ threshold: 0.1 }`, the value probed in `10-RESEARCH.md` §3.

**`frontend/journey/approve.mjs`** is a CLI: `node journey/approve.mjs <stepId> [--max-diff-pixels <int>] [--by <string>]`.

- It reads the most recent run's `actual.png` for that step id from the artifact root plan 10-04 owns,
  `frontend/.journey-runs/`, selecting the newest run directory by name.
- It **refuses** — exits 1, prints `APPROVE REFUSED: no artifact found for step <stepId>` — when no
  such file exists. Approval may never invent an image.
- On success it copies that PNG to `references/<stepId>.png`, writes the sidecar with
  `maxDiffPixels` (default `0`), `approvedOn` set to the current UTC date in `YYYY-MM-DD` form, and
  `approvedBy` (default `unattended-loop`), then prints `APPROVED <stepId> maxDiffPixels=<n>`.

Because plan 10-04 has not landed when this plan executes, `approve.mjs` must tolerate the artifact
root not existing and treat that as the refusal case rather than throwing.

</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| approved reference → gate verdict | A reference image is the expectation a money-path screen is judged against; whoever can write one can decide what "correct" means |
| gate process → reference store | A gate that could write its own reference could turn any failure green without a human seeing the change |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03 | Elevation of Privilege | `frontend/journey/references/` | mitigate | Only `approve.mjs` writes there; `diff.mjs` contains zero write calls, asserted by grep in Task 1's acceptance criteria; the gate registered in 10-06 never invokes `approve.mjs` |
| T-10-03b | Tampering | reference sidecar tolerance | mitigate | `maxDiffPixels` defaults to 0 and every approval is recorded with `approvedOn` and `approvedBy`, so a widened tolerance is a visible diff in review rather than a silent constant; `REFERENCES.md` names raising it to clear a red gate as prohibited |
| T-10-03c | Spoofing | approval of an image no run produced | mitigate | `approve.mjs` sources only from `.journey-runs/<run>/<stepId>/actual.png` and refuses when absent, so a reference cannot be conjured from a hand-placed file outside the artifact tree |
| T-10-03d | Repudiation | which mechanism failed | mitigate | Five distinct markers, and a step failing both mechanisms reports both, so a post-hoc reader can tell a stale reference from a wrong number |
</threat_model>
