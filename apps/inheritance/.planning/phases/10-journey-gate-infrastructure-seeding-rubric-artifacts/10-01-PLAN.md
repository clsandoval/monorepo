<objective>
Install the first browser automation this repository has ever had, and put every screenshot in the
project behind one launch helper.

`10-RESEARCH.md` §2.1 measured the starting point: zero Playwright, zero Puppeteer, zero pixelmatch,
zero pngjs. The single hit anywhere in the tree, `@vitest/browser-playwright@4.0.18` at
`frontend/package-lock.json:12363`, is vitest's own optional peer dependency with no `test.browser`
block anywhere — it is not wired up and buys nothing.

§3 then probed the whole stack live in a scratch directory rather than assuming it: `playwright@1.56.1`
installed, its chromium downloaded (104.3 MiB, build v1194), launched headless, screenshotted, and
`pixelmatch@7.2.0` + `pngjs@7.0.0` diffed the result — `PROBE_EXIT=0`. Those three exact versions are
what this plan pins.

The reason a launch *helper* exists rather than each caller invoking `chromium.launch()` is
determinism. A blinking text caret or an in-flight CSS transition changes pixels between two runs of
the same page on the same machine, and a perceptual-diff gate that flickers is a gate the loop learns
to ignore. Those settings are fixed in one place so no later plan can forget them.

Output: three pinned dependencies, one launch helper, two committed HTML fixtures, and a probe that
proves capture works.
</objective>

<constraints>

1. **Pin exact versions.** `playwright` is `1.56.1`, `pixelmatch` is `7.2.0`, `pngjs` is `7.0.0`, each
   written into `frontend/package.json` with no `^` and no `~`. These are the versions
   `10-RESEARCH.md` §3 probed. A range lets a later `npm install` pull a build whose chromium revision
   nobody has run.

2. **devDependencies only.** None of these three ship to a browser bundle. Adding one to
   `dependencies` would put a 100 MiB browser downloader into the deployed artifact's dependency graph.

3. **Do not edit `frontend/tsconfig.json`.** `10-RESEARCH.md` D-4 measured that `include` covers `src`
   only, so `frontend/journey/` is invisible to `tsc -b` and gate G4 stays exactly as it is. Widening
   `include` would drag Playwright's type surface into a gate whose current output is zero diagnostics.

4. **Do not edit `frontend/vitest.config.ts`.** Its `environment: 'jsdom'` is what gate G3's frozen
   2,449-test ledger was measured under. The journey harness runs as standalone `node`, never under
   vitest.

5. **Do not register any gate in this plan.** `gates.manifest.json` and `gates.manifest.lock` are
   read-only here; plan 10-06 performs the single permitted append.

6. **Do not run `npm audit fix`, `npm update`, or any command that rewrites unrelated lockfile
   entries.** The only permitted lockfile change is the one `npm install` produces for these three
   packages. A broad lockfile rewrite is indistinguishable from a supply-chain change in review.

7. **Commit explicit paths only.** Use `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited — a concurrent auto-committer runs on
   this monorepo.

</constraints>

<interfaces>

`frontend/journey/browser.mjs` exports exactly three functions. Later plans depend on these names and
signatures; they are fixed here so no later plan invents a variant.

| Export | Signature | Contract |
|---|---|---|
| `launchBrowser` | `async () => Browser` | Launches headless chromium with the fixed options below |
| `newJourneyPage` | `async (browser) => Page` | Opens a page at the fixed viewport, installs the determinism stylesheet, and starts capturing console errors and page errors |
| `captureScreenshot` | `async (page) => Buffer` | Returns a full-page PNG buffer. Returns a buffer, never writes a file — plan 10-04 owns all disk writes |

Fixed launch and page options, copied literally:

- `chromium.launch({ headless: true })`
- `browser.newPage({ viewport: { width: 1280, height: 800 }, deviceScaleFactor: 1, reducedMotion: 'reduce', forcedColors: 'none' })`
- injected stylesheet: `*, *::before, *::after { animation: none !important; transition: none !important; caret-color: transparent !important; }`
- `page.screenshot({ fullPage: true, animations: 'disabled' })`

`newJourneyPage` attaches the captured console errors to the page object as `page.__journeyConsoleErrors`,
an array of strings, appended by a `page.on('console', ...)` handler filtered to `msg.type() === 'error'`
and a `page.on('pageerror', ...)` handler. Plan 10-02's `no_console_error` assertion kind reads that
array; without it that kind cannot be implemented.

</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → this repository | Three new packages enter a repository that previously had no browser tooling; one of them downloads a 104 MiB binary |
| rendered page → captured pixels | Everything the later diff gate concludes rests on the capture being reproducible; a nondeterministic capture makes every downstream verdict noise |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `frontend/journey/browser.mjs` | mitigate | Viewport, device scale, reduced motion, forced colors, animation and caret are all fixed in the single launch helper, and Task 4 asserts byte-identical output across two consecutive captures of the same fixture |
| T-10-01b | Spoofing | npm dependency resolution | mitigate | All three versions are exact-pinned, so a later install cannot silently resolve a different chromium revision; constraint 6 forbids any broad lockfile rewrite |
| T-10-01c | Denial of Service | chromium download | accept | The browser binary is ~104 MiB and downloads once per machine into `~/.cache/ms-playwright`. `10-RESEARCH.md` §3 measured the download succeeding here. A CI run pays it once per cache miss, which is the standard cost of browser testing and has no cheaper form |
</threat_model>
