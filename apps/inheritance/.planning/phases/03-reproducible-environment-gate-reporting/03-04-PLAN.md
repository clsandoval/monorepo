<objective>
Make every gate report which of its assertions were skipped, so a partially-loaded suite can never be read as a clean pass.

Purpose: GATE-09 requires every gate's output to distinguish skipped from passed. Today only gate G3 does: `frontend/scripts/check-test-baseline.mjs` line 173 already fails on any pending, skipped or todo test. The other six gates report a single exit code and nothing about coverage within themselves. `cargo test` prints `0 ignored` and nobody reads it; `npx tsc -b --force` type-checks no `.d.ts` file at all because `frontend/tsconfig.json:7` sets `skipLibCheck: true`, and nothing records that.

The measured skip baseline across every mechanism is one declared skip and zero undeclared ones: `#[ignore]` in the engine returns 0, `.skip`/`.only`/`.todo`/`xit`/`xdescribe` under `frontend/src` returns 0, `@ts-ignore`/`@ts-nocheck`/`@ts-expect-error` returns 0, and `skipLibCheck` returns exactly 1 hit. That is the ideal opening position for a shrink-only ledger.

A constraint shapes the whole design. `gates.manifest.lock` freezes each gate's exact `command` string, and `scripts/check-gate-manifest.mjs` exits 1 with `GATE COMMAND CHANGED` when one differs, so wrapping `cd engine && cargo test` in a reporting wrapper is prohibited rather than merely inelegant. What is permitted: the manifest may grow, and `scripts/ci-gates.sh` is not locked. So the runner captures each gate's output to a log, a new gate G8 parses those logs with a fixed per-gate table, and the four gate scripts this project owns gain an accounting line — their file contents are not frozen, only the command strings that invoke them. See `03-RESEARCH.md` section 6.

Scope note: this plan does not create `gate-results.json` and does not add gate G9. Plan 03-05 owns both, and it consumes the skip report this plan produces.

Output: log capture in the runner, `scripts/check-gate-skips.mjs`, `gate-skips.lock`, gate G8 in the manifest and the lock, accounting lines in four owned scripts, `GATES.md` section 5, and three fixtures proving the check fires.
</objective>

| Gate | Source of the observation |
|---|---|
| G5, G6, G7, G2, G3 | The `GATE-SKIPS total=<n> skipped=<n>` line in `.gate-runs/logs/<id>.log` |
| G1 | `.gate-runs/logs/G1.log`: sum the `N ignored` and `N filtered out` fields on every line beginning `test result:`; `total` is the sum of the `N passed` fields on the same lines |

2. `UNDECLARED SKIP` — an observed skip whose id is absent from `declared_skips` for that gate. Print the gate, the id and the source.

4. `SKIP COUNT MISMATCH` — a gate whose emitted `skipped=<n>` does not equal the number of skip ids the check collected for it. A count and a list that disagree mean one of them is fabricated.

If any input file is missing or unparseable, print a message containing `SKIP SCAN UNREADABLE` and exit 1. Never exit 0 on an internal error.

Three flags, and no others:
- `--logs <dir>` — read logs from `<dir>` instead of `.gate-runs/logs`.
- `--lock <path>` — read the ledger from `<path>` instead of `gate-skips.lock`.
- `--manifest <path>` — read the gate list from `<path>` instead of `gates.manifest.json`.

Exit codes: `0` only when there are zero violations, `1` otherwise. No other exit code.

Success output: a line containing the literal string `SKIPS OK` plus three counts, in the shape `SKIPS OK — 8 gates accounted, 1 declared skip, 0 undeclared`. Then, on a second line, a `GATE-SKIPS total=<n> skipped=<n>` line of its own, so this gate is accounted for by the same mechanism as every other.

The script must never write to `gate-skips.lock` or to any log. Constraint 9 forbids an update flag, for the reason already established for `scripts/check-gate-manifest.mjs`: a check that can rewrite its own baseline is not a check.
