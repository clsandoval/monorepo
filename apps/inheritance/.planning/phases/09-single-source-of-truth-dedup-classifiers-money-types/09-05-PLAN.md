<objective>
Close the second money boundary — the estate-tax wizard — and delete the second implementation of
peso→centavo conversion while doing it.

`09-RESEARCH.md` §4.4 measured the shape: `EstateTaxWizardState` stores money as bare `number` in
**pesos**, the estate-tax engine's `EngineInput` stores bare `number` in **centavos**, and exactly one
adapter joins them — `wizardStateToEngineInput` at `frontend/src/lib/estate-tax-engine/pipeline.ts:110`,
with 24 `toCentavos(...)` call sites. That adapter defines its own local conversion arrow at line 113,
which §2.3 identified as the second implementation of a rule that already exists in
`frontend/src/types/money-units.ts`.

Both facts are fixed here at once: the two ends of the adapter get their units in the type system, and
the adapter's private arrow is replaced by the shared converter.

Output: a tax wizard whose peso state cannot be handed to a centavo consumer, and one fewer
implementation of the same conversion.
</objective>

## Trust Boundaries

|----------|-------------|
| tax wizard state → tax engine | The single point where a peso figure becomes a centavo figure; an error here scales every deduction, bracket lookup and tax due by 100 |
| tax engine output → succession engine | `lib/tax-bridge.ts` consumes the tax engine's centavo output; leaving that end untyped would let a peso reach it undetected |

| T-09-08 | Tampering | `frontend/src/types/estate-tax.ts` | mitigate | Both ends of the adapter are unit-typed, so a peso value reaching a centavo field is a compile error rather than a figure that is wrong by two orders of magnitude |
| T-09-09 | Repudiation | `frontend/src/lib/estate-tax-engine/pipeline.ts` | mitigate | The private conversion arrow is deleted and the shared implementation imported, so there is one place where the ×100 lives and one place a future fix has to land |
| T-09-13 | Tampering | the 252 estate-tax tests | mitigate | The plan forbids editing any expected value; a moved figure is a BLOCKED condition, which distinguishes "the types are now right" from "the arithmetic changed" |
