<objective>
Phase 17's four preceding plans each fixed a disagreement. This plan builds the thing that makes those
fixes permanent: a check that fails when the table, the narrative, the citation pill and the PDF
disagree about the article for the same heir. Registration into the manifest is plan `17-06`; this
plan writes the check and proves it works, in that order, because a gate registered before it has
been seen red is a gate nobody has tested.

The check is `scripts/check-citation-integrity.mjs`. It asserts five things, each with its own literal
violation marker so a failure says which rule broke rather than that the gate failed:

| Marker | Assertion | Layer pair it protects |
|---|---|---|
| `NARRATIVE DISAGREES` | for every heir in every corpus case, `narrative.legal_basis` equals `share.legal_basis` element-for-element | narrative versus table |
| `PROSE CITES ARTICLE` | `narrative.text` contains no occurrence of the literal `of the Civil Code` | narrative prose asserting authority |
| `CITATION UNRESOLVED` | every string in every `share.legal_basis` resolves through `parseArticleKey` plus `NCC_ARTICLE_DESCRIPTIONS` | pill and PDF |
| `LAYER DERIVES ARTICLE` | none of the four layer source files contains a token matching `/Art\.\s*\d/` | all four |
| `DUPLICATE RULE PRESENT` | `frontend/src/wasm/bridge.ts` contains neither `predictScenario` nor `computeMock` | the engine's monopoly on the rule |

`LAYER DERIVES ARTICLE` is what turns "no other layer may derive one" from an intention into a
mechanical fact. The four files it scans are fixed and named in the script:

- `frontend/src/components/results/DistributionSection.tsx`
- `frontend/src/components/results/NarrativePanel.tsx`
- `frontend/src/components/results/StatuteCitationsSection.tsx`
- `frontend/src/components/pdf/PerHeirBreakdownSection.tsx`

There is deliberately **no allow-list**. A gate that carries a list of tolerated disagreements
acquires entries the first time it is inconvenient, and the entry is invisible in the green run that
follows. If one of the five assertions cannot legitimately pass, the correct output is a BLOCKED
report with pasted output.

The red observation is done against **committed fixtures**, matching how every other check script in
`scripts/` is proven — `scripts/fixtures/` already holds `manifest-weakened.json`,
`coverage-stale-zero.json`, `legal-rules-vector-missing.json` and eighteen more, each existing so a
gate's failure path is exercised on every run rather than trusted. The two fixtures this plan adds are
engine-output documents, not source edits, so the tree under test is never deliberately broken.
</objective>

<constraints>
- The script uses `node:` builtins only and imports `scripts/citation-corpus.mjs` from plan `17-01`.
  No dependency is added to any `package.json`.
- The script's only flags are `--corpus <dir>` and `--articles <path>`, both read-only path
  overrides so the fixtures can drive the failure paths. It has no flag that writes, repairs,
  regenerates, accepts or waives anything, and it holds no allow-list, exception list or baseline
  file. A check that can rewrite its own baseline is not a check.
- It prints `GATE-SKIPS total=<n> skipped=0` on **every** exit path, success and failure alike,
  matching the accounting `scripts/check-gate-manifest.mjs` and
  `scripts/check-legal-traceability.mjs` both perform. A skip report that appears only on success
  says nothing about the run that needs investigating.
- Exit 0 on zero violations, exit 1 otherwise. There is no third exit code.
- Injection is done by pointing the script at a fixture directory with `--corpus`. `engine/src`,
  `frontend/src`, `gates.manifest.json`, `gates.manifest.lock` and every baseline are untouched by
  this plan and are absent from `files_modified`.
- The two fixtures are hand-written `EngineOutput`-shaped JSON documents with invented heir names.
  They are not committed engine inputs and are never added to `engine/examples/`.
- `bash scripts/ci-gates.sh` exits 1 at G3 on this branch for reasons this phase does not own. This
  plan runs the new script directly and makes no whole-suite claim.
</constraints>

<threat_model>
This script is a gate, so the threat model is inverted from a feature's: the asset being protected is
the gate's own credibility, and the attacker is a future agent under deadline pressure trying to make
a red run green.

Three defences are structural rather than advisory. **No allow-list** means there is no low-friction
place to record an exception; making the gate pass requires fixing the code. **No write flag** means
the script cannot regenerate a baseline that would encode today's failures as tomorrow's expectation.
**Fixture-driven red observation** means the failure path executes on every run of the gate's own
verification, so a later refactor that accidentally makes the check unable to fail is caught rather
than celebrated.

The one genuine correctness hazard is a check that passes because it measured nothing — an empty
corpus directory, or a WASM artifact that failed to load. `scripts/citation-corpus.mjs` throws with
the `ENGINE MISSING: ` prefix rather than returning empty, and Task 2 requires the script to exit 1
with `CORPUS EMPTY` when it computes zero heir rows. A green result on zero rows is the single most
dangerous outcome available to this design and is explicitly turned into a failure.

The fixtures contain invented names and no client data, and the script opens no socket and spawns no
subprocess.
</threat_model>
