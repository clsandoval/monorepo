<objective>
`frontend/src/wasm/bridge.ts` contains `predictScenario` — a hand-written TypeScript transcription of
`engine/src/step3_scenario.rs:52-235`, as its own doc comment states — and `computeMock`, which calls
it to produce a synthetic distribution. This is the surviving duplicate legal rule named by
`CLAUDE.md` invariant 5, owned by `EXT-02`, and it is the thing gate `G28` was built after a
hand-copied classifier had already drifted from the Rust engine once.

In a citation-first product it is worse than dead code. `predictScenario` decides a scenario code from
a family graph — `I1` through `I15`, `T1` through `T15` — which is the input to every legitime rule
downstream. It can disagree with the engine, and nothing anywhere compares the two.

`17-RESEARCH.md` section 4 measured its reach:

```
frontend/src/wasm/bridge.ts:5    * Falls back to computeMock() if WASM is not available.
frontend/src/wasm/bridge.ts:86   function predictScenario(
frontend/src/wasm/bridge.ts:219  export async function computeMock(input: EngineInput): Promise<EngineOutput> {
frontend/src/wasm/bridge.ts:230    const { scenarioCode, successionType } = predictScenario(
```

**Zero importers outside the file, including tests.** `predictScenario` is module-private.
`computeMock` is exported and nothing imports it. `compute()` delegates unconditionally to
`computeWasm()`, so no caller reaches the mock at runtime and there is no fallback to preserve — the
file header's sentence claiming one has been false for as long as `compute()` has looked like this.

The deletion is the whole block from the `predictScenario` doc comment through the end of
`computeMock`, plus its four now-unused helpers, plus two stale sentences in the file header. Because
`frontend/tsconfig.json` sets `noUnusedLocals`, a helper left behind after its only caller goes is a
compile error, not silent dead code — so the typecheck, not a careful reading, is what proves the
deletion is complete.

This plan is deliberately wave 2 and depends only on `17-01`. It shares no file with `17-02` or
`17-03` and can run beside them.
</objective>

<constraints>
- The deletion is total. `predictScenario` is not rewritten to call the engine, not moved to a test
  helper, not kept behind an environment flag, and not commented out. A second implementation of a
  legal rule that is merely unreachable is still a second implementation.
- `computeWasm`, `compute`, `ensureWasmInitialized`, `parseEngineError`, `EngineError` and
  `EngineErrorKind` are not touched. Their behaviour is out of this plan's scope.
- No test file is edited, deleted or skipped. Task 1 proves no test imports either symbol; if one
  does, the plan stops and reports rather than deleting the test.
- No import is removed until the typecheck names it. `noUnusedLocals` is the authority on what became
  unused; guessing at the list risks removing something a surviving function still needs.
- `frontend/test-baseline.json` is not edited. This plan deletes no test, so the test count must not
  move. Task 3 asserts that it did not.
- `bash scripts/ci-gates.sh` exits 1 at G3 on this branch for reasons this phase does not own. This
  plan proves the typecheck and the frontend suite scope directly and makes no whole-suite claim.
</constraints>

<threat_model>
`bridge.ts` is the boundary between the browser application and the compiled engine. It parses
untrusted-by-shape JSON from the WASM module and turns thrown values into typed errors, so it is
genuinely a trust boundary — and this plan touches none of that machinery. `parseEngineError`'s
`unknown` arm, which is what guarantees no boundary failure ends as an untyped value, is explicitly
out of scope.

The hazard being removed is the more serious one. `computeMock` validates its input with
`EngineInputSchema` and then returns a *plausible* `EngineOutput` — real heir ids, real names, an
equal split of the estate, per-heir narratives, and `legal_basis: []`. It is shaped exactly like a
real answer. Any future code path that reaches it, by a wrong import or a mistaken fallback, produces
a distribution that looks computed and is not, with an empty citation array in a product whose entire
claim is that every line carries its article. Deleting it removes the possibility.

The hazard introduced by the deletion is an incomplete one leaving a half-removed module. That is
bounded by `noUnusedLocals` and by the requirement that the typecheck exits 0 before the commit.
</threat_model>
