<objective>
Phase 17's five requirements are all of the form "X and Y agree". Nothing can be claimed about
agreement without a measured starting disagreement, and every later plan in this phase is verified by
re-running the same measurement and watching a specific number move to zero. This plan builds that
measurement once, as a committed module the later plans import, and records the starting values.

It also settles a question the later plans depend on and must not each re-answer: **what "the corpus"
means**. It means every `.json` file under these five directories, computed through the same WASM
artifact the product loads:

| Directory | Files |
|---|---|
| `engine/examples/cases` | 20 |
| `engine/examples/coverage-cases` | 31 |
| `engine/examples/testate-cases` | 20 |
| `engine/examples/defect-cases` | measured in Task 1 |
| `engine/examples/fuzz-cases` | measured in Task 1 |

`engine/examples/simple-intestate.json` sits at the top level of `examples/` and is **excluded**,
because it is a hand-written example rather than a generated case and the five directories above are
what `engine/examples/generate-test-cases.sh` produces.

The engine is loaded exactly the way `frontend/journey/engine.mjs` loads it — `initSync` over
`frontend/src/wasm/pkg/inheritance_engine_bg.wasm` with the sibling `inheritance_engine.js` glue.
This plan does not add a second engine call site with different behaviour; it adds a corpus iterator
around the same two files.

The four quantities this plan establishes, each of which a later plan drives to a target:

1. **Narrative-versus-table disagreement** — heir rows whose narrative text cites an article absent
   from that row's `legal_basis`. Plan `17-02` drives this to 0.
2. **Pill resolution** — distinct `legal_basis` strings that do not resolve to a description. Plan
   `17-03` drives this to 0.
3. **Duplicate legal rule** — the presence of `predictScenario` and `computeMock`. Plan `17-04`
   drives this to 0.
4. **Gate count** — the manifest length and the three prose statements of it. Plan `17-06` moves all
   four together.
</objective>

<constraints>
- This plan is measurement only. It does not edit `engine/src/`, `frontend/src/`, any test, any
  baseline, `gates.manifest.json`, `gates.manifest.lock`, `gate-skips.lock`,
  `assertion-baseline.json` or `frontend/test-baseline.json`.
- `scripts/citation-corpus.mjs` exports functions and **never calls `process.exit`**. A measuring
  library that can end the process cannot be reused by a gate that needs to print a full report
  before its own verdict.
- The module uses `node:` builtins only, matching every other script in `scripts/`. No dependency is
  added to any `package.json`.
- If `frontend/src/wasm/pkg/inheritance_engine_bg.wasm` is absent, the module throws with the message
  prefix `ENGINE MISSING: ` and the plan stops and reports BLOCKED. It does not silently measure zero
  files. Rebuilding it is `bash engine/build-wasm.sh`, which is gate G2's own command.
- An engine rejection for one corpus input is recorded in a `rejected` list and excluded from the
  row counts. It is never turned into an empty result.
- `bash scripts/ci-gates.sh` exits 1 at G3 on this branch for reasons this phase does not own
  (`.planning/phases/16-stabilise-the-deletion-milestone/16-FLOOR-BLOCKED.md`). This plan does not run
  the whole suite and makes no claim about it.
</constraints>

<threat_model>
The measuring module reads committed JSON from the repository and a committed WASM binary, and writes
one Markdown file under `.planning/`. It opens no socket, spawns no subprocess, touches no database
and reads no credential.

The one real hazard is **a measurement that reports success because it measured nothing**. A glob that
silently matches zero files, or a WASM load that silently falls back, would print `0 disagreements`
and every later plan in the phase would inherit a false green. Two defences are built in: the module
throws rather than returning empty when the WASM artifact is missing, and Task 3's acceptance
criteria assert a **positive** file count and a **positive** heir-row count before any disagreement
figure is believed. A zero row count is a failure of the harness, not a clean corpus.

A second hazard is scope: the corpus inputs contain decedent and heir names. They are committed test
fixtures with invented names, not client data, and `17-BASELINE.md` records counts and article
strings only — no heir name and no peso figure is copied into a planning file.
</threat_model>

Create `scripts/citation-corpus.mjs`. It is an ES module using `node:fs`, `node:path` and
`node:url` only, with no `process.exit` call anywhere in it, and it exports exactly these five
bindings:

`export const CORPUS_DIRS = ['cases', 'coverage-cases', 'testate-cases', 'defect-cases', 'fuzz-cases'];`

`export const ARTICLE_TOKEN_RE = /Arts?\.\s*\d+[\d\-]*(\s*¶\s*\d+)?/g;` — the token shape used when
scanning narrative prose. It matches both `Art. 887` and the range form `Arts. 1003-1008`, and it
tolerates the paragraph suffix the engine emits as `Art. 892 ¶2`.

`export async function loadEngine()` — resolves the pkg directory as
`path.resolve(<this file's dir>, '..', 'frontend', 'src', 'wasm', 'pkg')`, throws
`new Error('ENGINE MISSING: ' + wasmPath + ' does not exist. Build it with: bash engine/build-wasm.sh')`
when the `.wasm` file is absent, otherwise dynamically imports the glue, calls
`mod.initSync({ module: fs.readFileSync(wasmPath) })` once per process behind a module-level boolean,
and returns the module. This mirrors `frontend/journey/engine.mjs` exactly and adds no new behaviour.

`export async function computeCorpus()` — iterates `CORPUS_DIRS` under
`path.resolve(<this file's dir>, '..', 'engine', 'examples')`, skips a directory that does not exist,
sorts each directory's `.json` files by name so the report order is stable, and returns
`{ files, computed, rejected, results }` where `files` is the total count seen, `rejected` is an
array of `{ file, message }` for inputs the engine threw on, and `results` is an array of
`{ file, output }` for the rest.

`export function articleKeys()` — reads `frontend/src/data/ncc-articles.ts` as text and returns a
`Set` of every key in `NCC_ARTICLE_DESCRIPTIONS`, extracted with
`/^\s*"([^"]+)":/gm` over the region between `NCC_ARTICLE_DESCRIPTIONS: Record<string, string> = {`
and the first line that is exactly `};`. Reading the source text rather than importing the module is
deliberate: `scripts/` runs plain Node with no TypeScript loader, and every other script in this
directory is dependency-free for the same reason.

Add a file header comment in the register the other `scripts/*.mjs` files use, stating in its own
words that this module measures and never judges, that it never exits the process, and that the gate
which does exit is `scripts/check-citation-integrity.mjs`.
