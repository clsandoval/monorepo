<threat_model>
These four files render text the engine produced into a lawyer's screen and into a PDF. They accept
no user input, issue no request, and touch no credential, so injection and exfiltration are not
reachable here.

The hazard that matters is **a resolution failure that looks like a success**. Today's behaviour is
exactly that: a chip reading `Art. 996` with no panel is indistinguishable from a chip whose panel is
merely collapsed, and the PDF prints `Art. 996: Art. 996` as though the second half were a
description. A lawyer pastes that into a deed believing the citation was validated. The mitigation is
not "resolve more articles" — it is that an unresolved key must be *loud*, which is why Task 3
renders a distinct state with a stable `data-citation-unresolved` hook and why plan `17-05`'s gate
fails on any unresolved corpus article rather than counting them.

The inverse hazard is a description that resolves to the *wrong* article. `Art. 892 ¶1` and
`Art. 892 ¶2` both normalise to `Art.892`, so both paragraphs display the whole-article description.
The chip itself keeps rendering the engine's raw string including the paragraph, so nothing on screen
claims the paragraph was resolved individually; only the gloss is article-level. That is recorded in
the module comment Task 1 writes so a later reader does not mistake it for a bug.
</threat_model>

```ts
export interface ResolvedArticle {
  /** The engine's own string, displayed verbatim on the chip. */
  raw: string;
  /** The normalised map key, or null when the string is not article-shaped. */
  key: string | null;
  /** The description, or null when nothing resolved. */
  description: string | null;
  /** False when this citation could not be resolved — render it loudly. */
  resolved: boolean;
}

/**
 * The ONE place a legal_basis string becomes a description.
 *
 * The engine is the single attribution authority: it emits the article, and this
 * function only looks up prose for it. No caller may index
 * NCC_ARTICLE_DESCRIPTIONS directly, because a second lookup is a second place
 * that can silently miss — which is exactly the dead pill this replaces.
 */
export function resolveArticle(rawBasis: string): ResolvedArticle {
  const key = parseArticleKey(rawBasis);
  if (key === null) return { raw: rawBasis, key: null, description: null, resolved: false };
  const description = NCC_ARTICLE_DESCRIPTIONS[key];
  if (description === undefined) return { raw: rawBasis, key, description: null, resolved: false };
  return { raw: rawBasis, key, description, resolved: true };
}
```
