<objective>
Make the ascendant tier of intestate succession correct end to end, closing LAW-01 and LAW-04 in one
wave.

Two measured defects share one cause. `engine/src/step2_lines.rs:70` selects line anchors with
`.filter(|h| h.degree_from_decedent == 1)`, so a grandparent at degree 2 never forms a line,
`LineCounts.legitimate_ascendant` stays 0, and step 3 never reaches Regime B. Measured on
2026-07-31: three living grandparents with a ₱12,000,000 estate produce scenario `I15` and a single
`STATE` row of 1200000000 centavos; the committed input
`examples/coverage-cases/019-ascendants-grandparents-sp.json` produces `I11` with the spouse taking
2204680000 centavos, which is Art. 995 — an article conditioned on the absence of ascendants.

The same anchor set also lets a **predeceased parent** be represented. `build_single_line` sees the
`Predecease` trigger and `find_representatives_recursive` walks the dead parent's `children`, which
are the decedent's siblings. Measured: a predeceased father with one sibling in the tree and a
living mother, estate ₱120,000,000, gives `fa=6000000000` and `mo=6000000000`. Removing the sibling
from the same tree gives `fa=0` and `mo=12000000000`. Art. 972 ¶1 says representation "takes place
in the direct descending line, but never in the ascending", and Art. 986 ¶2 gives the whole estate to
the sole surviving parent, so the sibling-free control is the correct answer for both trees.

This plan fixes step 2 and step 7 together, in one wave, because either alone leaves the tree red.
Step 2 alone would make grandparents form lines while `distribute_i5` still divides across every
heir carrying the ascendant category — including predeceased parents — with no degree filter and no
line filter.

The selector step 7 needs already exists and is already correct: `engine/src/step5_legitimes.rs:443`
`divide_among_ascendants` filters to alive and eligible ascendants, takes the parent tier when it is
non-empty and otherwise the minimum degree present, then halves the collective between the paternal
and maternal groups when both are present. `.planning/research/LEGAL-CONFORMANCE.md` §2a states in
terms that step 7 must be routed through that helper rather than given a new one. Its return type is
`HeirLegitime` rather than `HeirDistribution`, so this plan extracts the **selection** into one
shared function and has both callers read it.
</objective>

**Add a public function** `anchor_ids_for_category(heirs: &[Heir], category: EffectiveCategory) -> Vec<HeirId>`
to `engine/src/step2_lines.rs`, placed in the internal-helpers region above the test module and
documented with a `///` comment that cites the codal sentences it transcribes.

Its behaviour, per category:

- `EffectiveCategory::LegitimateAscendantGroup` — collect the heirs of that category that are
  `is_alive && is_eligible && !has_renounced`. If that collection is empty, return an empty vector.
  Otherwise take the minimum `degree_from_decedent` among them and return the ids of every heir of
  that category at that minimum degree that satisfies the same three predicates. This is Art. 987 ¶1,
  "In default of the father and mother, the ascendants nearest in degree shall inherit."

  `degree_from_decedent == 1`, which is exactly today's behaviour. Plans 07-02 and 07-03 extend this
  function; this plan changes only the ascendant arm.

`LegitimateAscendantGroup`, `CollateralGroup`. Preserve the original heir-list ordering **within**
each category so that emitted row order stays stable, and deduplicate ids so no heir can be anchored
twice.

`get_representation_trigger` branch, add: when `anchor.effective_category` is
`EffectiveCategory::LegitimateAscendantGroup`, never construct a `Representation` line and never call

**Add a private helper** to `engine/src/step7_distribute.rs`:

    fn select_inheriting_ascendants(heirs: &[Heir]) -> Vec<&Heir>

It returns the ascendants that inherit, applying the same three tiers that
`divide_among_ascendants` applies, in this order:

1. Keep only heirs with `effective_category == EffectiveCategory::LegitimateAscendantGroup` that are
   `is_alive && is_eligible`. An ascendant that is not alive receives nothing.
2. If any of those is at `degree_from_decedent == 1`, keep only those. Otherwise keep only those at
   the minimum `degree_from_decedent` present. This is Art. 987 ¶1.

**Add a second private helper**:

    fn split_ascendant_amount_by_line(amount: &Frac, ascendants: &[&Heir]) -> Vec<(HeirId, Frac)>

It partitions the selected ascendants into those with `line == Some(LineOfDescent::Paternal)` and
those with `line == Some(LineOfDescent::Maternal)`. When both partitions are non-empty it gives each
partition `amount / 2` and divides each half equally among that partition's members. When one
partition is empty it divides the whole `amount` equally among the members of the non-empty
partition. When both are empty — meaning no selected ascendant carries a `line` — it divides the
whole `amount` equally among all selected ascendants. This is Art. 987 ¶2, "should they be of
different lines but of equal degree, one-half shall go to the paternal and the other half to the
maternal ascendants. In each line the division shall be made per capita," with the third case
mirroring `divide_among_ascendants`'s own single-line fallback.

`split_ascendant_amount_by_line(<the ascendant collective>, &select_inheriting_ascendants(heirs))`
