<objective>
Insert exactly 63 `// LEGAL-VECTOR: Art. NNN` marker comments into the engine's test code, one per
Civil Code article that the engine's production code cites, so that each of those 63 articles is
traceable by a single grep to exactly one named test function.

This plan writes markers only. The registry file, the untraced ledger and the checker script that
consume these markers are plan `14-05`, which depends on this plan. This plan runs first in the phase
because it measures `cargo test` counts and asserts they do not move; every other engine-touching
plan in this phase is sequenced after it for that reason.

The marker is a label on an assertion that already exists and already passes. It makes no new legal
claim, changes no number, and changes no assertion. That property is what makes this plan safe for a
cheap executor: nothing in it requires reading the Civil Code.
</objective>

<constraints>
- Comment lines only. Adding, removing or editing any non-comment line in these nine files is out of
  scope for this plan, and so is renaming any function.
- The marker text is fixed and literal: two slashes, one space, `LEGAL-VECTOR:`, one space, then the
  article exactly as it appears in the Article column of the table in `## Reference A` below —
  including the period and the single space, for example `// LEGAL-VECTOR: Art. 888`.
- Each marker goes on its own line, indented to match the first statement line of the function body
  it is placed in, and placed as the **first line inside the function body**, immediately after the
  line that opens the body.
- Each of the 63 markers appears exactly once across the whole `engine/` tree when the plan is done.
  Two different articles may live in the same function; the same article may not appear twice.
- `engine/src/step7_distribute.rs`, `engine/src/step8_collation.rs`, `engine/src/types.rs`,
  `engine/src/flags.rs` and `engine/src/pipeline.rs` are NOT edited by this plan. No row of the
  table designates a vector inside them.
- Every commit stages explicit paths through `bash scripts/safe-commit.sh`. `git add -A`,
  `git add .` and `git commit -a` are prohibited.
- No test, assertion or gate may be weakened, deleted, skipped or loosened. If `cargo test` reports
  a different passed count after the edits than before, that is a defect introduced by this plan and
  the correct response is to revert the edit that caused it, never to change a test.
- No point of Philippine law is decided here. If any task appears to require one, stop and report
  BLOCKED using the five-field template in `.planning/PLAN-STANDARD.md` section 3.
</constraints>
