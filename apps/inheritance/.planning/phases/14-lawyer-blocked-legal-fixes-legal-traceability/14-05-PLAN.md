<objective>
Plan `14-01` placed 63 `// LEGAL-VECTOR: Art. NNN` markers in the engine's test code. This plan turns
those markers into an enforced traceability map: a registry naming, for every Civil Code article the
engine's production code cites, the single test function that carries that article's marker — and a
shrink-only ledger naming the articles that have no such function yet, so the gap is a visible number
rather than an unstated absence.

Measured during planning against the current tree: the engine's production code cites **79** distinct
articles. **63** of them already have a passing test function whose body cites the article, and those
are the 63 that `14-01` marked. The remaining **16** do not, and they go into the ledger.

The check that enforces this is `scripts/check-legal-traceability.mjs`, registered by plan `14-06` as
gate G28. Once it is in place, an article added to production code without a vector or a ledger entry
turns the build red, which is what makes "every legal rule is traceable" a property of the repository
rather than a claim in a document.

This plan records where a rule is tested. It never states what a rule requires. That distinction is
what keeps it free of legal judgment.
</objective>

<constraints>
- No file under `engine/src/` and no file under `engine/tests/` is edited. `14-01` already placed
  every marker this plan reads; if a marker is missing, that is a `14-01` defect and the correct
  response is to stop and report BLOCKED, never to add the marker here.
- The registry is derived by two fixed rules, not by taste:
  - **Production region.** For each file under `engine/src/`, the production region is the file
    content up to but not including the first occurrence of the literal `#[cfg(test)]`. Article
    citations found after that point belong to tests and are ignored.
  - **`implemented_in`.** For an article, `implemented_in` is the sorted list of every `engine/src/`
    file whose production region contains that article's citation string, written as paths relative
    to `engine/`.
  Both rules are restated in the checker's header comment so a later reader can confirm the registry
  without re-deriving the intent.
- `engine/legal-traceability.lock` is a shrink-only ledger, in the same direction as
  `gate-skips.lock` and `engine/defect-baseline.json` and the exact inverse of `gates.manifest.lock`.
  Its `$comment` says so. Adding an article to it in order to turn a red check green is prohibited;
  the correct response to a new untraced article is a vector, not a declaration.
- `scripts/check-legal-traceability.mjs` is dependency-free Node ESM using `node:` builtins only. It
  writes no file and has no `--fix`, `--update`, `--accept`, `--regenerate` or waiver flag. Its three
  flags — `--rules`, `--lock`, `--engine` — are read-only path overrides so the committed fixtures can
  drive each failure path.
- The script prints exactly one `GATE-SKIPS total=63 skipped=0` line on every exit path, where the
  total is the number of traced rules. The 16 untraced articles are **not** reported as skips:
  `gate-skips.lock` is owner-owned and may only shrink, and declaring 16 new skips in it is
  prohibited. Untraced articles are reported instead as a coverage line the script prints in its own
  output, `LEGAL TRACEABILITY COVERAGE 63/79 articles traced, 16 declared untraced`.
- Gate registration is not part of this plan. Plan `14-06` registers this script as gate G28.
- Every commit stages explicit paths through `bash scripts/safe-commit.sh`.
- This plan runs after `14-02` for one reason: both plans run `cargo test`, and `14-02` adds a test
  file, so running them concurrently in the same working tree would make this plan's green run
  depend on the other plan's mid-edit state.
- No point of Philippine law is decided. If a task appears to require one, stop and report BLOCKED
  using the five-field template in `.planning/PLAN-STANDARD.md` section 3.
</constraints>

`untraced_articles`.

message says to delete that entry from the lock, which is what forces the ledger down when a vector
lands.
`TRACEABILITY SCAN UNREADABLE` — an input is missing or unparseable; exits 1 immediately.
