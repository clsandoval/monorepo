<objective>
Make `engine/BUGS.md` describe reality. Today it holds one entry, BUG-001, which asserts that two or
more simultaneous disinheritances make the distributed shares sum to twice the estate. That does not
reproduce: running BUG-001's own committed JSON through the current engine gives a sum of exactly
₱30,000,000, and the two disinherited children correctly receive ₱0.

Three artifacts come out of this plan:

1. BUG-001 is closed as non-reproducing, with the measured numbers written into the entry rather
   than an assertion that it was fixed.
2. BUG-002 is filed against the real, still-open defect at `engine/src/step7_distribute.rs:421`,
   where the excess of an institution over the instituted heir's legitime is computed
   unconditionally — including for `ShareSpec::EntireFreePort` — with a committed reproduction and
   the measured output.
3. Both entries are held to that description by two independent mechanisms: a Rust integration test
   that re-runs each entry's committed JSON and compares against the recorded numbers, and a Node
   structural check that validates the document's shape.

The two-mechanism shape is the one this project already uses for observability — `engine/tests/observability.rs`
catches a behavioral regression while `scripts/check-observability.mjs` catches a source regression.
The same split applies here: the Rust test catches the numbers drifting, the Node check catches the
document drifting.
</objective>

`### ` headings, in order:

| Heading | On an Open entry | On a Closed entry |
|---|---|---|
| `### Description` | required | required |
| `### Reproduction` | required, with a fenced `json` block | required, with a fenced `json` block |
| `### Expected` | required, attributed | omitted |
| `### Actual` | required, measured | required, measured |
| `### Why it was closed` | omitted | required |
| `### Owning requirement` | required | omitted |

preamble described in task 2, for the count of 13 that task 2's acceptance criteria checks. The two
