<objective>
The spec is the artifact a lawyer reads to sign off, and
`.planning/research/LEGAL-CONFORMANCE.md` section 2b records four passages in it that misstate the
law. A wrong spec is worse than a wrong line of code, because it will cause a correct code fix to be
reverted or a wrong rule to be re-implemented.

Measured during planning, the four stand as follows:

| # | Misstatement | State today |
|---|---|---|
| C1 | Art. 992 framed as an unqualified bilateral bar, with *Aquino v. Aquino* absent from the whole repo | uncorrected — `grep -rin aquino specs/` returns zero hits |
| C2 | Art. 900 ¶2 stated as a three-condition illness test, with the statutory three-month window omitted | uncorrected — the three-condition block is still at `specs/inheritance-engine-spec.md` and TV-16 still says `3-condition check` |
| C3 | Art. 972 ¶1's prohibition on representation in the ascending line is stated nowhere | uncorrected — `grep -n "never in the ascending" specs/` returns zero hits |
| C4 | The vanishing-deduction reduction ratio omitted paragraph (6), Transfers for Public Use | **already corrected in Phase 8 under LAW-09** — the corrected text and its `> **Corrected in Phase 8 (LAW-09).**` note are both present |

This plan corrects C1, C2 and C3, pins C4 against regression, and adds
`scripts/check-spec-legal-text.mjs` so that all four stay corrected. The check is a literal-string
check over named files at named anchors: it can be read in one sitting and it cannot drift into
interpretation.
</objective>
