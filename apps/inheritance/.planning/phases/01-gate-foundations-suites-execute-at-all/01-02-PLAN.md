  <action>
Append to `apps/inheritance/frontend/src/test-setup.ts`. Keep the existing two blocks exactly as they are — the `import '@testing-library/jest-dom/vitest'` line stays first, and the existing `navigator.clipboard` getter/setter block stays unchanged.

Add these polyfills, in this order. **Every one must be guarded so it installs only when the real implementation is absent** — an unconditional assignment would shadow a genuine jsdom implementation in a future jsdom release and turn a real regression into a silent pass.

1. `ResizeObserver` on `globalThis`, guarded by `if (!(globalThis as any).ResizeObserver)`. A class with three no-op methods: `observe()`, `unobserve()`, `disconnect()`. Required by Recharts and by Radix UI's popper/scroll-area primitives. This is the single largest cluster — 1,465 log occurrences.

2. `DOMRect` on `globalThis`, guarded by `if (!(globalThis as any).DOMRect)`. A class whose constructor takes `x = 0, y = 0, width = 0, height = 0`, exposes `top`, `left`, `right`, `bottom` as `0`, has a static `fromRect()` returning a new instance, and a `toJSON()` returning `{}`. Required by Radix positioning code.

3. Inside a `if (typeof window !== 'undefined')` guard:
   - `window.matchMedia`, guarded by `if (!window.matchMedia)`. Returns an object with `matches: false`, `media` set to the query argument, `onchange: null`, and no-op `addListener`, `removeListener`, `addEventListener`, `removeEventListener`, plus `dispatchEvent` returning `false`.
   - On `window.Element.prototype`, add each of these **only if absent**: `scrollIntoView` (no-op), `hasPointerCapture` (returns `false`), `setPointerCapture` (no-op), `releasePointerCapture` (no-op), `scrollTo` (no-op). These are the Radix Select pointer/scroll APIs jsdom does not implement; they produce `TypeError: target.hasPointerCapture is not a function` and `TypeError: candidate?.scrollIntoView is not a function`, and are the source of the 2 unhandled exceptions reported alongside the failure counts.

Add a header comment above the new block, in prose, stating: these are jsdom environment gaps, not product behavior; each is guarded so a real implementation always wins; and adding a polyfill here is the ONLY legitimate way to fix an environment failure — a test may never be skipped or its assertion loosened to work around one.

Use TypeScript. The file is type-checked by `tsc -b`, so `as any` casts on `globalThis` are expected and acceptable; `noUnusedLocals` and `noUnusedParameters` are enabled in `tsconfig.json`, so do not leave unused parameters unnamed-but-declared — prefix with `_` or omit them.

Do NOT add: `IntersectionObserver`, `crypto.randomUUID`, `fetch`, `structuredClone`, or any other polyfill not listed above. Each one added beyond this list is an unmeasured change to the environment. If a failure persists that you believe needs another polyfill, report it in the summary rather than adding it.
  </action>
