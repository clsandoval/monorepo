<objective>
Turn `npm test` from a permanently-red signal into a real regression gate, without skipping, deleting, or weakening a single test.

Purpose: after plan 01-02, 46 genuine test-vs-product failures remain (RESEARCH.md §2.1). They are heterogeneous, several require product judgment, and repairing them by rewriting test queries is exactly the weakening this project forbids — so they are out of Phase 1 scope. But roadmap criterion 4 requires CI to "fail the check when any of them fails", and a check that is red from day one through Phase 15 detects nothing: by Phase 7 nobody can distinguish a new regression from the standing 46.

The mechanism, decided in RESEARCH.md §3.1 so no executor has to decide it: run the complete unmodified suite and diff the result against a committed ledger. The ledger can only shrink. A skipped test becomes a hard failure — which makes this gate strictly *stronger* than plain `npm test`, where a skip is silently green.

Output: `frontend/scripts/check-test-baseline.mjs`, `frontend/test-baseline.json`, four fixture files that prove the gate can actually fail, and an `npm run test:gate` entry point.
</objective>

Create `apps/inheritance/frontend/scripts/check-test-baseline.mjs`, a plain Node ESM script with **no dependencies** beyond `node:fs`, `node:path`, and `node:child_process`. It must run under Node 20.

Behavior:

**Modes.** Two invocation modes.
- Default (no arguments): run the suite itself via `child_process.spawnSync` with command `npx` and arguments `vitest run --reporter=default --reporter=json --outputFile.json=<tmpfile>`, `cwd` set to the frontend directory, `stdio: 'inherit'`. The dual-reporter form is verified to work on vitest 4.0.18 (RESEARCH.md §4) and is required here: `--reporter=default` keeps the normal human-readable summary in the CI log, while `--reporter=json` with `--outputFile.json` writes the machine-readable report the gate parses. Note the flag is `--outputFile.json=<path>` (dotted, naming the reporter) when two reporters are active, not bare `--outputFile=`. `spawnSync` will return a nonzero status because tests fail — ignore that status entirely and judge only by the report contents; the exit code of `vitest` is not the gate's answer. Pass no other vitest flags — constraint 4.
- `--from-json <path>`: skip running vitest and read the report from `<path>` instead. This exists so the gate's own failure paths can be exercised against committed fixtures.

**Checks**, evaluated in this order against the parsed report. Collect every violation rather than returning on the first, then print all of them.

1. **UNKNOWN FAILURE** — for each assertion with `status === 'failed'` whose `{file, fullName}` pair is not in the ledger's `known_failures`, record a violation. Message must contain the literal string `UNKNOWN FAILURE`.
2. **STALE BASELINE** — for each ledger entry whose corresponding assertion in the report has `status === 'passed'`, record a violation instructing the operator to delete that entry from `test-baseline.json`. Message must contain the literal string `STALE BASELINE`. This is what forces the ledger to shrink instead of rotting.
3. **SKIPPED TESTS** — if `numPendingTests > 0` or `numTodoTests > 0`, or if any assertion has `status` of `pending`, `skipped`, or `todo`, record a violation naming each such test. Message must contain the literal string `SKIPPED TESTS`. Rationale, which must appear as a comment in the script: plain `npm test` reports a skipped test as green; this project forbids skipping a test to pass a gate, so the gate must treat a skip as a failure.
4. **TEST COUNT DROPPED** — if `numTotalTests < ledger.min_total_tests`, record a violation showing both numbers. Message must contain the literal string `TEST COUNT DROPPED`. This closes the "delete tests until green" escape hatch.

**Ledger entries missing from the report entirely** (neither passed nor failed — e.g. the whole file was removed) must be treated as a check-3-style violation with the literal string `BASELINED TEST NOT FOUND`, not silently ignored.

**Exit codes.** `0` only if zero violations. `1` if any violation. Never any other code, and never exit 0 on an internal error — if the report file is missing or unparseable, print a message containing `REPORT UNREADABLE` and exit 1.

**Output on success:** a summary containing the literal string `GATE OK` plus the counts: total tests, passed, known failures matched, and the ledger size. Print the ledger size prominently — it is a debt figure that should be shrinking.

Convert `testResults[].name` from absolute to frontend-relative before comparing against ledger `file` values, matching how Task 1 wrote them.

Do NOT make the script rewrite `test-baseline.json` under any circumstance. A gate that can edit its own baseline is not a gate. If you find yourself adding an `--update` flag, stop: constraint 5 forbids it.
  </action>
