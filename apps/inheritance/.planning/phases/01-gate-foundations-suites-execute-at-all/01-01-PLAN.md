Create a new executable bash script at `apps/inheritance/engine/build-wasm.sh`.

Note: `loops/forward/wasm/build-wasm.sh` is listed in `read_first` only so you can see it is DEAD — it points at `../inheritance-rust-forward` and `../inheritance-frontend-forward/app/src/wasm/pkg`, neither of which exists in this tree. Do not copy it, do not edit it, do not delete it.

The new script must:

- Start with `#!/usr/bin/env bash` and `set -euo pipefail`.
- Resolve its own directory into a variable `ENGINE_DIR` using `cd "$(dirname "${BASH_SOURCE[0]}")" && pwd`, so the script works no matter which directory it is invoked from.
- Define `OUT_DIR="$ENGINE_DIR/../frontend/src/wasm/pkg"`.
- Define `WASM_FILE="$OUT_DIR/inheritance_engine_bg.wasm"`.
- Preflight check 1: if `command -v wasm-pack` fails, print to stderr the exact remediation line `wasm-pack not found. Install it with: cargo install wasm-pack` and `exit 1`.
- Preflight check 2: if `rustup target list --installed` does not contain `wasm32-unknown-unknown`, run `rustup target add wasm32-unknown-unknown`. Do not fail here — add the target and continue.
- Run the build: `cd "$ENGINE_DIR"` then `wasm-pack build --target web --out-dir "$OUT_DIR"`.
- Post-build verification, all three of which must be enforced, each printing a distinct message to stderr and exiting 1 on failure:
  a. `test -f "$WASM_FILE"` — message must contain the literal string `WASM ARTIFACT MISSING`.
  b. Size floor: the file must be at least 100000 bytes. Obtain the size with `wc -c < "$WASM_FILE"`. Message must contain the literal string `WASM ARTIFACT TOO SMALL`.
  c. Magic-number check: the first four bytes must be `00 61 73 6d`. Read them with `head -c 4 "$WASM_FILE" | od -An -tx1 | tr -d ' \n'` and compare the result to the literal string `0061736d`. Message must contain the literal string `WASM ARTIFACT NOT A WEBASSEMBLY BINARY`.
- On success, print a line containing the literal string `WASM BUILD OK` followed by the artifact path and its byte size.

Make the file executable: `chmod +x apps/inheritance/engine/build-wasm.sh`.

Rationale for the three post-build checks: `wasm-pack` can exit 0 in configurations where nothing usable lands in `--out-dir`. A build script that trusts its own exit code is exactly the kind of gate that certifies nothing. The verification is the point of the script, not decoration.
  </action>
