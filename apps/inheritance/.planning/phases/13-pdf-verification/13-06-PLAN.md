<objective>
Close requirement PDF-04: "rendered pages are perceptually diffed against approved references."

`13-RESEARCH.md` §7 measured the placement constraint. `scripts/check-journey-registry.mjs:275` raises
`ORPHAN REFERENCE` for any `.png` under `frontend/journey/references/` whose name is not a declared
journey step, and its requirement list at line 59 is frozen to `JRNY-02 … JRNY-08`. Putting PDF page

directory and their own approval command.

takes `referencesDir` as its third parameter, writes nothing anywhere, and returns the five markers

`STEP ERROR`. The `maxDiffPixels` sidecar contract and the `approvedBy` rule come along with it.

machine, and §5 measured and fixed the one source of drift inside the document: the
`Report Generated:` line, pinned by plan `13-03`'s fixed page clock.

Output: one gate, one separate approval command, one new reference directory, and an approval
performed by a human looking at the images.

<constraints>

1. **`frontend/journey/pdf-visual.mjs` contains no write call into `frontend/journey/pdf-references/`
   of any kind.** No flag, no environment variable and no argument makes it write one. A gate that can
   approve its own reference goes green by rewriting its own expectation, and nobody sees the change.
   `grep -c "pdf-references" frontend/journey/pdf-visual.mjs` counting only read paths is an
   acceptance criterion below.

2. **`frontend/journey/pdf-approve.mjs` is the only writer into that directory**, it sources images
   only from `.journey-runs/<stamp>/pdf/page-<n>.png`, and it refuses with a named error when no run
   has produced any.

3. **No gate command invokes `pdf-approve.mjs`.** Plan `13-07` registers `pdf-visual.mjs` and nothing
   else.

4. **`maxDiffPixels` is `0` on every sidecar this plan writes.** `journey/REFERENCES.md` permits
   raising it for exactly one measured reason — a platform whose text rasterisation differs — and
   requires the raiser to be named in `approvedBy`. Nothing in this plan raises it.

5. **`frontend/journey/references/`, `frontend/journey/steps/`, `frontend/journey/rubrics/` and
   `scripts/check-journey-registry.mjs` are not touched.** The new directory exists precisely so that
   none of them has to be.

6. **The rasterisation parameters are fixed and are part of the reference contract**: `pdftoppm -png`
   at `100` dots per inch, through `rasterizePdfPages` from `journey/pdf.mjs`. Changing either
   invalidates every approved image, exactly as `journey/browser.mjs` states for its viewport.

7. **The exit contract is the project's three-valued one.** A stopped stack, a failed build, a missing
   browser, a missing PDF tool or a capture that produced no PDF is exit `2` with the
   `PDF VISUAL CANNOT RUN: ` prefix. A missing reference is exit `1` with `REFERENCE MISSING`, not
   exit `2`: an unapproved page is a real failure, not an environment problem.

8. **`GATE-SKIPS total=<n> skipped=<n>` is printed on stdout on both the pass and the fail path.**

9. **No application source file, no test, no rubric and no seed file is edited.**

10. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
    `git add -A`, `git add .` and `git commit -a` are prohibited.

11. **No point of Philippine law arises in this plan.** It compares images.

</constraints>

<interfaces>

### `frontend/journey/pdf-visual.mjs`

Run from `frontend/`. No arguments.

1. `captureExportedPdf()` from `./pdf-capture.mjs`.
2. `rasterizePdfPages(pdfBuffer, 100)` from `./pdf.mjs`.
3. Write every page image to `.journey-runs/<stamp>/pdf/page-<n>.png` using `newRunStamp` and
   `ARTIFACT_ROOT` from `./artifacts.mjs`, so a failure is inspectable and so `pdf-approve.mjs` has a
   source. `n` is one-based and matches the PDF's own page order.
4. Count the approved references: every `page-<n>.png` in `frontend/journey/pdf-references/`.
5. **Page count first.** When the number of rasterised pages differs from the number of approved
   references, report `PDF PAGE COUNT` naming both integers and attempt no pixel comparison. A page
   appearing or disappearing is a structural change, and reporting it as a pile of per-page diffs
   would bury it.
6. Otherwise, for each page, `compareToReference(pageBuffer, 'page-' + n, referencesDir)` from
   `./diff.mjs`. Collect every result; never stop at the first failure.
7. For every failing page, write the actual image, the reference image, the diff image when one
   exists, and a `FAILURE.txt` whose first line carries the markers, into
   `.journey-runs/<stamp>/pdf/page-<n>/`, following the shape `journey/artifacts.mjs` already uses.

Output:

- one line per failing page: `<marker> — page <n>, <diffPixels> differing pixels against a tolerance of <maxDiffPixels>`
- always, on stdout: `GATE-SKIPS total=<pageCount> skipped=0`
- pass path: `PDF VISUAL PASS pages=<n> diffPixels=0` and exit `0`
- fail path: `PDF VISUAL FAIL pages=<n> failed=<k>` and exit `1`

### `frontend/journey/pdf-approve.mjs`

Run from `frontend/`. No arguments; it approves every page of the most recent run, because a PDF's
pages are approved as a set and approving one page of a two-page document would leave the reference
set describing a document that never existed.

1. Find the newest `.journey-runs/<stamp>/pdf/` directory containing at least one `page-<n>.png`. When
   none exists, print `PDF APPROVE REFUSED: no run has produced page images; run node journey/pdf-visual.mjs first`
   and exit `1`.
2. Copy each `page-<n>.png` into `frontend/journey/pdf-references/page-<n>.png`.
3. Write `frontend/journey/pdf-references/page-<n>.json` containing exactly
   `{ "maxDiffPixels": 0 }`.
4. Delete any `page-<n>.png` and `page-<n>.json` in the reference directory whose `n` exceeds the
   number of pages just approved, so a shrunk document cannot leave a stale extra reference behind.
5. Print `PDF APPROVE OK pages=<n> from=<stamp>` and exit `0`.

### `frontend/journey/pdf-references/README.md`

A short file, committed so the directory exists in git before any image does. It states: that only
`journey/pdf-approve.mjs` writes here; that `journey/pdf-visual.mjs` never does; that the images are
`pdftoppm -png` output at 100 dots per inch and that changing the resolution invalidates all of them;
that `maxDiffPixels` is `0` and may be raised only for the one measured reason `journey/REFERENCES.md`
names, with `approvedBy` recorded; and that these images are deliberately not under
`journey/references/` because `scripts/check-journey-registry.mjs` requires every image there to be a
declared browser step.

### `frontend/journey/REFERENCES.md`

Gains one section, `## PDF page references`, pointing at the new directory and the new command and
naming the one difference from browser references: approval is whole-document rather than per-step.
Nothing already in that file is rewritten.
