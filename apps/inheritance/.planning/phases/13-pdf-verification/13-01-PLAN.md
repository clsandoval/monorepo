<objective>
Make every money string that reaches the generated PDF representable by the fonts that PDF actually
carries, so that requirement PDF-02 — "every peso figure in the PDF matches the engine output
exactly" — can be asserted at all.

`13-RESEARCH.md` §2 measured the problem live. The document's three fonts are PDF base-14
(`Times-Roman`, `Times-Bold`, `Helvetica`), non-embedded, WinAnsi-encoded, as reported by `pdffonts`.
WinAnsi has no peso sign, so `₱` (U+20B1) is written to the page as the byte `0xB1`, which extracts as
`±` (U+00B1) and is drawn at near-zero advance width, overprinting the first digit of the amount. The
lawyer's exported PDF shows a corrupted currency mark on every figure, and the extracted text splits
the amount onto its own line, which makes any deterministic text assertion impossible.

The same probe with `PHP ` in place of `₱` extracted cleanly, one contiguous line per label.

Output: one PDF-local module with two pure functions, four section components routed through it, and
the six committed expectations that asserted the broken string corrected to the fixed one.
</objective>

<constraints>

1. **`formatPeso` in `frontend/src/types/index.ts` is not edited, not wrapped and not re-exported.**
   It is the web user interface's formatter and a browser renders the peso sign correctly. Every
   screen and every committed expectation outside `src/components/pdf/` keeps `₱`. Only the PDF layer
   changes.

2. **No file under `engine/` is edited.** The `₱` inside `narratives[].text` is engine output; it is
   converted where it is drawn, not where it is produced.

3. **The replacement token is exactly `PHP ` — the three ASCII letters P, H, P followed by one
   space.** `PHP` is the ISO 4217 alphabetic code for the Philippine peso. No other spelling is
   introduced anywhere in the phase.

4. **`formatPesoPdf` produces the same digits `formatPeso` produces.** Thousands separated with
   commas via `toLocaleString('en-US')`, and a `.` plus exactly two digits only when the centavo
   remainder is non-zero. All arithmetic is `BigInt`, because `Money.centavos` is `number | string`
   precisely so a large estate can exceed `Number.MAX_SAFE_INTEGER`.

5. **No test is deleted, skipped or loosened.** The six committed assertions that name `'₱…'` are
   *corrected* to the string the fixed code renders, exactly as Phase 8 corrected the six
   medical-deduction expectations, and the test file gains cases rather than losing them.

6. **`frontend/test-baseline.json`, `gate-skips.lock`, `engine/defect-baseline.json`,
   `assertion-baseline.json` and `coverage-zero.lock` are read-only in this plan.** All five may only
   shrink. A newly failing test is a BLOCKED condition, never a ledger append.

7. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

8. **No point of Philippine law arises in this plan.** Choosing how to spell a currency unit inside a
   generated document is a typographic matter; no share, article or entitlement is affected, and every
   centavo value is unchanged.

</constraints>

### `frontend/src/components/pdf/pdf-text.ts`

```
export const PDF_PESO_PREFIX = 'PHP ';
export function formatPesoPdf(centavos: number | string | bigint): string
export function toPdfSafeText(text: string): string
```

`formatPesoPdf` — converts to `BigInt`, splits into pesos and centavos, and returns
`PDF_PESO_PREFIX` + `pesos.toLocaleString('en-US')`, with `.` and two zero-padded digits appended only
when the centavo remainder is non-zero. Examples that the tests pin:

| Input centavos | Output |
|---|---|
| `0` | `PHP 0` |
| `1` | `PHP 0.01` |
| `100` | `PHP 1` |
| `150000000` | `PHP 1,500,000` |
| `600000000` | `PHP 6,000,000` |
| `123456` | `PHP 1,234.56` |
| `"900719925474099"` | `PHP 9,007,199,254,740.99` |

`toPdfSafeText` — returns the input with every occurrence of the single character `₱` (U+20B1)
replaced by `PDF_PESO_PREFIX`. It changes nothing else: it strips no markdown, trims no whitespace and
touches no other code point.
