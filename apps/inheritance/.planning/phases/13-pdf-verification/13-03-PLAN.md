<objective>
Obtain the PDF the way a user obtains it, so that every assertion in plans `13-05` and `13-06` is made
about the real artefact rather than about a document the test harness built for itself.

This mirrors the Phase 12 decision recorded in `.planning/STATE.md`: the results view is reached by
clicking the real compute button, because a seeded engine result is a per-heir peso figure nothing
computed. The same reasoning applies one step further along — a PDF the harness rendered itself would
prove the harness works, not that the product's lazy `import('@react-pdf/renderer')` path, its
`profile: null` argument and its blob download all work.

`13-RESEARCH.md` §6 records the sequence and the one product change it needs: the Export PDF button in
`ActionsBar.tsx` has no test hook. §5 records the determinism blocker and its fix —
`CaseSummarySection` prints `Report Generated:` from `new Date()`, so the capture fixes the page clock
with `page.clock.setFixedTime`, which Playwright 1.56.1 documents as keeping timers running, unlike
`clock.install`.

Output: one added attribute, one shared capture module, and a probe that proves the captured bytes are
a real PDF.
</objective>

<constraints>

1. **Exactly one attribute is added to application source: `data-testid="export-pdf"` on the existing
   Export PDF button in `ActionsBar.tsx`.** No behaviour, no label, no ordering and no styling
   changes. This is the same kind of edit Phase 12 made when it added seven per-heir hooks.

2. **One further product change is pre-authorised and no other.** `downloadPDF`
   (`src/lib/pdf-export.ts` lines 78-83) revokes the blob URL on the statement after `a.click()`. If
   task 2's probe shows the `download` event never firing, wrap that single call as
   `setTimeout(() => URL.revokeObjectURL(url), 0)` and re-run. That is the whole permitted remedy: do
   not append the anchor to the document, do not change the filename, do not add a fallback path, and
   do not read the blob out of the page instead of downloading it. If the probe still fails after that
   one change, stop and report BLOCKED with the pasted output.

3. **The page clock is fixed to `2026-06-15T00:00:00Z` with `page.clock.setFixedTime`, never with
   `page.clock.install`.** `install` fakes timers, which stalls React scheduling and the debounced
   autosave. The date is chosen for two measured reasons recorded in `13-RESEARCH.md` section 5: it is
   after the seeded decedent's date of death `2026-01-15`, and it is before real time on the machine
   that mints the session token, so the token's expiry lies in the fake future and the client treats
   the session as live.

4. **The capture returns both the PDF bytes and the engine output for the same case, computed in the
   same run** through `journey/engine.mjs`. No expected figure is read from a file and none is
   committed.

5. **The exit contract is the project's three-valued one.** A stopped Supabase stack, a failed build,
   a missing browser, a download that never arrives, or bytes that do not begin `%PDF-` are all exit
   `2` with the `PDF CAPTURE CANNOT RUN: ` prefix — never exit `1` and never exit `0`.

6. **`frontend/supabase/seed.sql` and `frontend/supabase/fixtures.json` are not edited.**
   `scripts/check-seed-fixture.mjs` rejects a seeded engine result with `SEED WRITES OUTPUT`, and the
   Alpha case is driven to a computed state by the existing `case-alpha-no-output` reset plus a real
   click.

7. **`frontend/test-baseline.json`, `gate-skips.lock`, `engine/defect-baseline.json`,
   `assertion-baseline.json` and `coverage-zero.lock` are read-only in this plan.**

8. **Commit explicit paths only** with `bash scripts/safe-commit.sh -m "<message>" <path> ...`.
   `git add -A`, `git add .` and `git commit -a` are prohibited.

9. **No point of Philippine law arises in this plan.** It clicks a button and reads the bytes that
   come back.

</constraints>

### `frontend/journey/pdf-capture.mjs`

```
export const PDF_FIXED_CLOCK = '2026-06-15T00:00:00Z';
export async function captureExportedPdf() -> { pdfBuffer, expected, input, caseId }
```

Setup, each failure being exit `2` at the caller with the `PDF CAPTURE CANNOT RUN: ` prefix. The
function itself throws `JourneyCannotRun` from `./serve.mjs`, which is the class the other journey
scripts already branch on:

1. `readStackEnv()` from `./session.mjs`; a null return or a missing `API_URL` cannot run.
2. `readFixtures()` from `./seed.mjs` supplies `orgs.alpha.case_id`.
3. `adminClient(env)` reads and resets rows.
4. `buildApp()` and `startPreview()` from `./serve.mjs`.
5. `launchBrowser()` from `./browser.mjs`, then `newJourneyPage(browser)`.

Sequence:

1. `await RESETS['case-alpha-no-output'](admin)` so the product must compute rather than redisplay.
2. Read `input_json` for the Alpha case; a null value cannot run.
3. `expected = await computeEngineOutput(input)` from `./engine.mjs`.
4. `await page.clock.setFixedTime(new Date(PDF_FIXED_CLOCK))`, then
   `await seedAuthSession(page, preview.origin, session)` with an `alpha` session from `getSession`.
5. `page.goto(<origin>/cases/<caseId>?step=4)`, wait for `[data-testid="review-step"]`, click
   `[data-testid="compute-distribution"]`, wait for `[data-testid="results-view"]`, settle 4000 ms —
   the same settle `journey/money-parity.mjs` uses.
6. Wait for `[data-testid="export-pdf"]`, then register `page.waitForEvent('download')` **before**
   clicking, and await both together with a 60000 ms timeout on the download.
7. `await download.path()`; a null path cannot run. `fs.readFileSync` the path into a `Buffer`.
8. Assert the buffer's first five bytes are `%PDF-` and its length exceeds 1000; a failure of either
   is `JourneyCannotRun`, because a zero-byte file that reached the assertions would let every later
   check pass vacuously.
9. Close the page, the browser and the preview in a `finally`, matching `journey/money-parity.mjs`.

The function returns the buffer, the parsed engine output, the parsed `input_json` and the case id.
It writes nothing to disk beyond what Playwright's download machinery does in its own temporary
directory.

### `frontend/journey/pdf-capture-probe.mjs`

Run from `frontend/`. No arguments. Calls `captureExportedPdf()` and checks four things:

| Check | Passes when |
|---|---|
| `CAPTURE BYTES` | the buffer begins `%PDF-` and exceeds 1000 bytes |
| `CAPTURE PAGES` | `pdfPageInfo(buffer).pages` is at least 1, and `widthPt` rounded is `595` and `heightPt` rounded is `842` |
| `CAPTURE TEXT` | `extractPdfText(buffer)` contains `Estate of Pedro` and `Distribution of Shares` |
| `CAPTURE FIXED DATE` | the extracted text contains `Report Generated: 2026-06-15` |

Output:

- one line per failing check naming what was expected and what was observed
- always, on stdout: `GATE-SKIPS total=4 skipped=0`
- pass path: `PDF CAPTURE PASS bytes=<n> pages=<n>` and exit `0`
- fail path: `PDF CAPTURE FAIL checks=4 failed=<k>` and exit `1`
- cannot-run path: `PDF CAPTURE CANNOT RUN: <reason>` on stderr and exit `2`

`CAPTURE FIXED DATE` is the check that proves the clock fix took effect; without it, plan `13-06`'s
zero-tolerance reference would silently expire after one day.

This probe is **not** registered as a gate. It is the on-demand proof of the shared module, the same
way `journey/seed-smoke.mjs` proves the seeding seam without being registered.
