<objective>
Produce a per-module coverage report for the Rust engine that names, module by module, the regions
and functions no test enters — and make its disappearance fail the build.

Measured during planning, in `06-RESEARCH.md` section 5: neither `cargo llvm-cov` nor
`cargo tarpaulin` is installed, and neither is needed. The rustup component `llvm-tools-preview`
installs cleanly on this stable 1.96.0 toolchain and supplies `llvm-profdata` and `llvm-cov` inside
the rustc sysroot. The whole pipeline was run end to end during planning and produced a per-module
table across 17 engine modules, 20427 regions, 952 of them uncovered. **No crate is added to
`engine/Cargo.toml`, `Cargo.lock` is not touched, and no npm package is installed.**

Two facts fix the design so the executor never has to choose:

1. **Rust's stable coverage instrumentation is region-based; the `Branches` column of
   `llvm-cov report` is empty on stable** because MC/DC branch counters require a nightly flag.
   COV-04's phrase "which branches no test exercises" is therefore implemented as "which coverage
   regions and which functions no test enters", which is the finer of the two granularities and is
   what `llvm-cov` itself calls a region.
2. **COV-04 asks for a report, not a threshold.** Picking a coverage percentage would be exactly the
   ungrounded decision this project forbids. The gate asserts only things that are grounded: the
   report can be produced, every engine module appears in it, and the set of modules at *exactly
   zero* coverage matches a shrink-only ledger. Measured today that set is exactly two:
   `src/main.rs` (the CLI) and `src/wasm.rs` (the `wasm_bindgen` boundary, unreachable natively).

This plan also performs the gate reordering both Phase 6 gates need. `06-RESEARCH.md` section 1.1
records that `scripts/ci-gates.sh` currently halts at `G3` (position 6 of 11) because of Phase 5's
unresolved OBS-05/OBS-06 product decision, so any gate ordered after `G3` would never execute.
`gates.manifest.lock` freezes only `{id, command, blocking}` and `GATES.md` section 1 states that
`order` is deliberately unlocked, so this plan shifts every existing gate down by two and places
`G12` at `order` 4, leaving `order` 5 for plan 06-05's `G13`. Both new gates are static or
engine-only and neither depends on the frontend suite.
</objective>

Create `scripts/coverage-report.sh`, a Bash script with `set -euo pipefail`, modelled on
`engine/build-wasm.sh` for structure and on `scripts/ci-gates.sh` for message style.

**Locate the toolchain without assuming `PATH`.** `llvm-profdata` and `llvm-cov` ship inside the
rustc sysroot, not on `PATH`. Resolve them as:

    HOST="$(rustc -vV | sed -n 's/^host: //p')"
    LLVM_BIN="$(rustc --print sysroot)/lib/rustlib/${HOST}/bin"

If `${LLVM_BIN}/llvm-profdata` is not executable, print
`COVERAGE TOOLCHAIN MISSING: install with rustup component add llvm-tools-preview` and exit 1. The
manifest `precondition` added in task 3 tests the same path, so the runner reports this as a
`cannot-run` halt before the gate is ever reached.

**Generate.** From `engine/`, into `.gate-runs/coverage/` at the app root, which is already
gitignored by the `.gate-runs/` entry in `.gitignore`:

    rm -rf .gate-runs/coverage
    mkdir -p .gate-runs/coverage/profraw
    RUSTFLAGS="-C instrument-coverage" \
    LLVM_PROFILE_FILE="<abs>/.gate-runs/coverage/profraw/cov-%p-%m.profraw" \
    CARGO_TARGET_DIR="<abs>/.gate-runs/coverage/target" \
      cargo test --tests

Then merge with `"${LLVM_BIN}/llvm-profdata" merge -sparse <profraw>/*.profraw -o cov.profdata`, and
export with `"${LLVM_BIN}/llvm-cov" export -instr-profile=cov.profdata -format=text` passing one
`-object` argument per executable found directly under the instrumented `target/debug/deps`,
excluding names ending in `.d` and `.so`. Use `-ignore-filename-regex='(/\.cargo/|/rustc/)'`.

Write the raw export to `.gate-runs/coverage/export.json`. Then, with `node -e` using only `node:`
builtins, reduce it into `.gate-runs/coverage/summary.json` with this exact shape:

    {
      "generated_at": "<ISO8601>",
      "modules": [
        { "file": "src/step7_distribute.rs",
          "regions_total": 3015, "regions_uncovered": 114,
          "functions_total": 126, "functions_uncovered": 9,
          "lines_total": 1528, "lines_uncovered": 65,
          "uncovered_function_names": ["...", "..."] }
      ]
    }

Include only files whose path contains `engine/src/`, keyed by the path relative to `engine/`, so
test files do not appear as modules. Sort by `file`.

**Also write the committed human report** `engine/COVERAGE.md`, containing: a generated-on line, the
command that regenerates it, a markdown table of every module with its region, line and function
counts and uncovered counts, and for every module with at least one uncovered function a
`### Uncovered functions — <module>` section listing those function names. A short header states
that the `Branches` column of `llvm-cov report` is empty on stable Rust because stable
instrumentation is region-based, and that regions are the granularity this report uses.

On success print `COVERAGE REPORT WRITTEN — <n> engine modules` and exit 0.

**Four verdicts, each with its own literal marker, all collected before exiting once:**

1. `COVERAGE REPORT UNAVAILABLE` — the summary file is absent or unparseable, or its `modules` array
   is empty. Print the resolved path. Do not exit 0 on an internal error.
2. `MODULE ABSENT FROM REPORT` — a `.rs` file exists under `engine/src/` that has no entry in
   `modules`. Report every missing module, not only the first. A module silently absent from a
   coverage report is the failure mode a coverage report exists to prevent.
3. `UNDECLARED ZERO COVERAGE` — a module whose `regions_uncovered` equals `regions_total` and whose
   `file` is not listed in `coverage-zero.lock`. Report the module and the region count.
4. `STALE ZERO COVERAGE DECLARATION` — a `coverage-zero.lock` entry whose module now has at least
   one covered region, or which no longer exists under `engine/src/`. This is the direction that
   forces the ledger down: the day a module gains its first test, its declaration must go with it or
   this gate turns red.

**Output on success:** one line in the shape
`COVERAGE OK — <n> engine modules, <z> at zero coverage, all declared`, then a second line
`GATE-SKIPS total=<n> skipped=0` where `<n>` is the module count. Print the `GATE-SKIPS` line on
**every** exit path, success and failure alike, immediately before exiting — gate `G8` fails with
`SKIP REPORT MISSING` on a log that lacks it.

**Exit codes:** 0 only with zero violations, 1 otherwise. No other exit code. All matching is
literal string comparison, never a regular expression.
