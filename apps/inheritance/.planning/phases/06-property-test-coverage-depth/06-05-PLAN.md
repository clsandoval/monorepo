<objective>
Make a test that asserts nothing, or that asserts only `toBeDefined` or `toBeTruthy`, fail the
build.

Measured during planning, in `06-RESEARCH.md` section 6: a brace-matched body scanner over
`frontend/src` located **112** test files and **2383** `it` or `test` blocks. **Zero** assert
nothing. **Fifteen** have `toBeDefined` or `toBeTruthy` as their only matcher; every one of the
fifteen was opened and read, and all fifteen are true positives. They are enumerated verbatim in
section 6.2 and reproduced in task 2 of this plan.

Fifteen offenders means the gate is red on day one, and neither escape is available: weakening the
gate is prohibited, and rewriting fifteen tests would require, per test, deciding what the stronger
assertion should be. Several of those are genuine product questions — what a money input should do
with the text `abc` is one — and three of the fifteen sit on top of Phase 5's unresolved
OBS-05/OBS-06 product decision. Fifteen judgment calls handed to a cheap executor is the exact
failure mode this project exists to prevent.

So the gate ships with a **shrink-only ledger**, the identical mechanism, key shape and prohibition
language as `frontend/test-baseline.json`, which Phase 1 chose for the same reason. A sixteenth
weak-only test fails the build. A ledger entry that no longer matches a real test fails the build,
which is what forces the ledger down as those fifteen are strengthened.

The check is a **static source scan**. It reads test files and never runs Vitest, so it passes
independently of gate `G3`, which Phase 5 leaves red. Plan 06-04 already shifted the manifest and
reserved `order` 5; this plan takes it, placing `G13` ahead of `G1`.
</objective>

Create `scripts/check-assertion-discipline.mjs`, a Node ESM script importing only `node:fs` and
`node:path`. Read `scripts/check-coverage.mjs` first and follow its shape exactly: resolve default
paths from the script's own location, collect every violation into an array, print all of them, then
exit once.

**Two read-only path overrides and no other flag:** `--root` (default `frontend/src`) and
`--ledger` (default `assertion-baseline.json`).

**Discovery.** Walk `--root` recursively, skipping any directory named `node_modules`, `dist` or
`.git`, and collect every file matching `*.test.ts` or `*.test.tsx`.

**Block extraction, specified literally because a naive regex is not accurate enough.** A first
attempt during planning mis-parsed matchers nested inside `expect(...)` arguments; the technique
below was validated against the real corpus and agreed with a by-eye reading of all fifteen hits.

- Locate each block opener with
  `/(?:^|[^.\w])(it|test)\s*(?:\.(?:each\s*\(?[\s\S]*?\)?|concurrent|sequential))?\s*\(\s*(['"`])([\s\S]*?)\2/g`.
  Capture group 3 is the test name.
- From the opening parenthesis of that call, scan forward tracking parenthesis depth and string
  state, honouring `'`, `"` and backtick delimiters and backslash escapes. The first `{` seen at
  depth 1 is the callback body start; the parenthesis that returns depth to 0 is the body end.
- The body is the substring between them. Advance the outer regex past the body end so nested
  blocks are not double-counted.

**Matcher extraction.** Over the body, collect the unique set of matcher names from
`/\.\s*(to[A-Z]\w*)\s*\(/g`. Do not attempt to pair each matcher with its `expect(`; pairing is what
made the first attempt inaccurate, and the set is what the verdicts need.

**Weak set:** exactly `toBeDefined` and `toBeTruthy`, as a top-level `const` so the list is
auditable in one place.

**Four verdicts, each with its own literal marker, all collected before exiting once:**

1. `ASSERTION-FREE TEST` — a block whose matcher set is empty and whose body contains none of the
   literals `expect(`, `assert`, `toMatchSnapshot` or `toMatchInlineSnapshot`. Report the file, the
   line and the test name. There is no ledger for this verdict: the measured count today is zero and
   a test that asserts nothing is never acceptable.
2. `UNDECLARED WEAK ASSERTION` — a block whose matcher set is non-empty and every member of which is
   in the weak set, and which has no matching ledger entry. Report the file, the line, the test name
   and the matchers found.
3. `STALE WEAK DECLARATION` — a ledger entry whose `file` plus `fullName` pair matches no block that
   the scan classified as weak-only. This is the direction that forces the ledger down: the day one
   of the fifteen gains a real assertion, its declaration must go with it or this gate turns red.
4. `ASSERTION SCAN UNREADABLE` — the ledger is missing or unparseable, or the root directory does
   not exist. Print the message and exit 1 immediately. Never exit 0 on an internal error.

**Ledger matching is by `file` plus `fullName`, never by line number**, because line numbers move
whenever anything above a test is edited and a line-keyed ledger would produce false failures on
unrelated changes. `file` is the path relative to `frontend/`. `fullName` is the block's own name
string exactly as it appears in the source, unescaped.

**Output on success:** one line in the shape
`ASSERTION DISCIPLINE OK — <f> files, <b> blocks, 0 assertion-free, <w> weak-only all declared`,
then a second line `GATE-SKIPS total=<b> skipped=0` where `<b>` is the block count. Print the
`GATE-SKIPS` line on **every** exit path, success and failure alike, immediately before exiting.

**Exit codes:** 0 only with zero violations, 1 otherwise. No other exit code.

**Then create three fixtures** under `scripts/fixtures/`. They end in `.test.ts` but live outside
`frontend/src`, so Vitest never collects them:

| Fixture | Content | Drives |
|---|---|---|
| `assert-none.test.ts` | one `it('does nothing', () => { const x = 1; })` block with no matcher and no `expect(` | `ASSERTION-FREE TEST` |
| `assert-weak-only.test.ts` | one `it('only weak', () => { expect(v).toBeDefined(); })` block | `UNDECLARED WEAK ASSERTION` |
| `assert-strong.test.ts` | one `it('strong', () => { expect(v).toBe(3); })` block plus one nested `describe` wrapping a second strong block, so the block-extraction logic is exercised on nesting | passes cleanly, and confirms the scanner does not report a false positive |

Drive `ASSERTION SCAN UNREADABLE` by passing `--ledger` a path that does not exist.
