# Trending-repo noise detection

Not yet started — scoped 2026-07-05, deferred to a future session. Run the diagnostic first: give
him real trending repos, watch how he sorts signal from noise, and reverse-engineer the taxonomy he's
already applying so it becomes an explicit, teachable checklist. Then drill it with fresh reps.

## The taxonomy (extracted from HIS reasoning, 2026-07-05)
1. **Classify artifact TYPE first** (tool / framework / aggregator / demo / manifesto) — judge each on
   category-appropriate criteria. Docking an aggregator for "not producing work" is a category error.
2. **Signal vs noise = the NOVELTY GAP.** NOT "new algorithm?" but "new value on ANY axis — mechanism,
   ergonomics, integration, distribution — or just a new label?" A wrapper that kills real friction is
   signal (browser-use); "we present a new framework for X" that re-solves a solved problem is noise
   ("reinventing calculus"). Tell: strip the framing, find the value or its absence.
3. **Risk** (orthogonal) — signal can still be dangerous (autonomous action surface, broad perms).
4. **Significance-over-time** (orthogonal) — architecturally stale can still be a landmark (OpenClaw).

NOTE: this is the SAME critic reflex as [[agentic-harnesses]] ("why skills instead of files?" = find
the mechanism). One skill, two targets.
