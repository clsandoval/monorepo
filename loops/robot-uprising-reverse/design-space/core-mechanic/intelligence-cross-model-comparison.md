# 2.00k — Cross-Model Comparison Matrix: Formal Evaluation of All Intelligence Models

## The Question

Four intelligence models have been explored: Fully Deterministic (2.00a), Simulated Intelligence (2.00b), Hybrid LLM Enhancement (2.00c), and LLM-Native (2.00d). Each represents a fundamentally different answer to "how do agents think?" This document evaluates all four across 10 critical dimensions — not to pick a winner, but to map which model excels WHERE, making the trade-offs concrete enough that a design team can make an informed choice (or, more likely, identify which hybrid approach captures the best of each).

---

## The Ten Dimensions

| # | Dimension | What It Measures |
|---|-----------|-----------------|
| 1 | **Debuggability** | Can the player trace exactly WHY an agent did what it did? |
| 2 | **Spectator Drama** | Does watching the sealed watch create compelling emotional arcs? |
| 3 | **Personality Ceiling** | How human/alive can agents feel to the player? |
| 4 | **Educational Transfer** | How directly do skills learned in-game transfer to real AI engineering? |
| 5 | **Async PvP Fairness** | Can two players' configs compete when one player is offline? |
| 6 | **Computational Cost** | What does the game cost to run per session (client-side + API)? |
| 7 | **Accessibility Floor** | How approachable is the game for a total beginner? |
| 8 | **Skill Ceiling** | How deep is mastery — how much better can the best player get? |
| 9 | **Mod Support** | How easily can the community extend/modify the game? |
| 10 | **Platform Portability** | How many platforms can the game run on without modification? |

## Dimension 1: Debuggability

**The question:** When a player's agent does something unexpected, how quickly and completely can they understand why?

### 2.00a — Fully Deterministic: ★★★★★

Perfect debuggability. The Inspector can show the exact rule that fired, the exact buffer contents that matched the condition, the exact signal that populated that buffer slot, and the exact chain of hooks that delivered the signal. Every causal link is traceable. The decision trace is a proof, not an approximation.

**The player experience:** Click on Scout-1 at tick 12. The decision trace shows: "Rule 2 matched. Condition: `buffer contains enemy_spotted AND distance > 3`. Evaluated against: slot 3 = enemy_spotted(B5, T10), distance = 4. Action: EVADE." Every element is deterministic, reproducible, and falsifiable. The player can mentally replay the tick and confirm "yes, that's what I programmed." If the result is wrong, the fix is in the configuration, not in a black box.

**The vulnerability:** The system is SO transparent that advanced players can develop "analysis paralysis" — spending more time in the Inspector proving WHY something happened than designing better architectures. The debuggability is a feature when learning, potentially a trap when competing.

### 2.00b — Simulated Intelligence: ★★★★☆

Same deterministic core = same trace quality. But the presentation layer (personality names, micro-animations, character voice in the Inspector) can OBSCURE the mechanical truth. When the Inspector says "Kestrel panicked and fled," the player has to mentally translate: "Scout-1's Rule 1 matched because buffer slot 2 contained a threat entry at distance 2." The character layer is a veneer over perfect determinism — helpful for emotional engagement, occasionally misleading for diagnosis.

**The vulnerability:** A player who diagnoses in character-voice mode ("Kestrel always panics in this situation") may miss the mechanical truth ("Rule 1's distance threshold is 2, not 3"). The personality layer creates false mental models. The toggle between character and technical view in the Inspector mitigates this but doesn't eliminate it.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆

The deterministic execution core is fully debuggable (same as 2.00a). But the LLM enhancement layer introduces a new kind of "why" question: "Why did the LLM suggest this configuration?" If the player used natural language blueprint authoring ("I want a scout that runs from danger"), the resulting rules were generated by an LLM and may not be intuitive. The player debugs the rules, not the LLM's generation process. This creates a gap: the rules are transparent, but the authoring intent is opaque.

**The player experience:** Scout-1 fled instead of reporting. The player checks the Inspector — Rule 1: `IF enemy_spotted AND distance < 3 THEN EVADE`. But the player told the LLM "I want a scout that runs from danger" and expected it to mean "run from groups of 3+", not "run from any enemy within 3 tiles." The bug is in the translation from natural language to rules, and the Inspector can't show that translation because the LLM config generation happened in the planning phase, not the execution phase.

**The mitigation:** The LLM authoring step shows the generated config BEFORE deployment, with diff highlights. The player approves (or modifies) every rule. The gap exists between "what I said" and "what it generated," but the player has a checkpoint to catch mismatches.

### 2.00d — LLM-Native: ★★☆☆☆

Fundamentally compromised. The LLM's chain-of-thought is visible in the Inspector, yes — but the reasoning trace is a POST-HOC narrative, not a mechanical proof. When the LLM writes "I chose to evade because the threat was too close," the player cannot verify this is the ACTUAL reason the LLM chose evade. The LLM might have actually weighted token frequency in the prompt, or the attention mechanism might have focused on a different part of the context. The chain-of-thought is a story the LLM tells about its decision, not a deterministic trace OF the decision.

**The player experience:** Scout-1 fled. The reasoning trace says: "Enemy at B5, distance 2. Standing orders say to avoid combat. I'll evade to A6." This LOOKS debuggable. But the player can't falsify it — they can't prove that "standing orders" was the actual causal factor vs. "distance 2" vs. some other token interaction. If the player changes the standing orders and the scout STILL flees, was it because of the temperature setting? The context window contents? The specific token sequence? Debugging becomes hypothesis testing against a black box.

**The vulnerability:** The debugging loop in LLM-native is: change prompt → re-run → observe outcome → hypothesize → change prompt again. This IS real AI engineering debugging (prompt engineering is exactly this). But it's also slower, less certain, and more frustrating than the deterministic model's "read the trace, find the bug, fix the rule."

## Dimension 2: Spectator Drama

**The question:** Is the sealed watch emotionally compelling? Does the viewer (player or stream audience) feel tension, surprise, and narrative?

### 2.00a — Fully Deterministic: ★★★☆☆

Same config + same seed = same outcome. On first watch, the tension is real — the player doesn't know what will happen. But on replay (same mission, same config), the outcome is identical. The "invisible randomization" mechanic (each execute varies within constraints) helps, but within a single run, the sealed watch is a predetermined movie. The player is watching something that was already decided the moment they hit EXECUTE.

**The drama source:** Emergent behavior from agent interaction. The player designed the pieces, and the collision of those pieces produces surprises. But the surprises are structural (unexpected interactions between rules), not behavioral (an agent "deciding" something novel). Once the player understands their own architecture well enough, the surprises diminish.

**Spectator experience:** A stream viewer sees clean, legible action. Signal chains fire, units move, combat occurs. It's satisfying like watching a Rube Goldberg machine — the pleasure is in the unfolding of a designed system. But there's limited narrative tension because the system is visibly mechanical.

### 2.00b — Simulated Intelligence: ★★★★☆

Same deterministic outcome, but the presentation layer injects narrative. Micro-animations make units appear to hesitate, react, and deliberate. Personality names create characters. The sealed watch feels like watching characters act rather than watching a machine execute. Kestrel's "panic" animation when buffer fills, Kris's "determination" lean when receiving a strike order — these are cosmetic, but they transform the emotional register.

**The drama source:** Character identification + emergent behavior. The viewer anthropomorphizes the units. "Kestrel just dodged that — she's so smart!" (She's not. Rule 1 matched.) The drama is real for the viewer even though it's simulated for the system. This is the Pac-Man ghost effect at scale.

**Spectator experience:** Stream viewers will pick favorites. "Kestrel dies a lot, someone protect her." This is engagement that deterministic designator-only presentation can't generate.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆

Same as 2.00a/2.00b during the sealed watch (execution is deterministic). The LLM enhancement only operates during planning and debrief. The drama is identical to whichever presentation layer is used (character names or designators). The hybrid doesn't add or subtract from the sealed watch.

### 2.00d — LLM-Native: ★★★★★

Maximum drama. The LLM introduces genuine unpredictability — even the player who designed the system prompt doesn't know exactly what the agent will do THIS tick. Temperature > 0 means the agent's behavior varies between runs. The sealed watch is a genuinely uncertain event. The player is watching autonomous agents make real-time decisions that they can't predict.

**The drama source:** Authentic unpredictability + legible reasoning. The chain-of-thought (visible in debrief) gives the drama a narrative structure: "At tick 8, Kestrel *reasoned* that the threat was ambiguous and chose to hold position. At tick 9, the threat materialized and Kestrel's next reasoning said 'I should have retreated.'" The agent expresses regret. The agent has inner life. The drama is real.

**Spectator experience:** Stream viewers react to reasoning traces. "Chat, look at what Kestrel was thinking! She KNEW the enemy was there and she waited anyway!" This is Maximum Entertainment.

**The vulnerability:** Unpredictability means the player can't learn from the sealed watch alone. If the same config produces different outcomes on different runs, the "what did I do wrong?" question has no clean answer. Drama trades off against learnability.

## Dimension 3: Personality Ceiling

### 2.00a — Fully Deterministic: ★☆☆☆☆
Agents are designators. No personality. Scout-1 is a config, not a character.

### 2.00b — Simulated Intelligence: ★★★★☆
Rich presentation personality — names, micro-animations, character voice, personality archetypes. But the ceiling exists: the personality is a rendering of deterministic behavior. A perceptive player sees through it. "Kestrel doesn't panic — Rule 1 fires when distance < 3."

### 2.00c — Hybrid LLM Enhancement: ★★★☆☆
Same as 2.00b for presentation. The LLM enhancement could add richer character text (generated personality descriptions, procedural backstories), but the agent's in-battle behavior is still deterministic.

### 2.00d — LLM-Native: ★★★★★
No ceiling. The agent's personality is the system prompt. A player who writes "You are a cautious, paranoid scout who trusts nobody" gets genuinely cautious, paranoid behavior — not because a rule says `IF threat THEN evade` but because the LLM interprets every situation through that personality lens. The agent might refuse to share intelligence with an ally it "doesn't trust" even though sharing would be tactically optimal. The personality is load-bearing, not cosmetic.

## Dimension 4: Educational Transfer

### 2.00a — Fully Deterministic: ★★★☆☆
Teaches: rule composition, priority ordering, signal routing, buffer management, deterministic debugging. These are real engineering skills — but they map more closely to embedded systems / state machines than to modern AI engineering. The vocabulary is 1:1 (rules, hooks, context) but the execution model is pre-AI.

### 2.00b — Simulated Intelligence: ★★★☆☆
Same as 2.00a mechanically. The presentation layer doesn't add educational transfer — it adds emotional engagement. The player learns the same deterministic skills but through character narrative rather than raw data.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆
Teaches deterministic systems (same as 2.00a) PLUS prompt engineering (natural language config authoring), context window management (same concept applied to real LLMs), and the "two-tier architecture" pattern (deterministic core + LLM enhancement layer) that is standard in production AI systems. The player learns BOTH paradigms — deterministic rules AND LLM integration.

### 2.00d — LLM-Native: ★★★★★
Maximum educational transfer. The player IS doing agentic AI engineering. Writing system prompts, managing context windows, tuning temperature, budgeting tokens, debugging chain-of-thought — every skill is directly transferable to building real AI agents. A player who masters Robot Uprising's LLM-native mode could sit down with an LLM API and immediately apply their skills. The game isn't teaching METAPHORS for AI engineering — it's teaching AI engineering.

**The caveat:** Educational transfer is only valuable if the player can learn it. If the debugging loop is too opaque (Dimension 1), the player might learn "prompt engineering is frustrating guesswork" instead of "prompt engineering is a disciplined craft." The quality of transfer depends on the quality of debugging tools.

## Dimension 5: Async PvP Fairness

### 2.00a — Fully Deterministic: ★★★★★
Perfect fairness. Both players' configs run against each other with the same seed. Same inputs → same outputs. No variance. The match result is a mathematical fact about the two configs' interaction. Async PvP is trivially fair.

### 2.00b — Simulated Intelligence: ★★★★★
Same deterministic core = same perfect fairness. The personality layer is cosmetic and doesn't affect match resolution.

### 2.00c — Hybrid LLM Enhancement: ★★★★★
Execution is deterministic. LLM enhancement is planning-only. Async PvP fairness is identical to 2.00a.

### 2.00d — LLM-Native: ★★☆☆☆
Problematic. Temperature > 0 means the same config can produce different outcomes. If Player A's match was resolved when the LLM was "feeling creative" (high-variance token sampling) and Player B's match was resolved during a low-variance moment, the results aren't comparable. Even with temperature = 0, LLM inference isn't perfectly deterministic across API versions, hardware, or batching conditions.

**Mitigations:**
- Force temperature = 0 in PvP (removes personality variance, undermining the model's appeal)
- Run both sides of the match on the same LLM call batch (reduces but doesn't eliminate variance)
- Run 10 matches and aggregate (expensive, slow)
- Accept variance as a feature ("the agent's creativity is part of their strength")

None fully solve the fairness problem. Competitive players will perceive LLM variance as "RNG decided my match" — identical to the frustration card game players feel about draw order.

## Dimension 6: Computational Cost

### 2.00a — Fully Deterministic: ★★★★★
Zero API cost. Runs entirely client-side. A 30-tick match with 8 units requires ~240 rule evaluations — trivial for any modern browser. The game runs on a Chromebook. Works offline. Works forever.

### 2.00b — Simulated Intelligence: ★★★★★
Same as 2.00a. The personality layer is client-side rendering (animations, text templates). No additional computation.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆
The deterministic execution is free. The LLM enhancement features cost API tokens during PLANNING only — and are opt-in. A player who never uses natural language authoring or LLM debrief analysis pays nothing. A power user who uses the LLM heavily might spend $0.10-$0.50 per session (rough estimate based on current API pricing for mid-tier models).

### 2.00d — LLM-Native: ★☆☆☆☆
Expensive. Every agent, every tick, calls the LLM. A 30-tick match with 8 units = 240 LLM calls. Even with small models (Haiku-tier), at ~200 tokens per call, that's ~48,000 tokens per match. At current pricing (~$0.25/M input tokens for fast models), that's ~$0.01 per match. Cheap — but at scale (100 matches/day for competitive players), it's $1/day per player. And token costs for larger models (Sonnet/Opus tier reasoning) would be 10-40x higher.

**The infrastructure burden:** The game needs a backend. API keys. Token accounting. Rate limiting. Server infrastructure. The locked tech spec says "no backend" — LLM-native directly contradicts this. Either the player provides their own API key (friction, cost concern) or the game developer operates the backend (operational cost, scaling challenge).

## Dimension 7: Accessibility Floor

### 2.00a — Fully Deterministic: ★★★★☆
Rules and hooks are learnable. The boot log tutorial teaches each concept. The learning curve is similar to Gladiabots — approachable for casual players, with depth for experts. The accessibility floor is a drag-and-drop rule editor and a simple hook wiring interface. No programming knowledge required.

The ceiling for beginners: understanding rule ORDERING. The priority system (first matching rule wins) is intuitive for programmers but can confuse non-programmers who expect all matching rules to fire. Requires tutorial design attention.

### 2.00b — Simulated Intelligence: ★★★★★
Highest accessibility. The character layer gives beginners an emotional entry point ("I want Kestrel to be safe") that translates to a mechanical action ("set Kestrel's Rule 1 to evade at distance 3"). The personality archetypes provide TEMPLATES — the beginner doesn't start from blank; they pick "cautious scout" and modify from there. The micro-animations make the sealed watch legible without Inspector knowledge.

### 2.00c — Hybrid LLM Enhancement: ★★★★★ (for players with API access)
Natural language authoring removes the biggest barrier: "I want a scout that runs from danger" is more accessible than dragging condition→action pairs into a priority queue. But API access is a gate — players without an API key (or money for tokens) can't use the LLM features and fall back to 2.00a's accessibility level.

### 2.00d — LLM-Native: ★★☆☆☆
Paradoxically harder. Writing effective system prompts is a SKILL — not an intuitive one. "Make a good scout" as a system prompt produces mediocre results. The player needs to learn prompt engineering to play the game well. For a total beginner, writing "Be a cautious scout who reports enemies on channel alpha and evades threats within 2 tiles" is harder than dragging a rule strip that says `IF enemy AND distance < 2 THEN evade`.

The failure mode: the beginner writes a vague prompt, the agent behaves erratically, the chain-of-thought is unhelpful ("I decided to idle because nothing seemed urgent"), and the beginner doesn't know what to fix. The debugging loop (Dimension 1) is opaque, compounding the accessibility problem.

## Dimension 8: Skill Ceiling

### 2.00a — Fully Deterministic: ★★★★☆
High ceiling within the system. Mastery = optimal rule ordering, perfect buffer management, elegant signal architectures, minimal-resource configs. The Zachtronics-style optimization space is deep. But the ceiling EXISTS — a sufficiently advanced player can solve any mission provably optimally, and once solved, it's solved forever (Dimension 2 concern).

### 2.00b — Simulated Intelligence: ★★★★☆
Same mechanical ceiling as 2.00a. The personality layer doesn't add strategic depth. But it adds EXPRESSIVE ceiling — the best player's configs produce the most dramatically satisfying sealed watches. Optimization for efficiency AND for spectacle.

### 2.00c — Hybrid LLM Enhancement: ★★★★★
Combines the deterministic ceiling (same mechanical depth) with the meta-skill of effective LLM collaboration. The best players use the LLM to generate configs faster, explore the design space wider, and debug more creatively — then hand-optimize the deterministic rules for final precision. Two skill axes: architectural mastery AND tool mastery.

### 2.00d — LLM-Native: ★★★★★
Infinite ceiling. Prompt engineering has no known skill cap. A better prompt always produces better results. Temperature tuning, context curation, standing order optimization, token budget allocation — each is a continuous skill axis. And the game's meta-level (building agents that manage other agents) is unlimited: a command agent's system prompt can describe arbitrarily complex management strategies.

**The caveat:** Infinite ceiling means infinite frustration. The player can always feel "my prompt isn't good enough." There's no moment of "I solved it" (as in deterministic) — only "it's working better but could be better." The satisfaction profile is different: continuous improvement vs. discrete solutions.

## Dimension 9: Mod Support

### 2.00a — Fully Deterministic: ★★★★★
Everything is local, client-side, and data-driven. Modders can add new skills, rules, hook types, unit types, terrain, missions — all by editing config files. No API keys, no backend access needed. The modding community can create total conversions. Workshop support is straightforward.

### 2.00b — Simulated Intelligence: ★★★★★
Same as 2.00a, plus modders can create new personality archetypes, micro-animation sets, character names, and voice text. The personality layer is data-driven (text templates, animation configs). Modding the personality is as easy as modding the mechanics.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆
Deterministic core: same great mod support as 2.00a. LLM enhancement: harder to mod. The LLM integration requires API access, and modders can't easily modify the LLM's behavior (they can modify the prompts, but not the model). Custom LLM modules (e.g., "use a local Llama model instead of Claude") require technical sophistication beyond most modders.

### 2.00d — LLM-Native: ★★☆☆☆
Modding the game means modding the LLM integration. Adding a new unit type requires defining its prompt template, fallback rules, and token budget — possible but requires understanding of both game design and AI engineering. The modding floor is much higher than deterministic. And any mod that changes the execution model (e.g., "my mod uses GPT-4 instead of Claude") creates compatibility and fairness concerns.

## Dimension 10: Platform Portability

### 2.00a — Fully Deterministic: ★★★★★
Runs anywhere with a browser. No internet required. Mobile, tablet, Steam Deck, school Chromebook, airplane mode. The locked tech stack (React + Pixi.js + Vite, no backend) is designed for this.

### 2.00b — Simulated Intelligence: ★★★★★
Same as 2.00a. Additional rendering (micro-animations) is trivial for any device that handles Pixi.js.

### 2.00c — Hybrid LLM Enhancement: ★★★★☆
Deterministic mode works everywhere. LLM enhancement requires internet + API access. The game gracefully degrades: offline = 2.00a mode, online = 2.00c mode. Mobile usability is slightly reduced for natural language input (typing prompts on phone keyboards is slower than drag-and-drop rule editing).

### 2.00d — LLM-Native: ★☆☆☆☆
Requires internet, always. Every tick needs an API call. Latency matters — a 200ms API call means a 30-tick match takes 6+ seconds of pure API wait time (sequential) or requires parallel batching infrastructure. Mobile data costs compound token costs. Airplane mode = unplayable. School Chromebook behind a firewall = unplayable. The "no backend" constraint is violated.

## Key Insights from the Matrix

### Insight 1: Simulated Intelligence is the Quietly Best Option

2.00b scores highest overall (43/50) despite having the same mechanical core as 2.00a. The personality presentation layer adds no computational cost, no platform limitation, and no debugging complexity — but it dramatically improves spectator drama, accessibility, and personality ceiling. It's free emotional engagement.

**The design lesson:** Investing in how the deterministic system is PRESENTED is higher-ROI than changing how it WORKS. A $0 rendering improvement (names, micro-animations, character voice) adds more player value than a $100k LLM infrastructure investment.

### Insight 2: The Hybrid (2.00c) is the "Correct" Answer for Shipping

2.00c captures most of the educational transfer benefit of LLM-native (the player DOES interact with an LLM, just in the planning phase) while preserving the deterministic core's advantages (debuggability, fairness, portability, cost). The opt-in nature means the game works for everyone (deterministic fallback) while offering depth for those who want it.

The combination of 2.00b's presentation layer ON TOP of 2.00c's architecture — Simulated Intelligence aesthetics with Hybrid LLM Enhancement for planning — scores effectively 45+/50. This is the maximum-coverage design.

### Insight 3: LLM-Native is Educationally Superior but Practically Impossible

2.00d wins Educational Transfer and Personality Ceiling and Skill Ceiling — the three dimensions most aligned with Robot Uprising's pitch ("you are doing real AI engineering"). But it fails on five practical dimensions: cost, portability, debugging, fairness, and modding. The game's locked constraints (no backend, web-based, Playwright-testable) are directly contradicted by LLM-native.

**The design tension:** The game WANTS to be 2.00d (that's the fantasy). The game MUST be 2.00a/b/c (that's the reality). The hybrid (2.00c) is the bridge: deterministic execution satisfies the constraints, LLM enhancement delivers the fantasy in the planning phase.

### Insight 4: The "Best" Model Depends on the Configuration

The five game configurations from 8.03 map to models:
- **The Clockwork** → 2.00a (pure determinism, maximum debugging)
- **The Greenhouse** → 2.00b (simulated intelligence, character layer, warmth)
- **The War Room** → 2.00a with 2.00c's analytical LLM tools (deterministic execution + LLM debrief assistance)
- **The Laboratory** → 2.00c or 2.00d (experimentation, LLM exploration)
- **The Arcade Cabinet** → 2.00b (character presentation for casual accessibility)

If the game ships with configuration mixing (8.03a), the intelligence model could VARY by mode — Greenhouse uses 2.00b's personality layer, War Room uses 2.00a's raw designators, Laboratory optionally enables 2.00c's LLM enhancement. The models aren't exclusive; they're layers.

## Player Journeys: The Same Scenario Across All Models

### The Scenario

Mission 5. Factory just introduced. Player has a scout, relay, and two strikers. Enemy wave from the north. The scout spots the enemies, sends a signal, but the relay's buffer is full — the signal is lost. The strikers don't receive threat data. An enemy reaches the base.

#### Journey: 2.00a — Fully Deterministic

**The Sealed Watch:** Tick 14. Scout sends signal (cyan line). Relay's context bar is full (red). Signal arrives — overload. CRACK. Relay stuns. No forward signal. Strikers patrol obliviously. Enemy reaches base.

**The Inspector:** Player clicks relay at tick 14. Decision trace: "All 12 buffer slots occupied. Incoming signal: enemy_spotted(C4). Eviction policy: FIFO. Evicted: patrol_data(A1, T3). Buffer now: 11 filled + enemy_spotted(C4). But processing delay from eviction = 1 tick stun." The player sees the problem: stale patrol data filled the buffer. Fix: add an eviction rule that drops patrol data when threat data arrives.

**The feeling:** Clinical. Precise. Satisfying. Like fixing a failing unit test.

#### Journey: 2.00b — Simulated Intelligence

**The Sealed Watch:** Tick 14. Kestrel sends signal (cyan line). Monsoon (the relay) is visibly stressed — static lines, tremor. The signal arrives. Monsoon overloads — CRACK, lightning, the satellite dish sprite droops. Monsoon's "overwhelmed" idle animation plays during the stun tick: dish spinning erratically, small smoke particles. Kestrel's micro-animation shifts to "confused" — dish tilts, scanning for acknowledgment that never comes. Kris and Bolo (strikers) continue patrol, oblivious. Kris passes within 2 tiles of the enemy without reacting — he doesn't know it's there. Enemy reaches base.

**The Inspector:** Player clicks Monsoon. Character voice: "Monsoon was overwhelmed by incoming data and shut down for one tick. By the time it recovered, the threat window had passed." Below, the technical trace: same as 2.00a. The player reads both — the character voice for emotional context, the technical trace for the fix.

**The feeling:** Personal. The relay FAILED you. It had a name and it let you down. The fix is the same (eviction rules), but the motivation is different: "I need to help Monsoon handle more data" vs. "I need to fix the eviction policy."

#### Journey: 2.00c — Hybrid LLM Enhancement

**The Sealed Watch:** Same as 2.00a or 2.00b (deterministic execution).

**The Inspector:** Same technical trace. But additionally, the LLM enhancement offers: "I noticed your relay overloaded at tick 14. Would you like me to suggest an eviction policy?" The player clicks yes. The LLM generates: "Suggested eviction: Priority-weighted — threat data persists, patrol data evicted first, oldest entries break ties." The suggestion appears as a proposed edit in the workbench — green highlighting showing what would change. The player reviews, accepts or modifies, and redeploys.

**The feeling:** Collaborative. The game didn't just show the problem — it offered a solution. The player still makes the final decision (accepting or rejecting the suggestion), but the diagnostic-to-fix friction is dramatically reduced.

#### Journey: 2.00d — LLM-Native

**The Sealed Watch:** Tick 14. Scout sends signal. Relay receives it — but the relay's LLM reasoning says: "My buffer is very full. This new signal is about an enemy at C4, but I have 12 items already and I'm not sure which to drop. Let me... think about this." The relay hesitates for one tick (reasoning consumed the entire tick's token budget). By tick 15, the relay has "decided" to forward the signal — but the enemy has already moved. The striker receives stale data.

**The feeling:** Fascinating but frustrating. ## Comparable Games

- **Gladiabots → 2.00a:** Fully deterministic visual programming. No personality. Pure engineering satisfaction.
- **Screeps → 2.00a:** JavaScript programming, deterministic execution. No character layer.
- **Creatures (1996) → 2.00d:** Virtual life with neural networks. Agents learned and evolved. Personality was genuine (neural net outputs), not simulated. The debugging problem (WHY did my Norn do that?) was equally opaque.
- **Black & White → 2.00b:** The Creature learned from player gestures and displayed personality through animation. Deterministic under the hood but FELT intelligent through rich presentation. The best historical example of simulated intelligence in games.
- **Dwarf Fortress → 2.00b:** Dwarves have deterministic needs/desires systems but generate emergent narratives through interaction. The player anthropomorphizes heavily. DF proves that deterministic systems + rich simulation + player narrative generates unlimited personality without AI.
- **AI Dungeon → 2.00d:** Pure LLM-native interactive fiction. Demonstrated the appeal (infinite possibility) and the problems (incoherence, no debugging, cost, platform limitation) of LLM-native game design.
