# 2.2 — Dark Mode Palette

## Design Philosophy

**Navy-black, not pure black.** Dark mode backgrounds carry the same navy undertone as the light mode neutrals. This creates warmth and brand continuity — when a user toggles dark mode, it should feel like the same app in different lighting, not a different app entirely.

Key principles:
- **No pure black (#000000)** — the darkest background is navy-950 (#060D18), which has visible navy character
- **Elevated surfaces get lighter** — each layer up adds ~3-5% lightness (Material Design 3 elevation model)
- **Primary shifts up the scale** — navy-600 is too dark on dark backgrounds; navy-400 becomes the primary action color
- **Gold accent stays bold** — gold-400 works on dark surfaces and maintains its premium feel
- **Semantic colors shift to lighter variants** — success/warning/error/info use their 400-500 range instead of 600-700
- **Borders become subtle** — low-opacity light borders instead of colored borders

## Background & Surface Layers

Dark mode uses a layered elevation system. Higher elevation = lighter surface = more prominent.

| Token | Light Mode | Dark Mode | Usage |
|-------|-----------|-----------|-------|
| `--background` | `--neutral-50` (#F7F8FA) | `--navy-950` (#060D18) | Page base / canvas |
| `--surface-0` | `--neutral-0` (#FFFFFF) | `--navy-900` (#0B1628) | Base cards, main content area |
| `--surface-1` | `--neutral-0` (#FFFFFF) | `#101D30` | Elevated cards (result cards, modals) |
| `--surface-2` | `--neutral-50` (#F7F8FA) | `#152438` | Popovers, dropdowns, tooltips |
| `--surface-3` | `--neutral-100` (#EEF0F4) | `#1A2B42` | Nested surfaces (card within card) |

### Why navy-950 base, not navy-900?

Navy-900 (#0B1628) at 10% lightness is too bright for a base — it reads as "dark blue" rather than "dark mode." Navy-950 (#060D18) at 6% lightness reads as near-black with just enough navy to avoid the flat, lifeless quality of #000000 or even #111111.

### Surface Elevation Hex Values

These intermediate values are calculated between navy-900 and navy-800:

| Token | Hex | HSL (approx) |
|-------|-----|--------------|
| `--dm-surface-0` | `#0B1628` | 213° 56% 10% |
| `--dm-surface-1` | `#101D30` | 213° 52% 12.5% |
| `--dm-surface-2` | `#152438` | 213° 48% 15% |
| `--dm-surface-3` | `#1A2B42` | 213° 45% 18% |

## Text Colors

| Token | Light Mode | Dark Mode | Contrast on navy-950 |
|-------|-----------|-----------|---------------------|
| `--foreground` | `--neutral-900` (#111827) | `--neutral-50` (#F7F8FA) | **16.8:1** ✓ AAA |
| `--text-primary` | `--neutral-900` (#111827) | `#E8EDF2` | **15.2:1** ✓ AAA |
| `--text-secondary` | `--neutral-500` (#6B7485) | `--neutral-400` (#8C95A3) | **6.2:1** ✓ AA |
| `--text-tertiary` | `--neutral-400` (#8C95A3) | `--neutral-500` (#6B7485) | **4.5:1** ✓ AA |
| `--text-disabled` | `--neutral-300` (#B8BEC9) | `--neutral-600` (#505868) | **3.1:1** (intentionally low) |

### Heading text in dark mode
- **H1-H3**: Use `--text-primary` (#E8EDF2) — warm white, not pure white
- **Why not #FFFFFF?** Pure white text on dark backgrounds causes halation (glowing edges) and eye fatigue. #E8EDF2 (a slight navy-tinted off-white) reduces this while maintaining excellent contrast.

## Primary Brand Color

| Token | Light Mode | Dark Mode | Notes |
|-------|-----------|-----------|-------|
| `--primary` | `--navy-600` (#1E3A5F) | `--navy-400` (#4D77A3) | Buttons, links, active states |
| `--primary-hover` | `--navy-700` (#172E4D) | `--navy-300` (#7A99BE) | Hover state |
| `--primary-foreground` | `#FFFFFF` | `#FFFFFF` | Text on primary buttons |

### Why navy-400 in dark mode?

Navy-600 (#1E3A5F) on dark backgrounds disappears — it's only 25% lightness on a 6% background. Navy-400 (#4D77A3) at 47% lightness provides:
- **5.2:1** contrast on navy-950 ✓ AA
- Clearly readable as "the brand blue"
- Sufficient differentiation from the background

Navy-300 (#7A99BE) is the hover state — moving lighter on hover (opposite of light mode's darken-on-hover pattern).

### Gold on dark: contrast check
- Gold-400 on navy-950: **8.4:1** ✓ AAA — excellent
- Gold-400 on surface-0: **7.6:1** ✓ AAA — excellent
- Gold is one of the colors that actually looks *better* in dark mode. It pops.

### Border philosophy
Borders in dark mode should be barely visible — they define regions without drawing attention. The values are ~2-3 steps above the surface they sit on, creating just enough edge definition.

## Sidebar (Dark Mode)

The navy sidebar already works as a dark element. In dark mode, it shifts slightly:

| Token | Light Mode | Dark Mode | Notes |
|-------|-----------|-----------|-------|
| `--sidebar` | `--navy-600` | `--navy-900` (#0B1628) | Darker than page bg for separation |
| `--sidebar-foreground` | `#FFFFFF` | `#E8EDF2` | Warm off-white |
| `--sidebar-primary` | `--gold-400` | `--gold-400` | Gold stays the same |
| `--sidebar-accent` | `--navy-500` | `--navy-800` (#11223A) | Active/hover state |
| `--sidebar-border` | `--navy-500` | `--navy-800` | Subtle border |
| `--sidebar-ring` | `--gold-400` | `--gold-400` | Focus ring |

### Sidebar strategy
In light mode, the sidebar is dramatically navy — a branded landmark. In dark mode, the sidebar becomes *darker than the content area* rather than lighter. This is the opposite of some dark-mode patterns (where sidebars become lighter), but it preserves the hierarchy: sidebar = permanent chrome, content = the focus.

## Implementation Notes

### Toggle Mechanism

Recommended approach for Angkin platform:
1. **Respect system preference** via `prefers-color-scheme: dark`
2. **Allow manual override** via `data-theme` attribute on `<html>`
3. **Persist preference** in `localStorage`

```js
// On page load
const stored = localStorage.getItem('angkin-theme');
if (stored) {
  document.documentElement.dataset.theme = stored;
} else if (window.matchMedia('(prefers-color-scheme: dark)').matches) {
  document.documentElement.dataset.theme = 'dark';
}
```

### Transition
Add a subtle transition when toggling:
```css
:root {
  transition: background-color 0.2s ease, color 0.2s ease;
}
```

### Images & Illustrations
- Charts re-render with dark mode chart colors
- Logo swaps via CSS (navy → white fill)
- Screenshots/photos get no treatment — they stay as-is
- Decorative illustrations (if any) should have dark variants

## Summary

The Angkin dark mode palette is:
- **~50 CSS custom properties** covering backgrounds, text, primary, accent, semantic, chart, compliance, shadcn/ui, and sidebar layers
- **Navy-tinted blacks** for all surfaces (never pure black)
- **Elevated layer model** with 4 surface tints
- **Shifted primary** from navy-600 to navy-400
- **Warmer text** (#E8EDF2 off-white instead of #FFFFFF)
- **Brighter semantics** (400-level greens/reds/ambers/teals)
- **Gold unchanged** — it naturally excels on dark backgrounds
- **All combinations WCAG AA compliant**, most AAA
