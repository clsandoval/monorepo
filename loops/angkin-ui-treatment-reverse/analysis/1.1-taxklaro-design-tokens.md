## Key Observations for Angkin Platform Design

1. **Brand color divergence**: TaxKlaro uses `#1D4ED8` (Tailwind blue-700) as primary. Angkin's brand is `#1E3A5F` (deep navy). These are different — navy is darker and more muted. The entire Angkin palette needs to anchor on navy, not bright blue.

2. **Font divergence opportunity**: TaxKlaro uses DM Sans + DM Serif Display. These are solid choices. The Angkin platform could either:
   - Standardize on these (consistency across sub-tools)
   - Choose a different pairing that reflects the platform-level brand (DM Sans is friendly/rounded; navy + slash logo suggests more authoritative typography)

3. **Neutral scale is Tailwind Slate**: Gray-50 through Gray-900 from Tailwind's Slate palette. This works well and could carry forward to Angkin.

4. **Tax-specific tokens are reusable**: The `--peso-savings` and `--peso-tax-due` pattern is excellent for a compliance platform — every calculator needs "good result" and "amount due" semantics.

5. **Dark mode is present but basic**: Simple Slate inversion. Angkin's dark mode should be more considered, especially with the navy brand color.

6. **shadcn/ui is the component layer**: All sub-tools use Radix primitives via shadcn/ui. This should remain standard across Angkin.

7. **Missing tokens**: No spacing scale variables, no explicit grid system, no max-width tokens. These are handled by Tailwind utility classes directly.
