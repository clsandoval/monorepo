# 2.3 — Typography System

## Design Direction

**Geometric authority with warm readability.** The Angkin brand is "Radical Clarity" — a circle with a decisive diagonal slash. The typography must match: clean geometry for headings that project institutional confidence, warm humanist sans for body text that stays readable through dense compliance forms, and a monospace with presence for the peso amounts that are the whole reason users are here.

Three fonts. Three jobs. No ambiguity.

---

## Font Stack

### Headings: Plus Jakarta Sans (Variable, 200–800)

**Why**: Plus Jakarta Sans is a geometric sans-serif with softened terminals — it has the clean authority of a grotesque without the coldness. The variable weight axis gives precise control from elegant light (200) to commanding extrabold (800). Its x-height is slightly tall, which improves readability at heading sizes while giving it a modern, tech-institutional presence.

**Why not the others**:
- *Inter* (Inheritance) — too ubiquitous, reads as "default." For a platform branding 148 tools, the heading font IS the visual identity. Inter says nothing.
- *DM Sans* (TaxKlaro) — excellent for body text but too rounded for authoritative headings. The softness works at 15px, not at 48px.
- *DM Serif Display* — beautiful but too editorial/warm for a compliance platform. Serifs on a calculator feel anachronistic.
- *Lora* — same issue. Serif headings suggest content-heavy reading, not tool-driven workflows.

**Import**: `@fontsource-variable/plus-jakarta-sans` (WOFF2, ~45KB variable)

### Body: DM Sans (Variable, 100–1000)

**Why**: DM Sans is the best UI sans-serif that isn't Inter. Its slightly rounded terminals add warmth to dense form interfaces without sacrificing clarity. The variable font supports the full weight range. It's already proven in TaxKlaro's production deployment — we know it works for tax calculations at 15px body size.

**Why not Inter**: Inter is the Arial of 2025. It's technically excellent but visually invisible. When users move between Angkin tools, they should feel a subtle but consistent personality. DM Sans provides that.

**Import**: `@fontsource-variable/dm-sans` (WOFF2, ~45KB variable)

### Monospace: IBM Plex Mono (400, 500, 600)

**Why**: The most important typographic moment in any Angkin tool is the peso amount display. `₱1,234,567.89` needs to feel authoritative, precise, and real. IBM Plex Mono has a slightly humanist quality (the 'a' and 'g' are double-story) that prevents it from feeling like a code editor. Its proportions are wider than most monospaces, which gives numbers more presence.

**Why not JetBrains Mono**: Too developer-focused. Ligatures and code-editor associations are wrong for financial display.
**Why not Fira Mono**: Too narrow. Peso amounts need breathing room.
**Why not system monospace**: Inconsistent across platforms. The result display moment is too important to leave to OS defaults.

**Import**: `@fontsource/ibm-plex-mono` (WOFF2, ~15KB per weight × 3 = ~45KB)

### Fallback Stack

```css
--font-heading: 'Plus Jakarta Sans Variable', 'Plus Jakarta Sans', system-ui, -apple-system, sans-serif;
--font-body: 'DM Sans Variable', 'DM Sans', system-ui, -apple-system, sans-serif;
--font-mono: 'IBM Plex Mono', 'Menlo', 'Consolas', monospace;
```

## Weight Usage

| Weight | Name | Usage |
|--------|------|-------|
| 400 | Regular | Body text, form labels, descriptions |
| 500 | Medium | Emphasized text, table headers, nav items, peso amounts |
| 600 | Semibold | Section headings (H2–H4), card titles, button text |
| 700 | Bold | Page titles (H1, Display), strong emphasis |
| 800 | Extrabold | Hero text only — reserved for maximum impact |

**Rules**:
- Never use 300 (light) — it fails readability on non-retina screens, and compliance tools need to be readable in government offices
- Never use 900 (black) — Extrabold (800) is the ceiling
- Body text is always 400 or 500 — never bold body paragraphs
- Headings skip from 600 to 700/800 — this creates clear visual hierarchy without muddy in-between states

---

## Line Height Strategy

| Context | Line Height | Rationale |
|---------|-------------|-----------|
| Hero/Display (36px+) | 1.08–1.12 | Large text needs tight leading — loose leading at 48px looks like separate lines |
| Headings (20–30px) | 1.2–1.3 | Comfortable heading rhythm. Multi-line headings stay grouped |
| Body text (15px) | 1.6 | The sweet spot for extended reading. Forms, descriptions, paragraphs |
| Small/Caption (12–13px) | 1.4–1.5 | Tighter than body — small text is usually single-line (badges, captions) |
| Monospace/Peso (all sizes) | 1.1–1.4 | Numbers need tighter leading. Tabular data should be scannable |

---

## Letter Spacing Strategy

| Context | Letter Spacing | Rationale |
|---------|----------------|-----------|
| Hero/Display | `-0.02em` to `-0.025em` | Large text benefits from tighter tracking — prevents floaty appearance |
| Headings | `-0.01em` to `-0.015em` | Subtle tightening for cohesion |
| Body | `0` | Default tracking. DM Sans is optimized for body-size tracking |
| Small text | `+0.005em` | Slight opening helps readability at small sizes |
| Overlines (uppercase) | `+0.08em` | Wide tracking for uppercase labels — standard typographic practice |
| Monospace | `+0.01em` to `+0.02em` | Slight opening for digit readability |

## The Peso Amount Moment

This is the single most important typographic decision in the system. When a user fills in their income, clicks "Calculate," and sees `₱123,456.78` — that number needs to feel **real, precise, and authoritative**.

### Rules for Peso Display

1. **Always monospace** — IBM Plex Mono. No exceptions. Numbers that jump around when values change destroy trust.
2. **Always `font-variant-numeric: tabular-nums`** — even when the font is already monospace, this ensures alignment in tables and stacked comparisons.
3. **Always include the peso sign** — `₱` prefix, same font, slightly lighter weight if hero-sized to prevent visual heaviness.
4. **Comma separators always** — `₱1,234,567.89` not `₱1234567.89`. Filipino format matches US convention.
5. **Two decimal places always** — even for whole amounts: `₱50,000.00` not `₱50,000`.
6. **Color signals amount type**:
   - `var(--peso-amount)` (navy) — neutral display
   - `var(--peso-savings)` (success green) — money saved
   - `var(--peso-due)` (error red) — amount owed
7. **The hero result gets breathing room** — at least `24px` padding above and below the hero peso amount. It's the payoff for the entire interaction.

## Typography in Dark Mode

All font families, sizes, weights, and letter-spacing remain identical in dark mode. Only color and anti-aliasing change:

```css
[data-theme="dark"] {
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}
```

Dark mode text uses `--neutral-dark-text` (#E8EDF2) from the dark mode palette — a warm off-white that prevents halation against dark navy backgrounds. Heading text may use pure white (#FFFFFF) for maximum contrast at hero/display sizes.

## Migration Notes

### TaxKlaro
- Replace `--font-sans: "DM Sans Variable"` → keep as `--font-body` (DM Sans stays!)
- Replace `--font-display: "DM Serif Display"` → `--font-heading: Plus Jakarta Sans Variable`
- Add `--font-mono: IBM Plex Mono` (currently no explicit mono)
- Map existing `--text-*` variables to new scale (sizes are nearly identical, only Display/H1 shift slightly)

### Inheritance
- Replace `--font-sans: 'Inter Variable'` → `--font-body: DM Sans Variable`
- Replace `--font-serif: 'Lora'` → `--font-heading: Plus Jakarta Sans Variable`
- Add `--font-mono: IBM Plex Mono` for peso amounts
- Add explicit `--text-*` type scale variables (Inheritance currently relies on Tailwind classes)
- Keep `print.css` with Times New Roman — legal print output is a separate concern

### New Tools
- Import all three font packages
- Use heading classes for H1–H3, body classes for everything else
- Use peso classes for all financial amounts
- Never set font-family directly — always reference `var(--font-heading)`, `var(--font-body)`, or `var(--font-mono)`
