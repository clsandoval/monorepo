# 2.6 — Iconography

## Design Direction

**Phosphor Icons, regular weight (1.5px stroke), outline style.** The icon system matches the brand mark's geometry: clean lines, deliberate negative space, no fills. Phosphor was chosen over Lucide, Heroicons, and Tabler for its breadth (6,000+ icons across 6 weights), consistent optical sizing, and — critically — its dedicated "duotone" weight that we'll use for category hero contexts while keeping regular outline for all standard UI.

The Angkin mark is a circle with a diagonal slash — pure geometry, pure line. The icons must echo that: no filled icons, no rounded-cute icons, no hand-drawn illustrations. Outline icons with 1.5px stroke at a consistent 24px grid.

---

## Why Phosphor

| Library | Icons | Weights | Verdict |
|---------|-------|---------|---------|
| **Phosphor** | 6,000+ | 6 (thin, light, regular, bold, fill, duotone) | **Selected.** Best breadth-to-consistency ratio. Duotone weight enables category hero treatment without switching libraries. MIT license. |
| Lucide | 1,500+ | 1 (2px stroke) | Good but limited. Single weight means no ability to vary emphasis. Stroke is slightly heavy for the Angkin aesthetic. |
| Heroicons | 300+ | 3 (outline, solid, mini) | Too few icons. Would need supplementary library for 14 specialized categories. |
| Tabler | 5,000+ | 1 (2px stroke) | Comparable breadth but single weight. 2px stroke is heavier than desired. |
| Remix Icon | 2,800+ | 2 (line, fill) | Good range but inconsistent optical sizing across categories. |

### Import Strategy

Tree-shakeable ESM imports via `@phosphor-icons/react` (for React apps) or `@phosphor-icons/web` (for the treatment deck HTML). Each icon is ~200 bytes gzipped. With 14 category icons + ~30 UI icons, total icon payload is ~9KB.

For the HTML treatment deck, use the CDN:
```html
<script src="https://unpkg.com/@phosphor-icons/web@2.1.1"></script>
```

Usage: `<i class="ph ph-calculator-simple"></i>` (regular weight, 1.5px stroke)

## Icon Style Rules

### Stroke & Size

| Property | Value | Rationale |
|----------|-------|-----------|
| **Default weight** | Regular (1.5px stroke) | Matches the logo's line confidence — not wispy (thin/light), not chunky (bold) |
| **Grid size** | 24px × 24px | Standard. All Phosphor icons sit on this grid. |
| **Optical size** | 24px for UI, 20px for inline text, 40px container on cards | Phosphor scales cleanly across these sizes |
| **Color** | Inherits `currentColor` | Icons take on the text/element color — no separate icon color tokens |

### When to Use Each Weight

| Weight | Stroke | When |
|--------|--------|------|
| **Regular** | 1.5px | Standard UI: nav, buttons, form icons, breadcrumbs, badges |
| **Bold** | 2px | Active/selected states (e.g., active nav item, selected tab) |
| **Duotone** | 1.5px + 20% fill | Category headers on platform home, tool card icons (the 40px container) |
| **Light** | 1px | Decorative/atmospheric only — large sizes (48px+) in hero sections |
| **Thin** | Never | Too fragile for a compliance platform. Never use. |
| **Fill** | Never | Filled icons break the outline aesthetic. Never use. |

### Why Duotone for Category Icons

The tool card has a 40×40px icon container with `navy-50` background and `navy-600` icon color. At this size, a pure outline icon looks thin and underwhelming. Phosphor's duotone weight adds a 20% opacity secondary fill that gives the icon presence without going full solid. It's the same principle as the Angkin logo mark — the circle outline has a filled negative-space slash.

```css
.tool-card__icon i {
  font-size: 24px;
  /* Duotone weight: primary stroke is currentColor,
     secondary fill is currentColor at 20% opacity */
}

/* Duotone opacity control */
.tool-card__icon i {
  --ph-duotone-opacity: 0.15;
}
```

### Icon Selection Criteria

1. **Instantly legible at 24px** — no fine details that collapse at small sizes
2. **Domain-specific, not generic** — "Receipt" for tax is better than "Calculator" because calculator is the tool archetype, not the category
3. **Distinct silhouettes** — no two category icons should look similar at a glance (e.g., Buildings vs House Line are distinct; Buildings vs Office Building would not be)
4. **Culturally appropriate** — Airplane Takeoff for OFW resonates with Filipino context (departure from NAIA is a shared cultural touchpoint)

## CSS Integration

### Icon Sizing Tokens

```css
:root {
  /* === Icon Sizes === */
  --icon-xs: 14px;    /* Inside badges, inline with small text */
  --icon-sm: 16px;    /* Inline with body text, "by Angkin" badge mark */
  --icon-md: 20px;    /* Form input icons, button icons */
  --icon-base: 24px;  /* Default — nav icons, standalone actions */
  --icon-lg: 32px;    /* Tool header, section headers */
  --icon-xl: 40px;    /* Category hero on platform home (inside 40px container, icon is 24px) */

  /* === Icon Container (Tool Cards) === */
  --icon-container-size: 40px;
  --icon-container-bg: var(--navy-50);
  --icon-container-color: var(--navy-600);
  --icon-container-radius: var(--radius-sm);

  /* === Duotone Opacity === */
  --icon-duotone-opacity: 0.15;

  /* === Icon in Buttons === */
  --icon-btn-gap: 8px;  /* Gap between icon and button label */
  --icon-btn-size: 20px; /* Icon size inside buttons */
}
```

### Icon Container Component


## Anti-Patterns

Things that are NOT allowed in Angkin iconography:

1. **Filled icons** — breaks the outline-first aesthetic. The only exception is Phosphor duotone (which is outline + light fill).
2. **Custom SVG illustrations** — every icon comes from Phosphor. No one-off custom artwork. Consistency over creativity.
3. **Emoji as icons** — never. Not in nav, not in badges, not anywhere in the UI.
4. **Animated icons** — icons are static. Motion belongs to transitions and page-level animation, not individual icons.
5. **Multi-color icons** — icons are single-color (currentColor). The duotone secondary is an opacity variant of the same color, not a second color.
6. **Mixing icon libraries** — Phosphor only. No supplementing with Material, Font Awesome, or Heroicons for "that one missing icon."
7. **Icons without labels in navigation** — every nav icon must have a text label. Icon-only buttons require a `title` attribute and `aria-label`.

## Summary of Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Icon library | **Phosphor Icons** | 6,000+ icons, 6 weights, tree-shakeable, MIT, duotone support |
| Default weight | **Regular (1.5px stroke)** | Matches logo line confidence |
| Category weight | **Duotone** | Adds presence at 24px in 40px containers without going filled |
| Grid size | **24px** | Standard Phosphor grid, scales cleanly |
| Color mode | **currentColor (single color)** | Icons take parent color, no separate icon palette |
| Category icons | **14 specific Phosphor icons** | Domain-specific, distinct silhouettes, culturally appropriate |
| Archetype icons | **8 specific Phosphor icons** | Communicates tool interaction type |
| Filled/thin weights | **Never** | Filled breaks aesthetic; thin too fragile for compliance |

**Total new CSS custom properties: ~10**
