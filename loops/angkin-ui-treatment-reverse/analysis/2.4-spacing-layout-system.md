# 2.4 — Spacing & Layout System

## Design Direction

**4px base unit, 8px rhythm, constraint-driven layouts.** Angkin's 148 compliance calculators share one layout truth: the content is dense but must never feel cramped. Filipino compliance forms involve many fields, long labels, and multi-step wizards — the spacing system must create breathing room without wasting viewport on a population that's 70%+ mobile.

The system inherits the base-4px unit already proven in TaxKlaro and Inheritance (both use Tailwind's default 4px scale). No reason to change what works. The decisions here are about *which* steps in that scale to codify, how the page-level container behaves, and how layout adapts across breakpoints.

---

## Base Unit

**4px (`0.25rem`).** Everything is a multiple of 4px. This aligns with Tailwind v4's default spacing scale and both existing apps.

```css
:root {
  --space-unit: 0.25rem; /* 4px */
}
```

---

## Spacing Scale

A curated subset of Tailwind's scale. Not every step is used — we codify only the values that appear in the design system to prevent spacing drift across 148 tools.

| Token | Value | px | Usage |
|-------|-------|----|-------|
| `--space-0` | `0` | 0 | Reset, collapse |
| `--space-0.5` | `0.125rem` | 2 | Micro: icon optical adjustment |
| `--space-1` | `0.25rem` | 4 | Tight: between icon and text in badges |
| `--space-1.5` | `0.375rem` | 6 | Between label and input |
| `--space-2` | `0.5rem` | 8 | **Rhythm unit.** Gap in inline groups, button icon gap |
| `--space-3` | `0.75rem` | 12 | Input horizontal padding, between stacked labels |
| `--space-4` | `1rem` | 16 | **Standard.** Component padding, form field vertical gap |
| `--space-5` | `1.25rem` | 20 | Between form field groups |
| `--space-6` | `1.5rem` | 24 | Card padding (mobile), content section gap |
| `--space-8` | `2rem` | 32 | Card padding (desktop), wizard step gap |
| `--space-10` | `2.5rem` | 40 | Between major content blocks |
| `--space-12` | `3rem` | 48 | Section spacing (mobile) |
| `--space-16` | `4rem` | 64 | Section spacing (desktop) |
| `--space-20` | `5rem` | 80 | Hero vertical padding (mobile) |
| `--space-24` | `6rem` | 96 | Hero vertical padding (desktop) |

### Key Decisions

- **8px is the rhythm unit** — most component-level spacing snaps to multiples of 8px (8, 16, 24, 32). The 4px substeps (4, 6, 12, 20) are for fine-tuning within components.
- **No 7, 9, 11, 13, 14, 15, 18 values** — keeping the scale constrained prevents "spacing soup" where every developer picks their own value.
- **Above 24 (96px), the scale stops** — page-level vertical rhythm beyond 96px is handled by layout composition, not spacing tokens.

## Page Layout

### Container

The page container is centered with a maximum width and responsive horizontal padding.

| Breakpoint | Max Content Width | Horizontal Padding | Notes |
|------------|------------------|--------------------|-------|
| `< 640px` (mobile) | 100% | `16px` (space-4) | Full-bleed, padded |
| `≥ 640px` (sm) | 100% | `24px` (space-6) | Still fluid |
| `≥ 768px` (md) | 100% | `32px` (space-8) | Breathing room |
| `≥ 1024px` (lg) | `768px` | `32px` (space-8) | Content narrows |
| `≥ 1280px` (xl) | `960px` | `32px` (space-8) | Desktop optimal |
| `≥ 1536px` (2xl) | `1120px` | `32px` (space-8) | Wide screens |

```css
:root {
  --container-sm: 640px;
  --container-md: 768px;
  --container-lg: 960px;
  --container-xl: 1120px;
  --container-padding-mobile: var(--space-4);   /* 16px */
  --container-padding-sm: var(--space-6);        /* 24px */
  --container-padding-desktop: var(--space-8);   /* 32px */
}
```

### Why 960px, not 1024px or 1200px?

Compliance calculators are narrow by nature — forms, wizards, result cards. A 960px max-width:
- Keeps line lengths readable (65–75 characters at 15px body)
- Makes single-column forms feel spacious, not stranded
- Leaves room for a sidebar (256px) without cramping the content
- Matches TaxKlaro's `max-w-5xl` pattern for dashboard views

### Full-Width Exceptions

Some layouts need wider containers:
- **Platform home** (tool grid): `1120px` max-width — needs room for 3-4 tool cards per row
- **Comparison results**: `1120px` — three regime cards side by side
- **Individual tool forms/wizards**: `768px` max-width — focused single-column

```css
:root {
  --content-narrow: 576px;   /* Single form, wizard step */
  --content-default: 768px;  /* Standard tool page */
  --content-wide: 960px;     /* Dashboard, complex results */
  --content-full: 1120px;    /* Platform home, comparisons */
}
```

## Grid System

### Columns

A simple responsive column system using CSS Grid:

| Context | Mobile (< 640px) | Tablet (640–1023px) | Desktop (≥ 1024px) |
|---------|-------------------|---------------------|---------------------|
| Tool grid (home) | 1 col | 2 col | 3 col (4 col at 2xl) |
| Form fields | 1 col | 2 col | 2 col |
| Result cards (comparison) | 1 col stacked | 2 col | 3 col |
| Stat blocks | 2 col | 3 col | 4 col |
| Settings/profile | 1 col | 1 col | 2 col (sidebar + content) |

### Grid Gap

| Context | Gap |
|---------|-----|
| Tool grid | `space-4` (16px) mobile, `space-6` (24px) desktop |
| Form fields | `space-4` (16px) |
| Result cards | `space-4` (16px) mobile, `space-6` (24px) desktop |
| Stat blocks | `space-3` (12px) mobile, `space-4` (16px) desktop |

```css
:root {
  --grid-gap-tight: var(--space-3);   /* 12px — stat blocks, dense grids */
  --grid-gap-default: var(--space-4); /* 16px — forms, standard grids */
  --grid-gap-loose: var(--space-6);   /* 24px — tool cards, result cards */
}
```

## Component Spacing

### Cards

Cards are the primary content container in Angkin — tool cards, result cards, form cards, stat cards.

| Property | Mobile | Desktop |
|----------|--------|---------|
| Padding | `space-4` (16px) | `space-6` (24px) |
| Internal gap (between children) | `space-4` (16px) | `space-6` (24px) |
| Border radius | `--radius` (8px) | `--radius` (8px) |

```css
:root {
  --card-padding-mobile: var(--space-4);
  --card-padding-desktop: var(--space-6);
  --card-gap: var(--space-4);
}
```

### Forms

| Property | Value | Notes |
|----------|-------|-------|
| Label → input gap | `space-1.5` (6px) | Tight coupling — label belongs to its input |
| Input → next field gap | `space-4` (16px) | Clear separation between fields |
| Field group → next group gap | `space-6` (24px) | Visible section break |
| Input horizontal padding | `space-3` (12px) | Comfortable text inset |
| Input vertical padding | `space-2` (8px) | Default height |
| Input height (computed) | `40px` | 8 + 15 (text) + 8 + 2×1 (border) ≈ 40px |

```css
:root {
  --form-label-gap: var(--space-1.5);     /* 6px */
  --form-field-gap: var(--space-4);        /* 16px */
  --form-group-gap: var(--space-6);        /* 24px */
  --input-padding-x: var(--space-3);       /* 12px */
  --input-padding-y: var(--space-2);       /* 8px */
  --input-height: 2.5rem;                  /* 40px */
  --input-height-sm: 2rem;                 /* 32px */
  --input-height-lg: 3rem;                 /* 48px */
}
```

### Buttons

| Property | Small | Default | Large |
|----------|-------|---------|-------|
| Height | `32px` | `40px` | `48px` |
| Horizontal padding | `space-3` (12px) | `space-4` (16px) | `space-6` (24px) |
| Icon gap | `space-1` (4px) | `space-2` (8px) | `space-2` (8px) |
| Border radius | `--radius-sm` (6px) | `--radius` (8px) | `--radius` (8px) |

```css
:root {
  --button-height-sm: 2rem;      /* 32px */
  --button-height: 2.5rem;       /* 40px */
  --button-height-lg: 3rem;      /* 48px */
  --button-padding-sm: var(--space-3);
  --button-padding: var(--space-4);
  --button-padding-lg: var(--space-6);
  --button-gap-sm: var(--space-1);
  --button-gap: var(--space-2);
}
```

### Navigation

| Property | Value |
|----------|-------|
| Top nav height | `56px` mobile, `64px` desktop |
| Sidebar width | `256px` (16rem) |
| Sidebar collapsed width | `64px` (for icon-only mode) |
| Nav item padding | `space-2 space-3` (8px 12px) |
| Nav item gap | `space-1` (4px) |
| Breadcrumb gap | `space-2` (8px) |

```css
:root {
  --nav-height-mobile: 3.5rem;    /* 56px */
  --nav-height-desktop: 4rem;     /* 64px */
  --sidebar-width: 16rem;         /* 256px */
  --sidebar-width-collapsed: 4rem; /* 64px */
}
```

## Border Radius

Inheriting from Inheritance's radius system (which is more complete than TaxKlaro's single `--radius`):

| Token | Value | px | Usage |
|-------|-------|----|-------|
| `--radius-sm` | `0.375rem` | 6 | Badges, small chips, toggle tracks |
| `--radius` | `0.5rem` | 8 | **Default.** Buttons, inputs, small cards |
| `--radius-md` | `0.5rem` | 8 | Alias for default |
| `--radius-lg` | `0.625rem` | 10 | Cards, modals, dropdowns |
| `--radius-xl` | `0.875rem` | 14 | Large cards, hero sections |
| `--radius-2xl` | `1.125rem` | 18 | Feature cards, promotional surfaces |
| `--radius-full` | `9999px` | ∞ | Pills, avatars, circular elements |

```css
:root {
  --radius-sm: 0.375rem;
  --radius: 0.5rem;
  --radius-md: 0.5rem;
  --radius-lg: 0.625rem;
  --radius-xl: 0.875rem;
  --radius-2xl: 1.125rem;
  --radius-full: 9999px;
}
```

### Key Decision: 8px Default Radius

TaxKlaro uses `0.5rem` (8px), Inheritance uses `0.625rem` (10px). Going with **8px** because:
- 8px is the standard for professional/institutional UIs (government, finance)
- 10px starts to feel consumer/playful — wrong for compliance tools
- 8px aligns with the 8px rhythm unit
- The 2C Radical Clarity logo has sharp geometric forms — rounded corners should be present but not prominent

## Shadow Scale

Unified from both apps, with navy undertone for brand cohesion:

| Token | Value | Usage |
|-------|-------|-------|
| `--shadow-xs` | `0 1px 2px rgba(30,58,95,0.06)` | Subtle lift — inputs, small elements |
| `--shadow-sm` | `0 1px 3px rgba(30,58,95,0.08), 0 1px 2px rgba(30,58,95,0.04)` | Cards at rest |
| `--shadow-md` | `0 4px 8px rgba(30,58,95,0.08), 0 2px 4px rgba(30,58,95,0.04)` | Cards on hover, dropdowns |
| `--shadow-lg` | `0 8px 24px rgba(30,58,95,0.12), 0 4px 8px rgba(30,58,95,0.04)` | Modals, floating elements |
| `--shadow-xl` | `0 16px 48px rgba(30,58,95,0.14), 0 8px 16px rgba(30,58,95,0.06)` | Hero elements, dialogs |

```css
:root {
  --shadow-xs: 0 1px 2px rgba(30, 58, 95, 0.06);
  --shadow-sm: 0 1px 3px rgba(30, 58, 95, 0.08), 0 1px 2px rgba(30, 58, 95, 0.04);
  --shadow-md: 0 4px 8px rgba(30, 58, 95, 0.08), 0 2px 4px rgba(30, 58, 95, 0.04);
  --shadow-lg: 0 8px 24px rgba(30, 58, 95, 0.12), 0 4px 8px rgba(30, 58, 95, 0.04);
  --shadow-xl: 0 16px 48px rgba(30, 58, 95, 0.14), 0 8px 16px rgba(30, 58, 95, 0.06);
}
```

### Why Navy-Tinted Shadows?

Using `rgba(30, 58, 95, ...)` (the brand navy RGB) instead of `rgba(0, 0, 0, ...)` makes shadows feel warmer and more intentional. The difference is subtle but aligns with the navy-undertoned neutral scale from the color system.

## Responsive Breakpoints

| Token | Value | Purpose |
|-------|-------|---------|
| `--bp-sm` | `640px` | Large phones, small tablets |
| `--bp-md` | `768px` | Tablets portrait |
| `--bp-lg` | `1024px` | Tablets landscape, small desktops |
| `--bp-xl` | `1280px` | Desktop (design reference width) |
| `--bp-2xl` | `1536px` | Wide desktop |

These match Tailwind v4's defaults. No reason to deviate — the existing apps and the broader ecosystem use these values.

### Mobile-First Strategy

All styles are written mobile-first. Breakpoints add complexity, they don't remove it:

```css
/* Mobile default */
.card { padding: var(--space-4); }

/* Desktop enhancement */
@media (min-width: 1024px) {
  .card { padding: var(--space-6); }
}
```

## Touch Targets

Per WCAG 2.5.5 (Target Size Enhanced) and Apple HIG:

| Element | Minimum Size | Notes |
|---------|-------------|-------|
| Buttons | `44px × 44px` | Height from button-height tokens, width from content |
| Nav items | `44px` height | Full-width touch target on mobile |
| Form inputs | `40px` height | Slightly below 44px but text provides visual target |
| Checkboxes/radios | `20px` visual, `44px` touch | Larger invisible touch area |
| Mobile hamburger | `44px × 44px` | Minimum |

On mobile (`< 640px`), all interactive elements use `--button-height` (40px) minimum. The 4px gap to the ideal 44px is acceptable given the spacing between elements provides additional touch margin.

## Animation & Transitions

Carried forward from Inheritance's well-tuned values:

```css
:root {
  --duration-fast: 100ms;     /* Micro-interactions: focus rings, hover states */
  --duration-default: 200ms;  /* Standard transitions: color, background */

  --ease-in: cubic-bezier(0.4, 0, 1, 1);           /* Entries */
}
```

## Migration Notes

### TaxKlaro
- Already uses Tailwind spacing utilities — no changes to individual component spacing
- Add `--container-*` tokens to replace hardcoded `max-w-*` classes
- Add `--sidebar-width` token (currently hardcoded `w-64`)
- Shadow values shift from `rgba(0,0,0,...)` to navy-tinted `rgba(30,58,95,...)`
- Border radius stays at `0.5rem` (already matches)

### Inheritance
- Keep radius calculation system (`--radius` base with calc offsets) — it's compatible
- Shadow values already use similar patterns, just adopt navy tint
- Add `--container-*` and `--content-*` tokens for page layout consistency
- Animation timing variables already match — no changes needed

### New Tools
- Import the complete CSS custom properties block
- Use `--content-narrow` for wizard/form pages, `--content-default` for standard tool pages
- Use `--grid-gap-default` for form grids, `--grid-gap-loose` for card grids
- Never hardcode spacing — always use `var(--space-*)` or Tailwind utilities
- Mobile-first: write base styles for 375px, enhance at breakpoints

## Summary

The Angkin spacing & layout system is:
- **4px base unit** with a 16-step spacing scale (0 → 96px)
- **8px rhythm** — most visible spacing snaps to multiples of 8
- **4 content widths**: 576px (narrow) → 1120px (full)
- **5 breakpoints**: 640 / 768 / 1024 / 1280 / 1536px (Tailwind defaults)
- **Navy-tinted shadows** across 5 elevations
- **7 radius steps** from 6px to pill
- **6 z-index layers** from base to toast
- **~55 CSS custom properties** covering spacing, layout, radius, shadow, animation, and z-index
