# 3.6 — Modals & Overlays

## Design Direction

**Modals interrupt. Make the interruption worth it.** In a compliance calculator platform, modals serve two jobs: (1) confirmation gates before irreversible actions like "Delete this estate scenario?" and (2) focused information that needs full attention — a calculation breakdown, a regulation explainer, a data entry form that can't share the screen.

The overlay pattern is the visual language of "this matters enough to stop everything else." Navy-tinted backdrop, centered card with elevated shadow, decisive action buttons. No decoration, no animation flourishes — just clarity.

Three modal types:
- **Confirmation Dialog** — "Are you sure?" gate. Short text, 2 buttons, destructive intent.
- **Info Modal** — Content-rich. Titles, body text, sometimes tables or calculation breakdowns. Scrollable.
- **Bottom Sheet (Mobile)** — The mobile counterpart to modals. Slides up from the bottom, respects thumb reach, swipeable dismiss.

---

## Backdrop

The backdrop is the foundation of every overlay. It communicates "the world behind is paused."

| Property | Value |
|----------|-------|
| Background | `rgba(11, 22, 40, 0.6)` — navy-950 at 60% |
| Z-index | `var(--z-overlay)` (30) |
| Cursor | `pointer` (clicking dismisses, unless `persistent`) |
| Animation | Fade in 200ms ease-out |

### Why Navy, Not Black?

`rgba(0, 0, 0, 0.5)` is the default everyone uses. It creates a harsh, disconnected overlay that feels like a different app. `rgba(11, 22, 40, 0.6)` uses the darkest navy tone, creating a tinted veil that feels like a natural extension of the Angkin color system. The difference is subtle but contributes to the "everything is one surface" feeling.

### Backdrop CSS

```css
.backdrop {
  position: fixed;
  inset: 0;
  background: rgba(11, 22, 40, 0.6);
  z-index: var(--z-overlay);
  cursor: pointer;
  animation: backdrop-in var(--duration-default) var(--ease-out) forwards;
}

@keyframes backdrop-in {
  from { opacity: 0; }
  to { opacity: 1; }
}

@keyframes backdrop-out {
  from { opacity: 1; }
  to { opacity: 0; }
}
```

## 1. Confirmation Dialog

The simplest modal. Two states: "Yes, do it" or "Never mind." Used for destructive actions (delete scenario, clear form, remove heir) and irreversible submissions.

### Anatomy

```
┌──────────────────────────────────────┐
│  ⚠️ Icon (optional — danger only)    │
│                                      │
│  Title                               │  ← H3: Plus Jakarta Sans, 20px, 600
│  Body text explaining the action     │  ← Body: DM Sans, 15px, 400
│  and its consequences.               │
│                                      │
│          ┌─────────┐ ┌──────────┐    │
│          │ Cancel  │ │ Delete   │    │  ← Button group, right-aligned
│          └─────────┘ └──────────┘    │
└──────────────────────────────────────┘
```

### Specs

| Property | Value |
|----------|-------|
| Width | `440px` max, `calc(100vw - 32px)` min |
| Padding | `var(--space-6)` (24px) |
| Border radius | `var(--radius-lg)` (10px) |
| Background | `var(--neutral-0)` (white) |
| Border | `1px solid var(--neutral-200)` |
| Shadow | `var(--shadow-xl)` |
| Z-index | `var(--z-modal)` (40) |
| Title → body gap | `var(--space-2)` (8px) |
| Body → buttons gap | `var(--space-6)` (24px) |
| Animation | Scale from 0.95 + fade in, 200ms ease-out |

### Variants

**Standard confirmation** (non-destructive):
- Title: `--neutral-900`
- Body: `--neutral-600`
- Buttons: Secondary (Cancel) + Primary (Confirm)

**Destructive confirmation**:
- Warning icon: 40px, `--error-500` or `--warning-500` inside a tinted circle
- Title: `--neutral-900`
- Body: `--neutral-600`
- Buttons: Ghost (Cancel) + Danger (Delete/Remove/Revoke)
- The destructive button text should name the action: "Delete Scenario" not just "Delete"

**Key decisions:**
- **440px max width, not 480px or 500px** — confirmation dialogs should feel compact, like a focused question. Wider dialogs feel like they're expecting more content.
- **Ghost cancel, not Secondary** — in destructive dialogs, the cancel button should be as quiet as possible to avoid accidental cancellation. Ghost > Secondary for non-primary actions in high-stakes dialogs.
- **No close X button** — confirmation dialogs require a decision. The X creates ambiguity: "Did I dismiss or cancel?" Click backdrop or press Escape to cancel.

### CSS

```css

  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);

  background: var(--neutral-0);
  border: 1px solid var(--neutral-200);
  border-radius: var(--radius-lg);
  padding: var(--space-6);
  box-shadow: var(--shadow-xl);
  animation: dialog-in var(--duration-default) var(--ease-out) forwards;
}

.dialog-icon {
  width: 48px;

  border-radius: var(--radius-full);

}

.dialog-icon--warning {
  background: var(--warning-50);
  color: var(--warning-500);
}

.dialog-icon--info {
  background: var(--info-50);
  color: var(--info-500);
}

.dialog-title {
  font-family: var(--font-heading);
  font-size: var(--text-h3);
  font-weight: var(--weight-semibold);
  line-height: var(--leading-h3);
  color: var(--neutral-900);
  margin: 0;
}

.dialog-body {
  font-family: var(--font-body);
```

## 2. Info Modal

Larger, content-rich modal for: regulation explainers, calculation breakdowns, detailed help, form-in-modal patterns. Scrollable when content exceeds viewport.

### Anatomy

```
┌──────────────────────────────────────────────────┐
│  Title                                     [✕]   │  ← Sticky header with close button
├──────────────────────────────────────────────────┤
│                                                  │
│  Content area (scrollable)                       │
│                                                  │
│  Can contain: text, tables, calculation          │
│  breakdowns, form fields, lists, badges,         │
│  anything from the component library.            │
│                                                  │
│  The scroll region has top/bottom fade masks     │
│  when content overflows.                         │
│                                                  │
├──────────────────────────────────────────────────┤
│                           [Secondary] [Primary]  │  ← Sticky footer (optional)
└──────────────────────────────────────────────────┘
```

### Specs

| Property | Value |
|----------|-------|
| Width | `560px` max, `calc(100vw - 32px)` min |
| Max height | `calc(100vh - 64px)` — always 32px from top/bottom edges |
| Header padding | `var(--space-6)` (24px) with bottom border |
| Body padding | `var(--space-6)` (24px) |
| Footer padding | `var(--space-4) var(--space-6)` (16px 24px) with top border |
| Border radius | `var(--radius-lg)` (10px) |
| Background | `var(--neutral-0)` |
| Border | `1px solid var(--neutral-200)` |
| Shadow | `var(--shadow-xl)` |
| Z-index | `var(--z-modal)` (40) |
| Header border | `1px solid var(--neutral-200)` (bottom) |
| Footer border | `1px solid var(--neutral-200)` (top) |

### Header

The header is sticky, so the title remains visible as content scrolls.

| Property | Value |
|----------|-------|
| Title | H3: Plus Jakarta Sans, 20px, 600, `--neutral-900` |
| Close button | Ghost icon button, 32px × 32px, X icon 18px |
| Layout | Flex, space-between, align-items center |
| Border bottom | `1px solid var(--neutral-200)` |

### Close Button (X)

| State | Background | Icon Color |
|-------|-----------|------------|
| Default | transparent | `--neutral-500` |
| Hover | `--neutral-100` | `--neutral-700` |
| Focus | transparent | `--neutral-500` + focus ring |
| Active | `--neutral-150` | `--neutral-800` |

### Body (Scroll Region)

- `overflow-y: auto` with `-webkit-overflow-scrolling: touch`
- Custom scrollbar: 6px wide, `--neutral-200` track, `--neutral-400` thumb, `--radius-full` radius
- Scroll shadow: a subtle gradient mask at top and bottom edges when content overflows

### Footer (Optional)

Only present when the modal has action buttons (e.g., "Apply", "Save", forms). Info-only modals may skip the footer and rely on the X button to close.

## 3. Bottom Sheet (Mobile)

On screens ≤ 640px, large modals convert to bottom sheets. The bottom sheet slides up from the viewport bottom, filling width, with a drag handle for swipe-to-dismiss.

### Anatomy

```
┌──────────────────────────────────┐
│           ─── handle ───         │  ← 40px × 4px, neutral-300, rounded
│                                  │
│  Title                    [✕]   │  ← Same as modal header
├──────────────────────────────────┤
│                                  │
│  Content area (scrollable)       │
│                                  │
├──────────────────────────────────┤
│        [Cancel]  [Confirm]       │  ← Safe area padding at bottom
└──────────────────────────────────┘
```

### Specs

| Property | Value |
|----------|-------|
| Width | `100vw` |
| Max height | `calc(100vh - 64px)` — leaves top peeking |
| Border radius | `var(--radius-xl) var(--radius-xl) 0 0` (14px top, 0 bottom) |
| Background | `var(--neutral-0)` |
| Border | `1px solid var(--neutral-200)` (top and sides only) |
| Shadow | `0 -8px 32px rgba(11, 22, 40, 0.15)` (upward shadow) |
| Z-index | `var(--z-modal)` (40) |
| Animation | Slide up from bottom, 300ms ease-out |
| Drag handle | `40px × 4px`, centered, `--neutral-300`, `--radius-full` |
| Safe area padding | `env(safe-area-inset-bottom)` on footer for notch devices |

### Drag Handle

The drag handle is the primary affordance for dismissal on mobile. It sits at the top center of the sheet with `12px` padding above and below.

| Property | Value |
|----------|-------|
| Width | `40px` |
| Height | `4px` |
| Background | `var(--neutral-300)` |
| Border radius | `var(--radius-full)` |
| Margin | `var(--space-3)` auto `var(--space-2)` |

## Keyboard & Accessibility

| Behavior | Implementation |
|----------|---------------|
| Focus trap | Focus stays inside the modal while open. Tab wraps from last to first focusable element |
| Escape key | Closes the modal (unless `persistent` flag set) |
| Initial focus | First focusable element in the dialog, or the close button for info modals |
| Return focus | When modal closes, focus returns to the element that triggered it |
| `role="dialog"` | On the modal container |
| `aria-modal="true"` | Prevents screen readers from navigating behind |
| `aria-labelledby` | Points to the title element |
| `aria-describedby` | Points to the body text (confirmation dialogs) |
| Body scroll lock | `document.body.style.overflow = 'hidden'` while modal is open |

## Real-World Examples

### In TaxKlaro
- **"Clear all form data?"** — Destructive confirmation dialog. Warning icon, "Cancel" (ghost) + "Clear Data" (danger)
- **"Tax Regime Comparison Details"** — Info modal. Table showing all brackets, effective rates, explanation text. Scrollable body.
- **"Select Filing Status"** — Bottom sheet on mobile. List of radio options, "Apply" button.

### In Inheritance Calculator
- **"Remove heir from estate?"** — Destructive confirmation. Heir's name in the body text for clarity.
- **"Estate Tax Breakdown"** — Info modal. Full per-heir breakdown table, applicable law references, exemptions.
- **"Add Heir"** — Info modal with form. Name, relationship, share% fields inside a modal. "Cancel" + "Add Heir" footer.

### Platform Level
- **"Sign out?"** — Standard confirmation dialog. "Cancel" (secondary) + "Sign Out" (primary).
- **"What is Estate Tax?"** — Info modal triggered from help icon. Regulation text, external links.

## Anti-Patterns

1. **No nested modals** — never open a modal from within a modal. If a confirmation is needed inside a modal, use an inline alert within the modal body.
2. **No fullscreen modals on desktop** — fullscreen is for mobile bottom sheets. Desktop modals are always centered with visible backdrop.
3. **No auto-dismissing modals** — modals that disappear on a timer are hostile UX. Toasts auto-dismiss; modals require user action.
4. **No modals for simple feedback** — "Saved successfully" is a toast, not a modal. Only interrupt the user when they need to make a decision.
5. **No animate-in without animate-out** — if the modal scales in, it must scale out. Symmetric transitions.
6. **No more than 3 action buttons** — if a modal needs 4+ actions, rethink the UX.
7. **No modals wider than 560px** — at wider sizes, use a page instead of a modal. Side panels are an alternative for complex content.

## Summary

| Component | Width | Animation | Use Case |
|-----------|-------|-----------|----------|
| Confirmation Dialog | 440px max | Scale 0.95→1 + fade, 200ms | Destructive actions, irreversible submissions |
| Info Modal | 560px max | Scale 0.95→1 + fade, 200ms | Content-rich overlays, forms, breakdowns |
| Bottom Sheet | 100vw | Slide up, 300ms | Mobile replacement for modals |

Shared: navy-tinted backdrop at 60%, `--shadow-xl` elevation, `--radius-lg` corners, `--z-modal` (40) stacking, focus trap, Escape to close. Dark mode inverts surfaces and raises shadow opacity.
