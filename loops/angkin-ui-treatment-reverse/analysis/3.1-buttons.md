# 3.1 — Buttons

## Design Direction

**Precise, institutional, never playful.** Angkin buttons serve 148 compliance calculators where "Calculate" means real money. Every button variant is designed for one job: make the user confident that clicking it will do exactly what they expect. No gradients, no bouncy animations, no rounded-pill shapes. Clean rectangles with the 8px radius, navy brand color, and DM Sans semibold at 15px.

The button system has 5 variants, 3 sizes, and 6 states. That's 90 combinations. Every one is specified below.

---

## Variants

### 1. Primary — The Action Button

The primary button is the brand statement in miniature. Navy-600 fill, white text. Used for: Calculate, Submit, Continue, Save, Confirm.

| Property | Value |
|----------|-------|
| Background | `var(--navy-600)` #1E3A5F |
| Text color | `#FFFFFF` |
| Border | `none` |
| Font | DM Sans, 600 weight, 15px |
| Shadow | `var(--shadow-xs)` at rest |

**States:**
| State | Background | Text | Border | Shadow | Other |
|-------|-----------|------|--------|--------|-------|
| Default | `--navy-600` | white | none | `--shadow-xs` | — |
| Hover | `--navy-700` #172E4D | white | none | `--shadow-sm` | `cursor: pointer` |
| Focus | `--navy-600` | white | none | `--shadow-xs` | `outline: 2px solid var(--navy-400); outline-offset: 2px` |
| Active/Pressed | `--navy-800` #11223A | white | none | none | `transform: translateY(1px)` |
| Disabled | `--navy-200` #A8BBD4 | white | none | none | `opacity: 1; cursor: not-allowed` |
| Loading | `--navy-600` | white | none | `--shadow-xs` | Spinner icon replaces text, `pointer-events: none` |

**Key decisions:**
- **No opacity on disabled** — opacity makes elements look broken. Instead, the navy-200 fill clearly communicates "this exists but isn't available." The white text on navy-200 gives 3.0:1 contrast (AA large), which is intentional: disabled buttons shouldn't demand attention.
- **1px translateY on press** — subtle physical feedback without cartoon bounce.
- **Focus ring uses navy-400** (not the default browser blue) — stays on-brand while being clearly visible.

### 2. Secondary — The Alternative Action

Used when there's a primary action nearby and this is the "other option." Examples: Reset Form, View Details, Export PDF.

| Property | Value |
|----------|-------|
| Background | `var(--neutral-0)` #FFFFFF |
| Text color | `var(--navy-600)` #1E3A5F |
| Border | `1px solid var(--neutral-200)` #D5D9E1 |
| Font | DM Sans, 600 weight, 15px |
| Shadow | none |

**States:**
| State | Background | Text | Border | Other |
|-------|-----------|------|--------|-------|
| Default | `--neutral-0` | `--navy-600` | `--neutral-200` | — |
| Hover | `--neutral-50` #F7F8FA | `--navy-700` | `--neutral-300` #B8BEC9 | — |
| Focus | `--neutral-0` | `--navy-600` | `--neutral-200` | `outline: 2px solid var(--navy-400); outline-offset: 2px` |
| Active | `--neutral-100` #EEF0F4 | `--navy-800` | `--neutral-300` | `transform: translateY(1px)` |
| Disabled | `--neutral-0` | `--neutral-300` | `--neutral-150` #E3E6EC | `cursor: not-allowed` |

**Key decisions:**
- **White background, not gray** — secondary buttons are lighter than primary but shouldn't look "less important." White fill with a border gives them equal visual weight at a different tonal register.
- **Border darkens on hover** — the border is the visual affordance, so it strengthens on interaction.

### 3. Ghost — The Subtle Action

Transparent background, no border. Used for: tertiary actions, inline actions in cards, icon-only buttons, close/dismiss. "I'm here if you need me, but I'm not demanding attention."

| Property | Value |
|----------|-------|
| Background | `transparent` |
| Text color | `var(--navy-600)` #1E3A5F |
| Border | `none` |
| Font | DM Sans, 500 weight, 15px |
| Shadow | none |

**States:**
| State | Background | Text | Other |
|-------|-----------|------|-------|
| Default | transparent | `--navy-600` | — |
| Hover | `--navy-50` #EEF2F7 | `--navy-700` | — |
| Focus | transparent | `--navy-600` | `outline: 2px solid var(--navy-400); outline-offset: 2px` |
| Active | `--navy-100` #D8E1ED | `--navy-800` | — |
| Disabled | transparent | `--neutral-300` | `cursor: not-allowed` |

**Key decisions:**
- **Weight 500 not 600** — ghost buttons are quieter, so medium weight instead of semibold reinforces hierarchy.
- **Navy-50 hover background** — barely-there tint on hover gives feedback without creating visual noise in dense UIs.

### 4. Danger — The Destructive Action

Red fills for irreversible actions: Delete, Remove, Revoke. Used sparingly. When a user sees a red button in Angkin, they should pause.

| Property | Value |
|----------|-------|
| Background | `var(--error-700)` #991B1B |
| Text color | `#FFFFFF` |
| Border | `none` |
| Font | DM Sans, 600 weight, 15px |
| Shadow | `var(--shadow-xs)` |

**States:**
| State | Background | Text | Other |
|-------|-----------|------|-------|
| Default | `--error-700` | white | `--shadow-xs` |
| Hover | `--error-600` #B91C1C | white | `--shadow-sm` |
| Focus | `--error-700` | white | `outline: 2px solid var(--error-500); outline-offset: 2px` |
| Active | `#7F1616` | white | `transform: translateY(1px)` |
| Disabled | `--neutral-200` | white | `cursor: not-allowed` |

**Key decisions:**
- **Error-700 not error-500** — darker red reads as "serious" rather than "alarming." Error-500 (#DC2626) is too bright for a button fill — it screams error state rather than communicating "this action is destructive."
- **Same disabled treatment as primary** — disabled destructive and disabled primary look the same. This is intentional: when disabled, the action doesn't matter, so the variant distinction disappears.

### 5. Outline Danger — The Soft Destructive

For destructive actions that aren't the primary focus: Cancel (when paired with Save), secondary delete confirmation. Less aggressive than filled danger.

| Property | Value |
|----------|-------|
| Background | `transparent` |
| Text color | `var(--error-700)` #991B1B |
| Border | `1px solid var(--error-500)` #DC2626 |
| Font | DM Sans, 600 weight, 15px |
| Shadow | none |

**States:**
| State | Background | Text | Border | Other |
|-------|-----------|------|--------|-------|
| Default | transparent | `--error-700` | `--error-500` | — |
| Hover | `--error-50` #FEF2F2 | `--error-700` | `--error-600` | — |
| Focus | transparent | `--error-700` | `--error-500` | `outline: 2px solid var(--error-500); outline-offset: 2px` |
| Active | `--error-100` #FEE2E2 | `--error-700` | `--error-600` | — |
| Disabled | transparent | `--neutral-300` | `--neutral-200` | `cursor: not-allowed` |

## Sizes

### Small (32px height)

| Property | Value |
|----------|-------|
| Height | `32px` (`--button-height-sm`) |
| Horizontal padding | `12px` (`--button-padding-sm`) |
| Font size | `13px` (`--text-small`) |
| Icon size | `16px` |
| Icon gap | `4px` (`--button-gap-sm`) |
| Border radius | `6px` (`--radius-sm`) |

**Use for**: inline actions, table row actions, dense UI, badges with actions, settings panels.

### Medium / Default (40px height)

| Property | Value |
|----------|-------|
| Height | `40px` (`--button-height`) |
| Horizontal padding | `16px` (`--button-padding`) |
| Font size | `15px` (`--text-body`) |
| Icon size | `18px` |
| Icon gap | `8px` (`--button-gap`) |
| Border radius | `8px` (`--radius`) |

**Use for**: form submit, wizard navigation, card actions, modal actions. **This is the default.**

### Large (48px height)

| Property | Value |
|----------|-------|
| Height | `48px` (`--button-height-lg`) |
| Horizontal padding | `24px` (`--button-padding-lg`) |
| Font size | `15px` (`--text-body`) — same as medium! |
| Icon size | `20px` |
| Icon gap | `8px` (`--button-gap`) |
| Border radius | `8px` (`--radius`) |

**Use for**: hero CTAs, landing page primary actions, mobile full-width submit buttons, important single-action pages.

**Key decision: Large buttons don't increase font size.** 15px body text is the reading size across Angkin. Enlarging text in large buttons creates visual hierarchy confusion — the button looks like a heading. Instead, large buttons get more padding and a taller tap target. The text stays consistent.

## Icon Buttons

### Icon-Only

Square buttons with icon and no text. Used for: close, menu toggle, collapse, back arrow, settings gear.

| Size | Dimensions | Icon | Radius |
|------|-----------|------|--------|
| Small | `32px × 32px` | 16px | 6px |
| Medium | `40px × 40px` | 18px | 8px |
| Large | `48px × 48px` | 20px | 8px |

Icon-only buttons are almost always ghost variant. Padding is symmetric (centered icon). Must include `aria-label` for accessibility.

### Icon + Text

Icon on the left, text on the right. Standard layout. No icon-right unless it's a forward arrow (→) or external link indicator.

The icon gap values from the size table apply. Icons are vertically centered with the text baseline using `display: inline-flex; align-items: center`.

## Button Groups

When buttons appear together (e.g., "Cancel" + "Submit"):

| Property | Value |
|----------|-------|
| Gap between buttons | `12px` (`--space-3`) |
| Alignment | Right-aligned on desktop, full-width stacked on mobile |
| Order | Secondary → Primary (left to right), Danger always rightmost |

```css
.button-group {
  display: flex;
  gap: var(--space-3);
  justify-content: flex-end;
}

@media (max-width: 639px) {
  .button-group {
    flex-direction: column-reverse; /* Primary on top (thumb zone) */
  }
  .button-group > button {
    width: 100%;
  }
}
```

**Key decision: `column-reverse` on mobile** — the primary action moves to the top of the stack, closer to the user's thumb. This follows Material Design's mobile pattern.

## Transitions

All button state changes use the same transition:

```css
button {
  transition: background-color var(--duration-fast) var(--ease-default),
              border-color var(--duration-fast) var(--ease-default),
              color var(--duration-fast) var(--ease-default),
              box-shadow var(--duration-fast) var(--ease-default),
              transform var(--duration-fast) var(--ease-default);
}
```

`--duration-fast` (100ms) for buttons — interactions must feel instant. 200ms feels sluggish for direct-manipulation elements.

---

## Full-Width Buttons

On mobile forms or when explicitly needed:

```css
.button-full {
  width: 100%;
  justify-content: center;
}
```

Full-width buttons always use medium (40px) or large (48px) size. Never small — a full-width 32px button looks like a misrendered element.

## shadcn/ui Mapping

Both TaxKlaro and Inheritance use shadcn/ui Button. The mapping:

| shadcn variant | Angkin class | Notes |
|---------------|-------------|-------|
| `default` | `.btn-primary` | Navy-600 fill |
| `secondary` | `.btn-secondary` | White + border |
| `ghost` | `.btn-ghost` | Transparent |
| `destructive` | `.btn-danger` | Error-700 fill |
| `outline` | `.btn-secondary` | Same as secondary (shadcn outline ≈ our secondary) |
| `link` | Not a button | Use `<a>` with navy-600 text + underline |

## Anti-Patterns

1. **No gradient buttons** — gradients look like 2015 Bootstrap. Flat navy is the brand.
2. **No pill/fully-rounded buttons** — `border-radius: 9999px` is for badges and tags, not buttons. 8px radius is the ceiling.
3. **No uppercase button text** — CALCULATE reads as aggressive. Sentence case only: "Calculate"
4. **No letter-spacing on button text** — button text uses body tracking (0). Wide-tracked buttons feel like a different app.
5. **No colored text on colored background** — buttons are either solid-fill-with-white-text or transparent/white-with-colored-text. No navy text on gold background.
6. **No animation on click beyond translateY(1px)** — no ripple effects, no scale transforms, no color flashes.
7. **No more than 2 buttons per action group** — if there are 3+ actions, use a dropdown for overflow.
8. **Never put two primary buttons adjacent** — one primary, rest secondary/ghost.

## Accessibility

- **Focus ring**: 2px solid navy-400 with 2px offset. Visible on all backgrounds.
- **Color contrast**: All enabled variants pass WCAG AA. Primary (white on navy-600) = 8.5:1 (AAA). Danger (white on error-700) = 7.8:1 (AAA).
- **Disabled state**: Uses distinct colors (not opacity) so colorblind users can distinguish enabled vs disabled.
- **Touch target**: Minimum 32px height (small), recommended 40px+ for primary actions. Mobile full-width buttons always 48px.
- **Keyboard**: All buttons focusable, Enter/Space activates, focus-visible only on keyboard navigation.
- **ARIA**: Icon-only buttons require `aria-label`. Loading buttons get `aria-busy="true"`.
