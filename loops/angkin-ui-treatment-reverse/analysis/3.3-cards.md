# 3.3 — Cards

## Design Direction

**Cards are the atomic unit of Angkin.** Every tool, every result, every stat, every piece of content lives inside a card. With 148 compliance tools, the card is the most repeated element in the entire system. It must be invisible when doing its job (containing content) and unmistakable when it matters (the result moment).

Four card types, one visual language:
- **Content Card** — the generic container. White rectangle, subtle border, quiet shadow. Used everywhere content needs separation from the page background.
- **Tool Card** — already spec'd in 2.5. This aspect refines states and adds dark mode.
- **Result Card** — the crown jewel. When a user hits "Calculate" and sees ₱45,833.33, that moment lives in a result card. It needs to feel like a payoff, not just another rectangle.
- **Stat Card** — compact, dense, numbers-forward. Used in dashboards, comparisons, and summary grids. 2-4 across in a row.

### Shared Card DNA

All four card types share:
- White surface (`--neutral-0`) on light page background (`--neutral-50`)
- 1px border in `--neutral-200`
- `--radius-lg` (10px) corner radius — cards get the larger radius, distinguishing them from inputs (8px) and badges (6px/pill)
- Navy-tinted shadow (`--shadow-sm`) at rest
- 200ms transitions on border-color, box-shadow, transform
- Dark mode: `--surface-0` (#0B1628) surface, `#1E2D42` border

## 1. Content Card

The default container. Forms, text blocks, settings panels, info sections. It doesn't draw attention — it provides structure.

### Anatomy

```
┌──────────────────────────────────────┐
│                                      │  ← padding: 24px (desktop), 16px (mobile)
│  [Any content — forms, text, etc.]   │
│                                      │
└──────────────────────────────────────┘
```

### CSS

```css
.card {
  background: var(--neutral-0);
  border: 1px solid var(--neutral-200);
  border-radius: var(--radius-lg); /* 10px */
  padding: var(--space-6); /* 24px */
  box-shadow: var(--shadow-sm);
  transition: border-color var(--duration-default) var(--ease-default),
              box-shadow var(--duration-default) var(--ease-default);
}

/* Mobile */
@media (max-width: 639px) {
  .card {
    padding: var(--space-4); /* 16px */
    border-radius: var(--radius); /* 8px — tighter on small screens */
  }
}

/* When content card IS the page (full-width on mobile) */
.card--flush-mobile {
  @media (max-width: 639px) {
    border-radius: 0;
    border-left: none;
    border-right: none;
    margin-left: calc(-1 * var(--space-4));
    margin-right: calc(-1 * var(--space-4));
    padding-left: var(--space-4);
    padding-right: var(--space-4);
  }
}
```

### States

| State | Border | Shadow | Notes |
|-------|--------|--------|-------|
| Default | `--neutral-200` | `--shadow-sm` | Quiet presence |
| Hover (if interactive) | `--navy-150` #C2D0E2 | `--shadow-md` | Only if card is clickable |
| Focus-within | `--navy-400` | `--shadow-sm` | When a child input has focus |
| Active (if interactive) | `--navy-600` | none | Pressed state |
| Disabled | `--neutral-100` bg | none | Content faded, border lighter |

**Key decision: non-interactive cards have NO hover state.** A content card wrapping a form is not clickable — the form fields inside it are. Adding hover effects to non-interactive cards creates false affordances.

### Sectioned Content Card

When a card has distinct sections (e.g., header + body + footer):

```css
.card__header {
  padding: var(--space-4) var(--space-6);
  border-bottom: 1px solid var(--neutral-200);
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: var(--space-3);
}

.card__body {
  padding: var(--space-6);
}

.card__footer {
  padding: var(--space-4) var(--space-6);
  border-top: 1px solid var(--neutral-200);
  display: flex;
  align-items: center;
  justify-content: flex-end;
  gap: var(--space-3);
}

/* Remove padding from root when using sections */
.card--sectioned {
  padding: 0;
}
```

### Dark Mode

```css
[data-theme="dark"] .card {
  background: var(--surface-0); /* #0B1628 */
  border-color: var(--border); /* #1E2D42 */
  box-shadow: none; /* shadows don't read on dark — rely on border + surface contrast */
}

[data-theme="dark"] .card:hover {
  border-color: var(--border-strong); /* #2A3B52 */
}

[data-theme="dark"] .card__header,
[data-theme="dark"] .card__footer {
  border-color: var(--border); /* #1E2D42 */
}
```

**Key decision: no shadow in dark mode.** Navy-tinted shadows are invisible on navy-tinted dark backgrounds. Instead, surface elevation differences and borders create depth.

## 3. Result Card — The Crown Jewel

This is the moment the user came for. They entered their salary, their months worked, their dependents — and now they see the answer. The result card must feel like a payoff: authoritative, clear, unmistakable.

### Design Philosophy

The result card breaks from the quiet restraint of other cards. It earns visual emphasis through:
- **Larger border radius** (`--radius-xl`, 14px) — it's a "feature card" moment
- **Elevated shadow** (`--shadow-md` at rest) — it sits above the page
- **Navy top accent bar** — a 3px navy stripe at the top anchors the brand
- **Peso amount at large scale** — IBM Plex Mono, 32px or larger, navy
- **Semantic borders** for regime comparison (success/warning/neutral)

## Anti-Patterns

1. **No card within card nesting beyond 1 level.** A result card inside a content card is fine. A stat card inside a result card inside a content card is not — flatten the hierarchy.

2. **No full-width cards with rounded corners on mobile.** If a card spans the full viewport width on mobile, use `.card--flush-mobile` to remove side borders and radius. Rounded corners on screen-width elements waste space and look broken.

3. **No colored card backgrounds except semantic variants.** Content cards are white. Tool cards are white. Only result cards get semantic tinted backgrounds (success-50, warning-50) and only when comparing regimes.

4. **No hover animations on non-interactive cards.** If a card doesn't link anywhere, it doesn't hover-scale, hover-shadow, or hover-anything. False affordances are worse than no affordances.

5. **No card header with title AND icon AND description AND badge all competing.** Tool cards have this handled: icon top, name, description, meta. Don't reinvent the hierarchy for custom cards.

6. **No gradient borders on cards.** The navy-600 accent stripe on result cards is the maximum border treatment. Gradient borders read as "try-hard" in an institutional context.

7. **No card carousels.** Grid or stack. Never carousel. Carousels hide content, and compliance results should never be hidden behind a swipe gesture.

8. **No drop-shadow blur above 24px in light mode.** Large blur shadows make cards look like they're floating in space rather than resting on a surface. The shadow scale tops out at `--shadow-lg` (24px blur) for cards.

## Summary

| Card Type | Padding | Radius | Shadow | Border Accent | Interactive? |
|-----------|---------|--------|--------|---------------|-------------|
| Content Card | 24px / 16px mobile | 10px / 8px mobile | shadow-sm | None | Only if clickable |
| Tool Card | 20px | 10px | shadow-sm → shadow-md hover | Navy on hover, gold if featured | Always (links to tool) |
| Result Card | 24px / 16px mobile | 14px / 10px mobile | shadow-md | 3px navy top (or semantic color) | Never (displays results) |
| Stat Card | 16px | 10px | shadow-xs | Optional 3px left (semantic) | Never (displays data) |

**Total new CSS custom properties: ~20**

**Key design decisions:**
- Cards get `--radius-lg` (10px), larger than inputs (8px) and buttons (8px), creating a clear container hierarchy
- Result cards are elevated: larger radius (14px), heavier shadow, navy accent bar — the payoff moment
- Stat cards are compressed: tighter padding, smallest shadow, number-first layout — dashboard density
- No shadow in dark mode — replaced by surface elevation and border contrast
- Tool cards are the only always-interactive card — they get hover/active/focus-visible states
- Content cards are static by default — hover only when explicitly interactive
- Dotted leaders in result card breakdowns connect labels to values across the gap — institutional/tabular feel

---

*Cards defined. Four types sharing one visual language, differentiated by emphasis level. The result card is the hero — it gets the drama. Everything else stays quiet so the numbers can speak.*
