# 4.6 — Mobile Treatments

## Overview

Four mobile mockups at 375×812px viewport covering the key user journeys: discovery (platform home), input (wizard step), output (results page), and navigation (hamburger menu). These demonstrate how the Angkin design system adapts from desktop to mobile while maintaining brand coherence and usability on touch devices.

---

## Mockup 1: Platform Home (mobile-home.png)

**What it shows**: The entry point for mobile users discovering Angkin's 148 tools.

### Key Mobile Adaptations

| Element | Desktop | Mobile (375px) |
|---------|---------|----------------|
| Nav bar | 64px, logo + nav links + actions | 56px, hamburger + centered logo mark + search icon |
| Hero | 48px heading, 96px vertical padding | 24px heading, 48px vertical padding |
| Tool grid | 3 columns, 1120px max | 2 columns, 16px horizontal padding |
| Category filter | Inline below hero | Sticky bottom bar, horizontal scroll pills |
| Search | Icon in nav, opens overlay | Prominent search bar below hero heading |

### Design Decisions

- **Centered logo mark** (no wordmark) — at 375px, the wordmark competes with the hamburger and search icons. The circular mark alone is recognizable at 28px.
- **Search bar visible by default** — on mobile, users can't hover over a nav dropdown to browse tools. The search bar is the primary discovery mechanism, promoted from icon to full input.
- **2-column tool cards** — 3 columns would make cards ~100px wide (too narrow for tool names). 2 columns at ~165px each provides readable card content.
- **Sticky category pills at bottom** — keeps filter accessible during scroll without competing with the nav bar. Horizontal scroll with scroll-snap.
- **Cards show icon + name + description** — no badge, no accent border on mobile. Density is managed by removing secondary information.

## Mockup 2: Wizard Step (mobile-wizard.png)

**What it shows**: Step 3 of the Inheritance Calculator — the Family Tree builder on mobile.

### Key Mobile Adaptations

| Element | Desktop | Mobile (375px) |
|---------|---------|----------------|
| Step indicator | 32px numbered circles + connector lines | Compact text "Step 3 of 6 · Family Tree" + 4px progress bar |
| Content width | 576px narrow centered | Full width, 16px padding |
| Person cards | 2-column grid | Single-column stacked |
| Nav buttons | Flex row (Back left, Continue right) | Column-reverse (Continue on top for thumb zone) |
| Nav position | Sticky bottom bar | Sticky bottom bar, same |

### Design Decisions

- **Text + progress bar replaces numbered circles** — at 375px, 6 numbered circles with labels would be ~60px each = 360px, leaving no breathing room. The compact "Step X of Y · Name" format communicates the same information in 20px height instead of 60px.
- **4px progress bar** — fills proportionally (50% at step 3 of 6). Navy-600 fill on neutral-200 track. Provides at-a-glance progress without cognitive overhead.
- **Single-column person cards** — person cards contain name, relationship badge, and action buttons. At 2 columns, these would be ~165px wide — too narrow for names like "Maria Concepcion Santos-Reyes".
- **Green left border** on person cards marks compulsory heirs — this visual language carries over from desktop unchanged.
- **Column-reverse button layout** — "Continue" appears above "Back" in the sticky footer. On mobile, the primary action should be in the thumb zone (bottom of the reachable area when held one-handed). Column-reverse places Continue visually on top but at the bottom of the DOM for accessibility.

## Mockup 3: Results Page (mobile-results.png)

**What it shows**: TaxKlaro's 3-regime comparison results on a mobile screen.

### Key Mobile Adaptations

| Element | Desktop | Mobile (375px) |
|---------|---------|----------------|
| Regime cards | 3-column side-by-side | Single-column stacked |
| Verdict banner | Full-width bar | Full-width bar (same) |
| Peso amounts | 32px IBM Plex Mono | 24px IBM Plex Mono |
| Breakdown table | Always visible | Collapsed behind "View Full Breakdown" accordion |
| Download CTA | Inline button | Full-width sticky bottom button |

### Design Decisions

- **Stacked regime cards** — the crown jewel of the results page. At 375px, three cards side-by-side would be ~107px each — impossible for meaningful comparison. Stacked cards at full width allow the user to scan top-to-bottom: 8% Flat → Graduated (recommended) → Mixed.
- **Recommended card visual hierarchy** — 3px navy top border + gold "Recommended" pill badge. The navy border is the same as desktop. On mobile, this card also has a subtle navy-50 background tint to further distinguish it from the stack.
- **Collapsed breakdown** — on desktop, the full breakdown is visible below the cards. On mobile, it's behind an accordion ("View Full Breakdown" with chevron). This prevents the results page from being an infinite scroll of numbers. Users who want detail can expand; others get the verdict and comparison in one viewport.
- **Dotted leaders in breakdown** — maintained from desktop. The monospace alignment of peso amounts with dotted leaders (`. . . . .`) is essential for scannability of financial data. Works at 375px because item labels are left-aligned and amounts are right-aligned with `display: flex; justify-content: space-between`.
- **Full-width sticky "Download PDF"** — primary action on mobile results. 48px height, navy-600 fill, full viewport width minus padding.
- **Dollar signs in mockup** — note that the AI-generated mockup shows $ instead of ₱. The actual implementation uses `₱` (Philippine Peso). This is a generation artifact, not a design decision.

## Mockup 4: Navigation Menu (mobile-nav.png)

**What it shows**: The hamburger menu slide-in sheet with tool categories and utility links.

### Key Mobile Adaptations

| Element | Desktop | Mobile (375px) |
|---------|---------|----------------|
| Navigation | Horizontal nav links in top bar | Left-sliding 280px sheet |
| Categories | Mega-menu dropdown (720px) | Vertical list with icons + chevrons |
| Theme toggle | Icon button in nav | List item with toggle in sheet |
| Logo | Horizontal lockup (mark + wordmark) | Larger mark (40px) + wordmark, vertically stacked or horizontal |

### Design Decisions

- **280px sheet width** — leaves ~95px of the backdrop visible on the right, providing spatial context ("I can see the page behind this menu") and a touch target to close the menu.
- **Left-sliding entry** — `transform: translateX(-100%)` → `translateX(0)` with 300ms ease-out. Matches iOS convention for navigation drawers.
- **44px minimum touch targets** — every menu item is at minimum 44px tall per WCAG 2.5.5 (Target Size). The category items have 44px row height with icon + label + chevron.
- **Category icons (Phosphor line style)** — same icons defined in 2.6 (Receipt for Tax, Users Three for Labor, Shield Check for Social Insurance, etc.). Displayed at 20px in neutral-600.
- **Chevron indicates drill-down** — tapping a category navigates to the category page showing all tools in that domain. This replaces the desktop mega-menu's at-a-glance grid, which can't fit at 375px.
- **Dark mode toggle as list item** — instead of an icon button, the theme toggle is a full-width list item with label + toggle switch. This is clearer on mobile where icon-only buttons are harder to discover.
- **Navy-tinted backdrop** — `rgba(11, 22, 40, 0.6)` (not pure black), consistent with modal backdrop from 3.6. Tap to close.

## Cross-Cutting Mobile Patterns

### Safe Area Handling

All sticky bottom elements account for notch/home-indicator devices:

```css
.sticky-bottom {
  padding-bottom: calc(var(--space-3) + env(safe-area-inset-bottom));
}
```

### Touch Target Minimums

Every interactive element meets 44×44px minimum:
- Buttons: 48px height (exceeds minimum)
- Nav items: 44px row height
- Category pills: 32px height but with 6px vertical padding = 44px touch area
- Icon buttons: 44×44px tap area (even if icon is 20px)

### Scroll Behavior

- **Platform home**: natural scroll, category bar sticky at bottom
- **Wizard**: content scrolls between fixed nav (top) and fixed buttons (bottom)
- **Results**: natural scroll with sticky CTA at bottom
- **Nav sheet**: independent scroll within 280px sheet, body scroll locked

### Typography Scale Reduction

| Token | Desktop | Mobile |
|-------|---------|--------|
| Hero heading | 48px | 24px (50% reduction) |
| Section heading | 30px | 22px |
| Card title | 16px | 14px |
| Peso amount (result) | 32px | 24px |
| Body text | 15px | 14px (minimal change) |
| Caption | 12px | 12px (unchanged) |

### Anti-Patterns

1. **No bottom tab bar** — Angkin is not an app store app. A bottom tab bar implies 4-5 top-level sections, but Angkin has 148 tools organized by 14 categories. A tab bar would either be too crowded or too abstract.
2. **No pinch-to-zoom on results** — peso amounts and tables are already responsive. Pinch-to-zoom breaks the sticky footer behavior.
3. **No horizontal scroll for comparison cards** — stacked cards are easier to compare on mobile than horizontally scrollable cards (users can't see all options simultaneously with horizontal scroll).
4. **No floating action button (FAB)** — FABs are for creation-heavy apps. Angkin tools are input → compute → view. The primary action is always "Continue" or "Download", shown in the sticky footer.
5. **No pull-to-refresh** — these are computation tools, not feeds. Results don't change unless inputs change.
