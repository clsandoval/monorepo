# 3.2 — Form Inputs

## Design Direction

**Quiet containers, loud data.** Angkin's form inputs serve 148 compliance calculators where the average tool has 5–15 fields. Inputs must disappear into the background so the user's attention stays on their numbers. No heavy borders, no colorful fills, no decorative affordances. A thin neutral border, clean interior, and a decisive navy focus ring that says "you're typing here."

The existing apps prove this: both TaxKlaro and Inheritance use shadcn/ui primitives with Radix UI. The spec below codifies the exact treatment, unifies inconsistencies between the two apps, and adds compliance-specific patterns (peso inputs, fraction inputs, date pickers).

---

## Input Types

### 1. Text Input — The Default

The foundation. Used for names, addresses, TIN numbers, and any free-text field.

| Property | Value |
|----------|-------|
| Height | `40px` (`--input-height`) |
| Padding | `8px 12px` (`--input-padding-y` `--input-padding-x`) |
| Background | `var(--neutral-0)` #FFFFFF |
| Border | `1px solid var(--neutral-200)` #D5D9E1 |
| Border radius | `8px` (`--radius`) |
| Font | DM Sans, 400 weight, 15px (`--text-body`) |
| Text color | `var(--neutral-900)` #111827 |
| Shadow | `var(--shadow-xs)` — barely visible lift |

**States:**

| State | Background | Border | Shadow | Text | Other |
|-------|-----------|--------|--------|------|-------|
| Default | `--neutral-0` | `--neutral-200` | `--shadow-xs` | `--neutral-900` | — |
| Hover | `--neutral-0` | `--neutral-300` #B8BEC9 | `--shadow-xs` | `--neutral-900` | `cursor: text` |
| Focus | `--neutral-0` | `--navy-600` #1E3A5F | `--shadow-xs` | `--neutral-900` | `outline: 3px solid rgba(30,58,95,0.15); outline-offset: 0` |
| Filled | `--neutral-0` | `--neutral-200` | `--shadow-xs` | `--neutral-900` | Same as default — no special filled state |
| Error | `--neutral-0` | `--error-500` #DC2626 | none | `--neutral-900` | `outline: 3px solid rgba(220,38,38,0.12)` |
| Disabled | `--neutral-100` #EEF0F4 | `--neutral-150` #E3E6EC | none | `--neutral-400` #8C95A3 | `cursor: not-allowed; opacity: 1` |
| Read-only | `--neutral-50` #F7F8FA | `--neutral-150` | none | `--neutral-700` #374050 | `cursor: default` |

**Key decisions:**
- **Shadow-xs at rest** — gives inputs a subtle lift off the page background. This is barely visible but creates a sense of physicality. Inputs are "real things you put data into," not lines painted on a flat surface.
- **Navy-600 focus border, not just a ring** — the border itself turns navy on focus. Combined with the 3px soft navy outline, this creates a decisive "I'm active" state without the harshness of a 2px hard outline. The soft outline (15% opacity navy) acts as a glow.
- **No filled state distinction** — some design systems color the background when an input has a value. This creates unnecessary visual noise in forms with many fields. A filled input looks exactly like a default input.
- **No opacity on disabled** — same philosophy as buttons. Gray background + lighter border + lighter text = clearly disabled without looking broken.
- **Read-only is distinct from disabled** — read-only has a slightly tinted background but text is darker (readable, not grayed out). This is critical for compliance tools where computed/derived values display in read-only inputs.

### 2. Number Input — The Calculator's Input

Used for incomes, amounts, percentages, counts. Identical to text input visually, but with numeric-specific behavior.

| Property | Value |
|----------|-------|
| All visual properties | Same as text input |
| Input mode | `inputMode="decimal"` |
| Text alignment | Left (not right-aligned — we're not a spreadsheet) |
| `font-variant-numeric` | `tabular-nums` |

**Key decision: Left-aligned numbers.** Right-aligned numbers make sense in tables but feel wrong in form fields. Users type left-to-right. A right-aligned input requires visual tracking back and forth. Left-align the input, right-align the result.

### 3. Peso Input — The Star

This is Angkin's signature input. A text input with a ₱ prefix, formatted for Philippine peso amounts. Both apps have custom peso input components — we unify them.

| Property | Value |
|----------|-------|
| Height | `44px` (`--input-height-lg` minus 4px, or custom) |
| Padding left | `32px` (room for ₱ symbol) |
| Padding right | `12px` |
| Prefix | `₱` in `--neutral-400`, positioned absolutely, `font-family: var(--font-mono)` |
| Font | `var(--font-mono)`, 500 weight, 15px |
| `font-variant-numeric` | `tabular-nums` |
| Input mode | `inputMode="decimal"` |

**States:** Same as text input, with these additions:
- On focus: format stripping (show raw number for editing)
- On blur: apply formatting (thousand separators, 2 decimals)
- Prefix stays `--neutral-400` in all states (it's decorative, not interactive)

**Key decision: Monospace font in peso inputs.** Numbers must not shift when values change. Using IBM Plex Mono in peso inputs creates visual consistency between input and result display moments.

### 4. Select — The Chooser

Dropdown selection using Radix Select primitive (already in both apps).

| Property | Value |
|----------|-------|
| Trigger height | `40px` (`--input-height`) |
| Trigger padding | `8px 12px` |
| Trigger background | `var(--neutral-0)` |
| Trigger border | `1px solid var(--neutral-200)` |
| Border radius | `8px` (`--radius`) |
| Chevron icon | `ChevronDown`, 16px, `--neutral-400` |
| Chevron rotation on open | 180° with `--duration-fast` transition |

**Trigger states:** Same as text input.

**Content (dropdown):**

| Property | Value |
|----------|-------|
| Background | `var(--neutral-0)` |
| Border | `1px solid var(--neutral-200)` |
| Border radius | `10px` (`--radius-lg`) |
| Shadow | `var(--shadow-lg)` |
| Max height | `256px` (with scroll) |
| Animation | `slide-in` from trigger edge, `--duration-default` |

**Item states:**

| State | Background | Text |
|-------|-----------|------|
| Default | transparent | `--neutral-900` |
| Hover | `--navy-50` #EEF2F7 | `--neutral-900` |
| Selected | `--navy-50` | `--navy-600` |
| Selected + hover | `--navy-100` | `--navy-600` |
| Disabled | transparent | `--neutral-300` |

**Selected indicator:** Checkmark icon (16px, `--navy-600`) positioned right side of item.

**Key decisions:**
- **Navy-50 for hover, not neutral-100** — the select dropdown is a branded moment. Hover uses the navy tint instead of a neutral gray.
- **Dropdown radius is 10px (radius-lg)** — slightly more rounded than the trigger to create a "floating panel" feel. The trigger matches the input field; the dropdown floats above.
- **No placeholder distinction** — the placeholder text and selected value use the same font weight. If nothing is selected, show placeholder in `--neutral-400`.

### 5. Radio Group — The Regime Selector

Critical for Angkin: tax regime selection, heir type selection, employment type. Radio groups are used when the user must see all options at once.

| Property | Value |
|----------|-------|
| Group layout | Vertical stack, `gap: 12px` (`--space-3`) |
| Item layout | `display: flex; align-items: flex-start; gap: 12px` |
| Radio size (visual) | `20px × 20px` |
| Radio touch target | `44px × 44px` (invisible padding) |
| Border | `2px solid var(--neutral-300)` |
| Border radius | `50%` |

**Radio states:**

| State | Border | Fill | Indicator |
|-------|--------|------|-----------|
| Default | `2px solid --neutral-300` | `--neutral-0` | none |
| Hover | `2px solid --navy-400` | `--neutral-0` | none |
| Focus | `2px solid --navy-600` | `--neutral-0` | `outline: 3px solid rgba(30,58,95,0.15)` |
| Selected | `2px solid --navy-600` | `--neutral-0` | 10px navy-600 filled circle |
| Selected + hover | `2px solid --navy-700` | `--neutral-0` | 10px navy-700 filled circle |
| Disabled | `2px solid --neutral-200` | `--neutral-100` | none |
| Selected + disabled | `2px solid --neutral-300` | `--neutral-100` | 10px neutral-300 filled circle |
| Error | `2px solid --error-500` | `--neutral-0` | `outline: 3px solid rgba(220,38,38,0.12)` |

**Radio with label and description (card variant):**

For regime selection and other important radio choices, radio items become full cards:

| Property | Value |
|----------|-------|
| Card padding | `16px` (`--space-4`) |
| Card border | `1px solid var(--neutral-200)` |
| Card radius | `8px` (`--radius`) |
| Selected card border | `2px solid var(--navy-600)` |
| Selected card background | `var(--navy-50)` |
| Label font | DM Sans, 500 weight, 15px |
| Description font | DM Sans, 400 weight, 13px, `--neutral-500` |

**Key decisions:**
- **2px border on radio circles** — 1px is too thin and looks fragile. 2px gives radios enough visual presence to be clearly interactive.
- **Card variant for important selections** — when choosing between tax regimes (the most important decision in TaxKlaro), radio buttons deserve more visual weight. The card variant wraps the radio in a selectable card.
- **flex-start alignment** — radio dot aligns to the top of the label, not center. This matters when labels wrap to multiple lines.

### 6. Checkbox — The Acknowledgment

Used for "I agree to terms," toggling optional deductions, selecting multiple items.

| Property | Value |
|----------|-------|
| Size (visual) | `18px × 18px` |
| Touch target | `44px × 44px` |
| Border | `2px solid var(--neutral-300)` |
| Border radius | `4px` |
| Check icon | Checkmark, 12px, white, 2px stroke |

**States:**

| State | Border | Background | Icon |
|-------|--------|-----------|------|
| Default | `2px solid --neutral-300` | `--neutral-0` | none |
| Hover | `2px solid --navy-400` | `--neutral-0` | none |
| Focus | `2px solid --navy-600` | `--neutral-0` | `outline: 3px solid rgba(30,58,95,0.15)` |
| Checked | `2px solid --navy-600` | `--navy-600` | White checkmark |
| Checked + hover | `2px solid --navy-700` | `--navy-700` | White checkmark |
| Indeterminate | `2px solid --navy-600` | `--navy-600` | White dash (2px × 10px) |
| Disabled | `2px solid --neutral-200` | `--neutral-100` | none |
| Checked + disabled | `2px solid --neutral-300` | `--neutral-300` | White checkmark |
| Error | `2px solid --error-500` | `--neutral-0` | `outline: 3px solid rgba(220,38,38,0.12)` |

**Key decisions:**
- **18px not 16px** — both apps use `size-4` (16px) from shadcn. This is too small for a compliance platform used in government offices on older monitors. 18px gives better visibility and tap accuracy.
- **4px radius** — slightly rounded corners, not sharp. Matches the 8px radius system (half the base radius for small elements).
- **Indeterminate state** — needed for "select all" patterns in heir lists, deduction groups.

### 7. Toggle / Switch — The On/Off

Used for: dark mode toggle, optional calculation parameters, enabling/disabling sections.

| Property | Value |
|----------|-------|
| Track width | `44px` |
| Track height | `24px` |
| Track radius | `12px` (half of height = pill) |
| Thumb size | `20px × 20px` |
| Thumb radius | `50%` |
| Thumb shadow | `var(--shadow-xs)` |

**States:**

| State | Track | Thumb | Position |
|-------|-------|-------|----------|
| Off | `--neutral-200` | `--neutral-0` | Left (2px inset) |
| Off + hover | `--neutral-300` | `--neutral-0` | Left |
| On | `--navy-600` | `--neutral-0` | Right (2px inset from right) |
| On + hover | `--navy-700` | `--neutral-0` | Right |
| Focus | Track + `outline: 3px solid rgba(30,58,95,0.15)` | — | — |
| Disabled off | `--neutral-150` | `--neutral-100` | Left |
| Disabled on | `--navy-200` | `--neutral-0` | Right |

**Animation:** Thumb slides with `--duration-fast` (100ms), `--ease-default`.

**Key decisions:**
- **44px wide, 24px tall** — standard iOS toggle proportions, which Filipino users are familiar with (iPhone market share >40% in PH).
- **No label inside the toggle** — no "ON/OFF" text inside the track. The position IS the state. Adding text creates translation burden across 148 tools.
- **Navy-600 when on** — the brand color = active. Consistent with checkbox checked state.

### 8. Textarea — The Long-Form

Used for: notes, additional remarks, explanations. Rare in compliance tools but necessary.

| Property | Value |
|----------|-------|
| Min height | `96px` (3× input height) |
| Padding | `12px` |
| Resize | `vertical` only |
| Auto-expand | `field-sizing: content` (where supported) |
| All other properties | Same as text input |

**Key decision: `field-sizing: content`** — this CSS property (supported in Chrome 123+, Firefox 128+) makes the textarea grow with content. Eliminates the resize handle for most use cases while still allowing manual resize as fallback.

## Form Field Anatomy

A complete form field consists of these layers:

```
┌─────────────────────────────────────┐
│ Label ─────────────── [Optional]    │  ← 15px, DM Sans 500
│                                     │  ← 6px gap (--form-label-gap)
│ ┌─────────────────────────────────┐ │
│ │ Input                           │ │  ← 40px height
│ └─────────────────────────────────┘ │
│                                     │  ← 6px gap
│ Help text / Error message           │  ← 13px, DM Sans 400
└─────────────────────────────────────┘
                                         ← 16px gap (--form-field-gap)
                                            to next field
```

### Label

| Property | Value |
|----------|-------|
| Font | DM Sans, 500 weight (`--weight-medium`), 15px |
| Color | `var(--neutral-800)` #1F2735 |
| Required indicator | ` *` in `var(--error-500)` appended to label text |
| Optional indicator | `(optional)` in `var(--neutral-400)`, 13px, `--weight-regular` |

**Key decisions:**
- **Weight 500 for labels, not 400** — labels are the user's navigation through the form. Medium weight (500) gives them enough presence to scan quickly without the heaviness of semibold (600).
- **Required star, not optional tag** — in compliance calculators, most fields are required. Star the exceptions to reduce visual noise. BUT: if more than 50% of fields are optional, flip to marking "optional" and leaving required unmarked.

### Help Text

| Property | Value |
|----------|-------|
| Font | DM Sans, 400 weight, 13px (`--text-small`) |
| Color | `var(--neutral-500)` #6B7485 |
| Position | Below input, 6px gap |
| Max width | same as input |

Help text provides context: "Enter your gross annual income before deductions" or "Must match your BIR-registered TIN."

### Error Message

| Property | Value |
|----------|-------|
| Font | DM Sans, 400 weight, 13px (`--text-small`) |
| Color | `var(--error-600)` #B91C1C |
| Icon | `WarningCircle` (Phosphor), 14px, `--error-500`, inline before text |
| Position | Below input, replaces help text when error is active |
| Animation | `fadeIn` 150ms — errors should appear, not pop |

**Key decision: Error replaces help text, doesn't stack.** Showing both creates visual clutter and makes the form jump. When an error is active, it provides the necessary context; the help text is redundant.

## Form Layout Patterns

### Single Column (Default)

```
[Label]
[Input ──────────────────────────────── ]
[Help text]

[Label]
[Input ──────────────────────────────── ]
[Help text]
```

Used for: wizard steps, simple calculators, mobile layouts. Max width: `--content-narrow` (576px).

### Two Column

```
[Label]              [Label]
[Input ──────────]   [Input ──────────]

[Label]              [Label]
[Input ──────────]   [Input ──────────]
```

Used for: related field pairs (First/Last name, Start/End date), income + deduction side by side. Grid with `--grid-gap-default` (16px). Collapses to single column below 640px.

### Field Groups

```
GROUP HEADING ────────────────────────

[Label]
[Input ──────────────────────────────── ]

[Label]
[Input ──────────────────────────────── ]

                              24px gap (--form-group-gap)

GROUP HEADING ────────────────────────

[Label]
[Input ──────────────────────────────── ]
```

Groups are separated by `--form-group-gap` (24px). The group heading uses `--text-h4` (17px, semibold).

### Inline Fields

```
[Label]  [Label]  [Label]
[₱ Input]  [÷]  [Input]  [=]  [₱ Result]
```

Used for: fraction inputs (Inheritance), compound calculations. `display: flex; gap: 8px; align-items: flex-end`.

## Accessibility

- **Focus indicators**: 3px soft outline (15% opacity navy) + solid border color change. Visible on all backgrounds, both light and dark mode.
- **Touch targets**: All interactive controls have minimum 44px × 44px touch target area (radio/checkbox use invisible padding extension).
- **Color + shape**: Error states use both red color AND a different outline style. Never color alone.
- **Screen readers**: Labels use `<label htmlFor>` association. Error messages use `aria-describedby`. Required fields use `aria-required="true"`. Invalid fields use `aria-invalid="true"`.
- **Keyboard**: Tab navigates between fields. Space/Enter toggles checkboxes/switches. Arrow keys navigate radio groups. Escape closes select dropdowns.
- **Contrast**: All text passes WCAG AA. Placeholder text (`--neutral-400` on white) = 4.2:1 — borderline AA. Help text (`--neutral-500` on white) = 4.6:1 — passes AA.

---

## Anti-Patterns

1. **No floating labels** — they shrink to unreadable sizes, break screen readers, and add animation complexity for zero UX benefit in form-heavy apps.
2. **No underline-only inputs (Material style)** — they're ambiguous. Is it a link? A heading? An input? A full border makes the input container clear.
3. **No colored input backgrounds** — some design systems tint inputs by state (green for valid, red for error). This creates a Christmas tree effect in forms with many fields. Only the border changes color.
4. **No input icons on the right** — the right side is reserved for select chevrons, password toggles, and clear buttons. Decorative icons go on the left (like the ₱ prefix).
5. **No custom scrollbars in selects** — browser-native scrollbars are more predictable. Custom scrollbars break on mobile and confuse accessibility tools.
6. **No auto-complete dropdown styling beyond shadcn** — auto-complete is a Radix Combobox concern. Don't reinvent it.
7. **No inline validation on every keystroke** — validate on blur (field level) or on submit (form level). Keystroke validation annoys users who are still typing.
8. **No max-width on individual inputs** — inputs always fill their container. Layout constrains width, not the input itself.
