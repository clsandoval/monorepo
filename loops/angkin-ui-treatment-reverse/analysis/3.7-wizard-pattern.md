# 3.7 — Wizard Pattern

## Design Direction

**Wizards are the backbone of Angkin.** 43% of the 148 tools are single-form calculators, but the complex flagship tools (TaxKlaro: 14 steps, Inheritance: 6 steps) live or die on the wizard experience. A compliance wizard isn't a checkout flow — it's a guided interview where each answer reshapes what comes next. The user needs to know three things at all times: where am I, how far along, and can I go back?

Two existing patterns diverge: TaxKlaro uses a flat percentage bar ("Step 5 of 11"), Inheritance uses numbered circles connected by lines. The Angkin system unifies these with **a single wizard pattern that scales from 3 steps to 15+ steps** without breaking.

**Core decision: horizontal numbered steps on desktop, compressed progress bar on mobile.** Numbered steps give orientation (I'm on step 3 of 6). Connected lines give momentum (I've completed this path). But at 10+ steps, horizontal circles overflow — so the step indicator becomes scrollable with the current step centered, and mobile always collapses to a compact bar.

## Step Progress Indicator

### Desktop (≥ 768px) — Numbered Steps

```
  ✓ ─────── ✓ ─────── 3 ─────── 4 ─────── 5 ─────── 6
Estate    Decedent  Family   Will &    Donations  Review
Details   Details    Tree    Dispositions          & Config
```

Each step is a numbered circle connected by horizontal lines. Completed steps show a check icon. The current step is highlighted. Future steps are muted.

#### Step Circle Specs

| State | Circle BG | Circle Border | Icon/Number | Text Color |
|-------|-----------|---------------|-------------|------------|
| **Completed** | `--navy-600` | `--navy-600` | Check icon, white, 14px | `--neutral-700` |
| **Current** | `--neutral-0` (white) | `2px solid --navy-600` | Number, `--navy-600`, weight-600 | `--navy-700`, weight-600 |
| **Upcoming** | `--neutral-0` (white) | `2px solid --neutral-300` | Number, `--neutral-400`, weight-500 | `--neutral-400` |
| **Error** | `--error-50` | `2px solid --error-500` | Exclamation icon, `--error-500`, 14px | `--error-600` |

| Property | Value |
|----------|-------|
| Circle size | `32px` × `32px` |
| Circle radius | `var(--radius-full)` |
| Number font | DM Sans, 14px, weight-500/600 |
| Check icon | Phosphor `ph-check`, 14px, weight bold |
| Step label font | DM Sans, 12px (`--text-caption`), weight-400/600 |
| Step label margin-top | `var(--space-2)` (8px) |
| Label max-width | `80px`, centered, truncated with ellipsis if longer |

#### Connector Line Specs

| Segment | Background |
|---------|-----------|
| Between two completed steps | `--navy-600` |
| Between completed and current | Left half `--navy-600`, right half `--neutral-200` (gradient stop at 50%) |
| Between current and upcoming | `--neutral-200` |
| Between two upcoming steps | `--neutral-200` |

| Property | Value |
|----------|-------|
| Height | `2px` |
| Min width | `40px` |
| Flex | `1` (stretches to fill available space) |
| Vertical alignment | Center of step circles |

#### Overflow Behavior (10+ Steps)

When steps exceed the container width:
- The step indicator becomes horizontally scrollable (`overflow-x: auto`)
- Scroll snap: `scroll-snap-type: x mandatory` with each step as a snap point
- Current step is always scrolled into center view on mount and step change
- Subtle gradient fade masks on left/right edges when content overflows
- Hide scrollbar: `-webkit-scrollbar { display: none }`, `scrollbar-width: none`
- On step change, `scrollIntoView({ behavior: 'smooth', inline: 'center' })`

This handles TaxKlaro's 14 dynamic steps gracefully — the user sees 5-7 steps at a time with the current step centered.

### Mobile (< 768px) — Compact Progress Bar

On mobile, numbered circles don't fit. The step indicator collapses to a compact bar:

```
┌──────────────────────────────────┐
│  Step 3 of 6 · Family Tree       │
│  ████████████░░░░░░░░░░░░░░░░░░  │
└──────────────────────────────────┘
```

| Property | Value |
|----------|-------|
| Container padding | `var(--space-3) var(--space-4)` (12px 16px) |
| Container background | `var(--neutral-50)` |
| Container border-bottom | `1px solid var(--neutral-200)` |
| Step text | DM Sans, 13px, weight-500, `--neutral-500` — "Step 3 of 6" |
| Step label | DM Sans, 13px, weight-600, `--neutral-800` — current step name |
| Separator | " · " between step text and label |
| Progress bar height | `4px` |
| Progress bar margin-top | `var(--space-2)` (8px) |
| Progress bar track | `--neutral-200`, `var(--radius-full)` |
| Progress bar fill | `--navy-600`, `var(--radius-full)` |
| Progress bar transition | `width 400ms var(--ease-default)` |
| Fill percentage | `(currentStep / totalSteps) × 100%` |

**Why this mobile pattern?** The Inheritance app's numbered circles shrink to unreadable blobs on 375px screens. A text label + progress bar gives the same information (where am I, how far) in a fraction of the vertical space, leaving more room for the actual form content — which is what matters on a small screen.

## Step Content Area

The step content area sits between the progress indicator and the navigation buttons. It's where the actual form fields, radio cards, or informational content live.

### Desktop Layout

```
┌─────────────────────────────────────────────────────┐
│  ┌─ Step Indicator ───────────────────────────────┐  │
│  └────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─ Step Content ─────────────────────────────────┐  │
│  │                                                 │  │
│  │  Step Title                                     │  │
│  │  Step description or instructions               │  │
│  │                                                 │  │
│  │  ┌─ Form Fields ─────────────────────────────┐  │  │
│  │  │  Label                                     │  │  │
│  │  │  [Input field                            ] │  │  │
│  │  │                                            │  │  │
│  │  │  Label                                     │  │  │
│  │  │  [Input field                            ] │  │  │
│  │  └────────────────────────────────────────────┘  │  │
│  │                                                 │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─ Navigation ───────────────────────────────────┐  │
│  │  [← Back]                       [Continue →]   │  │
│  └────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

| Property | Value |
|----------|-------|
| Content max-width | `var(--content-narrow)` (576px) — wizards use narrow width |
| Content centering | `margin: 0 auto` |
| Content padding-top | `var(--space-8)` (32px) desktop, `var(--space-5)` (20px) mobile |
| Content padding-bottom | `var(--space-8)` (32px) — space before nav buttons |
| Content padding-x | `var(--container-padding-desktop)` (32px) desktop, `var(--space-4)` (16px) mobile |
| Step title | Plus Jakarta Sans, `--text-h2` (28px), weight-700, `--neutral-900` |
| Step title margin-bottom | `var(--space-2)` (8px) |
| Step description | DM Sans, `--text-body` (15px), weight-400, `--neutral-500` |
| Step description margin-bottom | `var(--space-6)` (24px) |
| Field spacing | `var(--space-4)` (16px) between fields, `var(--space-6)` (24px) between field groups |
| Min height | `calc(100vh - 64px - 80px - 72px)` — viewport minus nav, step indicator, wizard nav |

### Scroll Behavior

- The step content area scrolls independently if it overflows
- Navigation buttons remain visible (sticky at bottom or always visible)
- On step transition, scroll to top of content area

### Step Transition Animation

When navigating between steps, the content area transitions:

| Direction | Animation |
|-----------|-----------|
| Forward (Next) | Current step slides left + fades out. New step slides in from right + fades in. |
| Backward (Back) | Current step slides right + fades out. New step slides in from left + fades in. |
| Duration | `250ms` |
| Easing | `var(--ease-default)` |

```css
@keyframes step-exit-left {
  from { opacity: 1; transform: translateX(0); }
  to { opacity: 0; transform: translateX(-24px); }
}

@keyframes step-enter-right {
  from { opacity: 0; transform: translateX(24px); }
  to { opacity: 1; transform: translateX(0); }
}

@keyframes step-exit-right {
  from { opacity: 1; transform: translateX(0); }
  to { opacity: 0; transform: translateX(24px); }
}

@keyframes step-enter-left {
  from { opacity: 0; transform: translateX(-24px); }
  to { opacity: 1; transform: translateX(0); }
}
```

**24px, not 100px.** Subtle directional hint, not a carousel. The user should feel like they're stepping forward or back, not watching slides fly by.

The wizard navigation sits below the step content. It's the most-tapped area of the wizard.

### Desktop Layout

```
┌──────────────────────────────────────────────────┐
│  [← Back]                          [Continue →]  │
└──────────────────────────────────────────────────┘
```

### Mobile Layout

```
┌──────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────────┐│
│  │              Continue →                       ││  ← Primary, full width
│  └──────────────────────────────────────────────┘│

│  │              ← Back                           ││  ← Ghost, full width
```

| Property | Value |
|----------|-------|
| Container max-width | `var(--content-narrow)` (576px), centered |
| Container padding | `var(--space-4) var(--container-padding-desktop)` desktop, `var(--space-4)` mobile |
| Container border-top | `1px solid var(--neutral-100)` |
| Desktop layout | `display: flex; justify-content: space-between; align-items: center` |
| Mobile layout | `display: flex; flex-direction: column-reverse; gap: var(--space-2)` |

### Button Variants by Position

| Position | Variant | Size | Icon | Label |
|----------|---------|------|------|-------|
| **Back** (not first step) | Ghost | Medium (40px) | `ph-caret-left` before text | "Back" |
| **Back** (first step) | Hidden or disabled | — | — | — |
| **Continue** (not last step) | Primary | Medium (40px) | `ph-caret-right` after text | "Continue" |
| **Continue** (last step) | Primary | Medium (40px) | `ph-check` after text | "Review" or "See Results" |
| **Submit** (review step) | Primary | Large (48px) | `ph-calculator` after text | "Calculate" or "Compute" |

### Mobile: Column-Reverse

On mobile, the button order is `column-reverse` so the primary "Continue" button sits higher (closer to the thumb zone) while "Back" sits below it. This follows the same pattern established in the modals (3.6) — primary action nearest to the thumb.

### Continue Button Loading State

When the Continue button triggers validation or async operations:

| State | Background | Text | Icon |
|-------|-----------|------|------|
| Loading | `--navy-400` | Hidden | 16px spinner (CSS `@keyframes spin`) |
| Disabled by validation | `--navy-200` | `--navy-400` | Caret icon at 50% opacity |

## Validation States

Wizards validate at two moments: (1) on blur for individual fields, and (2) on "Continue" click to block forward navigation if the step is invalid.

### Per-Field Validation

Uses the form input error states defined in 3.2 (red border, error message below field). No change here — the wizard doesn't introduce new field-level validation UI.

### Step-Level Validation (On Continue)

When the user clicks "Continue" and the step has errors:

1. **Scroll to first error** — the first invalid field scrolls into view with `scrollIntoView({ behavior: 'smooth', block: 'center' })`
2. **Shake the Continue button** — a single 300ms horizontal shake animation to signal rejection without an alert
3. **Show all field errors** — all invalid fields display their error messages simultaneously
4. **Focus first error field** — after scroll completes, focus moves to the first invalid input

```css
@keyframes button-shake {
  0%, 100% { transform: translateX(0); }
  20% { transform: translateX(-4px); }
  40% { transform: translateX(4px); }
  60% { transform: translateX(-3px); }
  80% { transform: translateX(2px); }
}

.btn--shake {
  animation: button-shake 300ms var(--ease-default);
}
```

### Step-Level Error Summary (Optional, for 5+ Errors)

When a step has 5+ validation errors (common in TaxKlaro's financial input steps), show a summary banner above the form:

```
┌───────────────────────────────────────────┐
│  ⚠ 5 fields need attention               │
│  • Gross receipts is required             │
│  • Returns cannot exceed gross            │  ← Clickable — scrolls to field
│  • Cost of sales must be ≥ 0             │
│  ...                                      │
└───────────────────────────────────────────┘
```

| Property | Value |
|----------|-------|
| Background | `--error-50` |
| Border | `1px solid --error-200` |
| Border-left | `3px solid --error-500` |
| Border radius | `var(--radius-md)` (8px) |
| Padding | `var(--space-3) var(--space-4)` (12px 16px) |
| Title | DM Sans, 14px, weight-600, `--error-700` |
| List items | DM Sans, 13px, weight-400, `--error-600`, clickable (underline on hover) |
| Icon | Phosphor `ph-warning`, 18px, `--error-500` |
| Margin-bottom | `var(--space-4)` (16px) |
| Animation | Slide down + fade in, 200ms |

### Conditional Step Indicator (Error State)

When the user navigates back from a later step and an earlier step has become invalid (due to conditional logic changes), the step indicator shows the error state: pale red circle with exclamation icon. The user must fix that step before proceeding.

## Conditional Steps

Both TaxKlaro and Inheritance use conditional steps — steps that appear or disappear based on prior answers. The wizard pattern must handle this gracefully.

### How It Works

1. Each step has an optional `condition` function: `(formData) => boolean`
2. `computeVisibleSteps(allSteps, formData)` filters to currently-visible steps
3. The step indicator dynamically re-renders when visible steps change
4. Step numbers update (no gaps — if step 4 hides, old step 5 becomes new step 4)

### Visual Behavior on Step Change

When a step appears or disappears:
- **Step appears**: The new circle + line animate in with `opacity 0→1, width 0→auto` over 300ms. Adjacent lines stretch to accommodate.
- **Step disappears**: The circle + line animate out with `opacity 1→0, width auto→0` over 300ms. Adjacent lines compress.
- **Current step index adjusts**: If the user was on step 5 and step 3 disappears, they're now on step 4. The indicator updates instantly; no jarring jump.

### Conditional Step Notification

When a conditional answer changes visible steps, show a brief toast:

> **"Added step: Will & Dispositions"** (when `hasWill` toggled on)
> **"Removed step: 8% Flat Rate Election"** (when conditions no longer met)

Toast specs: 300ms appear, 3 second display, 300ms fade out. Positioned below the step indicator. Neutral background with info icon.

### Sticky Behaviors

| Element | Sticky | Border |
|---------|--------|--------|

| Property | Value |

| Position | Inside the wizard nav container, right-aligned, vertically centered |

## Real-World Examples

### TaxKlaro (14 Steps, Dynamic)

```
Steps: Mode → Taxpayer → Business → Tax Year → Gross → [Compensation] →
       Expense Method → [Itemized A] → [Itemized B] → [Itemized C] → [NOLCO] →
       CWT → [Prior Quarterly] → Registration → [8% Election] → Filing → Credits → Review
```

- Steps in brackets are conditional — typically 8-11 visible at once
- Step indicator scrolls horizontally, centering the current step
- The "Review" step uses a different layout (full summary, no form fields) but stays within the wizard chrome
- Submit button on review: "Calculate My Tax" with `ph-calculator` icon, Large size

### Inheritance (6 Steps, One Conditional)

```
Steps: Estate Details → Decedent Details → Family Tree → [Will & Dispositions] → Donations → Review & Config
```

- Always 5-6 visible steps — comfortably fits without scrolling
- The Family Tree step is the most complex: dynamic heir addition with cards
- Will step appears/disappears with toast notification
- Submit button on review: "Compute Estate Tax" with `ph-calculator` icon, Large size

### Generic Single-Form Tool (3 Steps)

Many of the 148 tools are simple enough for a 3-step wizard:

```
Steps: Input → Review → Results
```

- Step indicator shows all 3 steps without scrolling on any device
- Mobile still uses progress bar (consistency across all wizards)
- The "Results" step isn't technically a wizard step — it's a new page. The wizard covers Input → Review only.

## Anti-Patterns

1. **No vertical step list on desktop** — vertical step indicators waste horizontal space and break the left-to-right progression metaphor. Vertical is only for mobile, and even then we use a progress bar instead.
2. **No clickable step circles to jump** — clicking a completed step to jump back invites data loss if the user skips the review of intermediate changes. Use the Back button to navigate step-by-step. Exception: allow clicking the immediately-previous completed step as a "Back" shortcut.
3. **No "Save & Exit" button in the wizard nav** — auto-save handles persistence. A save button implies the data might be lost, creating anxiety.
4. **No progress percentage text on desktop** — "67% complete" is meaningless when steps have vastly different complexity. The numbered circles give better orientation.
5. **No skip button** — every visible step is required. Conditional logic hides irrelevant steps; it doesn't make them optional.
6. **No wizard inside a modal** — if the workflow needs a wizard, it needs a page. Modals are for single-decision moments.
7. **No horizontal scrolling form fields** — if a step's form content is too wide, restructure the fields vertically. Only the step indicator may scroll horizontally.

## Summary

| Element | Desktop | Mobile |
|---------|---------|--------|
| Step indicator | Numbered circles + connectors, horizontally scrollable at 10+ steps | "Step X of Y · Name" + 4px progress bar |
| Step content | 576px max-width, centered, 32px padding | Full width, 16px padding |
| Navigation | Flex row: Back (ghost) ← → Continue (primary) | Column-reverse: Continue on top, Back below |
| Validation | Scroll to first error + button shake + field errors. 5+ errors show summary banner. |
| Auto-save | "Saving..." / "Saved ✓" indicator in nav area, 12px text |
| Transitions | 24px horizontal slide + fade, 250ms, direction matches navigation |
| Dark mode | Navy-400 circles/fill, surface-0 backgrounds, #1E2D42 borders |

**~45 new CSS custom properties.** The wizard pattern is the most complex component in the system but follows the same visual language: navy-600 primary actions, DM Sans text, Plus Jakarta Sans headings, 8px rhythm, subtle navy-tinted shadows.
